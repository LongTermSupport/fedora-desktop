## 12:32 · finding · T5.5   — headless none boxes fail at the signing assert; gated on a declared state

A downstream deployment that provisions headless servers with
`RUN_BASH_GITHUB_ACCOUNTS=none` fails every provisioning run in `playbook-main.yml`, at
"Assert the Signing Key Is a Private File With Its Public Half Beside It": `/home/<user>/.ssh/id must be a regular file at mode 0600`. run.bash then reports HEADLESS PROVISIONING FAILED.

Two contracts contradict each other:

- run.bash's none path (Plan 00082) generates no login key on purpose ("no GitHub identity
  means no need for a login SSH key") and writes `github_accounts: {}`.
- Task 5.1 made the signing tasks in `play-git-configure-and-tools.yml` unconditional: they
  stat and assert `git_signing_key_path` (default `~/.ssh/id`) on every machine. Before
  `6001a540` they were gated on `git_signing_key is defined`.

The same play already treats "no accounts" as a declared state: its retire block runs when
`github_accounts` is undefined or empty.

Fix: `vars/git-signing.yml` gains `git_signing_declared`, true when `git_signing_key` is
defined, `github_accounts` is undefined, or it has an account. The seven signing tasks (stat,
assert, probe, assert, slurp, record, git_config) move into one block gated on it. So only
the explicit `github_accounts: {}` with no `git_signing_key` opts out. An undeclared
`github_accounts` keeps today's behaviour, so a desktop with a missing key still fails
loudly. The gate never asks whether the key file exists, because that would turn a lost key
into silent unsigned commits.

`scripts/test-git-signing-declared.bash`, a hard gate in `qa-all.bash`
(`git-signing-declared`), has three parts:

1. It evaluates the real `git_signing_declared` with ansible for five declared states.
2. It checks that every task touching the key, the recorded public key or `gpgsign` is inside
   the one gated block.
3. It lifts that block out of the play unchanged and runs it with git's HOME and the
   host_vars file in a temp directory.
   - none: runs clean, no signing config, no public key recorded
   - desktop with a passphrase key: `commit.gpgsign`, `tag.gpgsign`, `gpg.format`,
     `user.signingkey` set, public key recorded once
   - desktop with its key missing: fails at the key assert

Red against the old play: 8 of 8 failed (the gate undefined, the seven tasks listed as
ungated). Green after: 21 of 21. With the gate forced to `true`, exactly two cases fail: the
none verdict, and the none run, which fails with the same `must be a regular file at mode 0600` message the downstream box saw.

The test uses a throwaway `ANSIBLE_CONFIG`, not the repo's: `play_ledger` would record the
runs, and the vault password file would be needed to start. Part 3 needs
`community.general`, as `ansible-syntax` already does.

Other plays on the none path in `playbook-main.yml`:

- `play-github-cli-multi.yml` ends the play before its signing block when gh is not
  authenticated or `github_accounts` is empty.
- `play-basic-configs.yml` copies `~/.ssh/id` to root only when it exists.
- `play-git-hooks-security.yml` only installs the secret-scanning hooks.
- The self-update play needs the owner's public key, not this machine's.
- ccy's `configure_git_signing` returns early when `commit.gpgsign`/`tag.gpgsign` are off, so
  a none box's launches are not refused.

No other unconditional dependency on `~/.ssh/id` was found. Nothing after this assert in
`playbook-main.yml` has run on a headless none box since `6001a540`, so the rest of the path
is proven only by a real none provisioning run. The `server-fast-provision` and
`server-full-provision` VM scenarios provision exactly this path (`vmtest` defaults to
`RUN_BASH_GITHUB_ACCOUNTS=none`).

Not handled: a none box whose `~/.gitconfig` already carries `commit.gpgsign = true`, from a
hand edit or an earlier identity, keeps it. The play does not unset settings it did not
write on that run.
