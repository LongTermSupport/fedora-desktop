## 07:18 · decision · —   — Owner: a signing key per GitHub account, registered by IaC

The owner ruled again on Task 1.3: "GH key signing IS NOT JUST FOR THIS REPO / if we are doing it we can do it PROPERLY" and "you can make different keys / WE ALREADY DO THIS". The global `commit.gpgsign` signs every repo on the machine, and `gh-switch <alias> --update-git` sets a repo's email to that account's address. So one key registered on one account leaves most commits Unverified. Task 1.3 is rewritten to follow the existing `github_<alias>` auth-key pattern: `play-github-cli-multi.yml` generates and uploads a signing key per account, git picks it with `includeIf` on the `github.com-<alias>` remote, ccy stages the resolved key, and `admin:ssh_signing_key` joins the shared scope audit. A worktree fork is implementing it. The earlier fork's reasoning (one account only, keep the scope out of the shared list) is withdrawn.
