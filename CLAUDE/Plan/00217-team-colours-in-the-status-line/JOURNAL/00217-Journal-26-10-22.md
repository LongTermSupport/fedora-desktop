## 16:05 · decision · —   — The override travels as admin room state

How the override reaches every member's status line. Three routes were weighed.

- A key of the team record: rejected. `protocol.parse_team_record` refuses an unknown key, and the
  syncer then loses trust in the room and stops the team (`syncer._lose_trust`), so every member on
  an older pingbus (a ccy session started before the image rebuild, a running host session) would
  stop the moment a colour was set. The description stays out of the record for the same reason
  (protocol.py: it travels as the room topic).
- A file in the member kit, written by the play: rejected. The ccy image bakes the kit in, and the
  launcher rebuilds the base image only for a new CCY version or Dockerfile, so a ccy session
  would not see a changed colour; members on other machines never would.
- An admin-written room state event, `agent_bus.colour`, read by the syncer into
  `state/colour.json` like the topic into `about.json`: chosen. `state_default` 100 means only the
  admin writes it, an older member's sync filter never asks for it, and a bad one is no colour,
  never a loss of trust.

Palette measured with a scratch script (contrast against five dark backgrounds, HSV hue, CIE76
pairwise distance): ten colours from teal to pink, lowest contrast violet on #2e3440 at 4.59:1,
closest pair blue and indigo at 16.0 ΔE. Silver and ice were dropped: silver reads as default text,
ice is 20 from mint.
