## REFUTED (most consequential first)

1. **R1. "`system.Life` gains a fourth answer, declared served elsewhere" (D2).** `Life` already has
   four cases (`src-go/internal/teams/system/lifecycle.go:25-36`): status record (installed), no
   record and declared absent (removed), no record and declared present (not installed), no record
   and no entry (served elsewhere). The new answer would be a fifth, or a split of the fourth
   ("no entry" becomes "declared `served_by`" or "undeclared"). Change: say "splits the last
   answer in two" or "gains a fifth". Low consequence for the design, but the plan's own D5 text
   ("declared-not-installed", "undeclared-remote") already uses the split, so D2's count is the
   odd one out.

2. **R2. RESEARCH.md section 6 cites `seatadd.go:100` for the real argument shapes.** The file is
   `src-go/internal/teams/seatadd/seatadd.go` (the plan gives no directory, so the bare name does
   not resolve to one file). The line is right: line 101 is the `argv` of `SudoIssuer.Issue`. Weak
   refutation: a path-resolution defect, not a content one. Change: give the full path.

3. **R3. RESEARCH.md section 6 cites `admin/verbs.go` `memberFlags` for `member add --seat <n>`
   and "flags come in any order, each at most once".** `memberFlags` is at
   `admin/verbs.go:130`; `OpMemberAdd` is `{keyPrefix, keySeat, keyKind, flagHumanText, keyCredential}` (verified, `--team` is separate). The "any order, each at most once" part I did
   not find stated in `memberFlags`; it is `parseFlags` (verbs.go:317), which I did not read to
   its end, so that clause is UNVERIFIABLE-HERE (see row 17), not refuted. Listed here only so the
   reviewer knows the argument for "no `*` is narrow" leans on that unread behaviour.

(R2 and R3 are minor. R1 is the only content refutation.)

## Notes for the plan author

- The rule path `/usr/local/sbin/teamchat-admin` is a symlink that `play-teamchat.yml` creates
  (`ansible.builtin.file state: link`). sudo resolves the symlink and matches the rule's path
  against the command as typed (and a canonicalised path in some versions); this needs checking in
  acceptance, since a rule naming the link can fail where one naming the target works. This is not
  a refutation, only a gap the plan does not name.
- `Life` and the `declare` reader changes are in `src-go/internal/teams/system` and
  `src-go/internal/teamchat/declare`: two different packages (teams v1/teamchat v2 split), so
  Task 2.2 touches both.
