## 16:05 · decision · P1 — the once-a-day gate lives in Python, keyed on the message, not the day alone

Considered a stamp in the bash snippet. Put it in `login_message --once-a-day` instead:
the snippet stays the thin sourced file its test already pins, and the gate's rules are
unit-tested. The stamp holds the day and a hash of the rendered message, so the same
findings on the same day are one line and changed findings are the full report at once —
a document rewritten by the collector is news whatever the clock says. An unwritable or
corrupt stamp prints in full: the cost of that mistake is noise, the cost of the other is
a finding nobody saw. `--on-demand` never touches the stamp, so asking a direct question
cannot make the next login shell go quiet.

## 16:40 · finding · T1.3 — qa-reviewer BLOCK: the command swallowed the report's exit status, and `-m` shadowed the checkout

The reviewer caught `status=$?` inside an `if ! …; then` branch, where it is always 0, so
a failing report exited 0. Fixed with `|| status=$?`. Writing the gate case for it found a
second defect no reading had: `python3 -m` puts the caller's directory first on sys.path,
ahead of PYTHONPATH, so the new case passed from the repository root by importing the
real helpers instead of the broken stub — and on a host, a terminal open in any project
with a `helpers/` directory would have imported that project's code. Both templates now
run `python3 -P -m`, and the gate runs the broken-checkout case from the repository root
as well as from elsewhere. Also from the review: a clean host with sub-day clock skew was
told "collected -1 days ago"; the reminder said "1 item still need attention" and folded
not-checked lines into a count that reads as faults, so it now counts faults and unchecked
items apart; the qa-all header tally and CLAUDE/QA.md's gate counts were re-derived from a
run (44 gates, 45 stage names); the snippet gate header no longer says "server".
