# Plan 00098 — Journal 2026-09-17

## The gate named its own remedy and had no way to apply it

A batch run of every in-progress plan's scripts put this plan's `acceptance.bash` on the
host. Check 5 ("desktop store contained") failed: one directory under the Claude Code
state directory was group/other-accessible, so files below it were reachable by other
local users. The finding printed the exact playbook that fixes it.

Nothing ran that playbook, because this plan shipped no `deploy.bash`.

That is the whole defect. Under a `deploy → acceptance` harness a plan with only the
second half fails identically on every run, for ever, and each run reads as a fresh
finding rather than as the same fix nobody applied. The failure was real — the
permissions genuinely were loose — which is what made it easy to keep re-reading instead
of resolving.

Added `deploy.bash`, built on `_planlib.inc.bash` per the script standards: host-only,
one leg running `play-claude-code.yml`. That play already owns this exact ground — it
finds state entries carrying group or other permissions, restricts them while preserving
owner execute bits, and then asserts that none remain. So the remedy needed writing down,
not inventing.

The next batch run deploys before it judges, and check 5 either passes or names a
different problem.
