## 15:45 · action · —

DESIGN.md written (Task 1.1) on branch design/seat-broker. Key choices: one Go broker per host running as the existing agent-bus user; it mints only at collect, by running the existing admin zipapp (add-member --seat --out=-) with a fixed argv, so no privilege changes hands and registry.json keeps one writer. Approval is root through sudo (desktop launcher, ccy-teams) first and a team human's `approve <code>` in the room second; the 50-bit pairing code is computed from the requester's own keys and shown only where the request was made, which defeats a swapped key and a wrong-request approval. The bundle is sealed to the requester's X25519 key; the client is a static Go binary in the kit because Python's stdlib lacks the crypto. Handles are derived on the requesting side by ccy's rule (owner direction); the broker checks the repo is in the team's scope but cannot prove the checkout is that repo, and says why that is acceptable. Re-joins use an Ed25519 member key kept in the bundle directory; existing LXC members enroll a key with their valid token, then agent_bus_lxc_members is retired. 13 owner decisions in section 13. ## 16:01 · decision · T1.2   — design revised after the Fable review

DESIGN.md revised after the Fable review (verdict REVISE, report in subagent-reports/261014-fable-review-design.md); Task 1.2 done. The design shrank: the lasting Ed25519 member key, broker.json seat bindings, the rejoin (`/token`) and enroll (`/enroll`) endpoints and the enroll decision are gone, because the key outlived park and rotate-token and bought nothing a rebuilt container keeps. Keys are now per request and discarded after collect; a client reuses its bundle and token as ccy does today, and a failed token means a new request and a new approval, so park-member and rotate-token stay authoritative and the LXC migration needs no step. The desktop no longer runs a device flow against itself: root mints through the socket with `sudo agent-bus-broker ctl mint ... --out=-`, outside the request pools.

Added: every broker response is signed with an Ed25519 key whose public half ships in the kit (`broker.pub`), and the client refuses unsigned or badly signed answers (bridge MITM in the threat model); sealing pinned (HKDF info, zero nonce per derived key, mandatory body hash); request pools per arrival interface with flood audit lines capped per team, stating that spoofed sources defeat per-address limits; room approval off by default (any process of the desktop user can read the Element session) and never for a request from the host; ccy inside LXC (type podman, numbered by checkout.py's rule) separated from an agent-bus-claude LXC member (type lxc, named seat); `--address` mapped from the arrival interface to a team listen address; wrong codes refuse nothing and code collisions are ambiguous; unit device dependencies; seat reservations against a concurrent sudo mint; decision 7 now says play-agent-bus.yml must gain a Go build.
