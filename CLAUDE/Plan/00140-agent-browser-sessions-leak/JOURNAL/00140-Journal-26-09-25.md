## 11:32 · finding · T1.1   — every session name is a new Chromium, and upstream tells agents to make one

Measured with `agent-browser-headless` and `agent-browser-lite-headless` only (agent-browser
0.38.1), counting daemons and browser roots from `/proc`. A browser root is a chrome process
with no `--type=` argument.

**Each session name is its own daemon plus its own Chromium.** Reusing a name reuses the browser.

```
A1 default session, first open       daemons=1 chrome_roots=1 chrome_procs=13
A2 default session, second open      daemons=1 chrome_roots=1 chrome_procs=15
B1 --session task-a                  daemons=2 chrome_roots=2 chrome_procs=28
B2 --session task-b                  daemons=3 chrome_roots=3 chrome_procs=42
B3 AGENT_BROWSER_SESSION=task-c      daemons=4 chrome_roots=4 chrome_procs=56
C1 after bare `close`                daemons=4 chrome_roots=3   (only `default` closed)
C2 after `close --all`               chrome_roots=0             (one daemon still exiting)
```

**`session id --scope worktree --prefix task` depends on the cwd**, and the prefix is chosen
per task. From two directories the same prefix gave two different ids
(`task-<hash1>`, `task-<hash2>`), and `--prefix research` gave a third.

**Upstream's core skill, which our skill sends agents to first, says "Always use your own
session"** and has them `export AGENT_BROWSER_SESSION="$(agent-browser session id --scope worktree --prefix task)"`. Claude Code's Bash tool keeps no env between calls. So the next
call without the export lands on `default`, which is a second browser, and a later bare
`close` only closes that one.

Other facts the design depends on:

- `session` prints the session a command would target (flag anywhere in argv, env, config)
  and starts no daemon. `--json session list` gives `{"data":{"sessions":[...]}}`.
- Any command on a session that is not live starts a browser. `get url` on a new name did.
- The list is scoped by namespace: a live headless session does not appear in lite's list.
- A session closed with `close --all` stays listed for about 160 ms (3 of 3 rounds).
- The two probes together cost about 4 ms.
- The idle reaper works: with `AGENT_BROWSER_IDLE_TIMEOUT_MS=4000` the lite daemon and
  Lightpanda were gone within 8 s.

## 11:32 · decision · P1   — reaper covers headed; guard the wrapper, not a Claude hook

Upstream `cli/src/native/daemon.rs` at v0.38.1 (fetched with `gh api`) has
`IdleTimeout { is_default }`, with the comment "Only the default exempts headed and
user-attached browsers from shutdown". So the image's explicit
`AGENT_BROWSER_IDLE_TIMEOUT_MS=300000` does reap headed windows too. The reaper is not
broken. It cannot bound the count, because every new session starts its own five-minute
timer.

ccy settings: `entrypoint.sh` symlinks `/root/.claude` to the project's
`/workspace/.claude/ccy`. A container-level Claude hook would therefore have to be
merged into every project's settings by the entrypoint. That is Decision 2 in PLAN.md,
and it is rejected in favour of a guard in the wrapper (Decision 1).

The failsafe recovery cron was not created: this is a subagent, and the coordinator's
session owns its crons.

## 12:08 · finding · T3.2   — review round 1: the CLI is last-wins, so wrapper flags could be overridden

The first qa-reviewer pass returned FIX-BEFORE-MERGE. Its main finding was right:
**the CLI is LAST-wins for a repeated flag**, the opposite of what the Dockerfile said.

Re-measured here, launching nothing (`session`, `session info` only):

```
--session a --session b --json session        -> "session":"b"
--session=zz --json session                   -> "Unknown command: --session=zz", rc 1
--namespace headless --namespace escaped      -> "namespace":"escaped"
```

`--headed` was then measured with no display reachable, so no window was possible:
`WAYLAND_DISPLAY` and `DISPLAY` unset, an empty `XDG_RUNTIME_DIR`, and
`AGENT_BROWSER_NO_XVFB=1`.

```
--headed false                  open rc=0, root carries --headless=new
--headed false --headed true    open rc=1, "Chrome exited early" (it tried a headed launch)
--headed true --headed false    open rc=0, root carries --headless=new
```

So, before this fix, `agent-browser-headless --headed true open ...` would have opened a
window on the desktop. The Dockerfile had claimed a caller-supplied `--headed` could not
flip the mode. Its old measurement used a bare `--headed` followed by `open`, which is not
the same argv.

Fixed (PLAN.md Decision 3):

- The guard refuses (exit 2) a caller's copy of any flag the wrapper sets, derived from
  the wrapper's own argv.
- It forwards every `--session`, and a caller's `--config`, to its probes.
- A failing probe's own JSON error is included in the message.
- The cap is validated only when it is used, so a bad value no longer blocks `close`.
- The refusal, the skill, CCY-GUIDE and docs now say `--session <name> close`, not
  `close --all`.
- The skill has agents name their session on every command, because on `default`
  parallel agents share a browser without noticing.

Evidence:

- The fake binary is now last-wins and rejects `--session=`, as measured.
- The suite has 51 cases. Against the previous guard, 11 of them fail: every new hole,
  plus the changed close advice.
- `acceptance.bash --checkout` against the real binary: 16 of 16. The new checks are a
  repeated `--session` ending in a new name (exit 3) and a caller `--namespace` (exit 2).

Left as advisories:

- The pass-through list does not include `auth list`, `dashboard`, `confirm`/`deny` or
  `mcp`. A refusal there is loud, not a leak.
- The version stays at patch level (3.67.5), as the coordinator asked. Semver would call
  this minor.
