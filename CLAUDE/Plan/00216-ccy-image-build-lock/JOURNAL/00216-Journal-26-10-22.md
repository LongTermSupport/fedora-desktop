Findings on the way:

- Probe of bash: `cmd {fd}>&-` on a function call closes the lock descriptor for every program
  the function starts, while the shell keeps a saved copy marked close-on-exec, so the shell
  still holds the flock. The suite's "a child the build leaves behind" case proves it.
- The project image's hash files were written after `run_project_build` returned, outside the
  lock: a waiter re-checking at once would have rebuilt. They are now written inside it.
- The difftest's missing-image scenario built the image twice (first-time build, then a version
  rebuild of the fake's unlabelled image); it now builds once.
- The first lock library was over the bash limits (74 code lines); the start-time check moved
  to the Go reader (D5), which verifies a pid against the build's start.
