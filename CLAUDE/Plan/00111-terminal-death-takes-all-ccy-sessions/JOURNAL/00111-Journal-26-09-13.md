## 13:49 · finding · T1.3 — container survival is a red herring

Three of four CCY containers survived; `container-A` was killed and
removed. All four logged the same `Failed to write to remote console socket`,
so the console failure is not the discriminator — the foreground `podman run`
client is. The survivors' `conmon` has **ppid 2266 (`systemd --user`)** in its

`podman` client (pid 3892681) was still alive in a dying tab and ran its normal

So survival was incidental, not designed. **And it bought nothing**: all three
survivors sit at `TTY = ?`, `Ssl+`, in `ep_poll` — alive with no pty and
nothing on their stdio, so `podman attach` reaches a process that cannot be
driven.

The chain shows why:

```
ptyxis-spawn-<uuid>.scope → bash → podman run → [container] → claude-supervise.py (pts/0) → claude
```

Decisive conclusion: **the pty is what must outlive the terminal, not the
container.** Detaching the container is ruled out as a defence.

## 14:25 · decision · Phase 3 — tmux, inside the launcher, on CCY's own server

**3.1 tmux, not `systemd-run --pty`.** A transient unit keeps the *process* alive
but `--pty` forwards the terminal through the `systemd-run` client, which dies
with the tab; there is nothing to re-attach to afterwards. tmux is the only
option where re-attaching is the design, and Plan 00105 already installs and
configures it.

**3.2 Inside the launcher, not the `ccy` alias.** The alias seam looked
convenient but the launcher is the only place that knows which of its own
modes start a session: `--top`, `--help`, `--create-token`, `--headless` and
friends must not be wrapped (their output would vanish with the session, and
headless has no terminal at all). Every no-session mode has already exited by
the point after `--update-token`, so the re-exec goes there: after parsing,
before the first prompt. Protection is automatic; nothing for the user to
remember. This is the reversal of 00105's "no wrapper" — argued on one fact:
a terminal-emulator death now costs whole sessions, which 00105 never weighed.

**Own server, own scope.** Sessions live on a dedicated socket (`tmux -L ccy`),
and the client that creates the server runs under `systemd-run --user --scope`.
Verified by experiment: the server's cgroup is then
`user@1000.service/app.slice/ccy-tmux-<pid>.scope`, not the tab's
`ptyxis-spawn-*.scope`. A shared default server would sit in whichever tab
happened to start it, which is the exposure being removed. The image already
ships `tmux-256color` terminfo, checked with `infocmp` inside it.

**3.3 Naming mirrors containers.** `ccy-<project>`, then `ccy-<project>-2`, …
using the same `get_project_name` the container name comes from. Second
`ccy` in a project while the first is *attached* starts a new session; while
one is *detached* it re-attaches — a detached session is by definition one a
dead terminal left behind, or one the user parked on purpose. Arguments to a
re-attaching `ccy` are announced as not applied.

**3.4 No reaper.** A session ends when the launcher exits, so there is nothing
to reap in the normal case; a session that outlives its terminal is the whole
point and must not be reaped. `tmux -L ccy ls` shows what is parked. YAGNI.

**4.2 `--rm` stays.** With the pty owned by the tmux server, the `podman run`
client no longer dies with the tab, so the `--rm` teardown only runs when
`claude` itself exits. No launcher change and no conflict with Plan 00079.

**Acceptance cannot kill Ptyxis** — that would take down the user's real
terminals. It uses a throwaway pty from Python's `pty` module as the emulator
stand-in and SIGKILLs it, which delivers the identical pty hang-up the real
crash did. `script(1)` would have done but is not installed. Task 5.2 remains
the real Ptyxis kill, run by hand at a convenient moment.
