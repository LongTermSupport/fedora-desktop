## 01:03 · finding · T3.4 — the skip count read the whole capture, and both decoys beat it

The timestamp problem the previous day-file's closing entry admitted resolves itself here:
this is a new day-file, so the first honest stamp has nothing to overshoot. `date` reads
01:03 and that is what this says. Yesterday's file ends with entries stamped 01:02–01:04
that were invented; they stay as they are, because the journal is append-only.

The round-3 prompt I wrote asked one question about my own round-2 fix: the skip count came
from `[[ "$helper_out" =~ skipped=([0-9]+) ]]` against the **entire** captured output, and
`=~` takes the first match anywhere. A line earlier in the capture containing the text would
win the match ahead of `unittest`'s result line. I wrote in the prompt that I had not tested
it. Measured both ways before changing anything:

```
OLD code, decoy warning line : 99 (should be 2)
OLD code, decoy skip reason  : 42 (should be 1)
```

Reachable, then — and by the most ordinary route imaginable. A skipped test in this suite
prints its own reason, and this plan's Task 3.1 *wrote three of those reasons*. One of them
mentioning a count would have silently replaced the number on the stage line. The failure
mode is the one this whole plan is about: a line that looks like a measurement and is not,
with nothing to distinguish it from the real thing.

The count now comes from `unittest`'s own `^(OK|FAILED)` result line — the only place it is
authoritative — and is only then matched:

```
OK                                                         -> 0
OK (skipped=1)                                             -> 1
OK (skipped=1, expected failures=1)                        -> 1
FAILED (failures=1, skipped=3)                             -> 3
decoy: warning line says skipped=99, result says 2         -> 2
decoy: a skip REASON contains skipped=42                   -> 1
```

Six shapes, four real and two adversarial, all correct. A real local run still reports
`helper-tests: Ran 1456 tests, 1 skipped`, so the hardening is not paid for with a
regression.

**`TOOL_ABORT` re-verified against the source rather than against my memory of it.** Round 2
found the `no-run-summary` guard refusing `qa-all.bash`'s `exit 2` paths. The fix added a
pattern, and a pattern is worth only what it matches, so it was checked against every
`ERROR:` string the script can actually print — grepped out of `qa-all.bash`, not recalled:

```
True  ERROR: Missing required tools (ansible-playbook). Install them and re-run.
True  ERROR: Missing required tools (node / extensions node_modules). Install them and re-run.
True  ERROR: Missing required tools (semgrep). Install with: pipx install semgrep

True  ERROR: Missing required tools. Install them and re-run.

overlaps a stage line? False False
unrelated ERROR ignored? True
```

All six terminal states recognised, no overlap with a stage verdict in either direction, and
an unrelated `ERROR:` line still leaves the capture judged truncated — which it would be.
