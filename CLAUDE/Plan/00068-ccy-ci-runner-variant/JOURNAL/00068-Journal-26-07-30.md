## 09:05 — Renumbered 00066 → 00068 to clear a cross-branch collision

The plan number collided. This plan was scaffolded as **00066** on branch
`plan-00066-ccy-ci-runner`; independently, `F44` took **00066** for
`00066-ftp-camera-airbnb-wifi-and-hotspot-triage`. Both are real plans with real history, and
the collision is invisible while the branches are apart — it surfaces the moment they meet, where
plan-QA's `no-new-collisions` and `row-folder-bijection` checks reject it.

**This one moved, not the other, for two reasons.** The ftp-camera plan is already merged into
the default branch, so renumbering it would rewrite shared history; and the owner asked for this
one to move, since this agent owns it. 00067 was unavailable —
`Completed/00067-qa-gates-inert-in-nested-checkout` holds it — so **00068**.

**What the counter did and did not do.** `hooksdaemon.latestPlanNumber` read 67, which is
consistent with both 00066 and 00067 having been handed out. The counter is per-clone git config;
it serialises allocation *within* a checkout and cannot see a number another branch took. So this
is not a case of the counter being ignored — it is the counter working as designed and the design
not covering concurrent branches. Worth recording rather than filing as operator error.

The journal body is the important "left alone". Day-files are append-only by rule, and renaming a
file preserves its content while rewriting it would destroy the record of what was actually
written at the time. The correction is this entry plus the note in PLAN.md's header — never a
retroactive edit. Anyone reading `00068-Journal-26-07-29.md` will see 00066 throughout and should
read it as this plan under its old number.
