## 08:49 · decision · T3.2 — the desktop interactive check is human-only by definition, and the plan now says so

Task 3.2 sat marked ⬜ among tasks that are genuinely waiting on automation, which reads
as "not done yet" when the accurate reading is "no script can ever do this". Re-marked 🧑
with the reason stated in the task itself.

The argument is short and it is not going to change: an automated scenario cannot answer
"does this still prompt correctly", because driving the prompts is exactly what makes a
run non-interactive. The lab cannot help — `vmtest:918` sets `RUN_BASH_HEADLESS=1` for
every guest, and `desktop-fresh-install` is no exception, so the desktop scenario
exercises the interactive path precisely as little as the server ones do.

This matters for how the plan is read at a glance. 00063 stays In Progress on Tasks 3.3
and 3.4, which wait on a human running the opt-in `server-github-token` scenario with a
scoped PAT — real work with a real route. Task 3.2 waits on a person sitting at a desktop
reading prompts, and nothing in this repo will ever tick it. Leaving both in the same
visual state invites someone to go looking for the automation gap in 3.2 and find nothing,
which is the failure mode this entry exists to prevent.
