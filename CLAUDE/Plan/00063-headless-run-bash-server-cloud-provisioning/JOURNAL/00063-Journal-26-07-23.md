## 07:41 · decision · T1.4 — round-1 judgement (per finding)

**CONFIRMED blockers (folded into Design v2):**
- **GH auth is a `gh` OAuth device flow, not a bash prompt** (both, B1). `gh auth
  login`/`--web` (run.bash:1076/1111, gh-account-setup:297/328) — no read-helper
  touches it; `RUN_BASH_GITHUB_ACCOUNTS` = usernames, can't authenticate. THE
  central gap. → **D3**: `gh auth login --with-token` from a scoped token file;
  setting it makes `gh auth status` pass, skipping the whole interactive auth +
  SSH-confirm loop. Single-account v1; multi = per-alias token files, fail-fast.
- **Direct `sudo` starts at :906, before the Ansible --ask-become-pass logic**
  (AuditCoverage B2, AuditSecurity S2). Password-sudo + no TTY hangs at step 1.
  → **D4**: startup NOPASSWD probe, fail-fast; drop --ask-become-pass headless.
- **Secrets in env/user-data persist** (AuditSecurity B2/B3): user-data.txt +
  metadata service world-readable forever; /proc/environ child inheritance. →
  **D2 + Decision 4**: `0600` file-pointer vars (`*_FILE`), bytes never in env.
  Refinement of owner's env decision — path via env, secret via file. Owner FYI.
- **root refusal vs cloud-init-is-root** (AuditSecurity B4) → **D8**: run as
  non-root user; secret FILES cross the sudo boundary cleanly.
- **Failed main playbook → exit 0** (AuditCoverage B4): continue-anyway default-yes
  masks failure. → **D7**: headless failure ⇒ exit non-zero.
- **Auto-generate vault password footguns** (AuditCoverage B3 + AuditSecurity S1):
  corrupts an imported `!vault` config; unretrievable on ephemeral box. → **D6**:
  require+verify when `!vault` present; auto-generate only fresh, surfaced.
- **ssh-agent-less passphrase clone** (AuditCoverage S1): `~/.ssh/id` forces a
  passphrase, no agent anywhere → clone prompts. → **D5**: passphrase-from-file +
  ssh-agent, or passphraseless.

## 08:16 · decision · T1.4 — round-2 judgement → Design v3 deltas (all CONFIRMED)

**BLOCKER (AuditSecurity #1): `write_files` re-persists secrets in user-data.**
cloud-init `write_files` content lives *inside* the user-data blob → the `0600`
file I write is safe but the user-data copy is served by the metadata service
forever. My own v2 cloud-delivery example defeats Decision 4. → **v3**: secrets
must be **out-of-band** on cloud (runcmd fetch from a secrets store / vendor-data /
attached media), NEVER user-data/write_files. Plain **Server** (SSH-in) case:
operator drops `0600` files directly — no user-data — fine.

**BLOCKER-adjacent, both agents' #1 pick: `gh auth refresh` device-flow still
fires** at `run.bash:1111` AND `gh-account-setup.bash:328` when the token lacks a
REQUIRED_SCOPE — token pre-auth only skips `gh auth login`, not scope-triggered
`--web` refresh → HANG. → **v3 D3**: explicit **token-scope completeness gate**
against the FULL `vars/github-required-scopes.yml` + `admin:public_key`, checked
**before both** refresh sites, fail-fast naming missing scopes. Also: single-account
still routes through `--setup-all` (guard at 1487 = `grep github_accounts`, always
written) so it needs the same gate (AuditCoverage b).

**Reintroduced leak (both, #4/#d): D6 prints generated vault password to stderr** →
lands in `/var/log/cloud-init-output.log` + serial console (provider-captured). →
**v3 D6**: headless **requires `RUN_BASH_VAULT_PASSWORD_FILE`, fail-fast, NO
auto-generate**; never print secret bytes (only the path). Resolves S5/D6 tension.

**Secret files not trap-cleaned (AuditSecurity #2):** EXIT trap (`:56`) only rms
`/tmp/.github_ssh_pp`; a `set -e` abort leaves the new `*_FILE` secrets on a
persistent box. → **v3**: extend EXIT trap to rm all secret paths (trap-visible
array). Also pre-existing: `gh-account-setup.bash:211-232` mktemps a
passphrase-stripped private key, rm'd but not trap-guarded — fix too.

**gh persists token in `~/.config/gh/hosts.yml` (AuditSecurity #3):** deleting the
token file is false assurance. → **v3**: recommend fine-grained short-lived PAT +
`gh auth logout` at end; document `vault-pass.secret` as a standing key on a
persistent box.

**ssh-agent lifecycle underspecified + self-contradictory (AuditCoverage a) — the
messiest area:** `ssh-add` has NO argv passphrase flag → needs an `SSH_ASKPASS`
helper (itself a passphrase-echoing surface) or it HANGS; agent lifetime must span
to the `git pull` at `:1508` not just clone `:1159`; teardown (`ssh-agent -k`)
unspecified; passphraseless fallback contradicts the M2 non-empty invariant
(`:973-980`) AND leaves a standing passphraseless GitHub **auth** key at rest —
inconsistent threat model. **S3 argv exposure UNRESOLVED & genuinely hard**
(`ssh-keygen -P/-N` only take argv) — accept as *stated residual* on a dedicated
same-uid box, or go passphraseless. This is a genuine owner tradeoff (→ surface).

**`sudo -k -n true` not bare (both, #5/nit)** + document NOPASSWD:ALL assumption
(command-scoped NOPASSWD passes `true` probe, fails `dnf`).

**Optional-playbook failures still exit 0 (AuditCoverage B4-residual):**
`run_playbook` (1593-1600) swallows; D7 covers only main. → **v3 D7**: headless
optional failures propagate to a non-zero final exit.

**Passphrase handoff to gh-account-setup still env (AuditCoverage e):** `:1492`
passes `GITHUB_SSH_PASSPHRASE=` literal env; child inherits via /proc — the
Decision-4(b) exposure. → **v3**: teach gh-account-setup a `*_FILE` input (or
