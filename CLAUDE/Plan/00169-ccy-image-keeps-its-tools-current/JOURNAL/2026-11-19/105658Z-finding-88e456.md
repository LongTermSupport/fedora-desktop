Open gap: the ansible venv is unpinned everywhere.

- `.qa-versions` holds no ANSIBLE key, so none of its four consumers pins it: `play-python.yml` on the host, `.claude/ccy/Dockerfile`, `.github/workflows/qa.yml`, and the qa-toolchain assertion.
- run.bash's fresh install (`pipx install --include-deps ansible`) is unpinned too.
- A fresh install therefore lands on the newest ansible. CI's QA (diff) job installed ansible 15.0.0 / ansible-core 2.22.0, and the ccy image carries the same.
- A dependent project's vault-decrypt wrapper cannot use ansible-core 2.22 or later. A host reached 2.22 through shutdown-with-update's `pipx upgrade-all`. It was brought back to 2.21.5 by hand, and its venv was pinned with `pipx pin ansible`, so upgrade-all now skips it.
- Not changed: pinning CI and the image would be an upgrade-policy change, and the owner ruled against drift into upgrades.
- If this is taken up, the existing pattern is a pin in `.qa-versions` (all four consumers and the gate's pinned-tools list), plus a converge in run.bash before ansible starts. A play cannot replace the venv it runs from, and run.bash is on the bash-limits ratchet.
