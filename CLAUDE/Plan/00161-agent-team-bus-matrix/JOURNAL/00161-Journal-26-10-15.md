# Plan 00161 — Journal 26-10-15

_Scaffolded by `mkplan.bash`; timestamps in this file are UTC._

> **Append-only activity log** for plan 00161. One file per day
> (`00161-Journal-YY-MM-DD.md`). `PLAN.md` tracks the plan (what/why,
> current state, tasks); this journal tracks what actually *happened* —
> findings, decisions, dead-ends, hand-off state — the linear lifecycle a plan
> document structurally cannot carry.
>
> **Entry grammar** — append new entries at the BOTTOM; NEVER edit earlier
> entries (corrections are new entries):
>
> ```
> ## HH:MM · category · REF   — optional short title
> ```
>
> - `HH:MM` UTC 24h (the date is in the filename, also UTC); times increase
>   down the file. A file with no sentinel line above predates this system —
>   its times are local, zone unrecorded (legacy; never rewritten).
> - `category` ∈ `action` | `finding` | `decision` | `thought` | `blocker` | `handoff`
> - `REF` = optional task/phase ref (`T1.2`, `P1`) or `—`.
> - Bodies may embed fenced logs/diffs/snippets — no size limit — with a
>   one-line takeaway above the fence.
> - End a working session with a `handoff` entry so the next agent's entry
>   point is the last entry of the newest day-file.

## 12:02 · finding · —

U23.lxc failed on the 26-10-15 acceptance re-run: the lxc member's `pingbus suggest-handle`
exited 126, `env: 'pingbus': Permission denied`. The kit file modes were never the cause: the
installer puts pingbus 0755 and `helpers/agent_bus_lxc/members.py` sets 0755 explicitly.

The host run's umask changed. Every `_meta-deploy` and acceptance run directory up to 26-10-14
is 0755 with 0644 files; from the first 26-10-15 run they are 0700 with 0600 files, so the
owner's runs now start under umask 077 (the `cc` wrapper sets it, so a shell from a desktop
Claude session would carry it). sudo ORs its own 022 with the caller's umask and lxc-attach
keeps it, so root in the LXC member ran under 077 too. The acceptance's README step 1 copy
made the kit parent with `mkdir -p` and extracted with tarfile's "data" filter, which drops
directory modes and creates directories with the umask: both came out 0700, and the agent
user could not reach the symlink's target. docker and vm members start their own processes
and do not inherit it (they were not reached this run: lxc runs first and failed fast).

Fix: `U23_KIT_UNPACK_PY` in `_acceptance-u23.inc.bash` sets the parent and every kit directory
0755 explicitly and fails if the tar made no pingbus. `test_u23_kit_unpack.py` runs the
snippet as the include defines it under umask 077. It skips in the ccy container, whose
Python 3.11.2 has no extraction filters; run it on the host. Pending: acceptance.bash.
