## 08:24 · finding · —   — The GitHub SSH timeouts were ssh's DSCP marking, dropped by the Wi-Fi access point

The host's ssh timeouts to GitHub had nothing to do with the agent, the keys or ccy's forwarding. OpenSSH marks its packets with a DSCP priority by default (IPQoS ef cs0), and the Wi-Fi access point the desktop was on dropped frames in those priority queues. Every ssh connection from the host therefore timed out at the TCP connect, on port 22 and on 443 alike. Unmarked traffic crossed the same link: plain TCP, curl, gh and the rootless containers. The fix is in ccy 3.91.3 (commit 8dd6cabb). play-basic-configs.yml deploys /etc/ssh/ssh_config.d/40-ipqos.conf with IPQoS none, and ccy's GitHub probe passes -o IPQoS=none itself, because its -F /dev/null also drops the system config. The ssh-agent triage has served its purpose and leaves the meta-deploy list. The next host run is the basic-configs play, so every host ssh gets the setting, followed by this plan's full run, whose acceptance resumes at U20 and goes on to U23.

## 17:34 · decision · —   — Owner question: agent-to-agent free text on Matrix

OWNER QUESTION, open (raised 26-10-12, by voice): should agents be able to talk to each other in
free text on the team's Matrix room? The owner's concern: pings must reference forge content, so
agent-to-agent exchanges would push every message onto GitHub (issues, comments, commits), flooding
it, and the conversation would be scattered instead of showing up in context in the room.

Agent's analysis given to the owner: D13 (agent text reaches no agent) exists to stop prompt
injection spreading laterally, by acting only on human text or on pings whose reference resolves to
content on a trusted branch. Where agents push straight to the default branch, that gate is mostly
friction: the receiving agent reads the sending agent's words either way, by a longer route.
Recommendation: allow agent-to-agent free text, delivered by pingbus only to the agents it mentions
and labelled as peer information, not instructions; only a named human's text carries authority;
keep pings for structured actions (review, ack, waking an idle session) with forge refs where a
real artefact exists; keep the secret-shaped refusal on send and the rate and size limits;
consider Matrix threads per topic. Routing through the ccy supervisor would add a hop without
changing the trust question. Adopting it reverses D13 and changes privacy check P6, pingbus
delivery and labelling, PROTOCOL.md and the acceptance. Awaiting the owner's decision.

## 17:51 · decision · —   — ccy-teams revised: a ccy-sessions-style manager; teams already restore at boot

CORRECTION and owner revision of the ccy-teams request (same day). The earlier entry said a reboot
leaves sessions to be relaunched: wrong. `ccy-sessions restore` (the boot unit) replays each
recorded session's arguments, and files/var/local/claude-yolo/lib/session-registry.bash keeps
--teams among CCY_REGISTRY_KEEP_VALUE_FLAGS, so a ccy session in a team comes back after a reboot
in the same seats, history included, with no sudo (the seat exists). Only --no-restore keeps one
out.

Owner's direction: ccy-teams is to teams what ccy-sessions is to sessions, an interactive manager
over what already persists, not a launcher. No `join` verb (ccy --teams is the launch), no
`resume` verb (reboot restore does it), and control of restore lives in ccy-teams. `create` asks
for no port: it picks one no declared team and no listener uses.

Revised shape: `ccy-teams`, a picker in ccy-sessions' style, lists each team on this host (its
homeserver up or down; its members: ccy seats, LXC and host members, active or parked; for a seat,
the ccy session holding it and whether that session is restored at boot). Keys: Enter attaches to
the seat's session (through ccy-sessions); Ctrl-N starts a ccy session in a free or new seat of
that team in the current project (runs ccy --teams); Ctrl-R toggles that seat's session's restore
(the registry's --no-restore); Ctrl-X removes a seat or parks a member after a yes/no; Ctrl-E
opens the team in Element (password first if none). `ccy-teams -l` prints the table; `ccy-teams create` (name, humans, repos; port automatic) writes the agent_bus_teams entry into localhost.yml
and tells the owner to run meta-deploy; backup/restore stay on-machine until the owner answers the
backup question. To build after the LXC-member and agent-text units merge.

## 17:45 · decision · U22.lxc   — existing LXC containers join by IaC

The owner wants their existing LXC containers joined to a team by IaC, not by following
README.lxc by hand. Built `agent_bus_lxc_members` (untracked host_vars, documented in
`localhost.yml.dist`) and `helpers/agent_bus_lxc/members.py`, run by `play-agent-bus.yml`.

Where it sits: tasks in `play-agent-bus.yml`, not a play of its own. A member needs its
team installed in the same run (present entries run after the team step), and a member
leaving needs its team still running to park its handle (absent entries run before any
team is removed). `playbook-main.yml` already runs the LXC play before this one. A
separate play would have had to repeat the team list and the ordering.

How it stays idempotent: every member gets a fixed seat (by default the container's name,
which never collides with the counter's numbers), so its handle
`<repo>.<seat>+<host>.lxc` is known before anything is made. A bundle that names that
handle, holds a token, matches the bus address and `human_text`, and whose handle is
active in `agent-bus list` is left alone. Otherwise the stale bundle is removed, an active
handle parked, and `add-member --seat` returns it (or adds it) with a new token. A role
change is only `set-role`. An absent entry parks, removes the bundle, and takes the team
out of PINGBUS_TEAMS; the env file's other lines and teams are kept.

How the doc and the play cannot drift: the helper runs README.lxc's steps, in its order,
with the same commands (`pingbus suggest-handle` as the agent user in its checkout,
`agent-bus add-member`, `pingbus config check`). README.lxc and `docs/agent-bus.md` name
the play as the route on a fedora-desktop host. `config check` runs on every play run,
which is the deploy-time check.

It refuses, before it changes anything: a missing or stopped container, a missing agent
user, a team not declared present or whose homeserver is not active, a container whose
route to the bus address is not a bridge, and an `allow_from` that does not cover the
container's address. That last message names the bridge's CIDR to add.

The kit is synced into the container by content: only differing files are written, files
the host's kit lacks are removed, and an existing `/usr/local/bin/pingbus` that is not the
kit's link is refused.

Not done: a host run with a real container. U23's acceptance is unchanged; it still joins
its throwaway container by hand-written steps.
