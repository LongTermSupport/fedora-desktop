## 08:24 · finding · —   — The GitHub SSH timeouts were ssh's DSCP marking, dropped by the Wi-Fi access point

The host's ssh timeouts to GitHub had nothing to do with the agent, the keys or ccy's forwarding. OpenSSH marks its packets with a DSCP priority by default (IPQoS ef cs0), and the Wi-Fi access point the desktop was on dropped frames in those priority queues. Every ssh connection from the host therefore timed out at the TCP connect, on port 22 and on 443 alike. Unmarked traffic crossed the same link: plain TCP, curl, gh and the rootless containers. The fix is in ccy 3.91.3 (commit 8dd6cabb). play-basic-configs.yml deploys /etc/ssh/ssh_config.d/40-ipqos.conf with IPQoS none, and ccy's GitHub probe passes -o IPQoS=none itself, because its -F /dev/null also drops the system config. The ssh-agent triage has served its purpose and leaves the meta-deploy list. The next host run is the basic-configs play, so every host ssh gets the setting, followed by this plan's full run, whose acceptance resumes at U20 and goes on to U23.
