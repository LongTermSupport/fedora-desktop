## 13:20 · decision · —   — FOR THE OWNER: acceptance lends the desktop gh login to its throwaway members

FOR THE OWNER: acceptance.bash lends the desktop user's gh login to the members it makes.

With D66 every member needs gh logged in, including acceptance's throwaway members (M1's
two DynamicUser members on the host, U23's LXC, docker and VM members). The harness sets
those up, so it meets the requirement for the run:

- `read_gh_login` (a leg after the references) reads the desktop user's token once into a
  shell variable: never exported, never in an argv, the run log or a run-directory file.
  It fails fast when gh is missing or not logged in.
- Each member then runs `gh auth login --with-token --hostname github.com` as its own user,
  the token on stdin from a process substitution of a printf builtin. M1 members get
  HOME=/var/lib/<member> so gh keeps it in their StateDirectory; U23 members install gh
  (dnf in lxc and vm, apt in docker) and keep it in the agent user's home.
- It goes with the member: M1's state directories are removed by teardown, U23's
  containers and guest are destroyed by u23_teardown, both also on an interrupted run.

Chosen over the alternatives because it is the least code, runs pingbus exactly as a real
member does (gh's own login, no test-only path), and puts the token in no file outside a
member's own 0600 gh config. A run-directory 0600 file read through LoadCredential was the
other candidate; it keeps a copy on the host disk for the whole run.

Risk: for the run, the owner's full-scope gh token sits in five throwaway members' gh
config (gh's file storage, 0600, owned by the member user), so anything running as those
users could use it; only pingbus commands run there, and no agent. If a teardown fails,
the token stays in the leftover container, guest overlay or state directory until the
next run removes them first. Logging a member out does not revoke the token on GitHub.
A narrower token (a fine-grained, read-only one for the reference repository) would cut
the exposure but needs the owner to make it; say if you want that instead.
