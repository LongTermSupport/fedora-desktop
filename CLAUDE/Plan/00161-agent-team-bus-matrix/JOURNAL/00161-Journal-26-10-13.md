> **Entry grammar** — append new entries at the BOTTOM; NEVER edit earlier
> entries (corrections are new entries):
>
> ```
> ## HH:MM · category · REF   — optional short title
> ```
>
> - `HH:MM` UTC 24h (the date is in the filename, also UTC); times increase
>   down the file. A file with no sentinel line above predates this system —
>   its times are local, zone unrecorded (legacy; never rewritten).
> - `category` ∈ `action` | `finding` | `decision` | `thought` | `blocker` | `handoff`
> - `REF` = optional task/phase ref (`T1.2`, `P1`) or `—`.
> - Bodies may embed fenced logs/diffs/snippets — no size limit — with a
>   one-line takeaway above the fence.
> - End a working session with a `handoff` entry so the next agent's entry
>   point is the last entry of the newest day-file.

## 11:23 · finding · —

Risks found while building D64, for the host run:

- Protocol compatibility: a receiver built before D64 drops external references and pings
  carrying `branch`, and reads a team record holding `org` as untrusted. Every member (ccy
  image, LXC, docker and VM kits) must run the new pingbus before any team gains `org`.
- Forge rate: an org reference costs up to three GitHub API calls (repository, branch,
  compare), the repository cached per process. Unauthenticated members get 60 an hour.
- A private repository outside the org cannot be named in the acceptance without a
  credential; its refusal is covered by test_forge.py only.
- M1.6 needs the org to own a public fork; when it owns none the leg is
  SKIPPED-NEEDS-OWNER and the run ends NOT ACCEPTED, naming that.

Forge credentials, measured: a ccy session's pingbus has no GitHub token. The entrypoint
unsets GH_TOKEN after `gh auth login`, D62 refuses PINGBUS\_\* from ccy.env, and a running ccy
container has neither GH_TOKEN nor GITHUB_TOKEN. The acceptance members (DynamicUser) have
none either. Unauthenticated calls count against 60 an hour per public IP, shared by every
member on the machine. An org reference costs about 4 to 7 calls per ping per receiver at
first: on send the repository, the branch and the compare; on receive the same, then
`recv`'s re-check costs at least the repository again, since that answer lives only in the
process. Later pings to a known commit cost about 2. That is roughly 10 to 15 referencing
pings an hour for the whole machine. Follow-ups, not built: give ccy seats a forge token,
and keep the repository answer in the cache file.
