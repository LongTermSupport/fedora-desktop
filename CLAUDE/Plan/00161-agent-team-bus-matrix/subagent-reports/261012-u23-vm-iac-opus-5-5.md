# U23.vm by IaC: a vmtest lab guest instead of an owner-built one

The owner ruled that a hand-built guest is not acceptable. The decision and the
reasoning are in the JOURNAL entry of 2026-10-12. This report covers what was built and
what is still open.

## Design

- **The lab does the work.** Plan 00110's `vmtest` has four new verbs, in
  `files/home/.local/bin/vmtest`:

  - `ensure-base <key>` builds the base when it is absent and rebuilds it when the
    freshness gate refuses it. Otherwise it changes nothing.
  - `member-up <name> <key>` runs the gate and the RAM and disk floor. It then makes an
    overlay under `~/.local/share/vmtest/members/<name>/`, boots the guest with
    virt-install on qemu:///session and a passt SSH port forward, and waits for SSH (a
    bounded wait, 600 s). It leaves the guest running and prints `VMTEST-MEMBER-UP`. If
    it fails part-way, it removes the guest and the overlay and keeps `console.log`.
  - `member-ssh <name> <cmd>` runs the command as `fedora` with the lab key and
    passwordless sudo, passes stdin through, and exits with the remote status.
  - `member-down <name>` removes the guest (destroy and undefine) and the directory.
    When there is nothing to remove, it does nothing. A libvirt error stops it; it is
    never treated as "absent".

- **The acceptance.** `_acceptance-u23.inc.bash` drives the member:

  - `u23_prepare_vm` FAILS, naming `play-vm-test-lab.yml`, when the lab's CLI or
    `lab.env` is missing.
  - It then runs `vmtest ensure-base server-fast` and `vmtest member-up agent-bus-acceptance-u23 server-fast`, installs `git-core` with dnf (as the LXC leg
    does), and follows the same README steps as the other members.
  - `u23_remove vm` calls `member-down`. It runs in the leftover leg, the final
    teardown and the `plan_on_cleanup` path.
  - The marker, `U23_GUEST_REMOVE`, `u23_resolve_vm`, `--vm-ssh=` and
    `agent_bus_acceptance_vm` are removed.

- **The network.** The guest uses passt. It reaches `<bus_ip>` from the host's own
  network namespace, the same way pasta does for ccy, so nothing is added to
  `allow_from` and the bridge discovery is skipped for the VM. This is inferred from
  probe H1 (pasta, seen as `<bus_ip>`) and from how passt works. It has not yet been
  measured for passt. The join measures it, because the unit filter admits only
  loopback, the listen addresses and `allow_from`.

- **The IaC.** `play-vm-test-lab.yml` installs everything the member needs:

  - libvirt (session), virt-install, qemu-kvm, passt and the KVM assertion;
  - the CLI, the lab key and `lab.env`.
  - The base image is fetched and verified by `vmtest fetch`: a GPG-signed CHECKSUM,
    then sha256.

  No play changed. That play is now a leg of `deploy.bash`, after `play-claude-yolo.yml`.

## Open risks

- passt reachability is not yet measured. If SELinux's passt policy or passt's address
  mapping blocks the connection to `<bus_ip>`, the U23.vm join FAILS. Nothing hides it.
- The first run of `ensure-base` downloads the Cloud Base qcow2 (about 500 MB), then boots
  and upgrades it. That takes several minutes inside the acceptance; later runs do
  nothing unless the gate refuses the base.
- `deploy.bash` now deploys the whole vmtest lab on the host: linger, the bridge units
  and the nightly timer. That is more than U23 needs, but it is the lab's single play.
- The KVM assertion fails the play when `/dev/kvm` is unusable, for example nested
  without virtualisation.
- The bridge (qemu:///system) route for a VM member is documented but not exercised by
  any acceptance.
- P2's VM leg (DESIGN.md section 10) still says SKIPPED-NEEDS-OWNER and is not part of
  this change. Its design needs a VM whose source address is outside `allow_from`, which
  a passt guest cannot be.

## After the qa-reviewer's FIX-BEFORE-MERGE

- **The passt claim is now evidence, not just an assertion.** `u23_vm_check` samples
  `ss -tnpH` towards the bus port during the VM member's join and ping. The new helper
  command `acceptance_check.py passt-sources` (tested) prints the state and source
  address of every socket passt held, and FAILS, naming the source, unless each one is
  `<bus_ip>`. README.vm, `docs/agent-bus.md` and DESIGN.md 3.3 now say "expected, not yet
  confirmed".
- **Open PLAN.md tasks:** README.vm's untested bridge route, and P2's VM leg. DESIGN.md P2
  now uses the IaC wording and says the guest must be bridged.
- **`member-ssh` is bounded:** SSH keepalives, plus a `timeout` of
  `VMTEST_MEMBER_SSH_TIMEOUT` (default 1800 s; exit 124 with a message).
- **A failed `member-up` removes `ssh-port`.** The teardown is armed before the probe
  file is created, and `ensure-base` arms a removal before its probe too.
- **New test found a real bug, now fixed.** The interrupt case in
  `test-vmtest-member.bash` showed that SIGTERM during `member-up` exited 0: the trap's
  `$?` is the last command's status. Each signal now passes its own status (130, 143,
  129). The same pattern is still in `teardown_run` and `teardown_build` (an existing
  bug, not changed here).
- **Tests:** `test-vmtest-member.bash` now has 58 cases, including `ensure-base`, the
  interrupt and the timeout.
