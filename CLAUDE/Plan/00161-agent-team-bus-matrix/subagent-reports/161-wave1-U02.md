The docs file matches PROTOCOL.md apart from the two rules the builder added and the dropped DESIGN.md links. The link_check code-span fix is right and tested both ways.

1. **`helpers/pingbus/protocol.py:568-571`: the event-ID check runs before the type check.** A non-`m.room.message` event with a malformed `event_id` is dropped as `schema`, so it goes to `dropped.log` and changes the exit code. The spec rule this unit added (docs §9) says other types are ignored. I reproduced it with `{"type":"m.room.member","event_id":"bad"}`, which gives `drop schema`. Fix: test `type != EVENT_MESSAGE` first, then the event ID, and add a test for this case.

2. **`protocol.py:471-477`: a v2 ping is dropped as `schema`, not `version`.** The key-set and type checks run before the `v` check, so a `v: 2` ping that carries a new key gets `schema`. Spec §1 says any other `v` value is dropped as `version`. Fix: when `obj` is a dict and `obj.get("v")` is an int other than 1, raise `Refusal("version")` before the key and type checks, and add a test for it.

3. **The ping size rule in the doc (§4, "serialised content (UTF-8, as received)") does not match the code.** `content_size` measures the compact re-serialisation, not the bytes received. The doc is the single source of truth, so it must describe what the code does. Fix: change the §4 wording to "compact UTF-8 JSON serialisation". If wire-size matters, the syncer could also be given the raw byte count.

4. **The human-path order in docs §9 does not match the code.** The doc runs 09h stale and 10h rate before 11h fallback removal. `_human_outcome` (`protocol.py:549-552`) removes the fallback and returns `ignore` before the caller can apply stale or rate. So a stale reply that is empty after removal is ignored instead of dropped as `stale`, and it does not count towards the flood limit. Fix: move fallback removal ahead of the stale and rate steps in §9, so the doc says what the code does. The other way is to return the stripped-but-empty case for the caller to decide.

5. **Minor, `protocol.py:645`: `forge_api` is accepted with whitespace in it.** `"https://a b"` parses as a valid URL. Fix: require it to match `https://[^\s/]+(/\S*)?` and add a test for the bad value.
