## Review

**Verdict: FIX** (three small fixes; the core is sound)

Checked: the unit's 38 tests pass in the worktree. There are no QA suppressions, imports are stdlib only, and diagnostics go to stderr. `triage.bash` follows `_planlib` (gather mode, sudo primed before the log opens, host-only, no prompts). The `meta-deploy.bash` entry is right, and I found no install-specific data in the tracked files. The power levels match PROTOCOL §8 and the key set matches DESIGN §3.6 exactly.

1. **`triage_probe.py:1447-1456, 1471-1497` (H1 records a different fact without saying so).** DESIGN §13 H1 and H2 ask about a host `dummy` address. With no `--bus-address`, H1 tests only the primary address and still exits 0, so the report reads as if H1 were settled. Its firewalld zone and routing can differ from a dummy's. H2 fails when its facts are incomplete; H1 does not. Fix: when `bus_address` is empty, write "dummy/bus address not tested" into the report and raise `ProbeError` at the end, as H2 does. Also add the deviation to DESIGN §13 or the journal.

2. **`triage_probe.py:1165-1174` (the leak check only knows secrets it was told about).** `leaks()` checks only secrets registered in the scrubber. Any token field it was not told about would reach a fixture unflagged, such as a `login_token` from `login-get-token` (403 today) or a `refresh_token`. Fix: in `_write_fixtures`, walk each response. If any `access_token`, `login_token` or `refresh_token` value is not in `scrubber.secret_values()`, raise `ProbeError`. Add a test that fails without this check.

3. **`test_triage_probe.py:3-7` (the docstring promises tests that don't exist).** It says the "backup-meta reader and restore plan" are tested. There is no restore-plan function, and `_latest_meta` (`triage_probe.py:1239`) has no test. Fix: add a temp-dir test for `_latest_meta` (none, non-numeric names, picking the highest number), and drop "restore plan" from the docstring.

4. **`triage_probe.py:1545` (H2 can never pass on a libvirt host).** Whenever `virsh` is installed, H2 adds the libvirt guest leg to its unfinished list. So H2, and the whole `meta-deploy` run, exits 1 on every libvirt host. The owner section already lists that step (`triage_probe.py:1615`). Fix: record libvirt as a row pointing to the owner step instead of adding it to `owner_needed`. Or, if this is meant to fail, say so in the `triage.bash` header and EXIT CODES.

5. **`triage_probe.py:1193-1194` (a stop error hides the real one).** If `flows.run()` raises and `server.stop()` then raises too, the original H4 error is lost. Fix: call `stop()` in its own try and re-raise the first exception.

6. **Design drift, not a code defect.** The builder found that §3.6 needs `admin_signal_execute` and `login_via_existing_session = false`, and that P7 should change. These are in the journal only, while the tests still pin the §3.6 key set that is now known to be wrong. A follow-up DESIGN.md edit is needed before U15/U16 are built.
