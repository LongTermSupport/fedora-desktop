## 08:40 · finding · T1.2 — the self-test found two defects in its first run

`selftest-probes.bash` plants a real violation per invariant and requires the probe
to go red. Its first run failed twice, and both were genuine:

1. **The I1 probe reported a failed search as a clean pass.** Written as
   `if hits="$(grep ...)"`, grep's exit 2 (search error) fell into the same branch
   as exit 1 (no match). `/run` holds the Wayland socket, grep exits 2 on it, and
   the probe said "the token is in none of them". Exactly the "a control silently
   becomes a no-op" failure PlanScriptStandards was written about. Fixed by
   distinguishing all three statuses and enumerating regular files rather than
   recursing. Measured: neither `--devices=skip` nor `-D skip` suppresses the
   socket error during recursion.

2. **The I2 negative case planted no violation at all.** `bash -c 'sleep 30' bash
   <token>` gets optimised into a bare `exec sleep 30`, so the extra argument
   vanishes and the process command line is just `sleep 30`. The probe was correct
   and the test was wrong. Measured both forms; `bash -c 'sleep 30; :'` keeps the
   argument. The trailing `; :` is now load-bearing and commented as such.

Neither would have been found by reading the code, and the I1 defect would have
shipped a gate that passes on a search it never performed.

## 11:10 · finding · P2 — the wrapper's main error path was dead code

`set -euo pipefail` plus a `tr | grep | cut` pipeline kills the script AT THE
ASSIGNMENT when grep finds nothing, because `pipefail` propagates grep's exit 1.
So every diagnostic written for "PID 1 holds no token" was unreachable, and the
real behaviour was a silent `exit 1` with no output at all — the precise opposite
of the fail-fast-with-a-named-cause this repo requires.

Measured with a minimal reproduction rather than reasoned about:

```
before
EXIT=1          # the echo after the assignment never ran
```

Present in all three files that read the token: the wrapper, `probe-invariant.bash`
and `selftest-probes.bash`. Fixed with the sanctioned explicit-fallback form
(`var="$(...)" || var=""`), which the repo's own semgrep message names as the
correct alternative to error hiding — the empty case is then classified and
reported one line later, so the message is reachable.

Verified the fix by exercising the same pipeline shape and watching the message
print. Nothing else changed: the wrapper still passes argv verbatim and delivers
the credential, and all 13 selftest cases still pass.

Worth noting how this was found: not by review and not by any gate. Every linter
was clean on the broken version, because the code was correct — it was the CONTROL
FLOW that was wrong, and no static check models errexit interacting with pipefail.
