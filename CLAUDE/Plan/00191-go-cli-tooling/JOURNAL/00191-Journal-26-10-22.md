## 10:14 · action · T4.5   — regex group backslash defect, DBF

The host run of play-claude-yolo.yml (ansible-core 2.21.5) failed at "Read CCY_VERSION for the
Go Front's Build" with `'NoneType' object has no attribute 'group'`. This was fixed by Defence
Before Fix on `fix/regex-group-block-scalar`.

**Mechanism, proven.** I proved it with Ansible's own DataLoader and Templar on this container's
ansible-core 2.19.14, and read the same code in the 2.21.5 wheel. The scratch probes are
`untracked/scratch/regex_group_*.py`. YAML unescapes only double-quoted scalars. Inside `{{ }}`,
Ansible's `AnsibleLexer` doubles every backslash of a string constant, which cancels Jinja's
own unescape. So the filter got `\\1`, and `re.match(r'\\(\d+)')` found nothing. Conditionals
are evaluated with `escape_backslashes=False`, as are `{% %}` statements and `.j2` templates,
so Jinja does unescape there. The host's account of line 692 (`claude_channel_sync`'s
`changed_when`) was therefore wrong. It is correct as written, and returns True or False on
real input. Changing it to `'\1'` would fail with "Unknown argument".

**Defence.** The rule `regex-backref-escape` is a seventh check in qa-ansible. It parses each
file as YAML, works out the scalar style and the evaluation context, and judges each run of
backslashes before a digit or `g<` in the arguments of regex_search, regex_replace and
regex_findall. I committed it red (87bc54bbb) with the one finding. Every fixture case was
also rendered through the real Templar, and each label holds.

**Sweep.** Scope: playbooks/, tasks/, vars/, environment/, roles/. There were 7 backreference
sites and 1 instance (play-claude-yolo.yml:585), now `'\1'`. The independent search found the
same 7 and the same verdicts. Next wider rule, not built: `.j2` templates, where Jinja
unescapes. No `.j2` uses a regex filter today, so it is referred to the owner.

## 10:50 · correction · 10:14   — statement escaping, unknown escapes

The 10:14 entry said `{% %}` statements are evaluated with `escape_backslashes=False`. They are
not. They are templated with it set to True. `AnsibleLexer` doubles backslashes only in string
tokens between `{{` and `}}`, so a statement's constants, like those of any bare expression,
reach Jinja's own unescape. The conclusion stands: `{% %}` needs two backslashes.

The same mechanism covers the debug action's `var`. Jinja uses Python's `unicode-escape`, which
keeps an unknown escape, so `\g<name>`, `\8` and `\9` keep a lone backslash in these contexts.
The rule now judges them that way (review round 1, F1).
