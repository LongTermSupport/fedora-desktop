## 18:17 · finding · T3.10   — go-qa-ci diff-mode build fails on a test-only package; fixed in the clone

Fable found that go-qa-ci diff mode fails on a test-only package. Pin in use:
v0.0.0-20261015133126-7fc4547e92f2.

Cause: in a narrowed run, `runBuild` passes the changed packages and their importers by name to
`go build -o /dev/null <pkgs>`. `go build` rejects a named package that has no non-test Go file
("no non-test Go files in ..."), but `./...` skips it without a word, so the full run passes and
the diff run fails. Reproduced here: `src-go/internal/freeze/golden` holds only
`golden_test.go` and imports lxcfreeze. `go build ./internal/freeze/golden` exits 1, while
`go build ./internal/freeze/...` exits 0. Any change to lxcfreeze or podfreeze therefore fails
`qa-changed.bash` at the go stage.

Fix (go-qa-ci, branch `build-skips-test-only-packages`, commit `240fbf2`, on top of `7fc4547`,
not pushed):

- `internal/runners/build.go`: when patterns are named, `buildable` first runs
  `go list -e -f` with the build's own GOFLAGS environment. It drops each package that has no
  `.Error`, no GoFiles and no CgoFiles, but does have TestGoFiles or XTestGoFiles. Everything
  else stays in. If nothing is left, the build passes without running `go build`, so the empty
  list never turns into `./...`. If `go list` itself exits non-zero, the build fails with its
  output. A full run (no patterns) is unchanged.
- A named package that fails to load for a real reason still fails: a missing directory, a
  directory with no Go files, all files excluded by constraints, or a syntax error in a
  production file. `TestBuildNamingAPackageThatDoesNotLoadFails` covers these cases.
- Not handled by the build stage, by design: a syntax error in the test file of a test-only
  package. `go list` sets no `.Error` for it, and the build stage never compiles test files for
  any package. The test stage reports it.
- Tests: three runner tests and one diff-mode test
  (`TestDiffBuildPassesWhenATestOnlyImporterOfTheChangedPackageIsAffected`). That test failed
  with the exact "no non-test Go files" message while the fix was disabled, and passes with it.
- The clone's own QA passes: gofmt, go vet, `go test -race ./...`, golangci-lint (0 issues), and
  the self-gate `go-qa run --ci` (every step passed; ast-grep skipped as usual).
  `docs/runners.md` documents the behaviour.
- Checked on this repo's tree: the same `go list` filter marks `internal/freeze/golden`
  test-only and keeps freeze, freeze/app and freeze/cli.

Still to do: the coordinator reviews and pushes the go-qa-ci fix. After that, the pin in
`src-go/qa/go.mod` is bumped (Task 3.10 follow-up). Until then the defect remains here.
