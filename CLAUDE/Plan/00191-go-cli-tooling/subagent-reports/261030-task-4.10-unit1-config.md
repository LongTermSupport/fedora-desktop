# Task 4.10 unit 1 (B8): the saved launch configuration, read in Go

## What changed

- **Go, `src-go/internal/ccylaunch/launchconfig.go` (F16 in the package doc).** The front
  answers `claude-yolo --read-launch-config FILE`. It reads `.claude/ccy/.last-launch.conf`
  strictly, in the form the launcher's writer (the heredoc at the end of a launch) writes:
  `#` comment lines, `SAVED_CONFIG_VERSION=<digits>` unquoted, every other key as
  `KEY="value"` with no quote, backslash, `$`, backtick or control character in the value.
  Only the eight keys ccy writes are accepted; a key twice, a blank line, a last line with no
  newline (cut short) or non-UTF-8 text is malformed. Output is one `KEY<TAB>value` line per
  key, in file order. A file that cannot be read or is malformed: exit 1, one stderr line
  `ccy: cannot read the saved launch configuration <path>: <cause>` (the cause names the line
  for a bad line), nothing on stdout, and the file is never changed. Wrong argument count is
  exit 64. The flag is answered under `CCY_LEGACY` too: the bash asks it, so handing it over
  would ask the bash itself (and the bash refuses it, like `--build-lock`).
- **Bash, `load_launch_config`.** The `source ... || { warn; rm -f; return 1; }` block is gone.
  The bash captures the front's output (`$SCRIPT_DIR/claude-yolo`, the sibling front, as the
  `--build-lock` refusal already names it) and takes the lines with
  `while IFS=$'\t' read -r key value && [[ -n "$key" ]]; do printf -v "$key" ...`. Go only
  emits keys from its list, so `printf -v` never gets a name from the file. Any failure of the
  front is said ("not read (above); it is kept. Reconfiguring...") and returns 1.
- The format-mismatch and missing-key discards after a successful read are unchanged: they
  are decisions on a file that was read, not guesses. Which keys a format needs stays the
  launcher's decision (Go hands back whatever valid keys are there).

## Why reconfigure rather than stop

The launcher already treats every unusable saved state this way: no file, a file in another
format, a file missing a key all return 1 and ask again. Fail-fast is kept where it matters:
a headless launch (nobody to ask) with no usable saved choices is refused (rc 1, tested), so
nothing unattended runs on a guess. Stopping an interactive launch over a stale state file
would block the owner for no gain, since the launch asks for every choice anyway. What changes
is that the file is kept and its cause is printed. A launch that reaches its end rewrites the
file (the writer's `cat >`), so a kept file lasts until the next completed launch; an
unreadable one also makes that write fail loudly.

## Tests

- Go (`launchconfig_test.go`): good file; fewer keys and empty file read as they are; missing
  file; unreadable (a directory at the path, which root cannot read either); 16 malformed
  forms (unquoted, quoted format, `$(...)`, backtick, backslash, tab, NUL, non-UTF-8, blank
  line, key twice, cut short, leading space and others); unknown key; argument count; legacy.
  Each failure asserts exit 1, empty stdout, path plus cause on stderr, file bytes unchanged.
- Bash (`scripts/test-ccy-teams.bash`, Quick Launch block): it now builds the real front and
  points `SCRIPT_DIR` at it. New cases: a front that fails to read (a stand-in printing a
  permission error; the suite runs as root in ccy, where no regular file can refuse a read)
  gives headless refused, file kept, cause and "kept" shown, and interactive reconfigures with
  the file kept; a malformed line `LAST_LAUNCH_DATE=$(touch pwned)` is refused with line 8 and
  the path named, the file byte-identical, and nothing ran. Under the old code both fail (it
  sourced, and so ran, the line). Suite result: no failures.
- `scripts/go-binary-suites.tsv`: the claude-yolo row now lists `test-ccy-teams.bash`.

## What QA turned up, and the fixes in the same commit

- **The parity oracle (`internal/ccylaunch/difftest`) installed the bash launcher alone, as
  `claude-yolo`.** The play stopped laying it out that way when the front came in, and the
  bash now needs the front beside it, so in that layout Quick Launch failed
  (`launch-quick-replay`, `launch-quick-used-up`). `installBash` now installs it as the play
  does: the bash as `claude-yolo.bash`, lib/, and the front (the test binary) as
  `claude-yolo`. It still returns the bash's path, so the goldens are still recorded from a
  direct run of the bash. No golden changed. `installFront` is now that directory's front path.
- **`lib/session-registry.bash`:** `--read-launch-config` is in `CCY_REGISTRY_DROP_FLAGS`
  beside `--build-lock`, since test-ccy-session-registry.bash fails any flag the launcher parses
  that has no replay class. It exits before a session exists.
- **`scripts/test-ccy-token-handoff.bash`:** its "no fixed name" check banned the literal
  `"$SCRIPT_DIR/claude-yolo"`, so that re-runs always go through `CCY_LAUNCHER_PATH`. The front
  call re-runs nothing, so the check now exempts only `"$SCRIPT_DIR/claude-yolo" --read-launch-config`
  and asserts it appears exactly once. Any other use of the fixed name still fails.
- In the launcher, the bash's own `--build-lock` refusal now covers `--read-launch-config`
  too. Without that, a bash with no front beside it (a checkout run) would start a whole
  launch when it called itself; with it, the flag fails and the file is kept.

`qa-changed.bash` then passed across 14 changed files: go-qa on both modules, bash-limits,
test-ccy-teams, test-ccy-session-registry, test-ccy-token-handoff, test-qa-changed and the
other launcher suites.
