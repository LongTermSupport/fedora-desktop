**The rule (`suite-env-isolated`)**
- **Locale:** set to `LC_ALL=C.UTF-8`; the machine's `LANG`, `LANGUAGE` and `LC_*` are dropped.
- **Shell:** exported bash functions (`BASH_FUNC_*`), `BASH_ENV` and `ENV` are dropped.
- **PATH:** any directory holding a command this repo installs (from `scripts/go-binary-suites.tsv` and `files<home>/bin`) is swapped for a copy without those commands. `/usr/bin`, `/bin`, `/usr/sbin` and `/sbin` are kept.
- **Why not drop `~/.local/bin`:** semgrep, ruff and ansible live there, so removing it would break QA.
- **The guard:** `TestSuiteEnvIsolated*` in `src-go/qa/all` and `src-go/qa/changed`. It runs inside the `go` gate, so a failure blocks.
- **Why a test, not semgrep:** semgrep can spot an unpinned `sort`, but not which PATH directory a lookup reaches or which exported function a child process inherits. You allowed either kind of guard.

**Cause of #3, confirmed:** it is Fedora's exported `which` function. When an exported function is present, the Go front deliberately passes `--help` to the bash launcher instead of answering itself. Exporting a `which` function in the container reproduced exactly the two host failures.
