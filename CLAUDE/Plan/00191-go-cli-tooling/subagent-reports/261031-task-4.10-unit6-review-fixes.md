# Task 4.10 unit 6: the qa-reviewer's findings on units 1-5 (CCY 3.104.11)

Source: the qa-reviewer report on `28199aa1e^..8a6396691` (FIX-BEFORE-MERGE, seven findings).
Branch `plan/00191-4.10-unit6` from `e302f456c`.

## What each finding became

1. **The play's order.** The bash launcher went in before the Go front was built, and the libs
   (installed by `tasks/claude-yolo-image.yml`, before both) ask the front too. So a failed
   Go build left an old front with a new bash and new libs. The `CCY_VERSION` read is now
   its own `tasks/ccy-version.yml`, imported by the image tasks and by `play-claude-yolo.yml`.
   The play now reads the version, creates `/var/local/claude-yolo`, and builds and installs
   the front before the image tasks, then copies the bash. The comment is corrected.
2. **docs/ccy.md.** The Go front section lists F16-F22 (the questions the bash and its libs
   ask). The advice to run `claude-yolo.bash` directly without the front is replaced: there
   is no running the bash without the front, so the fix is to re-run the play.
3. **Cleanup option b (the B7 class).** Both options of the cross-engine Docker cleanup are now
   `ccy_docker_network_cleanup project|all` in the new `lib/docker-network-cleanup.bash`
   (one function, within the bash limits). It lists through `--list-containers`, stops through
   `--stop-containers` and removes through `--remove-network` (5 goes on). A failed listing,
   stop or prune returns 1 with the engine's words, and the launcher exits. The 3.104.9
   changelog text now says option a only, and 3.104.11 covers option b.
4. **create_token (the B2 class).** Both check sites (the setup-token token and a pasted one)
   now discard only on 3. Exit 1 saves the token and says it could not be checked (the
   front's cause is above). The new tests found the paste loop's prompts looping for ever
   on a closed input, and they now end it. The launcher's re-check of a token selected after
   a failure tells a refusal from a check that could not run.
5. **`network inspect 2>&1`.** Gone: option a lists a network's containers with
   `--list-containers docker network=NET`, so stdout holds only names. Tested with an engine
   warning on stderr.
6. **A failed inspect read as "not a zombie".** `find_zombie_containers` keeps the inspect's
   stderr apart in a temp file. On a failure it asks the listing again: a container gone from
   it is the race and is skipped, and one still listed returns 1 with the engine's words.
7. **Tests.** `scripts/test-ccy-container-menus.bash` drives the real Go front against a fake
   docker: exit 5 goes on, a removal, stop, listing or prune that failed stops, and a warning
   is never a name. It also covers the launcher's two call sites, the zombie scan's inspect
   failure and race, and the TTY zombie. `scripts/test-ccy-token-mode.bash` drives
   `create_token` under a hard timeout: accepted, refused, could not run (both paths), and a
   closed input. `scripts/test-ccy-token-handoff.bash` counts the front's three remaining
   names in the launcher.

## Red, then green

- Run against the old `docker-health.bash` (via `CCY_TEST_LIB_DIR`), the container-menus
  suite fails the two inspect-failure cases. It passes on the new lib.
- Run against the old `token-management.bash`, the token-mode suite fails the five
  create_token cases, and the closed-input paste case hung until the run was stopped. It
  passes on the new lib.
