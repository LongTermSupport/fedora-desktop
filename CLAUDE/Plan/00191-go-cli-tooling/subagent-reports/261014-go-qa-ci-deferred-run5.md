# go-qa-ci: minor items the verifiers deferred (run 5: M12 fix and M13)

Each is non-blocking; to be picked up in a polish milestone.

- M12: The Public safety workflow (.github/workflows/public-safety.yml) has been red on every push since M3, HEAD included, because the GQACI_DENYLIST repository secret is not set. It fails loudly, as designed, and README.md:241 and docs/PUBLICATION-CHECKLIST.md both document it. Setting the secret is the owner's job before publication. It is not an M12 defect, but it means one of the repository's two workflows is permanently red.
- M12: actionlint is pinned inline in ci.yml (ACTIONLINT_VERSION 1.7.12, checksum-verified) rather than in tools.lock. So tools.lock's header claim to pin 'every external tool ... this repository's CI use' is slightly overstated. shellcheck is also unpinned: it comes from the runner image.
- M12: tests/scripts/install_tools_test.go only covers --check, selection and version probing, using stub binaries. Nothing exercises the download, checksum and extract paths (install_golangci_lint, install_ast_grep) except the CI self-gate job. That job did install them green, and my clean-checkout run did too.
- M12: install-tools.sh's [go] version probe reads the 'mod' line of go version -m. That line is the main module's version, which here matches the pinned package's module (x/tools, x/vuln, gremlins). A future pin whose command lives in a submodule could misreport its version.
- M12: declaration.Reconcile does not compare gap summaries with the CONFORMANCE.md evidence text. It only checks that Gap/Partial rows and declared gaps match one to one, so the two descriptions could drift apart without a test failing.
- M13: internal/tools/diff.go:550: a narrowed run always skips vuln and mod with the reason 'go.mod and go.sum are unchanged'. That reason is not enough. govulncheck works from the call graph, so a changed .go file that starts calling a vulnerable function in a module already required is missed. A new import can also leave go.mod untidy. Better options: run vuln and mod when any package is affected, or reword the skip reason and the README row (README.md:42) so they do not suggest nothing could have changed.
- M13: internal/changed/widen.go:27 (ignoredByGo): changed .go files under testdata/ are dropped, and non-.go fixtures and embedded files never select a package. So editing an analyzer's testdata, or a golden file, with --changed runs none of the tests that use it. This matches the brief's wording ('packages containing changed .go files'), but it is a surprise for a normal user. Mapping testdata/ and embedded files to the package that owns them, or at least saying so in the README, would fix it.
- M13: internal/cli/run.go:333: the widening list compares the --config value as given. An absolute --config path, or one like ./qa/x.toml, never equals the root-relative changed path, so editing that config does not widen the run. (Under qa/ it still widens because of the qa/ prefix.) Fix by making the path root-relative before comparing.
- M13: internal/tools/diff_test.go: narrowing is proven through the real engines for test, golangci, coverage and suppression, but analyzers (the go vet -vettool path) has no engine-level test proving it is narrowed to the affected packages.
- M13: internal/runners/coverage.go:431: in a narrowed run, coverage applies the module-wide fail-under threshold to only the affected packages. A narrowed result can therefore pass or fail differently from the full run. The README could say this explicitly.
