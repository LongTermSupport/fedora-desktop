# Task 4.10 unit 3 (B3, B5): the network check and the version probes, in Go, with their causes

## What the bash did

- **B3, the network check** (after the network is chosen, before the launch config is
  saved): `container_cmd run --rm --network NET alpine wget -q -O- --timeout=10
  http://google.com >/dev/null 2>&1`. Any failure printed "NETWORK ERROR: NET has no internet
  access", scanned compose files for `driver: bridge` / `internal: true`, printed the debugging
  guide and exited 1. An engine that would not start, an `alpine` pull that failed (which is the
  host's network or the registry, not NET) and a missing `wget` were all reported as NET having
  no internet, with every word the engine or wget said thrown away.
- **B5, the version probes** (`auto_update_claude_code`, once a day per image):
  `run --rm --entrypoint claude IMAGE --version 2>&1` and `timeout 5 curl -fsSL
  <npm latest>`; each output was captured, and on a failure dropped. Either version unknown
  printed "Could not determine Claude Code version (offline?)", stamped the day and went on.

## What changed

- **Go, `internal/engine` E12**: `RunOnNetwork(ctx, network, image, args...)` (`run --rm
  --network NET IMAGE ARGS`, the image pulled if missing, as before), `ClaudeVersion(ctx,
  image)` (the same argv as the bash, merged output), and `ContainerFailed(err)`: the
  container command's own non-zero exit, as opposed to 125 (engine, pull), 126/127 (command
  not runnable / not in the image), a signal, or an engine that did not start.
- **Go, `internal/ccylaunch` F18, `--check-network ENGINE NETWORK`** (`netcheck.go`): exit 0
  silent when wget fetched; **4 (`ExitNoInternet`)** when the probe ran and wget failed,
  "ccy: the network NET reaches no internet: <wget's words>"; **1** when the probe could not
  be run, "ccy: the network NET could not be checked: podman could not run the probe:
  <engine's words>" (also for an engine name ccy does not drive). 64 on argument count.
- **Go, F19, `--claude-versions ENGINE IMAGE`**: stdout "INSTALLED LATEST", exit 0; exit 1,
  "ccy: the Claude Code versions could not be read: <cause>", the cause being the image run
  with its words, "printed no version: <text>", "the npm registry could not be reached:
  <curl's words>", "the npm registry answered with an error: <curl (22)'s words>", "did not
  answer within 5s", or "the npm registry's answer names no version" (JSON decoded; a version
  must be one word, since the bash splits the line). The 5 s bound is a constant context
  timeout, so the curl argv (`-fsSL URL`) is unchanged.
- Both answered under CCY_LEGACY too (the bash asks them); both in the bash's refusal of the
  front-only flags and in `CCY_REGISTRY_DROP_FLAGS`.
- **Bash.** The probe is `"$SCRIPT_DIR/claude-yolo" --check-network ...`: 0 passes, 4 shows
  the existing guide (wget's cause now printed above it), anything else stops with "The network
  check could not be run (above), so nothing is known about NET" and no guide. The two version
  probes and their parsing became one front call and a `read`.

## Behaviour kept, and the one change

- Network: still fail-fast on every non-pass; the guide still follows a network that reached
  nothing. **Changed:** an engine, pull or image fault no longer shows the network guide (which
  sent the person to recreate a network that was never tested); it stops with the cause.
- Versions: the skip-for-today on a read failure is kept (it is annotated FAIL-FAST-OK as a
  launch-time convenience, and is not itself a guess); only the guessed "offline?" went, for
  the real cause.
