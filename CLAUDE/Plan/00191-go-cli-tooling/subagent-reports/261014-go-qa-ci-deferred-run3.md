# go-qa-ci: minor items the verifiers deferred (run 3: M3c to M5)

Each is non-blocking; to be picked up in a polish milestone.

- M3c: internal/record/gate.go:43-45 and docs/record.md ('that is a gap, not a pass'): when there is no git history (no repository, or HEAD's record does not parse), the gate only adds a note and exits 0, even in CI. That contradicts the doc's own wording, and it is handled differently from the unresolvable history_base case, which fails in CI. Because the 'previous == nil' case is tested first, an unparseable HEAD record together with an unresolvable base is also only noted in CI.
- M3c: internal/record/ratchet.go:93 freshSignature uses a strict After() on day-granular dates, so a second legitimate raise signed on the same day as the previous signature can never pass. Either document this or allow an equal date when decided_by or reason changes.
- M3c: internal/cli/record.go:117 and internal/record/gate.go Prune: duplicate numbers (e.g. 'prune 2 2') make the CLI print 'removed 2 exception(s)' when only one was removed. Deduplicate the indexes or report the actual difference.
- M3c: No test covers the subdirectory-module history lookup that 5ba5122 fixed (rev:./path, ls-tree relative to root). I checked the git semantics by hand and they are correct, but nothing would catch a regression.
- M3c: No test checks that record check prints notes to stderr (internal/cli/record.go:47), or that the run executor passes mayLower=!CI (internal/tools/executor.go:32) end to end.
- M3c: internal/record/ratchet.go:30 cites 'TOOLING-SPEC 6.4' for the ratchet. 6.4 is the SHOULD on documented defaults, not a ratchet MUST. The ratchet is a toolchain default under 6.4, so this is defensible, but the citation could say so explicitly.
- M4: docs/defences.md (docs detector section) says the Go test and docs-check 'which the self-gate runs, fail the release' (TOOLING-SPEC 8.1). No CI job runs go test or the self-gate yet: .github/workflows has only public-safety.yml, and the self-gate arrives in M5 and M12. Reword it as future, or add it to the Recorded gaps list, so the doc does not describe a release block that does not exist yet.
- M4: README.md:3-4 still says 'No declaration or gap list exists yet', but docs/defences.md now has a 'Recorded gaps' section. Point the README at it.
- M4: internal/docs/docs.go Resolve: a project page overrides a bundled gqaci.* page, and project pages are not checked for content (a recorded gap). An empty project file named gqaci.record.stale.md (or a case or '-' variant of it) therefore replaces the bundled remediation and docs-check stays green. Consider auditing project pages that shadow a built-in, or refusing to let them shadow one.
- M4: internal/config/config.go:109 refers to a bundled gqaci.ast.* pack whose identifiers are not in internal/builtin. When that pack lands, its identifiers must join builtin.All() (or the 8.1 audit must enumerate them, applying family patterns per DETECTOR-SPEC 6.5). Otherwise the audit passes without covering them.
- M4: internal/docs/check.go Orphans and pageStems consider only regular files. A symlinked .md page in docs_dir is never checked as an orphan, but Resolve can still read it under its exact name.
- M4: internal/cli/docs.go runRuleDoc prints args[0] untrimmed in the dangling message, although Resolve trims whitespace. This is cosmetic only.
- M5: README.md:3-4 says 'No declaration or gap list exists yet', but docs/golangci.md and docs/defences.md now carry 9.2 gap records. The wording has drifted and should point to those records.
- M5: A consumer's own .golangci.yml is used as-is (internal/golangci/run.go:48). Its linters.exclusions, presets, generated handling or issues.new-from-rev/new-from-merge-base can silently drop findings without going through the project record. go-qa passes no overriding flags (it does pass the cap flags). M6 owns the suppression detector, but docs/golangci.md does not list config-file exclusions or new-from-* as a known gap against TOOLING-SPEC 4.3.
- M5: Config(dir) looks for .golangci.* only in the module directory. A nested module with no config of its own gets the embedded baseline, even when a parent directory's .golangci.yml exists, which golangci-lint's own discovery would use. This is an edge case and is undocumented.
- M5: The codePrefixed set in internal/golangci/parse.go:17 is hard-coded to five linters. Other multi-check linters print only the linter name. This is recorded as a DETECTOR-SPEC 4.3 partial gap, so it is acceptable for now.
