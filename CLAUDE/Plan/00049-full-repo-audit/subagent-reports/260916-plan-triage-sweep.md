# Cross-plan triage sweep — 27 In Progress plans

Read-only sweep. No file in the plan tree was edited. Excluded by instruction and not
read: 00099, 00109, 00112, 00122, 00124.

Method: each plan's `PLAN.md` read in full (header, Overview, task tree, Success
Criteria, Delivery). Where a plan's own state was ambiguous, the claim was checked
against the tree — `git ls-files` for artefacts, `grep` for whether a named finding is
still live, `hooks-daemon explain-handler` for whether an upstream mechanism has since
landed. Journals were not needed except where noted.

## Headline

**No plan in this set is strictly CLOSEABLE.** Every one has at least one unticked task
or Success Criterion that is genuinely undischarged. That is the honest answer, and it
is worth stating plainly rather than promoting a near-miss: there is no 00076 hiding
here.

What there *is*, and what matters more:

- **Two plans should be closed as superseded, not completed** — 00046 (its entire
  purpose now shipped upstream in the hooks daemon) and 018 (a pre-template F43 design
  doc that the tree has long overtaken). Neither can ever be "finished"; both will sit
  in the blocked list for ever until someone cancels them.
- **One plan is 90% done-but-unticked** — 022 reads 0/52 ticked while five of its six
  phases are demonstrably implemented in `fedora-install/`.
- **One plan's last remaining task is half-obsolete** — 00075 Task 4.4's upstream report
  covers two issues; one was fixed upstream and the other is still live but mis-cited.
- **Eleven plans are blocked on exactly one host/human action each.** That concentration
  is the real finding: the bottleneck is not work, it is access to a host.
- **Plans 011 and 013 are verbatim duplicates of 009.**

## Supersession and duplicates

**Superseded — 00046 by the hooks daemon itself.** `bin/hooks-daemon explain-handler sensitive_content` confirms the daemon scans `gh issue|pr create/edit/comment` bodies
(inline `--body`/`-b` and `--body-file`/`-F <file>`) plus `git commit`, `git tag`,
branch names, `git config user.name|user.email` and `git merge -m`, against both
configured public patterns and a gitignored secret word list. Plan 00046 exists to block
exactly the first of those. The upstream mechanism is strictly wider (it covers git
metadata, which 00046 never proposed) and is already enabled at priority 44. Residue
genuinely uncovered: `curl --data` / `-X POST`, `wget --post-*`, `gh api`, and bodies
piped on stdin.

**Superseded — 018 by four later plans.** 021 (firstboot wizard, Completed) replaced its
Step 2; 00049 GAP-01 / FUP-08..18 hardened its `fedora-install/` bootstrap (secret
lifecycle, strict mode, ISO verification); 022 implemented adaptive partitioning, GRUB
password and the `%pre` auth gate on top of its `ks.cfg`; 00110 (Completed) added the
VM-lab kickstarts. It also still says F43.

**Partially superseded — 026 Task 5.2 by 00049 PERF-06.** 026 wants `state: latest` →
`state: present` on pipx pdm; 00049 deliberately kept `state: latest` there and deleted
the separate `pdm self update` task *because* of it. `play-python.yml:53` carries the
PERF-06 comment saying so. Doing 026's 5.2 would undo 00049's decision.

**Partially superseded — 00046 Phase 3 deliverable by 00049.**
`.claude/public-token-allowlist.yml` was created and committed by Plan 00049 Batch 1
(`2ac7e6a5`), not by 00046, whose header still reads "implementation not started".

**Duplicates — 009 / 011 / 013.** All three are `claude-devtools (ccdt) Installation`,
all created 2026-02-17. Plan 013's own H1 reads "# Plan 011: claude-devtools (ccdt)
Installation" — it is a copy that was never even retitled. 011 and 013 are both "Not
Started" and both sit in the top-level plan tree. 009 is the one with the work in it.

**Related-but-not-duplicate — 00128 Task 2.1 and 00049 QA-09.** Both are the same
unanswered question ("does dev-only tooling belong in a provisioning playbook?") reached
from different directions: 00049 needs `pytest` in the CCY image, 00128 needs `eslint`
in a fresh clone. One owner decision would close both. They should be pointed at each
other.
