## 17:41 · decision · —   — Owner verdict on Nheko vs Element; forking advice

Owner's first verdict after trying Nheko 0.12.1 (Flathub im.nheko.Nheko) beside Element on one team: "nheko is better than element in some ways but really both of them are very clunky", no winner yet. Sending from Nheko into a team room works.

Nheko login quirk: autodiscovery fails (the server name is internal-only) and Nheko pre-fills a wrong homeserver; typing http://127.0.0.1:<team port> in full makes it sign in.

The owner raised forking a client. Implementation languages: Element is TypeScript/React (element-web on matrix-js-sdk) in Electron; Nheko is C++ with Qt/QML on mtxclient; gomuks is a Go backend with a TypeScript/React web frontend (on mautrix-go); Commet is Dart/Flutter. Advice given: do not fork a general client (a permanent sync/E2EE/spec maintenance burden). Cheaper order: try gomuks web (untested, threads in its release notes, Go backend); report specific annoyances upstream (non-resizable composer, quit dialog defaulting to quit); only then consider a small Go team console for the bus rooms, which would sit beside a general client since Matrix is not to be coupled to the bus.
