## 13:10 · finding · — — filed on Plan 00125's own instruction, not on a fresh hunch

I reported this gap twice today in loose terms and got the framing wrong both times,
calling it an unaddressed IaC gap as though someone had forgotten it. Two things correct
that.

**`qa-js.bash` already decided this deliberately.** Lines 107–112 say the deps are
dev-only, that no playbook installs them, that most users never edit the GNOME-extension
JavaScript, and that auto-installing "would force dev tooling on every install". There is
a reasoned position in the code, and the `exit 2` is the fail-fast rule being obeyed
rather than ignored.

**Plan 00125 had already measured and costed it.** Its Non-Goals name it — *"An IaC gap
wanting its own plan"* — and `FINDINGS.md` carries the measurement:

```
- No playbook installs the deps (grep over playbooks/ tasks/ roles/ files/ returns nothing)
- The CCY Dockerfile CANNOT supply them: no node stage, and extensions/node_modules is
  under the bind mount, so anything a RUN created there is covered at start-up

- extensions/node_modules is gitignored, so it survives in a working checkout and is
  absent in every fresh one

and closes: *"the remedy is a real decision — whether extension dev tooling belongs in the
desktop provision at all, or in a separate bootstrap — and that is the owner's, not this
plan's. Flagged, costed, and left for its own plan."*

So filing is what 00125 prescribed, and the owner decision is this plan's Phase 2 gate

## 13:12 · thought · T3.1 — why Phase 3 is worth doing under any of the three answers

Phase 2's decision is the owner's, but it does not gate Phase 3. None of the three options
makes it correct for one gate's missing tool to erase thirty other gates' verdicts. Even
under option A — a playbook installs the deps — the abort path stays reachable for the
other six `exit 2` guards, and the next missing tool would cost the same thirty verdicts.

This is Plan 00125's subject one level up. Its Task 4.3 fixed the equivalent for hard gate
*failures* and deliberately kept the seven tool aborts, so the suite still has one exit
path along which a clean-looking run says nothing about most of itself.

The assertion Task 3.2 needs is the one 00125's Task 4.3 used: mutate a gate's tool
precondition and assert the census still names every other gate. A count read off a
passing run cannot distinguish "thirty gates passed" from "thirty gates never ran", which
is the property.
