**Task 1.1 by clone, not by moving the directory aside.** `extensions/node_modules` is

```

```

**31 gates lose their verdict.** PLAN.md said "roughly thirty" from reading the script;
the measured number is 31, and the static cross-check agrees from the other side — 29 gate
invocations sit after the js gate's line against 6 before it, the difference being gates

**The contrast in that one run is the real finding, and I did not go looking for it.**
`ansible-syntax` failed **83 times** in the fresh clone (no `roles/` — galaxy deps are not
vendored). Every one of those failures printed, the gate was named in the census, and the

So in a single run: a gate that is comprehensively broken costs its own verdict and
nothing else, while a gate whose OPTIONAL dev tool is missing costs thirty-one other gates

better argument for Phase 3 than anything in the filed plan.

**A live instance, not a hypothetical population.** Of the two worktrees under

**Two lines further on, QA.md already names the remedy:**

> `qa-deployed-drift.bash` is the shape to copy: it states the dependency, skips only for
> a reason it prints, and the reason is checkable.

That is Task 3.1's requirement, written down as this repo's own standard, which
`qa-js.bash` does not meet. Phase 3 applies an existing convention rather than inventing
one — a materially better position than the filed plan assumed.

**And the named model has a residue of the same defect.** Its skips read
`✓ deployed-drift: skipped (CCY container — …)`. A TICK. The reason is printed, which is
the important half, but the SYMBOL says pass and `helpers/qa_environment/verdicts.py`
parses that symbol — so anything counting ✓ stages counts a gate that ran nothing as a
gate that passed. The recurring defect class, surviving inside the gate held up as the
example of avoiding it.

So Task 3.1's `⚠ <name>: not run — <tool> absent` stays a third SYMBOL rather than a tick
with prose after it. Three states need three symbols if a machine is going to read them,
and one already does.

## 14:00 · action · T1.4 — the measurement is now a script, and its own guard is falsified

`triage.bash` plus `probe-gate-census.bash`, on `_planlib.inc.bash`. Run once and it
re-derives Task 1.1's numbers independently of my hand measurement:

```
[probe] fresh clone 7 gates (exit 2); this checkout 38 gates (exit 0)
**Gates that lose their verdict on a fresh clone: 31**
```

The report **names** all 31 rather than only counting them. A bare count cannot show WHICH
coverage went missing, and a coverage gap is precisely how a census fails silently — the
lesson Plan 00125's `PANEL-CONTRACT-OK` and `VERSION-PINS-OK` lines already encode.

**Three design decisions worth the words:**

**A clone, not `mv extensions/node_modules aside`.** The directory is gitignored, so a
clone has never had it — the absent state is reached by construction rather than
manufactured. A move-it-back probe owns a window in which the developer's working tree is
broken, and a probe that dies in that window leaves it broken.

**`plan_require_container`, and for the measurement rather than convenience.** R2 says pick
exactly one location, so this needed an actual reason. The finding is a same-machine
differential, so the tool inventory cancels out — but what does NOT cancel is a gate that
behaves differently by location. `qa-deployed-drift.bash` compares the repo against real
deployed copies under `~/.local/bin`: on a host it does genuine work and can fail for
reasons unrelated to this plan, moving one leg's count independently of the other. In the
container it self-skips, identically in both legs. The container is the more STABLE
comparison, not merely the easier one.

**`|| rc=$?` rather than `!` on the suite runs.** Exit 0, exit 1 (a gate failed) and exit 2
(a tool abort) are three different answers here, and the probe reports whichever it got.
Collapsing them into "the probe failed" would discard the exact distinction being measured.

**The probe's own guard, falsified rather than assumed.** A probe whose two legs somehow
agree has established nothing, and would print "0 gates lost" — which reads as the problem
being fixed. Mutant pointing both legs at the same checkout:

```
[probe] fresh clone 38 gates (exit 0); this checkout 38 gates (exit 0)
[FATAL] both checkouts reported the same 38 gates, so this probe measured nothing
rc=1
```

Zero is the signal, so it is an error. `shellcheck -x` clean on both scripts, both `+x`
per R12.

One shellcheck lesson recorded: markdown containing backticks cannot go in a
single-quoted `printf` — SC2016 reads a backtick inside single quotes as a command
substitution. A quoted heredoc (`<<'MD'`) is literal by definition, so the linter and the
reader agree.
