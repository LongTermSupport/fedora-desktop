## 11:24 · decision · —   — ccy.env.local.dist: the daemon owns the template, ccy lets it be tracked

The owner asked mid-plan for a tracked `ccy.env.local.dist`: commented, documented
placeholders for install-specific overrides (not secrets), first of all the hostname role
override, created and refreshed automatically as new hooks-daemon versions install, with the
real `ccy.env.local` naming the dist version it was based on so the agent can review it.

A search of the vendored daemon found: it copies `claude-supervise.py` into `.claude/ccy/`
on install and upgrade only (`install/ccy_supervisor.py`), overwriting it each time; the
role override is `HOOKS_DAEMON_HOSTNAME` (`utils/cron_hosts.py`), which decides which
`persistent_crons` `hosts:` entries match; no `.dist` convention exists, though agents carry
an in-file version marker. So the template is the daemon's to ship and refresh. ccy's part
is letting it be tracked: CCY 3.81.0, with `scripts/test-ccy-gitignore-safety.bash` red on
the three dist cases first. The daemon side was filed upstream as issue #88, through
`hooks-daemon issue-report`.

## 14:18 · decision · —   — ccy owns ccy.env.local.dist (correction): CCY 3.83.0

Correction of the earlier ownership decision: the owner said ccy, not the hooks daemon, creates the dist. `.claude/ccy/` is ccy's, and not every hooks-daemon project is a ccy project. The owner also said an install's `ccy.env.local` is placed by that install's own IaC (for the hooks daemon's SDLC runner, by the infra agent), never by ccy, the daemon or an agent working in the checkout.

Done in CCY 3.83.0 (db3f53bd):

- `ccy_env_local_dist_sync` writes the versioned dist on every launch.
- It warns when a `ccy.env.local`'s "based on" version is older than the dist's, or missing.
- It leaves a newer ccy's dist alone.
- It stops the launch if the write fails.
