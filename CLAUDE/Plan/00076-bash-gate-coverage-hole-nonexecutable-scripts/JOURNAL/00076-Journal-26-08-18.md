## finding · the execute bit decides whether a file is linted at all

`semgrep/target_manager.py:1024`:

```python
elif not path_has_permissions(path, stat.S_IRUSR | stat.S_IXUSR):
    return None
```

`get_shebang_line()` refuses to read a file that is not owner-executable. For a
file with no recognised extension the shebang is the *only* language signal, so
no execute bit ⇒ no language ⇒ never scanned. `git ls-files -s` gives the mode:

| File                                       | Mode     | Scanned |
| ------------------------------------------ | -------- | ------- |
| `files/var/local/docker-in-lxc`            | `100755` | yes     |
| `files/var/local/claude-yolo/claude-yolo`  | `100644` | **no**  |
| `files/var/local/claude-yolo/entrypoint.sh`| `100644` | yes — the `.sh` extension carries it |

`qa-bash.bash` has the same hole from the other direction: its two `find` passes
are "named `*.sh`/`*.bash`" **or** "`-type f -executable` with a shell shebang".
A mode-644 extensionless script is in neither, so it gets no `bash -n` either.

27 tracked scripts are in that state. The census (`shellcheck -S style`) is in
PLAN.md; the number that matters is **SC2155 ×19**, because Task 4.1 of Plan
00075 raised the shellcheck bar to `warning` *for that code specifically* and
then fixed 12 instances. The raise was real; its reach was not.
