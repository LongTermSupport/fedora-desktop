## 12:08 · action · — — C.2 boot unit through lxc@

Task C.2, the boot unit, built and committed (7366a5787). `lxc start-recorded` starts each recorded container as `lxc@<container>.service` through the host systemd (`units.Manager.Containers`, start-only, `lxc@` instances in the container grammar alone), because both boot units carry the v1 `InaccessiblePaths=` and a container started from inside one would inherit its private mount namespace. It then waits up to 60 s on the clock for `RUNNING`, and a timeout is a named `REFUSED` line. The drop-in `lxc@.service.d/teamchat.conf` (`Before=teamchat-lxc-record.service`) takes the shutdown record before any instance stops. `host.Systemd` was not used: its unit check refuses everything but teamchat's own units, which no fake would have shown. The host variable was renamed `teamchat_lxc_seat_restore_starts_containers` (paths D 3.1, the lead's decision; the asking seat had not wired the old name).
