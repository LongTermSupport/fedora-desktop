# Plan 00266 Task C.3: verify-restore reports the LXC set

## What was built

- **`lxcstate.ReadRunningRecord`** returns the containers recorded at the last shutdown, plus
  whether the record exists at all. This tells "no record written" apart from "recorded none
  running". `ReadRunning` now wraps it.

- **`lxc.CheckRunning` / `teamchat-admin lxc check-running`** runs as root and only reads. It
  takes no argument and always exits 0 once it has read everything. It prints one line per
  container, in the form `<kind>\t<container>\t<why>`:

  - `UP`: recorded and running.
  - `DOWN <lxc-info state | ABSENT>`: recorded and not running.
  - `UNRECORDED`: running but not recorded.
  - `NO-RECORD\t\t<record path>`: printed first when the record was never written.

  If it cannot read the record, the container list or a state, it fails. It never reports
  that as a container's state.

- **`systemd.UnitEnabled`** returns the word `systemctl is-enabled` prints, whatever its exit
  status. It is an error only when there is no word or systemctl cannot run.

- **`ccy-sessions verify-restore`** first checks `teamchat-lxc-boot.service`:

  - `disabled` or `not-found`: it says so on stderr and asks nothing.
  - any other word but `enabled`: it fails.
  - `enabled`: it runs `sudo -n /usr/local/sbin/teamchat-admin lxc check-running` through
    `internal/sudo`. It then prints `lxc:<c> RUNNING`, `lxc:<c> NOT-RUNNING <state>`,
    `lxc:<c> NOT-RECORDED` and `lxc NO-RECORD` after the session lines.

  The LXC lines are printed even when the sessions' half failed, and the exit is 0 only when
  both halves pass. `NOT-RUNNING` and `NO-RECORD` fail; `NOT-RECORDED` is said on stderr and
  passes. `--wait` shares one deadline with the sessions' half and looks again while a
  container is DOWN. The lines are read strictly: an unknown line, a sudo that wants a
  password, or a failed check is a failure.

- **`play-teamchat.yml`** installs `/etc/sudoers.d/teamchat-lxc-check-running` (template
  `files/etc/sudoers.d/teamchat-lxc-check-running.j2`, checked with visudo, mode 0440) while an
  LXC member is present, and removes it otherwise. The rule is
  `%<teamchat_owner_group> ALL=(root) NOPASSWD: /usr/local/sbin/teamchat-admin lxc check-running`,
  which allows that exact argument list only.

## Departures from DESIGN.md and the brief

1. **Root is reached through sudo.** DESIGN.md has the root verify unit report the LXC set.
   The brief has verify-restore report it. verify-restore runs as the user (`cycle.py`
   `_ccy_sessions` uses runuser), and both the record (root 0600) and the container list are
   root's. A scoped NOPASSWD rule bridges the two. It follows the agent-bus-read-only
   precedent and is granted to the owner group, the group that already reads teamchat
   status. Unlike agent-bus, it has no host variable to turn it off.
2. **NOT-RECORDED passes.** The boot unit promises at least the recorded set, and
   `lxc.start.auto` or a host's own IaC may start more.
3. **Seats are not judged here.** `lxc boot`'s reconcile lines in the boot unit's journal
   report them. The PLAN.md open item (a guest's systemd not ready when reconcile reaches
   it) still waits for the live reboot.
4. **A stale record cannot be detected.** If the record unit failed at a shutdown, the record
   left from the shutdown before looks like a fresh one, because the record carries no boot
   stamp. Possible follow-up: stamp the record with the boot id it was written in.
5. **The quiet pass now prints one line.** `TestVerifyRestorePassesWhenEverythingIsPastItsPrompts`
   expected an empty stderr. It now expects the one line that says the LXC boot unit is
   disabled.
