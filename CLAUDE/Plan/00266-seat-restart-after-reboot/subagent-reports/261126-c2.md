# Task C.2 report (26 Nov)

## Built

- **The record of started seats:** `/var/lib/teamchat-admin/_lxc-started.json`
  (`paths.LXCStartedFile`), root 0600. It is `lxcstate.Started`, decoded strictly; a file that
  does not decode is refused, never replaced. `lxc start --member` adds the seat after a start
  that succeeded. A refused or offline start records nothing.

- **`teamchat-admin lxc stop --member C/K`:** this verb did not exist. The record rule ("not since
  stopped on purpose with `lxc stop --member`") needs it, so it was added. It takes the seat out of
  the record first, so a stop still counts when the container is offline (that case exits 69, as
  the other one-seat verbs do). Then it stops the session unit (`StopUnit`), with no lookup of
  claude.

- **`teamchat-admin lxc reconcile [--container C]`** (`lxc.Reconcile`). For each recorded seat, in
  record order:

  - `STOPPED` with the cause when the container is stopped or missing. The container is never
    started.
  - `LIVE` when the seat lock is held. Liveness is read the way the L3 probe reads it, so a live
    session is never touched.
  - `STARTED` otherwise, through `lxc.Start`, which is the same path as R77's claude lookup.
  - `REFUSED` with the cause when the start, the seat's record entry or a read fails.

  The output is one line per seat: `<KIND>\t<container>/<key>\t<why>`. The verb exits non-zero (1)
  only when a seat is REFUSED. An unreadable record or a failed container list is a host error.

- **Tests:**

  - `host/lxc/reconcile_test.go` covers the four seat cases, a refused start (counted, and the
    seat kept), the record kept across a container stop and then started, `--container`, a stray
    seat, the faults, the start recording and the stop forgetting.
  - `lxcstate/started_test.go` covers the decode and the round trip.
  - `admin/lxc_test.go` covers usage, stdout and the exit codes, and adds `stop` to the one-seat
    verb table.

- The docs (`docs/agent-bus-lxc-members.md`) are updated, and so are the CCY version and the
  container label (the paths package is in the image source).

## Not built: the boot unit and `lxc_seat_restore_starts_containers`

This was stopped on a question the plan does not settle. The unit is to come from
`play-lxc-install-config.yml`, and the logic is to be in Go. That play runs before
`play-agent-bus.yml` in `playbook-main.yml`, and it also runs on hosts with no teamchat, so
`teamchat-admin` may not exist when the unit is installed or run. There are two ways out:

1. The container snapshot at shutdown and the start at boot do not belong to teamchat-admin.
   They need a home of their own (a small Go command, with `lxc-start` added to
   `commandOwners`). The unit then runs `teamchat-admin lxc reconcile` only where it is
   installed.
2. The unit moves to the teamchat play.

## Also open

A seat that leaves its team (`lxc apply --phase absent`) stays in the started record. Every later
reconcile then reports it REFUSED ("names no seat") and exits 1, until `lxc stop` forgets it. The
plan's rule names only `lxc stop` as a stop on purpose, so leaving the team was not made one.
