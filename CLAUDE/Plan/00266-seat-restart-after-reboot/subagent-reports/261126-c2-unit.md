## Why it is not committed: two findings, and a design fault behind one of them

1. `paths` `TestEveryExportedNameIsSampled`: `HostVarLXCStartsContainers` needs adding to
   `sampleNames` in `separation_test.go`. This one is trivial.
2. `v1names` `TestEveryInstalledFileIsJudgedOrRunsNothing` and
   `TestEveryUnitTextCarriesTheSixV1Paths`. Every installed service must list the six v1 paths in
   `InaccessiblePaths=`, which means a private mount namespace. **A container started by
   `lxc-start` from such a unit inherits that namespace.** So the boot unit must not run
   `lxc-start` itself.

**Proposed fix (not built):**

- `start-recorded` starts each container through the host systemd as `lxc@<name>.service`
  (LXC's own template unit, upstream `lxc@.service`: `lxc-start -F`, `Delegate=yes`). That needs a
  host-systemd `Start` in `lxc.Deps`, wired from `sys.Host.Systemd` in `admin/wire/lxc.go`.
- Drop `lxccmd.Start` and its `commandOwners` row.
- After the start, wait (bounded, on `Deps.Clock`) for lxc-info's state to be `RUNNING`, so that
  reconcile does not report the container STOPPED.
- **The shutdown order:** `lxc@X` instances stop in parallel with the record unit. Install a
  drop-in, `lxc@.service.d/teamchat.conf` with `Before=teamchat-lxc-record.service`, as another
  `unitfiles` file, so the record is taken before they stop.
- Both units then take `v1names.InaccessiblePaths`. Add them to the `want` list of the v1names
  test.
- Check on the host that the `lxc` package ships `lxc@.service`.

## Open

- Readiness of the guest's systemd: after a boot start, reconcile's guest D-Bus may not be up
  yet, so a seat may be REFUSED. This is unverified, and is for C.3 and the live reboot.
- A failed start of the boot unit does not lose the shutdown record. The record is kept by its
  own unit, which is why there are two units.
- `localhost.yml.dist`: no teamchat variable is declared there (the convention is the play's
  "Inputs" header plus `paths.HostVar*`), so this one is not either.
- `meta-deploy.list` already queues `playbooks/imports/play-teamchat.yml`. Its description needs
  a C.2 sentence when the unit lands.
- PLAN.md: only the absent sub-item can be marked done.
