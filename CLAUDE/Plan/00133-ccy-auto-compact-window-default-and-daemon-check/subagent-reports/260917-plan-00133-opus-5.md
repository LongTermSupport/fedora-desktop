## Three findings worth your attention

1. **`600k` is inert below a 1M-context model.** The effective threshold is the
   minimum of the setting and the model's window, so on a 200k-context model the
   setting changes nothing. It is not harmful and the intent is coherent — the
   recovered strings show this variable is *designed* as the 1M-context cap
   enforcement mechanism — but the plan states it plainly rather than implying
   the default changes every session. **Task 1.5** puts it to the owner as a
   confirmation, not a challenge.

2. **Setting the env var disables the `/config` control for the window.** A
   documented consequence of the override, also surfaced in Task 1.5.

3. **The brief's daemon rule would flag upstream's own recommended value.**
   "Warn if not set or greater than 600k" catches `auto`, which the CLI calls
   "strongly recommended". This is a genuine design question rather than an
   oversight, so **Task 3.2** makes the owner settle it *before* the issue body
   is generated, and asks that the issue carry it as a question rather than an
   asserted design.

## Two corrections to the brief's premises

- **`entrypoint.sh:288` is now `entrypoint.sh:382-391`** (the assignment is at
  386). The mechanism is exactly as the brief described — only the line has
  moved since Plan 00098's research. The plan cites the marker, not the line.
- **A `ccy.env` override must use `export`.** The entrypoint carries its own
  comment recording that a bare assignment does not survive the `exec` into
  `claude`. The plan requires the documented example to use `export`, which is
  the difference between the override working and silently not.

## Where the default goes, and why not the alternative

**Chosen:** the launcher's `container_cmd run` `-e` block in
`files/var/local/claude-yolo/claude-yolo`, using
`${CLAUDE_CODE_AUTO_COMPACT_WINDOW:-600k}` — the idiom a sibling line already
uses, which is what preserves host override.

**Rejected:** `ENV` in the Dockerfile. It bakes the value into the image, forces
a rebuild to change it, loses the host-override idiom, and drags in a
`REQUIRED_CONTAINER_VERSION` bump. The launcher placement needs none of that,
but **does** require the `CCY_VERSION` bump (currently `3.57.0`) — the script
self-checks and refuses to run if that is missed, so the plan makes it a task in
its own right rather than a footnote.

## The upstream half

The ask is **"add a seventh check to `optimal_config_checker`"**, not "write a
new handler" — that handler already audits six Claude Code environment
variables, one of which (`CLAUDE_CODE_MAX_OUTPUT_TOKENS`) has the identical
shape. Framing it that way makes it a materially smaller and more acceptable
request, and the plan says so explicitly.

Per `R-UPSTREAM-ISSUE-UNVERIFIED-BODY`, the body **must** come from
`hooks-daemon issue-report`. The plan states this, names Plan 00075's precedent,
and explicitly forbids hand-drafting a body anywhere in the plan folder — so the
next agent cannot repeat 00075's wasted work by drafting one "ready to paste".
