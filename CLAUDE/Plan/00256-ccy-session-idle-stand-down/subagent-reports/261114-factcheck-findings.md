## REFUTED / overstated (most consequential first)

1. Claim 6 ("`on_idle` is called about every 2 s on an idle session with the plugin loaded") is only partly supported.
   R shows `supervise/` changing every 2.00 s in one project (project-3, 89 changes). The other loaded project (project-4) showed no change in the window, and J says so.
   The 2 s tick is also inferred. R's own header says `supervise/` changes on every plugin hook call, and the "in-hook marker" was never caught (0 samples). So the tick is "a hook call", not proven to be `on_idle`.
   Whether that session was idle is not shown either.
   Plan change: say "observed in one of two loaded projects; the tick is a plugin hook call, assumed to be `on_idle`".
2. Claim 9 ("`stop` ... keeps the containers (`down` removes them)") is not shown by the evidence.
   R prints only the `stop` and `down` help texts. The `stop` help says nothing about keeping containers. The `down` help of podman-compose and docker compose says nothing about removal except `-v` and `--rmi`.
   The script's own header calls it "expected" (probe-idle.bash:499).
   The existence of `stop` in podman-compose 1.5.0 and Docker Compose v5.7.0 is verified.
   Plan change: drop "keeps the containers" or mark it as the documented behaviour of compose, not observed.
