## 00:21 · finding · T4.1   — RealtimeSTT hangs after a failed init

The streaming leg's hang is RealtimeSTT's, not the check's: read in the 1.0.0 wheel.

- `AudioToTextRecorder.__init__` logs, then re-raises, an error loading the real-time model
  (audio_recorder.py, "Error initializing ... realtime transcription model").
- `_start_thread` on Linux starts the main transcription worker as `threading.Thread` and sets
  `thread.deamon = True` (misspelt), so the worker is not a daemon and keeps the process alive
  after the constructor raises. The child therefore sat out the 600 s timeout.
- `no_log_file` (default False) is what stops `logging.FileHandler('realtimesst.log')` in the
  working directory; `realtime_model_type` defaults to `"tiny"`.

The same non-daemon worker means `wsi-stream` itself can hang on any other recorder init
error (it ends with `sys.exit(main())`); Task 4.1 removes the missing-model cause only.
