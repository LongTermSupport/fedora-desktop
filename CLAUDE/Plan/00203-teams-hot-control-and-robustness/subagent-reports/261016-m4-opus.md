## Settled where the spec was open (also in SPEC H21, "As built in M4")

01. **Where the allocation lock lives.** It is in the runtime directory, not `seats/.alloc.lock`:
    - pingbus `list_seats` refuses any non-team entry under `seats/`, so every deployed image would break;
    - the checkout is container-writable, so a lock there could be a symlink trap or held forever.
02. **What "live" means.** For ccy-teams, a session on ccy's tmux server (as the board defines it). For agent-bus, a session whose container runs. Because of that, a launcher's own desired file, written just before its `seat take`, never blocks it.
03. **Which records count (N4).** Only a `restore=yes` record of a stopped session in the same checkout counts. A non-restore record does not.
04. **How `hand-to=<seat>` resolves.** It names a full handle, or the one active, non-leaving member whose handle has that seat. More than one match is exit 64.
05. **`add --role=coordinator`.** Like `role`, it needs `--demote-current` when another member holds the role.
06. **The interactive coordinator remove.** It asks one yes/no question (demote, default yes). Handing the role over is done only with the option. The picker menu is M5.
07. **What `move` does.** It passes `--coordinator` to its remove half, and checks the non-interactive coordinator case before the add changes anything.
08. **What `session list` shows.**
    - Roles come from the keeper's report (`told`), so no sudo is needed.
    - "unguarded" means no `pingbus seat keep` process in `podman top`.
    - It lists running labelled containers only.
    - Its states are `old or --no-bus`, `unguarded`, `<team> down`, `<seat>@<team> not held` and `ok`.
09. **`session role` when the session is not told within 10 s.** It exits 1 and the role stays changed. Running the same command again waits again.
10. **`ccy-teams remove`.** It stays terminal-only (never `--yes`, its own rule). Sessions are taken off with `--coordinator=demote`.

## Second round (after fix/acceptance-host-3 landed)

- **H26, the in-session `bus: <team>(down)`.**
  - While a team's homeserver does not answer (a `MatrixError`), the watcher keeps `PINGBUS_HOME/down/<team>` (0600, directory 0700). Each retry refreshes it.
  - The mark is removed when the team syncs again or when its thread ends.
  - The status line appends `(down)` for a mark younger than 300 s, so a mark left by a killed watcher stops counting.
  - Another kind of sync failure (a full disk) is not marked.
  - A mark that cannot be written is reported on the watcher's stderr, and the team stays watched.
  - `statusline.py` owns the place, as it does for the session record.
  - M4 acceptance (d) now also checks that A's status line says `acc-m4b(down)`.
- **The M3 launch.** `m3_start` no longer uses `exec` and gains the load-bearing `; echo "$?" >session.status`, as `m2_launch` does.
  - `m2_adopt` takes a third argument, the path the session's `.status` and `.err` start with. `m2_ended_early` reads those, so an early end of an M3 or M4 session reports its own exit status and stderr. Before this, it read M2's paths.
  - M4's launch already had the safe form; it now passes its own log prefix.
- **A flaky helper test.** `assertGone` in `test_statusline.py` now counts `ProcessLookupError` as gone, as well as `FileNotFoundError`. That error is ESRCH, raised when the process is reaped between the open and the read of `/proc/<pid>/stat`.
  - A new test forces both errors by patching the read. It was red before the fix and green after.
  - The only other `/proc` read in the pingbus and agent_bus tests is `test_seat.py:1099`. There a single-threaded child lists its own `/proc/self/fd`, already filtered by `exists`. No other process can vanish there, so it was left as it is.
