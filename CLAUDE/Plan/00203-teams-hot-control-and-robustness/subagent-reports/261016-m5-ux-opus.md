# Plan 00203 M5 rework: visible choices, not magic keys (Opus)

Branch `fix/picker-visible-actions`, from F44 741191c3. The owner rejected the M5 picker's
Ctrl-A/X/O ("magical key combos again instead of UX"), and set the rule: "TUI must be UX
controls not magic keys - keys are OK but MUST NOT BE THE ONLY CONTROL SURFACE". That rule is
now CLAUDE/InteractiveScripts.md rule 14, and src-go/CLAUDE.md points to it.

## What changed in `ccy-teams`

- **The teams list.** It ends with a row, "Running sessions: change a session's teams while
  it runs (Tab)". Tab is a shortcut for that row, printed beside it and in the header ("Tab
  running sessions (the last row)").

- **Running sessions.** Ctrl-A, Ctrl-X, Ctrl-O and Tab are removed. The list ends with two
  rows: "What this list shows (?)" (the help) and "Back to the teams". The view's only key is
  `?`, the help row's printed shortcut.

- **The session menu.** Enter on a session lists, in words, in this order:

  - Add to a team;
  - Remove from `<team>`, once per team;
  - Change role in `<team>` (now `<role>`), once per team;
  - Move to another team (with several teams: Move from `<team>` to another team);
  - Attach;
  - Repair (its seat keeper has stopped), only when the session is unguarded.

  The team is in the line, so no flow asks "which team" (`askTeamOf` is deleted). A session
  that cannot be changed offers Attach only, and its menu header says why.

- **One code path.** Unchanged. Every flow ends in `Hot.Run` with the argv a person would
  type, and the tests assert the exact argv.

## Hidden action bindings found elsewhere in `ccy-teams`

- **Ctrl-U (fixed).** It ran "update every team" from any row, but it was printed only on a
  team row's menu and footer. Now every teams-view key acts only on a row whose menu offers
  it (`act` checks `actionsFor(row)`); anywhere else it says "That key does nothing on this
  row." Ctrl-R on a row with no restore and Ctrl-P on a non-person row now get that line
  instead of their old refusal text. `scripts/test-ccy-teams-command.bash` is changed in
  this commit to match, with the reason given there.
- **Compliant.** Every other teams-view key (Ctrl-N, Ctrl-P, Ctrl-E, Ctrl-U, Ctrl-R, Ctrl-X,
  `?`) is a line of the row's menu that you can reach with the arrows and Enter. It is
  printed beside that line as "(Ctrl-E)" and in the row's footer. `?` is "What the columns
  and keys mean" in every row's menu. `q` is navigation, and the header says so.

## Follow-ups (not ccy-teams)

- **`ccy-sessions`** (`src-go/internal/sessions/picker.go`). Ctrl-T (take over), Ctrl-X (end)
  and Ctrl-N (new) are printed in the header, but they are not choices you can select:
  each key is the only way to its action. The fix is a per-row menu, through the
  `ui.Action` helper the DBF branch adds.
- **`ccy --teams`.** Its multi-select marks rows with Tab (fzf `--multi`) in the bash
  launcher. Tab is selection, not an action, but check that its header says so.
