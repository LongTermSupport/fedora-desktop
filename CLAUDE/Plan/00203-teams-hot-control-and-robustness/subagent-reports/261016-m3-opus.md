# M3: the first end-to-end hot add and remove (Opus build notes)

Branch `feat/hot-control-m3`, from `feat/hot-control-m1-pingbus` with local F44 merged in.
CCY 3.99.8, container 2.73, ccy_lifecycle plugin 1.1.0.

## What was built

### pingbus (helpers/pingbus)

- `membership.py`: `inbound` (optional) in the applied file and the report; `told.json` with
  its own `told.lock` (the watcher and the prompt hook tell, the keeper copies the told roles
  into `applied.told` and republishes when it changes). `ToldRecord.left` keeps the teams the
  session was told it left, so a command for one is refused with "removed by the owner".
- `config.py`: `removed_reason` (a farewell entry in the desired file, or `told.left`) and the
  64 message for a removed team.
- `envelope.py`: the `MEMBERSHIP` kind (H12), `render_membership`, which takes only pingbus's
  own template lines and refuses control and separator characters and `<<`/`>>`.
- `hooks.py`: the joined/left/teams-now templates, `membership_notice`, `tell_membership`.
  Session start records the socket and baselines silently; each prompt adds the lines the
  watcher has not told (the H13 fallback).
- `notify.py`: `socket.json` (path and token, 0600), written by the SessionStart hook.
- `seat.py`: the keeper starts the watcher when a seat is applied and the watch lock is free
  (H11), from `socket.json`; republishes on a told change; reports `inbound`.
- `cli.py`: the watcher follows the membership every tick (`_Following`). A removed team's
  thread gets its stop event and releases its sync lock after the in-flight long poll; an added
  team gets a new thread; the notice goes over the socket; with no team left it exits 0.
  `wait` follows the same way. `seat retire` and the new `seat farewell` wait up to
  `sync_wait_s` (30 s long poll + 10 s) for the sync lock.
- `statusline.py`: with `PINGBUS_MEMBERSHIP` set, the segment comes from the applied file, the
  desired file as fallback (H14).

### Go (src-go/internal/teams)

- `discover/`: one session-discovery index; `board`'s `SeatSession` and `shutdown`'s `seatsOf`
  use it.
- `hot/`: `ccy-teams session add` and `remove`. Per-step ✓/✗/-, idempotent (a re-run marks
  every step `-`), rolled back on a failed apply. Remove writes the farewell entry, waits for
  the seat to be released, then re-baselines (`pingbus seat retire`) and says goodbye
  (`pingbus seat farewell`) before dropping the entry; a failed half stays owed and the same
  command finishes it. No role options.
- `membership/desired.go`, `report.go`: the only writer of the desired file (atomic, by
  rename) and the report reader. Nothing from the bus is accepted.
- `find/restart.go` and `ccy-teams internal restart-args`: the launcher's restart replay takes
  `--teams` from the registry record, so a relaunch carries the hot-added teams.
- `registry.SetTeams`, `agentbus.SeatTake`/`SeatChooseIn`, `config.Pingbus`
  (`CCY_TEAMS_PINGBUS` overrides).

### The first join of a zero-seat session

`session add` writes `relaunch.json` into the membership directory; the ccy_lifecycle
supervisor plugin returns ExitForRestart at idle; the launcher replays through
`ccy-teams internal restart-args`; `membership-init` removes `relaunch.json`. The add reports it
on its own line. The entrypoint loads the lifecycle plugin for every bus session, and warns
(does not fail) when it cannot, because the session still works without the relaunch.

## Deviations from the spec

1. A removed team's sync lock is released after the in-flight long poll ends (up to 30 s), not
   within 2 s. Retire and farewell wait `sync_wait_s` for it rather than failing.
2. H5's `restart-args` was done here, early, because the first-join relaunch needs it.
3. The relaunch goes through the lifecycle supervisor plugin (`relaunch.json`), not a signal
   to the session.
4. Not done in Go: H20 locks on the desired file across two concurrent `ccy-teams` runs, the
   H27 64-agent roster check, and docker-engine sessions (podman only).
5. The headless acceptance session has no supervisor, so the first-join relaunch is the
   owner's step M3 (g); `_acceptance-m3.inc.bash` launches its session on `acc-m3a` and adds
   `acc-m3b` hot.
