## 04:07 · action · —

The two acceptance failures of the F44 7fd72106 host run are fixed on fix/acceptance-host-2. Both fixes are in the acceptance scripts, so nothing is deployed and there is no version bump.

- **00203 M2, the launch leg.** The cause is in the test, not in the launcher identity fix. The leg started ccy in tmux as `exec ccy … <fifo >out 2>err`. With all three streams redirected, an exec'd ccy holds no descriptor on the pane's terminal. tmux then reads end of file from the pty, takes the pane as exited and sends SIGHUP. That happens before ccy writes a byte, so the .out and .err files were empty. Reproduced in the container with real tmux 3.3a: `exec` with `</dev/null` or a fifo dies of signal 1, while stdin left on the pty, or no `exec`, survives. The leg had never run on the host before (the bbbd0604 run stopped at the SELinux check), so the identity fix only looked like the cause. The fix runs ccy as the child of the pane's own shell, which keeps the terminal and writes ccy's exit status to `<name>.status`. ccy is still that session, by the `$PPID` branch of `ccy_tmux_current_session` (the registry trampoline's shape), and the container proof printed the pane's own name. A session that ends early now prints its exit status (or "not written" if the shell itself was killed) and its stderr. U20 M2.11 used the same form and gets the same fix.

- **00161 M2.3.** The check expected one unsupervised `pingbus watch`, but M0 runs `watch --supervise` with its `watch --child` (SPEC-inject E26). Under E26, a session with a socket is never given Stop's "no waker" block, which is for a session with no socket only. The hooks start the supervisor again unless their last start was within 300 s. In that case they report `watcher_failed`, which says to run `pingbus wait` meanwhile. The check now:

  - finds the supervisor and its child by argv and parent (`u20_check.py supervised-watcher`, red then green) and sends TERM to the supervisor first, then to the child;
  - gives accc a turn with nothing to do;
  - if the hooks start the watcher again (`watcher_restarted`), waits out their 30 s grace, stops it again and gives a second idle turn, still inside the 300 s;
  - then requires `wake=waiter` and the `watcher_failed` text, read from the transcript or from a hook output saved beside it (`expect-hook-text`, which replaces `expect-no-waker-block`).

  The rest is unchanged: the review, the ack, no deliveries, and 2 or 3 stdin lines. Rule 3 of the standing orders now covers "the watcher could not be started". M2.4 onwards make no assumption about the watcher. DESIGN.md M2.3 and D59 are updated.
