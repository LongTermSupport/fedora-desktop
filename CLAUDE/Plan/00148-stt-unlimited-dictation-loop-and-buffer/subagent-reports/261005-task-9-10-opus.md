# Task 9.10: paste target pinned at Insert (sub-agent report)

## What was built

- `extensions/speech-to-text@fedora-desktop/pasteTarget.js` (new, added to the
  playbook's "Copy Extension Files" loop): `PasteTargetPin` with `pin(window)`,
  `release()`, `window`, and `answer(focusWindow)` returning `{window, focused, gone}`.
  The activate function is injected (default `Main.activateWindow`, checked against the
  extracted GNOME Shell `main.js`: it switches workspace via `activate_with_focus`, else
  `window.activate`, and hides the overview).
- `extension.js`: the pin is taken in `_launchWSI` and `_launchWSIClaude` (after the
  "already recording, so stop" branch, before the recorder is spawned) and released on
  IDLE / SUCCESS / ERROR and in `disable()`. `PasteKey` gains `b focused`, `b gone`.
  `_pasteTargetForFocus()` is now `_pasteTargetFor(window)`.
- `focusOutline.js`: `show(window)` frames that window only; no focus signal. Hides on
  `unmanaged`; overview behaviour kept.
- `wsi-stream`: `PasteTargetUnavailable`, `ask_paste_key`, the retry loop in
  `paste_target_now` (`PASTE_FOCUS_WAIT_SECONDS` 2.0, `PASTE_FOCUS_POLL_SECONDS` 0.1),
  `report_unpasted`, and `paste_and_report` used by the final paste in all three modes
  (server, standard streaming, pre-buffer). `paste_chunk` treats an unavailable target
  like a failed paste (not counted, goes with the next).
- `wsi`: the same loop (`PASTE_FOCUS_POLLS=20`), `PASTE_TARGET` ready/closed/unfocused;
  on closed/unfocused the text is already on CLIPBOARD, no key is pressed, exit 1.

## Design decisions differing from or adding to the brief

- A three-field `PasteKey` reply (an extension loaded before this change, until the
  owner logs out and in) is read as `focused=true, gone=false`, not as "no answer": the
  recorders deploy at once and the extension only at the next login, so this keeps
  today's behaviour (paste into the focused window with the panel's key) in between.
- With no pin (nothing focused at Insert, or a recorder started by hand) the outline is
  not shown at all, rather than following focus. Pastes still go to the focused window.
- Mid-dictation chunks are silent on an unavailable target; the user is told once, at
  stop, with only the text not yet pasted on the clipboard and the count of words
  already pasted (the same wording as Task 9.9's failure report).
- In `wsi` the error goes through `log_error` (which already emits ERROR, the Error
  signal and a transient notification) followed by `notify_desktop ... 0`, which replaces
  that notification with one that stays. A separate `emit_state ERROR` would have sent
  ERROR twice (the test caught it).

## Article mode and Claude post-processing

- Article mode (`wsi-article-window`) never auto-pastes; its window has a Copy button.
  The outline is already off for it. Nothing changed.
- Claude post-processing (Ctrl+Insert / Alt+Insert) runs through `wsi` / `wsi-stream`
  and pastes through the same paste block / `paste_and_report`, so it is pinned too. Its
  failure path (Task 9.8) is unchanged.
