# Plan 00148 — Journal 26-10-12

_Scaffolded by `mkplan.bash`; timestamps in this file are UTC._

> **Append-only activity log** for plan 00148. One file per day
> (`00148-Journal-YY-MM-DD.md`). `PLAN.md` tracks the plan (what/why,
> current state, tasks); this journal tracks what actually *happened* —
> findings, decisions, dead-ends, hand-off state — the linear lifecycle a plan
> document structurally cannot carry.
>
> **Entry grammar** — append new entries at the BOTTOM; NEVER edit earlier
> entries (corrections are new entries):
>
> ```
> ## HH:MM · category · REF   — optional short title
> ```
>
> - `HH:MM` UTC 24h (the date is in the filename, also UTC); times increase
>   down the file. A file with no sentinel line above predates this system —
>   its times are local, zone unrecorded (legacy; never rewritten).
> - `category` ∈ `action` | `finding` | `decision` | `thought` | `blocker` | `handoff`
> - `REF` = optional task/phase ref (`T1.2`, `P1`) or `—`.
> - Bodies may embed fenced logs/diffs/snippets — no size limit — with a
>   one-line takeaway above the fence.
> - End a working session with a `handoff` entry so the next agent's entry
>   point is the last entry of the newest day-file.

## 11:27 · finding · P11   — Phases 11 and 12 researched; design note written

Phases 11 and 12 researched and made concrete; detail in RESEARCH-thin-extension.md.

Findings that changed the draft:

- The caller map (Task 11.5) is in the research doc, section 1.2, not here: it is a
  table of files and functions, durable detail rather than a log.
- Server mode never sends PREPARING; only batch, pre-buffer and article mode do. So
  `panelSession.js`'s CAPTURING goes with Phase 11 (Insert in an article is `_stopArticle`).
- `claude-enabled` is loaded by the extension and never consulted: Settings shows a
  switch that does nothing. Put to the owner as Task 11.4.
- `faster-whisper-transcribe` (play-written) is used only by `wsi`, so it goes with it.
- Between a Phase 11 play run and the logout, the old extension still launches
  `wsi-stream --server-mode`; the flag must stay accepted until Phase 12. The retired
  keys must not leave the compiled schema while a running Shell still reads them, so
  they are reset in Phase 12's switch-over deploy, which has a logout anyway.
- "Mic-health reporting" in the draft is `wsi-stream`'s `microphone_shortfall`, not
  extension code; it stays in `wsi-stream` until that client's duties move.
- A service that spawns recorders directly would kill a live dictation, and any warm
  server it started (`start_new_session` keeps the cgroup), on `systemctl --user restart`. Design: each recorder in its own transient scope via `systemd-run --user --scope`; to be proven by the first integration test.
- A recorder started by a user service gets the user manager's environment, not the
  Shell's; triage before building (Task 12.4).
- PLAN.md is at about 34.6 KB, just under the 35 KB edit block; further detail for these
  phases belongs in the research doc.
