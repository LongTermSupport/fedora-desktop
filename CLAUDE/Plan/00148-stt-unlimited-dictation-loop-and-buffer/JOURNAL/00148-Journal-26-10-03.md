## 15:56 · finding · —

Task 7.4 and Phase 8 (keep the server warm) built on top of the interrupted WIP commit.

Reviewed the WIP: `wsi-resolve-model`, `wsi-setting` and the `wsi-stream` changes were sound in
shape, but `wsi-stream` did not compile (`debug_mode` assigned in `main()` before its `global`
declaration, a SyntaxError that broke every wsi-stream unit test), the at-login path ignored the

by the play. All fixed.

faster-whisper evidence: the play installs `faster-whisper` unpinned with `state: present`, so a
fresh host gets 1.2.1 (latest on PyPI) but an existing host keeps whatever it had. RealtimeSTT
1.0.4 and 1.1.2 depend on faster-whisper only through extras (`==1.2.1`); 0.3.104 pins
`faster-whisper==1.1.1` outright. The 1.1.1 wheel's `faster_whisper/utils.py` has no
`distil-large-v3.5` in `_MODELS`, so the short name raises "Invalid model size"; 1.2.1 maps it to
`distil-whisper/distil-large-v3.5-ct2`. Both accept any `org/name` as a repo ID
(`re.match(r".*/.*", size_or_id)`). So the resolver always hands over the repo ID.

Phase 8 choices: the login unit is enabled on every host and decides at login from GSettings, so
the switch needs no play run; it execs the server so systemd tracks it; `Restart=no` (idle exit and
the play handler mean stopped; a failing model load must not loop on the GPU). The server's
PID-file check was check-then-write and the loser of a race also truncated the winner's log; it now
claims the file with a hard link and truncates the log only after claiming.

Not established here: `glib-compile-schemas` is not in the container (the schema XML is parsed by
the harness, not compiled); whether `import ctranslate2` sees the GPU without the CUDA
`LD_LIBRARY_PATH` (streaming already imports it the same way, and the play's new verify task
proves it on the host); real model load and login behaviour (Task 8.4, HOST).

## 16:09 · finding · —

CORRECTION to the previous Task 7.4 / Phase 8 entry, after qa-reviewer (FIX-BEFORE-MERGE).

That entry said the play's "Verify The Auto Model Resolves" task proves on the host that
CTranslate2 sees the GPU. It did not: `ctranslate2.get_cuda_device_count()` returns 0, not an
error, when CUDA is broken, and the resolver took that 0 as "no GPU" and quietly picked the CPU
model, which the task accepted. Now `wsi-resolve-model` fails when `/dev/nvidiaN` nodes exist but
the count is 0, and a new `--gpu-count` probe lets the play assert a non-zero count on hosts with
an NVIDIA GPU (and pass on hosts without one).

The same entry's PID-file claim (hard link) was not race-free over a stale file: two servers could
both judge the same stale PID dead, and the second unlink removed the first one's fresh file. A
reused PID also blocked every start, and a server whose model failed to load left its file. The
server now holds an exclusive `flock` on the PID file for its lifetime (re-checking the inode after
locking), removes the file on every exit path it controls, and `wsi-stream` asks the lock, not the
PID, whether a server exists. A test races six starts, with and without a stale file naming a live
PID: exactly one wins.

Also: the play reads back that the live user manager pulls in the login unit; the troubleshooting
docs point at the Settings Whisper Model and Language instead of `stt_model`/`stt_language`; the
"from 1.2.0" claim is replaced by what was read (1.2.1 knows the name, 1.1.1 does not); and `wsi`
run by hand without `--language` now takes the language setting and exports it, so the resolver and
`faster-whisper-transcribe` use the same language.
