> **Append-only activity log** for plan 00148. One file per day
> (`00148-Journal-YY-MM-DD.md`). `PLAN.md` tracks the plan (what/why,
> current state, tasks); this journal tracks what actually *happened* —
> findings, decisions, dead-ends, hand-off state — the linear lifecycle a plan
> document structurally cannot carry.
>
> **Entry grammar** — append new entries at the BOTTOM; NEVER edit earlier
> entries (corrections are new entries):
>
> ```
> ## HH:MM · category · REF   — optional short title
> ```
>
> - `HH:MM` UTC 24h (the date is in the filename, also UTC); times increase
>   down the file. A file with no sentinel line above predates this system —
>   its times are local, zone unrecorded (legacy; never rewritten).
> - `category` ∈ `action` | `finding` | `decision` | `thought` | `blocker` | `handoff`
> - `REF` = optional task/phase ref (`T1.2`, `P1`) or `—`.
> - Bodies may embed fenced logs/diffs/snippets — no size limit — with a
>   one-line takeaway above the fence.
> - End a working session with a `handoff` entry so the next agent's entry
>   point is the last entry of the newest day-file.

## 15:09 · finding · P0   — delayed stop implemented; per-mode losses found

Phase 0 (Tasks 0.1-0.4) implemented; findings per mode in RESEARCH-stop-path.md.

- Pre-buffer streaming installed no signal handlers, so Insert's SIGTERM killed it outright: no text, no IDLE. Found by reading, not reproduced on a host.
- Server mode dropped the pw-record pipe (feeder stopped before pw-record) and froze the text at the last realtime pass: RealtimeSTT 1.1.2 publishes realtime text only while recording, so the post-stop poll never saw an update.
- Grace source: GSettings key stop-grace-seconds (default 3) read by a new wsi-stop-grace; no extension.js change.
- The end-to-end wsi test caught a real defect in the first draft: a bare `return` inside a TERM trap reports the interrupted `wait`'s 143, and set -e then exits before transcription.
