## 16:09 · finding · —

CORRECTION to the previous Task 7.4 / Phase 8 entry, after qa-reviewer (FIX-BEFORE-MERGE).

That entry said the play's "Verify The Auto Model Resolves" task proves on the host that
CTranslate2 sees the GPU. It did not: `ctranslate2.get_cuda_device_count()` returns 0, not an
error, when CUDA is broken, and the resolver took that 0 as "no GPU" and quietly picked the CPU
model, which the task accepted. Now `wsi-resolve-model` fails when `/dev/nvidiaN` nodes exist but
the count is 0, and a new `--gpu-count` probe lets the play assert a non-zero count on hosts with
an NVIDIA GPU (and pass on hosts without one).

The same entry's PID-file claim (hard link) was not race-free over a stale file: two servers could
both judge the same stale PID dead, and the second unlink removed the first one's fresh file. A
reused PID also blocked every start, and a server whose model failed to load left its file. The
server now holds an exclusive `flock` on the PID file for its lifetime (re-checking the inode after
locking), removes the file on every exit path it controls, and `wsi-stream` asks the lock, not the
PID, whether a server exists. A test races six starts, with and without a stale file naming a live
PID: exactly one wins.

Also: the play reads back that the live user manager pulls in the login unit; the troubleshooting
docs point at the Settings Whisper Model and Language instead of `stt_model`/`stt_language`; the
"from 1.2.0" claim is replaced by what was read (1.2.1 knows the name, 1.1.1 does not); and `wsi`
run by hand without `--language` now takes the language setting and exports it, so the resolver and
`faster-whisper-transcribe` use the same language.

## 17:00 · decision · P2   — server retires RealtimeSTT; panel shows elapsed time

Decisions made while building Phases 2-4, for the owner to confirm or reverse.

- RealtimeSTT is retired from `wsi-stream-server`. The server loads faster-whisper's
  `WhisperModel` and bundled Silero VAD itself, and EVERY server-mode recording runs
  through the new dictation session. `continuous-dictation` off does not mean "the old
  path": it means the client sends the fixed 120 s cap (`STREAMING_MAX_SECONDS`) as the
  session limit and no silence stop. Reason: the old path pasted the tiny model's text
  (Task 4.1), and keeping it beside the new one meant two server pipelines. Effect with the
  toggle off: server mode now pastes the selected model's text, transcribed per segment;
  the at-most-120 s behaviour is unchanged. Standard and pre-buffer streaming still use
  RealtimeSTT, so the play keeps installing it.
- The panel no longer stops a recording itself and no longer counts down in batch or
  standard/pre-buffer/server-without-continuous mode; it shows elapsed m:ss. Every
  recorder already stopped itself at its own cap (`wsi` 30 s, `wsi-stream` 120 s), so the
  panel's 117/27 auto-stop was a second copy of each limit. The only countdown is the last
  minute of continuous dictation's `max-recording-minutes`, read from the same key the
  client sends the server. A batch user loses the "27..." countdown.
- The server's "Layer 2" client-disconnect stop is gone. It compared `getpeername()` of
  Unix-socket clients, which is the empty string for every client, so any empty connection
  stopped the recording; the 15 s KEEPALIVE heartbeat replaces it.
- STOP now replies at once with the session's progress (`draining`); the client polls
  PROGRESS until `done`/`failed`, which carries the text. Replies are read to their newline
  on both sides (a long dictation is far over the old single 4 KiB read).
- A FAILED session's text goes to the CLIPBOARD (Ctrl+V), never the primary selection and
  never auto-pasted; the failure notification stays until dismissed.
- Defaults chosen for the new keys: `max-recording-minutes` 60 (1-480),
  `silence-autostop-seconds` 120 (0-3600, 0 = never). Backlog ceiling 120 s, heartbeat
  15 s, drain deadline 10 s + 3 x backlog x RTF (RTF 1.0 until measured), as researched.
- Segmenter: a phrase with under 1 s of speech closes after a 2 s pause rather than
  waiting for more speech (the research's rule left a short "yes." open until the soft
  max). 0.5 s of pre-roll is kept before the first speech of a segment.
