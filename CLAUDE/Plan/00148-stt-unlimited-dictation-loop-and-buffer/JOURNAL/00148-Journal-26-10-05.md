# Plan 00148 — Journal 26-10-05

_Scaffolded by `mkplan.bash`; timestamps in this file are UTC._

> **Append-only activity log** for plan 00148. One file per day
> (`00148-Journal-YY-MM-DD.md`). `PLAN.md` tracks the plan (what/why,
> current state, tasks); this journal tracks what actually *happened* —
> findings, decisions, dead-ends, hand-off state — the linear lifecycle a plan
> document structurally cannot carry.
>
> **Entry grammar** — append new entries at the BOTTOM; NEVER edit earlier
> entries (corrections are new entries):
>
> ```
> ## HH:MM · category · REF   — optional short title
> ```
>
> - `HH:MM` UTC 24h (the date is in the filename, also UTC); times increase
>   down the file. A file with no sentinel line above predates this system —
>   its times are local, zone unrecorded (legacy; never rewritten).
> - `category` ∈ `action` | `finding` | `decision` | `thought` | `blocker` | `handoff`
> - `REF` = optional task/phase ref (`T1.2`, `P1`) or `—`.
> - Bodies may embed fenced logs/diffs/snippets — no size limit — with a
>   one-line takeaway above the fence.
> - End a working session with a `handoff` entry so the next agent's entry
>   point is the last entry of the newest day-file.

## 11:17 · action · —   — Task 9.10: paste target pinned at Insert

Task 9.10 built: the paste target is pinned at Insert.

- Extension: `pasteTarget.js` (`PasteTargetPin`) takes the window focused when `_launchWSI` / `_launchWSIClaude` start a recording (before the recorder is spawned), tracks its `unmanaged` signal, and is released on IDLE, SUCCESS, ERROR and in `disable()`. `PasteKey` now answers `(wm_class, with_shift, save_after, focused, gone)` for the pinned window; when focus has moved it calls `Main.activateWindow` (which switches workspace and unminimises) and answers `focused=false`. With no pin (nothing focused at Insert, or a recorder started by hand) it answers for the focused window as before. `_pasteTargetForFocus()` became `_pasteTargetFor(window)`.
- `focusOutline.js`: `show(window)` frames the given window and no longer follows focus; it follows the window's moves and resizes, hides when it closes, and keeps the overview behaviour.
- `wsi-stream`: `paste_target_now` asks again every 0.1 s for up to 2 s until `focused`; `gone`, or never focused, raises `PasteTargetUnavailable` before anything is copied or pressed. The final paste (all three modes, via `paste_and_report`) then puts the text not yet pasted on the clipboard, emits ERROR and a notification that stays, saying how many words chunks had already pasted. A chunk that cannot paste is not counted and goes out with the next one, so a closed window is reported once, at stop. A three-field reply (a panel loaded before this change, until the next login) is read as focused.
- `wsi`: the same loop; on `closed` / `unfocused` the text is already on CLIPBOARD (the copy precedes the keys), no key is pressed, `log_error` tells the panel ERROR, and a notification that stays says why. Exit 1.
- Article mode does not paste (its window has a Copy button), so it is untouched. Claude post-processing (Ctrl+Insert, Alt+Insert) pastes through the same `wsi` block / `paste_and_report`, and now pins at Insert too; a long Claude call no longer lets the text follow a focus change.
