## 07:15 · finding · — — the numbers that caused this plan

The owner reacted to Plan 00068's `PLAN.md` being 131 KB. Measured rather than
estimated, it is worse than the headline:

```
total lines      : 1894   (137 KB)
blockquote lines :  953   (50%)  <- correction/commentary blocks
checkbox lines   :   56   ( 2%)  <- actual tasks
numbered D-blocks:   27
## Success Criteria section alone: 314 lines
the actual deliverable, reports/one-page-restatement.md: 83 lines
```

Growth was monotonic: 42 KB at creation → 137 KB across 34 commits, and **not one
commit ever made it smaller**. I contributed 6 KB of that this morning, so this is
not a finding about someone else.

Takeaway: the cause is a *correct* rule applied in the wrong place. "Corrections
APPEND, never rewrite" protects line-number citations and is right for `JOURNAL/`.
In `PLAN.md` it makes size a monotonic function of review effort — so the better a
plan is audited, the less usable its plan document becomes. That is a perverse
incentive, not a discipline problem.
