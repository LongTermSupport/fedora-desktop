## 14:00 · decision · T6.2   — the restore-only askpass, as built

Implemented the owner's T6.1 choice (CCY 3.72.0, container 2.39). Choices made where the brief
left room, each picked as the one closest to `run.bash --headless`:

- **"Headless server" is `provisioning_profile == 'server'`**, the variable every play already
  scopes by (group_vars/desktop.yml, from `systemctl get-default`). Combined with
  `ccy_restore_sessions` and **a non-empty `github_accounts`**: `run.bash --headless` requires the
  SSH passphrase only when GitHub is configured, so a server provisioned with
  `RUN_BASH_GITHUB_ACCOUNTS=none` keeps restore working with no passphrase demanded.
- **Where the passphrase comes from at restore time: a 0600 file the play writes**
  (`~/.claude-tokens/ccy/restore-ssh-passphrase`, `no_log`), not a boot-time vault decrypt.
  `run.bash --headless` itself takes the passphrase as a 0600 file
  (`RUN_BASH_GITHUB_SSH_PASSPHRASE_FILE`). Decrypting at boot would make the user unit depend on
  ansible-vault, the checkout path and the vault password file. A systemd credential was ruled
  out because the restore unit is a oneshot. Its credentials directory goes when it exits, and
  that is before the panes it started run ssh-add. The trade-off is the one T6.1 accepted:
  user-readable at rest, the same boundary as the vault password file.
- **The marker is a unit drop-in** (`ccy-sessions-restore.service.d/ssh-unlock.conf`, which sets
  `CCY_RESTORE_SSH_PASSPHRASE_FILE`). It is deployed where the unlock applies and removed
  everywhere else. Without it, a missing file on a server would look the same as a desktop, so
  the restore could not fail loudly.
- **The container prompts too.** The entrypoint runs its own `ssh-add` for each mounted key, so
  the host-side fix alone would still hang the pane. The container gets its own copy and helper
  through a read-write mount and three `-e` variables. The entrypoint's `restore_askpass_finish`
  deletes both and unsets the variables before Claude starts. That is an image change, hence
  container 2.39.

Finding, measured with the real tools: OpenSSH 9.2's `ssh-add` asks a wrong askpass again
for ever ("Bad passphrase, try again for …", 24 times in 5 s). So the helper answers only
"Enter passphrase for", and a wrong passphrase fails at once. `run.bash`'s `hl_ssh_agent_start`
has the same latent loop: a wrong `RUN_BASH_GITHUB_SSH_PASSPHRASE` hangs instead of reaching
its `hl_abort`. It is not fixed here because that is a different file and a different plan. It
is reported to the owner.

## 14:38 · action · T6.2   — review fixes

The qa-reviewer pass on the T6.2 merge returned FIX-BEFORE-MERGE
([`subagent-reports/261002-qa-reviewer-t62-opus.md`](../subagent-reports/261002-qa-reviewer-t62-opus.md)).
All of it is fixed, tests first, as CCY 3.72.1 and container 2.40. Neither 3.72.0 nor 2.39
has reached a host.

- **The restore's environment reached every later pane.** `ccy_registry_restore` read
  `CCY_RESTORE_SSH_PASSPHRASE_FILE` but left it exported. At boot the restore starts ccy's tmux
  server, and tmux copies the server's starting environment into its global environment. A ccy
  started later in one of its panes was then refused by `ccy_restore_passphrase_take` and
  exited 1. The restore now unsets it before tmux runs. A server that was already running
  does not import a client's environment beyond `update-environment`, so the unset is the only
  place it needs to happen. The old test stubbed `ccy_tmux_start_detached` and recorded only
  argv. It now runs the real one, with shims for tmux, `systemd-run` and `systemd-escape` that
  record what tmux is started with.
- **A launcher killed mid-probe left its passphrase copy and its probe agent.** Measured:
  bash runs the EXIT trap when SIGTERM or SIGHUP kills it during a foreground child, so
  `trap _probe_agent_stop EXIT`, set just before the probe, is enough. INT gets no trap of its
  own: it reaches a foreground child first, and a signal trap would change how Ctrl+C behaves
  around `podman run`. `cleanup` keeps the same duty once it replaces the trap. The probe agent
  holds the unlocked key, which the review did not raise. The test kills the launcher from
  inside ssh-add, and an unguarded control run shows the copy and the agent left behind.
- **`podman exec` inherited `SSH_ASKPASS_REQUIRE=force`** pointing at a deleted helper. The
  three `-e` variables are gone. The mount alone signals a restore, and the entrypoint sets
  the variables only on its own `ssh-add` (`restore_askpass_ssh_add`). So the container's
  configuration, which every exec starts from, never holds them. That is an entrypoint change,
  hence container 2.40.
- `CCY_RESTORE_ASKPASS_DIR` is no longer exported. The export had silenced shellcheck's
  SC2034, and the lib now uses the variable itself instead.
- `play-claude-yolo.yml` writes the passphrase file before it deploys the drop-in, and removes
  the drop-in before the file. A run that fails part-way can no longer leave a drop-in that
  names a missing file.
