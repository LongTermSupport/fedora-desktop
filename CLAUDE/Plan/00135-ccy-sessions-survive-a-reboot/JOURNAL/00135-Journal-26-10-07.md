## 18:45 · decision · —   — Task 7.5: Quick Launch kept across ccy versions

Task 7.5 settled by the owner: option A, keep the saved Quick Launch settings across ccy
versions when their shape has not changed. Built in CCY 3.86.3.

The explicit format version the decision needs already existed: `CONFIG_VERSION=1`, written
into every `.last-launch.conf` as `SAVED_CONFIG_VERSION` since the file was introduced, and
the three choice keys (`LAST_TOKEN`, `LAST_SSH_KEYS`, `LAST_NETWORK`) have not changed since
(git log -S on each). So no second format line was added; `CONFIG_VERSION` is now documented
as the format and bumped only when keys or meaning change. `load_launch_config` keeps the
file whenever the format matches, whichever ccy version wrote it; it discards it (as before)
on another or missing format, and also when a choice key is missing. The keys are unset
before sourcing so the environment cannot fill a missing one. Same version with another hash
still prints the developer-error warning but no longer discards.

Existing files written by older ccy: all carry `SAVED_CONFIG_VERSION=1` and the same keys,
so they are kept as they are (no migration step needed; the next launch rewrites them with
3.86.3's version and hash). A file with no format line is not ccy's and is discarded (fail
closed). Values still pass the token lookup, SSH key checks and network existence check
downstream, unchanged.
