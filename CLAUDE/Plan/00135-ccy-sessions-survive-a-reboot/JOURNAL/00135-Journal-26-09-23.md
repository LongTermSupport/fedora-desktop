## 08:35 · decision · T3.6   — review fixes - the warning kind follows the restore opt-in

qa-reviewer on 4d808e9f returned FIX-BEFORE-MERGE. It found no BLOCKs. Resolved as Task 3.7:

- F1: the daemon's `shutdown-warning` text says "NO session restore will follow… leave a
  handoff", and `reboot-warning` says a restore will follow. Picking by the command name
  was wrong in two of the four cases. With restore on, a shutdown made the agents hand

  them a restore was coming that never came. The kind now follows the restore opt-in

  the warning (an EXIT trap). The N answer exits 1. `reboot-with-update` no longer
  `exec`s systemctl, so a failed reboot request withdraws too.
- F3: the `play-basic-configs.yml` comment is corrected.
- F4: `SUDO_USER=root` is refused before the updates. Intended consequence, recorded
  here: since 3.6, a live session that cannot be warned (its project has no daemon
  CLI) blocks a plain `shutdown-with-update`, not only the reboot. That is the
  warn-or-refuse rule, and it is deliberate.
- F5: `scripts/test-ccy-sessions-reboot.bash` now drives `going-down` in both opt-in
  states, an explicit `shutdown-warning`, and `shutdown-with-update` and

  no terminal, blocked with Y, reboot, and the root refusal. The new cases failed

- Nit, not done: skipping the countdown when no session is live. The countdown is also
  the operator's Ctrl-C window before an unrecoverable power-off, and the session count

## 16:45 · action · T3.8   — PR #47's review findings ported; the PR itself is superseded

PR #47 (the earlier registry design) is not merged; F44's design replaced it. Its review
still found gaps in F44, ported here with tests written first and seen failing:
- `ccy-sessions reboot` left a warned project uncancelled when a later project refused its
  warning. It now withdraws on every non-zero exit (EXIT trap armed before the first
  warning). INT/TERM are ignored while `systemctl reboot` runs: bash runs an EXIT trap
  when an untrapped TERM kills it, which would otherwise withdraw a reboot that is going ahead.
- Replay flags and restore prompts are now derived from the launcher's source and checked
  against the classification and `ccy_known_prompts`. The compose-stop and token-setup
  prompts were missing from `ccy_known_prompts`.
- A registry path that exists but is not a readable directory fails the restore.
Decision: the daemon's `signal --all-sessions` returning 1 for a project with no session
sidecar stays a failure. `discover_session_ids` counts any `<session>.json`, live or
stale, so an empty list means no daemon-tracked session ever ran in that project. The
refusal cannot tell that apart from a live agent the daemon is not tracking, and the
wrong guess reboots an agent unwarned. The cost is that such a project blocks
`ccy-sessions reboot` (and the Plan 00137 cycle, which then alerts) until the session is
ended or the daemon runs there. With this fix, the projects warned before it are
cancelled cleanly.
