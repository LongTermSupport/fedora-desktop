## 12:04 · action · #69   — Phase 7: fedora-desktop#69, three restore defects

Phase 7 opened for fedora-desktop#69, which reported three defects found by a planned restart.

- **Defect 1, `verify-restore` (`=name` pane target): blocked.** The brief requires a test
  against a real tmux server, and tmux is not installed in the CCY container. I stopped
  there rather than stub it. The fake tmux in the reboot suite strips the `=`, which is why
  the suite passed. A sweep found `capture-pane` in `restore_states` to be the only pane
  command with an `=name` target.
- **Defect 2, the SSH key menu on restore: fixed in CCY 3.82.0.** The container's
  `ccy-ssh-keys` label cannot carry the choice across a reboot: the container is started
  with `--rm`, and the label holds basenames, not paths. So the launcher now writes a key
  chosen at the menu into its own session record as `--ssh-key`. Only records that skip
  Quick Launch get it, because an `--ssh-key` would switch Quick Launch off and bring the
  token and network prompts back.
- **Still open:** `load_launch_config` deletes the saved Quick Launch config on any
  `CCY_VERSION` change. So the first restore after an upgrade of a session with no launch
  flags still goes through every prompt. This needs an owner decision.
- **Defect 3, `ccy-sessions reboot` from a headless login: fixed.** It now asks logind's
  `CanReboot` and checks every session before it warns anyone, and lists every problem
  together. A failed `systemctl reboot` is reported as a failure. The sessions are still
  sent `reboot-cancelled`, because that is the daemon's only withdrawal kind.

Details are in `subagent-reports/261006-issue69-fixes-opus.md`.
