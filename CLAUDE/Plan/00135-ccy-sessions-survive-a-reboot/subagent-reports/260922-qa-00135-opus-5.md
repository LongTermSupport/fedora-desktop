## Blocking

### 1. A reboot proceeds, unwarned, when the session list cannot be read

`<repo>/files<home>/bin/ccy-sessions:127`

`signal_projects` collects projects with `mapfile -t projects < <(live_projects)`.
`live_projects` propagates a listing failure correctly (`listing="$(ccy_tmux_list)" || return 1`),
but `mapfile` always exits 0, so the failure is converted into an empty array and takes
the "nothing to signal" branch.

Demonstrated against a `tmux` stub that fails `list-sessions` for a reason that is not
"no server running":

```
=== ccy-sessions reboot --in 1, with a tmux that cannot list sessions ===
ERROR: tmux list-sessions failed: lost server
No CCY or cc sessions are running; nothing to signal.
Rebooting in 1 minute(s); 0 project(s) warned.
SYSTEMCTL CALLED: reboot
EXIT: 0
```

The same failure on the restore path, in the same library, is refused correctly:

```
=== restore, same failing tmux, absolute state dir ===
ERROR: tmux list-sessions failed: lost server
ERROR: the live session list could not be read, so nothing is restored: starting
       sessions on top of an unknown live set could double every one of them.
EXIT: 1
```

This is the fail-fast HARD RULE, and it defeats the plan's own success criterion
("Each live session's project is signalled exactly once per warning"). It also
disarms `reboot-with-update`'s rehearsal: the `--dry-run` call at
`<repo>/files/usr/local/bin/shutdown-with-update:52` reports success having checked
nothing, then twenty minutes of dnf run and the machine reboots with agents mid-task.

`ccy_registry_restore` guards this exact case with an explicit check and a comment
explaining why. The lesson was applied on one path in the file and not the other —
the "Generalise a fix past the file you were reading" class in `CLAUDE/AgentNotes.md`.

**Fix:**

```bash
local listing
listing="$(live_projects)" || return 1
mapfile -t projects <<<"$listing"
```

**Why it shipped green:** `<repo>/scripts/test-ccy-sessions-reboot.bash` never makes
the fake `tmux` fail. The fake answers `list-sessions` from a file and errors only on an
*unexpected subcommand*. The suite does test the empty-list case (line 200,
"no sessions: nothing to warn, still reboots") — which produces output identical to the
failure case. That is the guard-the-empty-case / miss-the-failed-case shape from
AgentNotes. Add a case where `list-sessions` exits non-zero and assert nothing reboots
and nothing is signalled.

## Should fix

### 2. A `cc` record replays a stale opening instruction into a resumed session

`<repo>/files/var/local/claude-yolo/lib/session-registry.bash:109`

`ccy_registry_replay_args` returns early for any prefix that is not `ccy`, keeping every
argument verbatim. `cc` ends in `claude "$@"` (`<repo>/files/var/local/claude-code/cc:340`),
so `cc "refactor the parser"` records that text and restore starts
`cc "refactor the parser" --continue` at boot. Claude resumes the conversation and
receives the stale instruction, unattended.

This is exactly the hazard the filter's own header names for `--prompt` and a bare first
message — reasoned through for `ccy` and not carried across to `cc`. The journal's
reasoning for "cc replays verbatim" is about `--supervise` and ccy's flags, not about the
bare message, so the case was never weighed.

`<repo>/scripts/test-ccy-session-registry.bash:145` asserts the current behaviour
("cc: everything is kept"), so the test locks the defect in.

**Fix:** drop a bare word before `--` for `cc` as well. ccy's flag-specific rules still
do not apply there, but the stale-prompt rule does.

### 3. Phase 5 does not re-verify the guarantee this change restructured

`ccy_tmux_insulate` no longer `exec`s a single `systemd-run` that creates, hooks and
attaches in one round trip. It now calls `ccy_tmux_start_detached` (which returns,
leaving the scope abandoned with the tmux server inside it) and then `exec`s a separate
`tmux attach-session` in the terminal's own cgroup.

Reading it, the guarantee holds:

- the single-attach hook is still installed in the **same server command** as
  `new-session -d`, so no client can reach the session before the hook exists;
- the server is still the only long-lived process in the scope, and the attaching client
  is meant to die with the terminal;
- an abandoned-but-non-empty scope is the same state the old code reached the moment a
  user detached, so `--collect` behaves as before.

But that is reasoning, not evidence, and no test can run `systemd-run` in this container.
Plan 00111's terminal-death property is the thing this change is most likely to have
broken and the thing nothing now checks.

**Fix:** add a Phase 5 task — start a session interactively, kill the terminal, confirm
the session survives and `ccy` in that directory re-attaches it.

### 4. The record is written before the session exists, and survives a failed start

`<repo>/files/var/local/claude-yolo/lib/tmux-session.bash:521`

```
ccy_registry_write ... || return 1
ccy_tmux_start_detached "$name" "$PWD" "$launcher" "${launch[@]}" || return 1
```

On the second `return 1` the record survives with no session behind it. The launcher
exits (`claude-yolo:908` has `|| exit 1`), and the next boot starts a session that was
never running. Remove the record on that failure path.

### 5. `--no-restore` is absent from `ccy --help`

`<repo>/files/var/local/claude-yolo/claude-yolo:206-249`

The flag is parsed (line 600), changelogged, and documented in `docs/ccy.md`, but the
launcher's own option list does not mention it. It is also missing from the `ccy_flags`
did-you-mean array (~line 716), so a typo gets no suggestion. (`--ssh-agent` is already
missing from that array too — pre-existing.)

Not a functional break: the parser consumes `--no-restore` before `CLAUDE_ARGS`, so the
claude-flag validator never sees it. Confirmed.

### 6. Nothing ever sends `reboot-cancelled`

`<repo>/files/usr/local/bin/shutdown-with-update:10`

The signal kind exists, `ccy-sessions notify reboot-cancelled` implements it, and the two
places that warn about a reboot never use it:

- `shutdown-with-update` traps INT/TERM with `echo "Shutdown cancelled by user"` — wrong
  noun in reboot mode, and sent to the operator's terminal rather than to the sessions
  that were told a reboot was coming.
- `ccy-sessions reboot` has **no trap at all**, so Ctrl-C during the countdown leaves
  every project warned about a reboot that never happens.

Send `reboot-cancelled` from both traps.

### 7. `shutdown-with-update` has no strict mode

`<repo>/files/usr/local/bin/shutdown-with-update`

No `set -e`, no `set -u`, no `pipefail` anywhere in 199 lines. Pre-existing, but this diff
adds ~70 lines including all the new guard logic, and the file is in the diff. A failed
`getent` or a failed `sudo -u` in the new block continues to the next statement.

### 8. The playbook read-back fails with a message that misdescribes the cause

`<repo>/playbooks/imports/play-claude-yolo.yml:543`

The `when:` fires on `rc != 0` as well as on a graph mismatch, but the message offers only
two graph-mismatch sentences. A host where `systemctl --user list-dependencies` cannot run
at all (no user manager, missing `/run/user/UID`) now fails the **core** play with a claim
about the opt-in that is not true.

The precedent this follows, `play-host-health-login-report.yml:243`, gates its assert on
`rc == 0`. Failing on a failed probe is the stricter and better choice here — the
precedent's version is itself the discarded-failure-signal shape — so keep the strictness
and add a third message branch that says the probe did not run.

Note also that `play-claude-yolo.yml` is in `playbook-main.yml`'s core path, whereas the
precedent play is under `optional/common/`, so the unconditional `daemon_reload` and
read-back now run on every desktop deploy.

## Nits

- **The filter keeps a bare word after any unknown flag.** `ccy --verbose "do the thing"`
  replays the instruction, because `-*` sets `value_slot=true`. Documented as a trade-off
  in the journal, and the right call for `--model opus`, but it means the stale-message
  guarantee is partial for `ccy` too.
- **`notify shutdown-warning` is accepted and not in the help text.**
  `<repo>/files<home>/bin/ccy-sessions:169` supports it; the usage block at
  lines 26-34 does not list it. The help is the header comment printed back, so it is one
  line.
- **`shutdown-with-update --help` exits 64.** The new argument parser rejects every
  unrecognised option including `--help`. (The file is under `files/usr/local/bin/`, so it
  is outside `CLAUDE/InteractiveScripts.md`'s declared scope — hence a nit.)
- **`systemd-escape` is used but not in the tool-presence check.**
  `<repo>/files/var/local/claude-yolo/lib/tmux-session.bash:545` checks only `tmux` and
  `systemd-run`, then line 556 shells out to `systemd-escape`.
- **A manual `tmux kill-session` leaves a record restore will act on.** Related:
  `docs/ccy.md` says that on a machine that has not opted in "the records still accumulate
  and are removed as sessions end", which is untrue for precisely the killed sessions that
  leave records. Nothing prunes them. Growth is bounded by the set of distinct session
  names ever used, so this is small — but the doc sentence is wrong.
- **A restored `ccy` session gets an armed supervisor the original did not have.**
  `--supervise` forces the PTY supervisor ARMED and injects `/compact`; the default is
  UNARMED. Documented in `docs/ccy.md` and deliberate, but it means the restore is not a
  faithful reproduction of the session. Worth an explicit Phase 5 observation.

## Credit where it is due: the deferred-trap bug

Item 6 was written as "send `reboot-cancelled` on Ctrl-C". Implementing it surfaced a
defect no reading of mine had found and that the original code would have shipped with:
**bash runs a trap handler only after the foreground command finishes**, so a trap around
`sleep 120` honours Ctrl-C two minutes late, after the reboot. Both countdowns now
background the sleep and `wait`, which returns at once. This is the shape AgentNotes
describes as "a test of the happy path cannot test a failure-path guarantee" — the naive
implementation looks identical until the failure path is actually exercised.

The test for it is properly constructed: it starts the real tool, polls until the warning
has demonstrably landed, sends TERM, and asserts exit 130 plus two `reboot-cancelled`
signals plus no `systemctl`. The comment correctly explains why TERM and not INT (a job
started with `&` from a non-interactive shell has SIGINT ignored at entry, and an
ignored-at-entry signal cannot be trapped).

## Nits

- **The bare word after an unknown `ccy` flag** stays a documented trade-off. Accepted by
  the team lead; recorded here so it is a decision and not an oversight.
- **A trap-arming window before the first warning.** `trap cancel_reboot INT TERM` is set
  *after* `signal_projects reboot-warning` returns. Ctrl-C landing mid-loop (project 1
  warned, project 2 not yet) leaves warned projects with no cancellation. The loop is fast,
  so the window is small.
- **The post-warning refusal paths do not cancel.** If the one-minute
  `signal_projects reboot-warning 1 false` fails, `cmd_reboot` returns 1 with every project
  already warned and no `reboot-cancelled` sent.
- **Strict mode changes three pre-existing paths in `shutdown-with-update`.**
  `CCY_SESSIONS="$(getent passwd ... | cut ...)"` (line 93) now aborts silently under
  `set -e` + `pipefail` if `getent` fails, instead of reaching the clear
  "`$CCY_SESSIONS` is missing" error two lines later. `systemd-inhibit --list | awk` (line
  239) now aborts before the "Force shutdown anyway?" prompt if it fails. `read -p` on EOF
  now aborts. All three are more fail-fast and less diagnosable; capturing the status
  explicitly at line 93 would give the best of both.
- **`systemd-escape`'s missing-tool message misdirects.**
  `tmux-session.bash:552` now checks three tools and tells the operator to run
  `play-tmux-sessions.yml` for whichever is missing. That play installs tmux; it does not
  mention systemd at all, and `systemd-escape` and `systemd-run` ship with systemd. The
  message was already inaccurate for `systemd-run`; the fix extended it to a third tool.
- **Two cancel paths, two exit codes.** `ccy-sessions` exits 130 on cancellation,
  `shutdown-with-update` exits 1. Trivial, but they are the same event.
