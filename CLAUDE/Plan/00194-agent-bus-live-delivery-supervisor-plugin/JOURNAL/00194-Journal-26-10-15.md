> **Append-only activity log** for plan 00194. One file per day
> (`00194-Journal-YY-MM-DD.md`). `PLAN.md` tracks the plan (what/why,
> current state, tasks); this journal tracks what actually *happened* —
> findings, decisions, dead-ends, hand-off state — the linear lifecycle a plan
> document structurally cannot carry.
>
> **Entry grammar** — append new entries at the BOTTOM; NEVER edit earlier
> entries (corrections are new entries):
>
> ```
> ## HH:MM · category · REF   — optional short title
> ```
>
> - `HH:MM` UTC 24h (the date is in the filename, also UTC); times increase
>   down the file. A file with no sentinel line above predates this system —
>   its times are local, zone unrecorded (legacy; never rewritten).
> - `category` ∈ `action` | `finding` | `decision` | `thought` | `blocker` | `handoff`
> - `REF` = optional task/phase ref (`T1.2`, `P1`) or `—`.
> - Bodies may embed fenced logs/diffs/snippets — no size limit — with a
>   one-line takeaway above the fence.
> - End a working session with a `handoff` entry so the next agent's entry
>   point is the last entry of the newest day-file.

## 17:10 · decision · —   — Owner: inject the structured message itself, now

The owner, in the session on 2026-10-15 (spoken, relayed by the coordinator): the bus began as pings telling an agent to fetch content elsewhere and has become a message board, which is why a count-only notice fits badly. Inject the message itself as a structured message that shows plainly where it came from: who sent it, whether a human or an agent, by what route, and on which team. The agent and the watching human both read it in the turn. The agent keeps the ability to read the board's full history and to send. It must stay locked down: no injection route, the sender and kind set by pingbus and never by the message text.

This lifts the hold in decision B on delivering through the existing socket while hooks-daemon issue #119 waits for a release: the owner wants teams usable with a human in the loop by the morning of 2026-10-16, so delivery is built now through what ships today, keeping B's envelope (kind and sender from pingbus, the body as escaped data, a size cap with a pointer to `recv`, delivered once). The plugin route of Task 2.1 stays the target once the daemon release carries #119.
