## 09:16 · finding · 2.0b   — No goodbye was ever sent: the 1.5 s SessionEnd bound; disconnect notice from the launcher

The owner asked whether mashing Ctrl-C in a ccy session sends the goodbye. It did not, and nothing else said the session had gone. Facts, read from the code and Claude Code 2.1.303's binary, and measured in this container:

- `pingbus history` does show a goodbye: it is an agent `text` addressed to the coordinator, so the coordinator's history lists it as a `PEER` line with the text (`syncer.py` `_history_item`, `protocol.py` `_agent_text_outcome`). Zero "left the team" lines means none was posted.
- Claude Code bounds all SessionEnd hooks together by `getSessionEndHookTimeoutMs`: `CLAUDE_CODE_SESSIONEND_HOOKS_TIMEOUT_MS` if set, else max(1500 ms, the largest `timeout` of a settings-file SessionEnd hook). Plugin hooks are not in that snapshot, so the kit's `"timeout": 6` never counted. Probe (a plugin SessionEnd hook sleeping 4 s, `claude -p`): cancelled ("Hook cancelled") with the default; finished with the variable at 8000, set in the environment or in a `--settings` file's `env`. `pingbus --help` alone takes about 1 s here, and the goodbye needs a sync and a send on top: it was always cut off.
- Ctrl-C: the supervisor's gate swallows every other press; Claude Code's double press exits through `shutdown`, which restores the terminal before it runs SessionEnd; later presses become SIGINTs to Claude Code, whose handler returns while a shutdown is under way. Hooks are spawned `detached` (their own session), so no terminal signal reaches them.
- `podman stop` and a closed terminal or tmux window: tini forwards the signal to the supervisor, which has no SIGTERM or SIGHUP handler and dies; tini exits and the kernel kills the container. Claude Code never reaches SessionEnd. A crash or SIGKILL likewise. The plan's acceptance line expected SIGTERM to reach the hook; it cannot.
- A keeper's explicit release empties `seat.lock`; a keeper killed with its container leaves `seat <claim ms>` in it.

Fix, test first (red then green): the session's settings (and the member kit's) set `CLAUDE_CODE_SESSIONEND_HOOKS_TIMEOUT_MS=8000`; the hook ignores SIGINT and SIGHUP while posting and records each posted goodbye in its seat (`said-goodbye.json`, the claim it ends); a new host command `pingbus seat disconnected --root --session --since`, run last in the launcher's cleanup, posts `<handle> disconnected: session ended without a goodbye` for each seat of the session's report whose lock still names a claim of this launch with no goodbye for it, and empties the claim, so each claim is told once.

Why the launcher: it is the one thing that outlives the container on every path it survives (exit, `podman stop`, a crash, a closed terminal: bash runs its EXIT trap on SIGHUP), it runs in the checkout, where the seats and their bundles are, and it knows its session's name and start. The watcher and the keeper die with the container; there is no host-side release to hook. The launcher cannot grow (bash ratchet), so the call is one line in `cleanup`, offset by folding three `echo` lines of the compose notice into one `printf`; the logic is pingbus's.

Not covered: a host reboot or a launcher killed with SIGKILL (no notice; the seat shows free); a hook killed between its post and its record (both messages). Follow-ups: a lifecycle restart now really says goodbye, then comes back; `cc`/LXC members have no launcher fallback.
