## 09:29 · decision · —   — Compact before a cold wake: pingbus cannot compact; stage 1 measures

The owner asked for a pingbus-level defence against waking a large, cache-cold context:
compact first, then the message, as one turn, and make sure the work continues.

The facts (SPEC-compact-wake.md section 1) say pingbus cannot do it alone:

- a socket message is framed by Claude Code 2.1.303 as "Another Claude session sent a
  message:", so a `/compact` in it is text, never a command (F2);
- the supervisor's plugin API is still 1.0 and cannot type for pingbus (F3);
- `/compact <message>` would make the sender's text the summary's instructions, which the
  owner ruled out (F5);
- the supervisor types `continue` after every compaction of its session, whoever started it,
  so a bus compaction would get a stray turn before the message (F4).

The honest cost (section 2): the compaction call is itself a cold read of the whole context,
so the wake is never cheap. The saving is in the turns after it, and in avoiding a cold
full-context turn plus a later compaction. At 60k tokens, a one-turn wake costs more if the
compaction call writes the cache (not measured; host check HC3).

So stage 1 is built, observe only: `helpers/pingbus/coldwake.py` reads the size, the last call
and the cache TTL from the transcript, and the watcher logs one `cold wake:` line of numbers per
delivery that meets the trigger. Stage 2 (the supervisor compacts with a fixed body, pingbus
holds the batch and delivers after the `compact_boundary`, bounded at 60 s and 600 s, no
`continue`) is specified as C7-C18 and needs upstream U1-U3 and the owner's D1-D7.
