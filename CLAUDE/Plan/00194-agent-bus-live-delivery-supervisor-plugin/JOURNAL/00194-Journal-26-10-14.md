## 16:40 · decision · 2.0b   — Goodbye trigger path: the SessionEnd hook

Trigger path for the goodbye: the `SessionEnd` hook (`pingbus hook session-end`), one path.

Why not the seat release: there is no code at the release. `seat exec` hands the locks to
the process that replaces it, so the kernel frees them when the last process of the session
exits (protocol section 12). Nothing of ours runs then, and a hook in that place would have
no `reason` and could not tell `/clear` from the end.

Why not the ccy launcher's teardown: it runs on the host after the container exits, covers
ccy only (not `agent-bus-claude` in an LXC member or a future harness), has no `reason`,
and would need the member's token outside the container.

Why the hook: it is the one place that carries the hook payload's `reason` (so `clear` and
`resume`, where the session goes on, send nothing), it runs inside the session that holds
the seat's bundle, and every harness that loads the pingbus plugin (the ccy image and the
member kit alike) gets it from the same `hooks.json`. A harness with no SessionEnd, a hard
kill or a lost container sends nothing: teammates see the seat free, documented.

Details. Once per session: the attempt is recorded in `goodbye.json` in the session home
keyed by `session_id` before the post, so a double firing or a retry after a failure sends
nothing more (an end straight after the start sends at most one). The text is
`<handle> left the team: session ended (<reason>)`, `reason` mapped from the payload to
`exit`, `logout` or `other`; no free text. It goes to every listed human and every other
agent holding a role, at most 16. Cap: 4 s for all seats; the posts run in daemon threads
that are joined against one deadline, and the hook answers `{}` either way; a failure is
`pingbus: hook session-end: goodbye to team <team> not sent: <reason>` on stderr, a
homeserver failure's own one-line message or the exception class name only.
