## 10:03 · finding · P1   — upstream facts behind the play and the design

Upstream findings that shaped Phase 1 and Phase 2.

- `sst/opencode` redirects to `anomalyco/opencode`; the pin tracks the new name.
- No checksum file is published; the sha256 is the release API digest, and the release is
  immutable with a release attestation (`gh release verify-asset` passes), but there is no
  SLSA build provenance.
- In 1.19.3 the update-notice check reads only the user's global config, so the managed
  `autoupdate: false` in /etc/opencode does not silence the notice; the check never installs.
- `opencode serve` listens on loopback TCP only (no Unix socket) and is unauthenticated
  unless `OPENCODE_SERVER_PASSWORD` is set; the design makes the keeper set a per-run one.
- `prompt_async` stores the user message first and joins a running loop, so a busy session
  keeps a delivery (host check H-OC2 confirms); proof can read the message list, a documented
  API, instead of scanning a transcript.
