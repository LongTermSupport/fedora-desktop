# Plan 00137 Task 4.3: the cycle's result in the host-health report

**Task:** make a failed, stopped or unverified self-update cycle show up in the
host-health report (the login snippet, `fedora-desktop-health` and the panel).

## Decisions

1. **A published copy, not a looser state directory.** `state/` stays root:root 0700.
   Its files (`deployed`, `owed-verify`) decide what the next root run does. The cycle
   now also writes `/var/lib/fedora-desktop/self-update-status/result` on every
   `write_result`. The directory is `root:<user's primary group>` 2750, so setgid gives
   each file the user's group with no chown. The file is 0640 and written atomically:
   the user can read it, and only root can write it. The cycle never reads it back.
2. **Enabled means the directory exists.** `play-self-update.yml` creates it when
   enabled and removes it when disabled. The report says nothing when the directory is
   absent. The entry point refuses with exit 70 when it is missing, as it does for
   `state/`.
3. **Findings** (`helpers/host_health/self_update_check.py`, section `self-update`):
   - a failed outcome is a fault, naming when, the phase and the detail;
   - an unknown outcome, an unreadable record or stamp, or a stamp in the future is
     "not checked".
   - A newest result older than 3 days is a fault. The timer is nightly and every run
     that reaches the update records a result, including "nothing", so 3 days is two
     whole missed nights of margin. With no result at all, the age is taken from when
     the directory was created.
   - `owed_boot` from an earlier boot is a fault once this boot is 35 minutes old. That
     is the verify unit's `TimeoutStartSec=30min` plus a margin. An unknown uptime does
     not buy the grace, and an unknown boot id is "not checked".
4. **The section is always present** in the document, so the section set does not
   depend on the host. The panel hides it while it is clean (`quietWhenOk`), since
   desktops never self-update. A missing section still renders as unavailable. Both
   `check_panel_contract` and the panel section tests cover it.
5. **Drift guard.** A test reads `cycle.py`'s source and fails if it writes an outcome
   that `published.py` has not classified as ok, in progress or failed.

The contract is recorded in DESIGN-cycle.md, under "The published copy".
