Built as `helpers/self_update/` (stdlib only, test-first):

- `gate.py` holds the pure decisions: signature kind, per-commit verdict, target choice,
  and the Fedora pin.
- `update.py` is the git executor and the CLI.
- Tests: `tests/helpers/self_update/test_gate.py` (27, pure) and `test_update.py` (28).
  The second file runs real git against real bare remotes, with throwaway ed25519 keys

  (`GIT_CONFIG_GLOBAL`/`GIT_CONFIG_SYSTEM`=/dev/null).

CLI: `python3 -m helpers.self_update.update --checkout PATH --remote origin --branch F44 --allowed-signers FILE --principal NAME [--os-release /etc/os-release]`

## Exit codes

| Code | Name                   | Meaning                                                                                                                        |
| ---- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 0    | `EXIT_OK`              | Fast-forwarded (`SELF-UPDATE-OLD`/`-NEW`), or nothing trusted to deploy (`SELF-UPDATE-NOTHING`)                                |
| 2    | `EXIT_USAGE`           | argparse error, or an empty `--principal`                                                                                      |
| 10   | `EXIT_FETCH_FAILED`    | `git fetch <remote> <branch>` failed                                                                                           |
| 11   | `EXIT_DIRTY`           | Modified tracked files or untracked files (ignored files are fine)                                                             |
| 12   | `EXIT_DETACHED`        | Detached HEAD                                                                                                                  |
| 13   | `EXIT_WRONG_BRANCH`    | On a branch other than `--branch`                                                                                              |
| 14   | `EXIT_AHEAD`           | Deployed commit is ahead of the remote: local commits, or the remote was rewound                                               |
| 15   | `EXIT_DIVERGED`        | The remote no longer contains the deployed commit (history rewritten)                                                          |
| 16   | `EXIT_SIGNERS_FILE`    | Allowed-signers file: missing, not a regular file, symlink, wrong owner, group/world-writable file or directory, or no entries |
| 17   | `EXIT_BAD_SIGNATURE`   | A commit above the newest trusted one has a `B`/`R`/`E`/unknown status                                                         |
| 18   | `EXIT_FEDORA_MISMATCH` | The target commit pins a different Fedora, or the pin cannot be confirmed; nothing moved                                       |
| 19   | `EXIT_GIT_FAILED`      | An unexpected git failure or timeout, `ssh-keygen` missing, or HEAD not at target after the ff                                 |

stdout carries only the marker lines, and every refusal leaves stdout empty. Diagnostics
go to stderr (CLAUDE/StderrHygiene.md).

## Signature states, measured on git 2.39

Measured with a throwaway probe, not assumed:

| Commit                                   | `%G?` | `%GS`                          |
| ---------------------------------------- | ----- | ------------------------------ |
| unsigned                                 | `N`   | empty                          |
| signed by the pinned key                 | `G`   | the principal                  |
| signed by another key                    | `U`   | empty ("No principal matched") |
| a signed commit with its message altered | `B`   | empty                          |
| no allowed-signers file                  | `U`   | empty                          |

Policy (`gate.judge`):

- **Trusted:** only `G` with the pinned principal.
- **Untrusted, walk on:** `N`, `U`, `X`, `Y`, and `G` with another principal. An agent
  signing with its own key is not an attack, and refusing on it would block every cycle.
- **Refuse:** `B`, `R`, `E` and any unknown letter.

A refusal ABOVE the newest trusted commit refuses the cycle. One below it is vouched for
by the owner's signature on the descendant.

## Decisions made inside the task

- **Untracked files count as dirt.** An untracked file can shadow one the incoming commit
  adds, making the ff fail half-way, or be read by a play's `with_fileglob`. The deploy
  clone should never hold one. Ignored files are exempt, because the vault password file
  and run logs live there.
- **The Fedora pin is checked BEFORE the fast-forward**, on the target commit's own
  `vars/fedora-version.yml` (`git show <sha>:…`). The directive said "after the ff".
  Checking the same bytes before moving means a refusal never leaves the clone on a
  commit the host cannot run. The comparison mirrors the preflight play
  (`distribution_major_version | int == fedora_version | int`): `fedora_version` from
  the vars file against `VERSION_ID` from os-release.
- **The first-parent walk stops at the first commit that does not descend from the
  deployed one.** Below a merge that brought the deployed commit in through a second
  parent, the first-parent line predates it, and a fast-forward there is impossible.
- **A remote rewound behind the deployed commit reads as `EXIT_AHEAD`** (the message says
  "local commits, or the remote was rewound"). Any other non-ancestor relationship is
  `EXIT_DIVERGED`.

## Security: nothing from the checkout judges the checkout

- **The allowed-signers path comes only from `--allowed-signers`.** It is passed on every
  git call as `-c gpg.ssh.allowedSignersFile=<abspath>`, which overrides any repo-local
  value. The test sets the clone's own `gpg.ssh.allowedSignersFile=/dev/null` and
  verification still uses the argument.

- **`gpg.ssh.program` is pinned** to the `ssh-keygen` resolved on PATH. The test
  configures a repo-local program that touches a marker; it never runs. Mutation:
  removing the pin makes that test fail (the evil program ran, `E`, exit 17).

- **Non-SSH signatures are never verified, in two layers.**

  1. `gate.signature_kind` reads the raw `gpgsig` header and routes PGP/X.509 to
     UNTRUSTED without calling git's verifier.
  2. `gpg.program`, `gpg.openpgp.program` and `gpg.x509.program` are pinned to `false`.

  Mutations: removing layer 1 alone still passes, because layer 2 runs `false`. Removing
  both makes the test fail, because the repo's program executed. A second test asserts
  the pins directly, so layer 2 cannot be dropped silently.

- **Hooks are disabled** with `core.hooksPath=/dev/null` on every call. `post-merge`,
  `post-checkout` and `reference-transaction` hooks in the clone do not run. Mutation:
  removing it makes the hook test fail.

- **`core.fsmonitor=false`**, because a configured fsmonitor runs a program on
  `git status`. **`protocol.ext.allow=never`** closes the `ext::` transport.

- **The allowed-signers file must be a regular file**, not a symlink, owned by root or
  the caller, with no group or other write bit on it or on its directory, and at least
  one non-comment entry.

- **Environment:** `GIT_TERMINAL_PROMPT=0`, with an empty `GIT_ASKPASS` and
  `SSH_ASKPASS`. Timeouts are 120s for the fetch and 60s for every other call.

Not covered here: the remote URL and `core.sshCommand` still come from the clone's
`.git/config`. That is acceptable only because D4/D5 make the deploy clone root-owned
and never container-mounted. Task 4.6 has to make that ownership true.
