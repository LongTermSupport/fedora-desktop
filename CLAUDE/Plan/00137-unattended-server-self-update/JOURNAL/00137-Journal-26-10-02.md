# Plan 00137 — Journal 26-10-02

_Scaffolded by `mkplan.bash`; timestamps in this file are UTC._

> **Append-only activity log** for plan 00137. One file per day
> (`00137-Journal-YY-MM-DD.md`). `PLAN.md` tracks the plan (what/why,
> current state, tasks); this journal tracks what actually *happened* —
> findings, decisions, dead-ends, hand-off state — the linear lifecycle a plan
> document structurally cannot carry.
>
> **Entry grammar** — append new entries at the BOTTOM; NEVER edit earlier
> entries (corrections are new entries):
>
> ```
> ## HH:MM · category · REF   — optional short title
> ```
>
> - `HH:MM` UTC 24h (the date is in the filename, also UTC); times increase
>   down the file. A file with no sentinel line above predates this system —
>   its times are local, zone unrecorded (legacy; never rewritten).
> - `category` ∈ `action` | `finding` | `decision` | `thought` | `blocker` | `handoff`
> - `REF` = optional task/phase ref (`T1.2`, `P1`) or `—`.
> - Bodies may embed fenced logs/diffs/snippets — no size limit — with a
>   one-line takeaway above the fence.
> - End a working session with a `handoff` entry so the next agent's entry
>   point is the last entry of the newest day-file.

## 10:28 · action · T4.8   — the server trusts a list of the owner's keys

The self-update server trusted exactly one key: the play wrote one `<principal> <key>` line from
`self_update_signing_public_key`, and the docs said to give it the desktop's `~/.ssh/id.pub`. Since
Plan 00139 D5 a commit made in a ccy session is signed by the session's GitHub account key
(`~/.ssh/github_<alias>`), and nearly every commit on the branch is made in ccy, so a server pinned
to `~/.ssh/id` would wait on those for ever, and one pinned to an account key would wait on host
commits.

Fixed as Task 4.8. `self_update_signing_public_keys` is a list; the older single key is still read
and added, de-duplicated by key type and blob. `helpers/self_update/signers.py` validates each
line, refuses an empty list, and prints one allowed-signers line per key; the play runs it in the
input checks and writes its output. The consumers were read for a single-key assumption:
`update.py`, `gate.py`, `cycle.py` and the sbin wrapper all hand the file to git and compare the
principal, so a file of several lines with one principal already worked there; only their wording
("the pinned key") changed. Plan 00139's `deploy.bash` now prints `~/.ssh/id.pub` and the key named
in each `~/.config/git/github-signing-<alias>.gitconfig`.

Tests first: `test_update.py` and `test-self-update-cycle.bash` import or run the new helper and
deploy a commit the second listed key signed; both failed before the helper existed and pass now.
