## 16:15 · decision · D5   — IaC merged; D5 hardened: system ansible + ptrace_scope=1

IaC (27f2cff8) merged: T0.3, T2.2, T4.2, T4.6. Opt-in play-self-update.yml (server scope, self_update_enabled). Commit signing lives in play-git-configure-and-tools.yml, written to the XDG git config ccy does not copy, with no commit.gpgsign default and a passphrase required, so agents can never sign.
The IaC review found that D5 does not hold against a same-uid process: the plays run as the user through the user's own Ansible, and the controller holds the password in memory (ptrace_scope is 0). The owner chose to trust the user account and add cheap hardening: a root-owned system ansible-core and collections path for the cycle, plus kernel.yama.ptrace_scope=1 on the server (new Task 4.7). Controller-as-root was rejected, because every play assumes it starts as the user.
The orchestrator fork was sent three contract additions from the IaC: the vault password on /dev/fd/N, the fact-cache override, and the system ansible and ANSIBLE_COLLECTIONS_DIR requirement.

## 16:55 · action · rollout — RUN_BASH_CCY_RESTORE_SESSIONS (run.bash 1.24.0)

The self-update cycle needs `ccy_restore_sessions: true`, and a guest provisioned only through `RUN_BASH_*` had no way to declare it. `RUN_BASH_CCY_RESTORE_SESSIONS=0|1` now reconciles exactly one `ccy_restore_sessions:` line into `localhost.yml` on every headless run. Unset leaves the file alone. Ten new cases in `test-run-bash-headless-localhost-yml.bash`. The `self_update_*` inputs have the same gap; they wait on the Task 0.4 sink decision and the pin-vs-update decision downstream.
