## 10:10 · action · T0.4 T4.5   — the optional Slack webhook sink, built and reviewed


The owner chose the alert sink for D8: a Slack webhook, optional and per install. They said
it lives in the install's own config (host_vars, which the install's config repo supplies),
and that `run.bash` can ask for it or it can be provided as IaC. There is no GitHub-issue sink.

Built on branch `agent-ae517b7f65bc17b55-d944a94e`, commit `01ff3387`:

- **Supplying it.** `self_update_slack_webhook_url`, vault-encrypted, in host_vars. When it
  is undeclared, `play-self-update.yml` asks for it with `pause` (no echo) on an interactive
  run, then `ansible-vault encrypt_string` (on stdin) and `blockinfile` save it to
  `localhost.yml`, following the pattern `play-qobuz.yml` set. A blank answer, or a run
  with no tty, means no Slack alerts and saves nothing, so the next interactive run asks
  again. Declaring it as `""` declines for good.
- **On the server.** The play writes `/etc/fedora-desktop/self-update.slack-webhook`
  (root 0600) and `ALERT_SINKS=slack` only when a webhook is declared. Otherwise it removes
  the file and leaves `ALERT_SINKS` empty. The file also goes when self-update is turned off.
- **In the cycle.** `alerts.py` validates the URL shape, builds the message from the result
  record only, and posts with a 10 s timeout through an injected opener, so no test touches
  the network. `load_sinks` reads the webhook only when `slack` is configured, and only for
  `run` (not `--dry-run`) and `verify`. A missing, open or malformed file exits 70.
- **A lost alert is loud.** The result is recorded first. When a sink does not accept, the
  journal says so, and the result is recorded again with a new `alert` key (for example
  `slack: HTTP 500`). The host-health report makes a non-empty `alert` a fault whatever the
  outcome. A record written before the key existed reads as `alert` empty. The exit code is
  unchanged.
- **What the message carries.** Outcome, phase, time, detail, plays and a short commit;
  never a hostname or username. So an owner with several servers tells them apart by giving
  each its own webhook or channel.

Tests: `test_alerts` is new, and `test_cycle`, `test_published` and `test_self_update_check`
are extended, all RED then GREEN. The helper suite passes, and so do
`test-self-update-cycle.bash`, the health, snippet and panel suites, the secret scan and

The qa-reviewer returned BLOCK on `01ff3387`. Every finding is fixed in `e7d6b98f`:

1. **(BLOCK) The saved webhook had a trailing newline.** The play's `encrypt_string` task
   read the URL from `stdin:` without `stdin_add_newline: false`. Ansible added a
   newline, and it was vaulted with the secret. The next run then failed its own assert,
   or the webhook file ended in `url\n\n` and the cycle refused with exit 70. The two
   Last.fm tasks in `play-qobuz.yml` had the same fault, which `run.bash` already warned
   about, and both are fixed. They were the only such tasks. A new test,
   `test_vaulting_plays`, reads every tracked play and flags both plays at the previous
   commit.
2. **The default opener followed redirects.** A 302 turned the POST into a GET with no
   body, and the 200 at the end read as delivered. Now any 3xx is a failed delivery.
   That is tested with the real opener against a stub server on 127.0.0.1, in place of
   a fake 302 the real opener could never return.
3. **Some HTTP errors escaped.** `http.client.HTTPException` is not an `OSError`. It got
   past the first record, which left `alert` empty (read as delivered) and exit 1. It is
   now a failed delivery.
4. **The entry point is now tested with Slack configured.**
   - A missing, other-readable or malformed webhook file stops `run` and `verify` with
     exit 70, before anything runs and without echoing the file.
   - `--dry-run` and `status` never read the file.
   - An announced result goes out from the root process to a stub HTTPS proxy on
     127.0.0.1, which refuses the CONNECT. The refusal is journalled, recorded and
     published, and the secret path appears in no output.
5. **A run that sets no webhook now says so in one line.** That covers a blank answer and
   a headless `run.bash`, and the line names `self_update_slack_webhook_url` in host_vars.
   The docs say `run.bash` reaches the prompt through its optional-playbook menu.
