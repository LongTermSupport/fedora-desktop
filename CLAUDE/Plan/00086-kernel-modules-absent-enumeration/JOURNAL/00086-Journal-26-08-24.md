## 16:04 · finding · T1.1 — confirmed via triage: kernel-modules is genuinely absent, not a half-install

Ran a read-only diagnostic play against dc-lts-dev-vm (lts-infra Plan 00045's
guest): `rpm -qa` for the full kernel-family package set returned only
`kernel-core` and `kernel-modules-core` (3 versions each, matched). No
`kernel-modules`, `kernel-modules-extra`, `kernel-devel`, `kernel-tools`, or
`python3-perf` present at all — confirmed with both a targeted list and a
`kernel*` wildcard. This is a minimal/cloud-style image, not a half-installed
kernel in the sense `play-AB-dnf-upgrade.yml`'s comment describes.

Then probed `rpm -q kernel-modules --queryformat '%{VERSION}-%{RELEASE} '`
directly (the exact invocation used by the play) against the same guest:
rc=1, stdout=`package kernel-modules is not installed`, stderr=empty. Cross-
checked against a package name that cannot exist by any definition
(`this-package-name-does-not-exist-anywhere`) — identical shape. This
confirms rc=1 + that exact stdout substring is rpm's stable "not installed"
signal, safe to key a `failed_when` exemption on.

## 16:10 · decision · T1.1/T1.2 — probe-then-fail, not a blanket failed_when: false

Per this repo's fail-fast doctrine (`failed_when: false` prohibited without a
same-line `# FAIL-FAST-OK:` annotation, and the "probe-then-fail" pattern —
register + explicit check): added `failed_when: false` with an inline
FAIL-FAST-OK annotation to the kernel-modules enumeration task, followed by a
new `ansible.builtin.assert` task that only tolerates rc=0 or
(rc=1 AND stdout contains "is not installed") — any other failure shape
(permissions, rpm db corruption, etc.) still hard-fails the play.

Also fixed the difference computation two tasks later: it was doing
`kc_versions.stdout.split() | difference(km_versions.stdout.split())`, which
on the not-installed path would have split the literal string
"package kernel-modules is not installed" into words and fed them into the
difference as if they were installed versions — silently corrupting the
half-installed-kernel list rather than just leaving it empty. Fixed to
substitute an empty string for `km_versions.stdout` whenever
`km_versions.rc != 0`.
