## QA Review: commit 395457460 (Plan 00237, QA lock and low priority)

**Verdict: FIX-BEFORE-MERGE.** Nothing blocks the merge. The code does what the owner asked, but three claims in the plan and docs are not demonstrated by any test, and there are two latent hazards. I did not write a report file, as your correction asked, so the full findings are here.

### Should fix
1. **The nesting path that matters is never exercised for real.** The real chain is qa-all (Go) → bash `qa-go-qa.bash` → `go-tool.bash` → built `qa-lock`. Only fakes cover it (`qalock_test.go:300`, fake parents). `TestTheRealLockIsExportedToTheCommand` (`cmd/qa-lock/main_test.go:143`) checks that the variable is exported, not that a nested take is inherited. Even so, `PLAN.md:72` ticks "does not wait for itself", while Task 2.2, the only real run, is still open. Fix: have that test's command run a nested `qa-lock --no-wait` and assert exit 0.
2. **Child I/O class is claimed but never asserted.** `priority_test.go:213` says "ionice reads its class", but line 218 checks only the child's nice value. `PLAN.md:74` and the journal (`091434Z…md:19`, "a started child are nice 19 / class 3") both claim class 3. Fix: read the child's class with `ioprio_get` and assert 3.
3. **The cross-container claim is unproven.** `QA.md:1999` says `TestTwoProcessesShareTheLock` proves the lock is shared through a bind mount. That test uses one path in one mount namespace, so it proves nothing about a bind mount. Container and host sharing is the core of the owner's rule and no task verifies it. Fix: add an `unshare -rm` plus bind-mount test, or a host verification queued in `meta-deploy.list`, and correct the sentence.
4. **A run with a scrubbed environment hangs silently on its own parent.** The ancestor check only runs when `QA_LOCK_HELD` matches (`qalock.go:232`). A nested run whose environment was cleared (`env -i`) or set differently waits on its own ancestor, and with no default timeout that wait never ends. No current gate does this (I grepped `qa-gates.tsv` and the `env -i` users), so it is latent. Fix: always walk the ancestry. If the record's pid is an ancestor but the variable does not match, fail fast with a "would deadlock" error rather than wait. Record the pid-namespace inode in the record so the check cannot match a pid from another namespace.
5. **Orphaned children run unlocked.** The lock fd is close-on-exec and `proc.go:73` puts each gate in its own process group. If qa-all or qa-lock is SIGKILLed, the kernel frees the lock while go-qa or `go test -race` keeps running, so the next run overlaps it. That is the parallel load this plan exists to prevent. Fix: let gates inherit the lock fd (flock follows the open file description), or set `Pdeathsig`.
