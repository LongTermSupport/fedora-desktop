## 09:14 · action · —   — Phase 1: the QA lock, low priority, and the wiring

Phase 1 built, tests first.

- `src-go/qa/internal/qalock`: the lock path from `git rev-parse --path-format=absolute --git-common-dir`, flock(2) LOCK_EX|LOCK_NB polled once a second on a clock seam (`Clock`,
  `RealClock` with a realClocks row in `qa/rules/table.go`), the holder record as JSON in the
  lock file, cleared on release. Wait line once, then a minute line naming the current holder
  (it re-reads the record, so a lock that changed hands is named right). `--no-wait` is
  `ErrBusy`; `QA_LOCK_TIMEOUT` is `ErrTimedOut`. Nesting: `QA_LOCK_HELD` naming the same lock
  and the record's pid among this process's ancestors (`/proc/<pid>/stat` ppid walk); the
  variable alone does not skip the lock (tested). A two-process test re-runs the test binary as
  the holder and proves no-wait refusal and the wait line against a real second process.
- `src-go/qa/internal/proc/priority.go`: nice 19 and ioprio idle are per thread on Linux, so
  setting them in a running Go program would leave the runtime's other threads at normal
  priority. Ensure locks the OS thread, lowers it, and re-execs the program from it (execve
  keeps that thread's values and it becomes the only thread). A marker variable turns a re-exec
  that did not lower into an error rather than a loop; `QA_FULL_PRIORITY=1` opts out. A real
  test re-runs the test binary, lets it re-exec itself, and checks every thread in
  `/proc/self/task` and a started child are nice 19 / class 3.
- Wiring: `qa-all` takes the lock after the session loads and holds it to the verdict;
  `qa-changed` takes it after preflight, before the first check (so `--plan`, `--help` and
  "nothing changed" take none). Both gained `--no-wait`; a nil lock is refused (exit 2). The
  two golden deviations pinning `--help` text were re-pinned (`-update-deviations`): the usage
  text grew the lock lines, nothing else changed.
- `src-go/qa/cmd/qa-lock`: runs one command under the lock at low priority, with its exit code;
  `scripts/qa-go-qa.bash` runs go-qa through it (a leading `--no-wait` is passed to it). Inside
  qa-all/qa-changed it inherits their lock.

Why the lock is not around the `go build` in lib/go-tool.bash: the build is a cached go build,
and the lock needs the run's own flags (`--no-wait`); taking it in the command keeps one place.
