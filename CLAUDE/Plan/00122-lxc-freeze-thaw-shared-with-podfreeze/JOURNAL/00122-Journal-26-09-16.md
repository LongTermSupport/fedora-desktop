## 09:20 · finding · P5 — thawed, and unreachable for minutes

The owner froze every container overnight, thawed them this morning, and could ssh
into none. Triage on the host, all read-only:

- `lxc-ls -f`: all RUNNING, every freezer cgroup `0` — the thaw itself worked.
- Most containers had no IPv4 on `eth0`. The ones that did had leased it AFTER the
  thaw, one every minute or so.
- Inside a container: NetworkManager and its `dhclient` both alive, `sshd` listening,
  but the last lease renewal was an hour before the freeze. Lease time is 3600 s from
  the host's dnsmasq, so every lease expired mid-freeze and the kernel dropped the
  address. NetworkManager still reported the device "connected" with the stale lease
  and had logged nothing since the thaw.
- The host's DHCP log showed the recovery: `DHCPDISCOVER` from each container between
  two and eight minutes after the thaw, on NetworkManager's own retry timer.

So nothing was broken; it was slow, and slow looks broken when the ssh wrapper gives
up after ten seconds. The forwarded ssh agent inside the containers died the same way:
the host-side session carrying its socket timed out with the freeze.

## 09:21 · finding · P5 — one reconnect renews in a tenth of a second

`lxc-attach -n NAME -- nmcli device connect eth0` on a still-waiting container:
`dhclient` restarted, same address back, 0.14 s wall clock. That is the thaw-time fix,
and it is engine-specific enough to live in `lxcfreeze`'s act hook rather than the
shared library — podfreeze's containers have no DHCP client of their own.

Triage hazard for Task 5.5: `lxc-attach` chowns the file its stderr points at, so a
probe run with stderr unredirected leaves a root-owned capture the harness cannot read
back. Three probes were lost to it before the cause was seen.

## 10:00 · finding · T6.1 — CRIU refuses at the first namespace it meets

`criu check` on the host says "Looks good". `lxc-checkpoint` on the designated
container, leaving it running, fails in 20 ms. One takeaway, then the lines from
CRIU's own log:

CRIU cannot dump a nested UTS namespace, and systemd-logind creates one.

```
Error (criu/namespaces.c:460): Can't dump nested uts namespace for <pid>
Error (criu/namespaces.c:721): Can't make utsns id
Error (criu/cr-dump.c:1975): Dumping FAILED.
```

Only one unit in the container sets `ProtectHostname=yes` — `systemd-logind.service`,
the Rocky 9 default — and it is the only process in a second UTS namespace. Everything
else (systemd, nginx, php-fpm, redis, sshd, NetworkManager, journald, rsyslog, crond,
agetty ×5) shares the container's own.

What a fix would mean: a drop-in overriding `ProtectHostname=no` on logind in EVERY
container, applied by IaC, before CRIU gets as far as the second blocker — and the
nested-namespace class is one of several CRIU is known to hit under systemd (mount
propagation, cgroup v2 ownership, TCP state). The retry with that override was not
run: the hooks daemon blocks a service restart inside a container as a manual system
change, and it is right that a spike should not be doing that by hand.

Timings for the record: dump attempt 90 ms wall including LXC's setup; nothing was
written but a 22 KB log. The container never stopped.

## 12:05 · action · T5.3 T5.4 — the column, and the cost said before it is paid

Both of Phase 5's remaining tasks, in one change across three files.

**T5.3, the `IPV4` column.** `lxcf_parse_ipv4` matches the address by SHAPE
(`(^|[[:space:]])([0-9]{1,3}\.){3}[0-9]{1,3}([[:space:]]|$)`), not by taking the first
line of `lxc-info -n NAME -iH`. That distinction is the whole function: `-i` prints
every address it has, and on a dual-stack container the IPv6 one can come first, so a
first-line read would print an IPv6 address under a column headed IPV4. The same shape
check is what stops `lxc-info`'s stderr reaching the cell — a failure message is not a
dotted quad.

`grep` exiting 1 is an ANSWER here, not an error: a frozen container, or one on no
bridge, legitimately has no address. Above 1 is grep itself failing, and returning `""`
for that would report "no address" from a probe that never ran — so it dies. In
`load_inventory` the address read is deliberately decoupled from the state read: a
failed address blanks the cell and the container stays in the list, because state is
what gates which verbs may be offered, and a RUNNING row with an empty IPV4 cell is
this phase's symptom rather than a reason to hide the row.

**T5.4, `FREEZE_FREEZE_NOTE`.** A library slot, printed beside the "Thaw them with:"
line — at freeze time, which is the last moment the cost is still avoidable. The
library carries the slot and neither the text nor the assumption that there is one:
DHCP leases and severed ssh sessions are LXC facts that say nothing about a Podman
container, and an empty note prints nothing at all rather than a blank line.
`lxcfreeze` fills it with the half the thaw renewal cannot fix — the lease comes back,
the TCP connections do not, so reconnect rather than trust an old session.

**Four of my own new assertions failed, and none was a defect in the tool.** Three
used `trim "$(freeze_hook_table_row 1)"`, which on a now-two-column row returns the
LAST non-blank cell — so an assertion written to read the BRIDGE was in fact reading
the address, and had been passing for the wrong reason the moment a second column
existed. Replaced with a position-based cutter:

```bash
col() { local row="$1" n="$2"; trim "${row:$(( (n - 1) * 16 )):16}"; }
```

That is not cosmetic. Trimming cannot tell a blank address from a short row, which is
precisely the distinction the column exists to make, so a suite that trims could not
have caught the column silently disappearing. `eq "the blank row still has its bridge"`
pins it. The fourth failure was a needle case mismatch (`reconnect` vs `Reconnect`).

`shellcheck -x` clean on all three files — the one remaining diagnostic in `lxcfreeze`
is the pre-existing SC2119 on the deliberately-bare `assert_on_host`, which carries its
own comment saying why taking shellcheck's advice would loosen the guard. Suite
`passed: 99 failed: 0`; `./scripts/qa-all.bash` green, 924 files. `docs/playbooks.md`
gains the two bullets, since both changes are visible tool behaviour.
