Issue 192 fixed in v2 (v1 `helpers/pingbus` untouched, as the owner directed). Two defect classes.

Class 1, a definite claim from a record not known to be current. In v2 it had four instances: (1) the
SessionStart frame said "you are ?, the member; the team has no coordinator now" for a team not
verified yet, and stated the last role and coordinator of a stopped (untrusted, token refused) team;
(2) teamsync wrote the role (setRoster) and main's facts (setFacts) in two SetHealth calls, so a
reader between them saw the new role beside the old coordinator, or none: the v2 form of "a record
mid-change"; (3) `say --to-coordinator` and `--to` refused with "team X has no coordinator" or
"no team held has a member" from the roster cache (n3d-D3), a copy from an earlier run; (4) the same
for `reply --to-coordinator`. Fix: `proto.ClaimCoordinator(current, coordinator)` is the one decision
of the coordinator clause, and both the frame (`hooktext.teamLines`) and the notice (`roleLine`,
`coordinatorLine`) go through it; `team.Health.Verified` is written with the role and facts in one
SetHealth and cleared at a stop; `engine.TeamRole.Current` / `HookTeam.Current` are Verified, a role,
and no stop; a team not current is framed "your role and the team's coordinator are not known yet:
run teamchat status --team <t>" and is not recorded as told; a send or reply unaddressable from the
cache alone is 20 `msgNoRoster`. No detector rule can express this class: it is a property of which
runtime state a text was derived from, not of a code shape an analyzer sees. It is pinned instead by
the table tests over every record state (TestClaimCoordinator,
TestAWorkersRoleLineNeverClaimsAnAbsenceFromARecordNotCurrent,
TestTheFrameNeverClaimsARoleOrAnAbsenceFromARecordNotCurrent, TestTheHookViewSaysWhetherTheRoleIsCurrent),
the atomic write (TestAVerificationNeverShowsARoleWithoutItsCoordinator), and the cache refusals
(TestACachedRosterNeverClaimsAnAbsence, TestACachedRosterReplyNeverClaimsNoCoordinator).

Class 2, a change the session must know of that is never re-told. `Membership.Coordinators` and
`session.json` `told.coordinators` (per worker team, "" for none) make a coordinator named, handed
over or removed one notice line for a worker whose role is unchanged; one first seen after a stale
start is told with the role. An unchanged coordinator tells nothing; a stop tells nothing. No detector
can express it either (it is a missing behaviour, not a code shape). Expectation tests in
`member/link/membership_test.go`: TestMidChangeStartIsTold (a), TestStaleStartCoordinator (b, g),
TestCoordinatorHandover (c), TestCoordinatorRemoved (d), TestSameCoordinatorQuiet (e),
TestOwnRoleChangeAsBefore (f), TestAnUntrustedRecordIsNotKnown and TestAStopIsQuiet (g).

Wire and record changes: `session.json` gains the required `told.coordinators` (still v 1: v2 is not
deployed, so no file of the old shape exists); MaxSession 16 KiB to 20 KiB so 64 teams with the longest
coordinator handle, `<` escaped, fit. A new corpus fixture
`proto/testdata/envelope/membership-coordinator.txt`, written by `go test ./internal/teamchat/proto -update`;
no existing fixture changed.

Left for a decision, not changed: the sender's re-check at post time (`engine/sender.go` recheck)
