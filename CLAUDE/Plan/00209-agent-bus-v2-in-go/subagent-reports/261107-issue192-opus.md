## The two classes

1. **A definite claim from a record not known to be current.** Hazard: a session acts on a false
   absence ("no coordinator") and has no one to report to. **Detector: none can express it.** It
   depends on which runtime state a text was derived from, not on a code shape a `go/analysis` rule
   sees. Fixed conventionally and pinned by table tests over every record state: verified, not
   verified yet, stopped untrusted, token refused, restarted and not verified again, and down, each
   with and without a coordinator. Every coordinator clause the frame and the notice write goes
   through `proto.ClaimCoordinator`.
2. **A change the session must know about is never re-told.** Hazard: a stale picture of the team
   lasts the whole session. **Detector: none** (a missing behaviour, not a code shape). Fixed with
   `Membership.Coordinators` and `session.json` `told.coordinators`, pinned by expectation tests
   (a) to (g).
