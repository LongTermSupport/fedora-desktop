## Verdict: FIX-FIRST

## Findings

### 1. MINOR: an identity change now unlinks a `seat.json` that GU1 says must be refused (GU1, GU3)

`member/guest/places.go:189`. `into` takes the identity-change path whenever `sameIdentity` is
false, and `sameIdentity` (`places.go:201`) is false for **any** failed read of `seat.json`:
missing, undecodable, and also a `homefs.ErrConfig` read (another uid's file, a symlink, a FIFO,
a file over `seat.MaxBundle`). The new `dir.Unlink(p.seat.Bundle())` then removes whatever is at
that name, a non-directory of any owner or type, and `replace` writes a fresh one. Before the
fix that same `seat.json` reached `replaceIfDiffers`, whose `Read` refused it as 78 `bundle`
("a file there that is not the user's regular file, or is over limit, is refused, never
replaced"). The fix therefore turns GU1's "refuses a path owned by another uid" into a silent
delete-and-replace for `seat.json` on this path. (A link is never followed, so nothing outside
the seat directory is touched, which is why this is MINOR and not MAJOR.)

A related point, older than the fix but made worse by it: a refusal found later in the op (for
example `token` owned by another uid, `TestPlaceBundleRefusesAnotherUsersSeat`'s second case)
now comes after the store has been set aside **and** `seat.json` has been unlinked, so a refused
placement leaves the seat with no bundle, where it used to leave the old `seat.json`.

**Fix.** Treat only "missing" and "reads cleanly but does not decode, or decodes to another
identity" as an identity change. In `into`, before `holdSeat`, read `seat.json` and `token`
through `dir.Read` with their caps. Any error other than `fs.ErrNotExist` is returned (it
becomes 78 `bundle` through `seatFault`), so nothing is set aside or unlinked. `sameIdentity`
can return that read's error, which removes the second read. **Tests**, in
`member/guest/places_test.go`, each a different identity:

- a `seat.json` that is a symlink, a FIFO, or over its cap: 78 `bundle`, the entry still there,
  `store.json` not set aside, no CHANGED lines;
- under root, as in `TestPlaceBundleRefusesAnotherUsersSeat`, a `seat.json` `Lchown`ed to
  `otherUID`: the same.

By reading the code (this review was read-only, so the test was not run): on HEAD the symlink
case would be red. `sameIdentity` is false on the link's ELOOP read, `Unlink` removes the link,
and the op exits 0 with `store.json`, `token` and `seat.json` CHANGED.

### 2. NIT: the unlink is not reported if the op then fails

`places.go:189-196`. If `replace` fails after the unlink, the op exits non-zero with `seat.json`
removed and no `CHANGED` line for it, while the store's set-aside before it was reported. The
host fails the phase on the error anyway, so nothing is acted on wrongly. One fix: report the
unlink as `WhatBundle` when it removes something, and let the later replace (which finds
nothing there) report it again, or keep the line only for the unlink. A change in which `what`
gets reported needs a TB2.4 check that the set already includes it, which it does.

### 3. NIT: rule text "a awaiting entry is over N bytes"

`member/state/store.go:260` builds `fmt.Sprintf("a %s entry is over ...", l.name)`, which reads
"a awaiting entry". The new test pins that wording (`store_test.go`, the "awaiting size" row).
"an entry of %s is over %d bytes" (and the test's row with it) reads correctly for every list.

## What was checked and holds

- **Finding 1 (AdoptSeat / NewStoreWriter).** `homefs.SameFile` does an
  `fstatat(AT_SYMLINK_NOFOLLOW)` from the parent's fd (reached by openat2 beneath the root) and
  compares type, dev and inode with `fstat` of the description. Full paths resolve correctly
  against both the state root (`AdoptSeat`) and a `Sub` seat directory (`LocksIn`). A refused
  description is closed. `NewStoreWriter` checks the directory it opened and then writes only
  through that fd, so a later rename of the directory cannot move the writes away from the held
  `seat.lock`. The tests cover another file, another seat's lock, `keeper.lock`, a replaced
  directory, a released lock, and `TestSameFile`'s link, directory, missing-file and closed-fd
  cases. `AdoptSeat` has no production caller yet (the link is n3c), so the signature change
  breaks nothing.
- **Finding 2.** `SetAside` opens `--state` as `Private`, and the 0755 test checks 78 `bundle`
  with the store untouched and no aside file.
- **Finding 3, ordering.** A reader can no longer get a mismatched pair. If it reads the old
  `seat.json` first, the token is still the old one (the token is replaced only after the
  unlink); a later swap makes the second `seat.json` read either `ErrNotExist` or a new inode,
  so `ErrTorn` and a retry. A failure or kill between the unlink and the placement leaves
  `token` and `seat.lock` with no `seat.json`. That reads as no bundle (`fs.ErrNotExist`, the
  state MS3 leaves for the next event), and a retried place-bundle takes the identity-change path
  again and completes, because the set-aside and the unlink are both idempotent. The test now
  asserts the pair read between the renames (same identity: own user, new token; another:
  `os.ErrNotExist`) and the exact CHANGED list.
- **Finding 4.** Each row names its own rule string. Every string matches the encoder's text
  (all rows pass), and none of them is the file-cap text.
- **Finding 5.** The `flock` helper takes "sh" or "ex", and both callers pass the argument.
  `onSleep = holder.Release` waits for the helper to exit, so the lock is gone before the second
  try. The test asserts exactly one 50 ms wait, the files removed, and the same `seat.lock`
  inode.
- **Nit 6.** `createAt` unlinks its own exclusively created name when fchmod, write, sync or
  close fails, so `Replace`'s temp file is covered too. The test runs the create in a reexec
  child under `RLIMIT_FSIZE` 4 and checks EFBIG and that nothing is left, in the child and in
  the parent.
- `go test -race ./internal/teamchat/...` passes. Coverage of every `member/*` package is at
  least 93.1% (guest 94.0, homefs 93.5, lock 93.3, state 99.7, bundle 93.1). `golangci-lint run` reports 0 issues with and without `--build-tags tuwunel`. The fix diff has no discarded
  errors, no `//nolint` and no wall clock in tests.
- Skim of the slice: `Establish` (GU1: uid 0, set-id, name/uid both ways, groups, umask
  first); LK1's acquire loop (three tries, typed Busy, closed on every failure path); and
  `bundle.ReadPair`'s MS3 read order and torn retry. None of these showed anything round 1
