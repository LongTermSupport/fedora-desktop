## Fix pass (fa3f2243..HEAD): each round-1 finding

1. **Blocker 1 (the cgroup is forgeable): closed.** `hostnet/network.go:360` `systemService`
   accepts only this shape:

   - `/system.slice/`;
   - then non-empty `*.slice` elements;
   - then a non-empty `*.service` as the last element.

   The new `TestCgroupUnit` rows (`network_test.go:158-172`) cover the user subtree, a `.service`
   intermediate, a `/child` sub-cgroup, `machine.slice`, `lxc.payload`, an empty element and a
   relative path. The user-subtree row fails against the old last-element rule.

   Step 9 (`host/apply.go:804-811`) refuses a unit that does not hold the port. So a squatter
   that wins the bind after step 2 stops the apply before step 10's bootstrap.

   n2f-D11's reasoning is sound: a delegated subtree always sits under a `.service` element, or
   outside `/system.slice`.

2. **The bus by the environment, programs by PATH: closed.**

   - `units/bus.go:16` dials the fixed socket (EXTERNAL with the euid, then Hello).
   - `TestSystemBusIgnoresTheEnvironment` fails if the environment's address is used: it would
     dial the scratch bus, and the bus ids would match.
   - `firewall-cmd`, `systemctl` and `journalctl` run by absolute path, with `CleanEnv` and
     `PATH=/usr/bin:/bin`, `LANG=C`. `checkProgramEnv` and the units test check this on every
     call.

3. **Nothing bounded the child, the job wait or the dial: closed.**

   - `ChildWait` wraps every `Ask` (`execchild.go:46`).
   - `JobWait` bounds the job's `JobRemoved` (`units.go:467`). It keeps the connection, and the
     test asserts that.
   - The dial is raced against the context. On abandonment, the connection's own context is
     cancelled, so godbus closes it. `TestTheDialEndsWithTheContext` uses a socket that never
     authenticates.

4. **The pipe was never run as two real processes: closed.** `execchild_os_test.go`'s `TestMain`

## Findings

### 1. Nit: the ChildWait test does not pin the bound's value

**Location.** `src-go/internal/teamchat/admin/execchild_test.go:256`.

**What is wrong.** `TestExecChildIsBoundedByChildWait` asserts that some deadline exists, and
that `ChildWait == 10m`. A bound of one second in `Ask` would pass it too.

**Fix.** Have the test's `bound` hook receive the duration (make `bound` take a
`time.Duration`, or expose the default as a func of it), and assert that `Ask` passes
`ChildWait`. This needs no clock.

### 2. Nit: CS5's rationale overstates what ChildWait guarantees

**Location.** `SPEC-n2f.md:70-71`, and the comment at `execchild.go:30`.

**What is wrong.** `ChildWait` is equal to the play's lock wait (C 3.5.2 step 1, 10 minutes),
not below it. And `team apply` holds the lock across several bounded waits: the job waits
(`JobWait`, each 10 minutes) and the child. So a waiter can still time out behind one legitimate
run. Each wait is bounded, which is what C12 needs. But "no op may outlive the play's wait" is
true only per op, and the comment implies the lock holder is bounded by it.

**Fix.** Reword it as "every op is bounded, so the lock holder is", or state the sum.

### 3. Minor: n2f-D12 is recorded only in the slice SPEC, not where the owner sees decisions

**Location.** `SPEC-n2f.md:284`; `PLAN.md:70-79` (the decisions table).

**What is wrong.** The text is honest and accurate. But it calls itself "owner-visible" and says
"Accepted for now", while PLAN.md's decisions table has no entry for it. That table carries the
VISIBLE and IRREVERSIBLE flags the coordinator relays to the owner before a milestone acts. A
token leak to a port squatter, which gives full homeserver admin, is the class INT6 sits in. As
it stands, nobody routes it to the owner before the install that makes it live.

**Fix.** Add n2f-D12 to PLAN.md's table, either as its own row like INT6 or within VISIBLE.
State: defaulted (accepted); to the owner before the first install (gate A); the unix-socket
alternative named.
