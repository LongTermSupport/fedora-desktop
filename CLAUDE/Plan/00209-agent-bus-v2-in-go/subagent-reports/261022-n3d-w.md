## What was wired

- **The forge checker.** `link.Main` builds one `forge.New(forge.Config{Login: forge.NewLogin(execx.OS{}, clk), Clock: clk})` per link process. `gh` runs only when a check
  needs a credential. The checker reaches the code like this:

  - `link.Config.Forge` (new) carries it to `engine.Config.Forge`;
  - `engine.TeamConfig.Forge` (new) gives every team the engine's checker;
  - wiring's `teamsyncConfig(engine.TeamConfig, teamsync.Watcher) teamsync.Config` (new, the
    adapter the brief names) carries it into `teamsync.Config.Forge`.

  So sends and receives share one login, one set of caches and one health (n3d-D20).

- **D2's owed item.** In forge, `Result` is now `= team.ForgeResult`, `Proven` is
  `team.ForgeProven`, and `ErrLogin` and `ErrDown` are `team.ErrForgeLogin` and
  `team.ErrForgeDown`. forge also declares `var _ team.Forge = (*Checker)(nil)`. forge imports
  team; team does not import forge.

- **The verbs.** `reply`, `say` and `ping` are `client.Main` verbs in `wiring.Verbs()`, which
  `cmd/teamchat` uses. They are in `cli.Outside()` and off `unbuilt` (n3e and n3f remain).

## Decisions

- **W-n3d-1: the checker is built in `link.Main`, as the brief says, not in `wiring`.** It
  then exists only in a link process, and every other verb's `Verbs()` call builds nothing.
  `link.Config.Forge` stays an interface, so link's tests pass a stub.
- **W-n3d-2: `engine.TeamConfig` carries the forge.** The alternative was a closure in
  `wiring.NewTeam`, but the engine is the one that owns the link's checker. A team made only
  for its notices also gets the field and never uses it.
- **W-n3d-3: the end to end addresses K by its short name** (`myrepo.2`, P69), which is how
  an agent names a peer.
- **W-n3d-4: the failpoint rows do not judge the killed say's own exit.** It is whatever a
  dead link leaves the client. The rows judge what the owner's rule promises: the text is in
  main exactly once once the queue is empty, and it reaches K once.
