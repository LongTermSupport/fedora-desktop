## Decisions (for the lead to put in SPEC-n3 at merge)

- **fixa-D1 (A1): drop, not deliver unrestored.** B 2.7.3 says a restored item "that no longer
  passes is dropped with its reason". An item that can never be fetched again cannot be judged
  again. Delivering it unjudged would let a planted store id through, which B 2.6.5 relies on
  the re-fetch to prevent. A parse failure counts as gone too, because the event as served
  never reads.
- **fixa-D2 (A2): the clean end is `Engine.Shutdown`.** The link's teardown calls it on every
  exit, after `finish`. It stops each team before flushing, so no later move goes unput. The
  bounds are a removal's, with the teams in parallel. The flush runs under
  `context.WithoutCancel`, so a cancelled link context still gets its 2 s. For SY10's text: a
  floor moved down is put at once and never coalesced, and a session start owes a put unless
  the goroutine already put that floor.
- **fixa-D3 (A4): the raised floor is the newest settled item's `SentMS`, not the true
  high-water.** The store keeps no high-water. Changing the store schema for it was not worth
  it: a lower floor only replays ignored events, and never loses one. The marker follows
  through `FloorRaised`, which is coalesced like any upward move.
- **`putFloor` with no floor known is no longer a put.** A `FlushFloor` before any floor is
  known used to start the 10 s coalescing window, which delayed the first real put. The A4
  teamsync test found this.

## Left alone

- `engine.Remove` and wire's `Removed`, which B2 owns. Shutdown's flush repeats Remove's five
  lines rather than sharing a helper, so as not to edit Remove.
- One residual: teamsync's session-local `s.floor` does not learn of a `FloorRaised` until the
  next persist. Only a clock step can then lower the store floor below the raise, and that
  lowering only replays ignored events.
