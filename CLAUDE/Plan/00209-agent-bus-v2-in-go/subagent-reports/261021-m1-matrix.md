## What M44 drives against a real Tuwunel

Tuwunel is started through `execx` with `TUWUNEL_CONFIG` on a loopback port, with a temporary
database and a random registration key. The config uses the bare top-level keys of
`render.py`, with `allow_room_creation = true` so a member can create the room. The test waits
for `/versions`, then drives the client:

- shared-key `Register` of a server admin, then `ServerAdmins`
- `CreateAccount`, `Account`, `MintToken`, `Devices` and `Whoami` for two members
- `CreateRoom` with an invite, then `Join` and `Membership`
- a `Send` repeated under one transaction ID, which must give one event ID
- `Sync`, `Messages` and `ReadReceipt`
- lock, unlock and deactivate, each read back, after which the token must be refused

When the test ends the server is stopped with SIGTERM. Exit 0, or death by that signal, is
clean; anything else fails the test.

## Departures from v1 (SPEC section 9)

- **MB1.** IDs are checked only as safe `!`/`$`-led path segments; the v12 grammar is
  `bus/proto`'s.
- **MB2.** Every segment must be printable ASCII and at most 255 bytes.
- **MB3.** The admin base URL refuses port 0.
- **MB4.** Admin calls get the 429 retry. Their errors carry no server `error` text and no
  non-`M_` errcode.
- **MB5.** A non-boolean `limited`, or a non-string `/messages` `end`, is malformed (exit 7).
- **MB6.** No `/relations`.
- **MB7.** The client checks `next_batch` and `prev_batch`.
- **MB8.** One general client: `Admin` embeds `Client`, and `Register` asks its own nonce.
- **MB9.** A per-side default User-Agent, which `Config.UserAgent` replaces.
- **MB10.** `Send` retries only a transient `Unreachable`.
- **MB11.** In `RoomFilter`, a nil list is not sent and an empty list asks for none.
  `/messages` `from` is optional. `leave` is read like `join`.
- **MB12.** `Token` formats as a placeholder and refuses `MarshalText`. The client holds the
  token only in a closure. A call refused before any request is `ErrInvalid`.
- **MB13.** The member base URL port and IP literal must be canonical. `Membership` refuses an
  empty user ID.

## Open questions

1. **The govulncheck finding.** GO-2026-6809 blocks a green qa-changed until the toolchain bump
   to go1.26.10 or later lands. That is the lead's or the owner's call, in IaC.

2. **M44 has never run against a real server.** It needs `FAKEHS_TUWUNEL_BIN` pointing at the
   pinned Tuwunel on the host (`go test -tags tuwunel ./internal/bus/matrix/`). These are
   unconfirmed until it runs:

   - that `database_path` is created when it is missing
   - that `v2/users/{id}/devices` lists a device for an admin-minted token
   - that deactivation revokes the token

3. **Lock and deactivation consequences are unmodelled in fakehs.** No H4 recording shows what
   Tuwunel answers to a locked account's request, to a sign-in to a deactivated account, or to
   a mint for one, so fakehs answers 500 and reports it. The real answers need a recording, or
   a first M44 run extended to capture them, before `bus/admin` relies on them. Round 2 note 1
   adds two more unmodelled cases: a locked account can still sign in, and can be minted a
   token, in the fake.

4. **The net/http GET resend.** A held sync dropped on a reused connection is held again on
   the restarted server rather than reported `Unreachable`. The reviewer judged this the right
   behaviour for a bus, and the package doc states it. Round 2 note 2 says the doc sentence is
   narrower than what net/http does. If the member sync engine ever needs to see every drop,
   the client would have to stop the resend, for example by not reusing connections for
   `/sync`.

5. **Remaining review notes**, none of them blocking:

   - Several fakehs answer texts are unrecorded and not yet labelled as such.
   - The fake's "held" means "received".
   - `Config.Token` and `Registration.Password` print in clear under `%v`.
   - `devices`, `joined_rooms`, kick, leave and receipt are proven only by v1 code.
   - Two tests are slow: TestCloseLeavesNoGoroutine (a fixed 2 s) and TestAnswerCap (a 32 MiB
     decode).
   - No fake-backed test calls `CreateAccount` with an empty display name.
   - The name TestDeactivationRevokesAndRefusesLogin is now stale.

   All are listed in the review file.
