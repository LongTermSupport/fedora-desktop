## What was built

- `internal/teamchat/colour` (new, std only): Plan 00217's palette, the dark backgrounds, the
  contrast floor, the automatic colour, the override grammar, and the escape.
- `failpoint`: n3e's five names, also listed in the armed build's `known` map.
- `member/team`: the room facts on `Health`, `Batch.HeldBack`, and the `Receipts` interface.
- `member/state`: `StatusTeam` gains `member`, `colour` and `stalled`.
- `proto`: the colour override, the description reader, `ValidShortName`, the colour argument
  to `Desired`, the topic and colour in `StateTypes`, and every farewell reason.
- `member/engine` (`status.go` `statusRow`, `publish`): rows fill `Member` and `Colour`, so
  every `status.json` the engine writes passes the new codec (see D2).

## Decisions

- **D1. `Desired` writes no colour event for `""`.** The brief's "main gains
  `ColourContent(colour)`" would put `{}` into every team's main room at the first apply (round 1
  low 13). Only a stored hex adds the event. Clearing an override that exists (C8's `{}`) is
  n3e-8's job in rooms, with `ColourContent("")`. Both callers, `rooms/rooms.go` and
  `health/view/view.go` (round 1 low 11), pass `""`.
- **D2. The engine fills `colour` and `member` now.** `colour` is required stored hex, so an
  engine row without it would make `status.json` unwritable. `statusRow` sets
  `Member = handle.Short()` (nil before seat.json is read) and
  `Colour = Health.Colour if stored, else colour.Auto(team)`. A refused row gets `Auto` and a
  null member. n3e-7 only has to fill `Health.Colour` in teamsync, and should not touch these
  lines. `Stalled` stays false until the stall is built.
- **D3. The topic and the colour joined `StateTypes`** (round 1 low 12, and round 2 found it
  harmless). A change to either in the timeline triggers a verification, which is where n3e-7
  reads them again. The `StateTypes` doc says so.
- **D4. Additions beyond section 5:** `colour.Reset`, and `proto.ValidShortName` for the state
  codec's member check.
- **D5. `MainColour` on an admin event it cannot read is `("", false)`.** The caller decides;
  falling back to `Auto` is the natural reading. An event from a member is ignored, not refused.
- **D6. Farewell texts** are n3e-D6's, word for word. `FarewellNone` (`""`) has a text, so
  `Reason: ""` now renders "taken out of this session" where it was a `reason` refusal before.
  An unknown reason is still refused.
