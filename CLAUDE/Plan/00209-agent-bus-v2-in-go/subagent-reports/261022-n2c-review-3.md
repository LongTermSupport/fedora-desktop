## New findings

1. **Medium: the n2c-D12 judgement reads the session's own copy, which the container writes.**
   `release.go:86-99` and `114-124` (`copyOfAnother`).
   `sessions/<session>/<team>/` is mounted read-write into the session's container (C 3.7.1).
   C41 says "the host never reads it back" and that nothing a container wrote is read by the host
   as a bundle. Step 2 must move "whatever is there, a link included, without following it". At
   HEAD, before step 1, the release reads `<team>/seat.json` from that directory and decodes it
   as a held bundle. It then trusts the `claim` in it to decide whether steps 1 and 2 run at all.

   - **A forged claim skips steps 1 and 2.** The container rewrites its copy's `claim` to any
     valid id. A leave or a remove then neither waits for the live keeper (SX1) nor moves the
     seat directory out of the container (SX2). Instead it logs the token out under the running
     keeper and completes. The seat directory, with its member state and seat lock, stays mounted
     in the session. Because of the leftover directory, every later take of a seat of that team
     into the same session fails at `mkdirFresh` (EEXIST).
     Reproduction: `TestReviewForgedCopyClaimSkipsStepsOneAndTwo`. It holds the keeper's lock,
     makes the session restorable, and forges the claim. At HEAD the release returns `nil`, the
     directory is still in the session, `held/` is gone and the token is dead. At 1f7442ef the
     same release is ErrBusy after the bounded wait, as SX1 requires.
   - **A link, FIFO or oversized `seat.json` stops every release for good.** `s.root.read`
     refuses it (ELOOP or ErrInvalid), and `releaseHeld` returns the error before step 1, on
     every retry. This holds even after the session is over. It also blocks every other
     session's take of the pool seat, since `clearHeld` runs the same release. The seat's live
     token is never logged out. Only a hand mend clears it.
     Reproduction: `TestReviewLinkedCopyStopsTheRelease`. With `seat.json` a link to the pool
     password, the release fails with `too many levels of symbolic links`, and so does a take by
     `s2`. At 1f7442ef both succeed.
     (A FIFO seat lock already stops step 1's probe by design, "refused". This is a second way to
     stop it, added by the fix, through a file the design never reads at all.)

   **Fix:** decide whether the directory belongs to another holding from host-owned state, never
   from the copy. One session holds at most one seat of a team, because the path is per team. So
   the session seat directory belongs to another holding exactly when another pool seat of the
   same team in this checkout has a complete `held/held.json` naming this session. As a second
   check, `ReleasedSession(session, team, claim)` already existing means this holding's step 2
   was done. Delete `copyOfAnother`. Record the rule in n2c-D12, replacing "its `seat.json` names
   another claim". Add both reproductions as tests.

2. **Low: the D12 judgement runs outside the allocation lock, but the rename it guards runs
   inside it, so the fix still moves another seat's live copy.** `release.go:86-98`.
   Here is the case. A holding of seat A whose take never made its session copy is released, for
   example by the sweep. The take could have died at step 5, or the session directory could have
   failed its check (C 3.7.3 line 1184). At the same time, the same session takes seat B of the
   team. The release reads `ENOENT`, so `another` is false, and step 1 finds no directory. B's
   take then completes under the lock and writes B's copy at the same path. A's step 2 takes the
   lock and renames B's live copy into A's quarantine. `RENAME_NOREPLACE` does not stop it,
   because A never moved a copy of its own there. B's `held/` and token stay live, but the session
   has no copy of B. Its keeper cannot start until B is released.
   Reproduction: `TestReviewCopyJudgedOutsideTheLock`. It uses `gateClock` to stop A's release
   in `Lock` while the test's take of B holds the lock. B's `token` ends up in A's
   `released/sessions/...-<A claim>/`. The test fails at HEAD and at 1f7442ef alike.
   **Fix:** run the judgement in finding 1 inside the `locked` closure, just before the
   `renameat2`. Keep only a lock-free first look to decide whether step 1 waits. Add the
   reproduction as a test.
