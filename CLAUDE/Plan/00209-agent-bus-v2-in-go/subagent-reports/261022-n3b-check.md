## Findings

### C1 (major): a guest FUSE server can forge a host errno and fail every seat of its container

- **Where:** `guestroot/bound.go:117`, the case for `EMFILE`, `ENFILE` and `ENOMEM`.
- **Cause:** `guestFault` takes these errnos as the host's from any call below the root. A FUSE
  server picks the errno of every reply it sends. The kernel passes any value from 1 to 511
  back to the caller, so a guest can answer -EMFILE as easily as -EACCES.
- **Scenario:** This is R2-1's own scenario with a different errno.
  - A non-team guest user mounts a FUSE filesystem on its `/run/user/<uid>/teamchat/run` and
    answers getdents with -EMFILE. `runsOf` (`kit.go:~286`) gets an error that is not
    `refused()` and returns it. `placeKit` (`kit.go:131-134`) then calls `r.step` for every
    live seat, so every seat fails at `kit`.
  - A member can do the same on its checkout's `.git`. `member()` takes its `default` branch,
    and `readsFailed` (`apply.go:~665`) fails every seat of the container as a host fault.
- **Fix:** take one of these errnos as the host's only when the host confirms it.
  - For EMFILE and ENFILE, `F_DUPFD_CLOEXEC` the root fd. If the dup succeeds, the process is
    not out of descriptors: close the copy and class the error as `ErrGuest`. If it fails the
    same way, the fault is the host's.
  - ENOMEM cannot be checked that way. Class it as `ErrGuest` below the root. A real ENOMEM on
    the host still shows up in the calls outside `bounded`.
  - Tests: a fake `sys` returns EMFILE from getdents while dup succeeds, and the result is
    `ErrGuest`. With dup also failing, the result is not `ErrGuest`. The EMFILE, ENFILE and
    ENOMEM rows of `bound_test.go:199` change to match.

### C2 (major): the per-user stall memo fails a seat that would have succeeded

- **Where:** `apply.go:153-164`, `rootOf`, which keys the memo by `m.decl.User`. The check is
  in `bound.go:67`.
- **Scenario:**
  - Guest user `agent1` has seat 1 on checkout `/srv/a` and seat 2 on `/srv/b`. Under n3b-D2
    any number of entries per user is allowed.
  - `/srv/a/.git` lies under a mount that stalls. That mount need not be agent1's. In a
    privileged container root can make it, or it can be a shared NFS mount.
  - Seat 1's reads wait out the bound and set the memo. Seat 2's `g.checkout` read of
    `/srv/b` then answers "was not tried: ErrStalled". Seat 2 is refused at the reads even
    though its facts are correct. This happens on every run while the mount stalls.
  - The same holds in the unit step: a stall on seat 1's unit write or dial refuses all of
    agent1's later seats.
- **Why it matters:** this breaks the owner rule. A member is (team, container, checkout,
  seat), not a user, so only the member with wrong facts should fail. The result also depends
  on the order the seats are read in: if seat 2 is read first, it joins. fix4's argument that
  "a stall is the user's own mount" does not hold for a checkout path.
- **Fix:** key the memo by the path that stalled, not by the user.
  - The `Memo` keeps the stalled paths. A later call answers at once only when its path is at
    or below one of them.
  - One memo per box per run is then enough, and it can also cover passwd and the kit sweep.
  - The review's scenario still costs one bound: a second seat on `/srv/a` re-reads the same
    `.git/config`, because a failed read is not cached.
  - Test: one user with two checkouts, one of them stalled. The other seat joins, and
    `waits == 1`.

**Scope (asked): the memo is held to one run.** The memos live on a `guestBox`. A box is built
for each run, in `containers()` (`apply.go:588`) and in `leaveBox` (`absent.go:234`). The
absent and present phases have separate boxes, so a stall can be waited out once in each phase.
The health probe takes no memo. Nothing carries over between runs.

### C3 (nit): a systemd socket that answers an errno is now a failure, not the unit down

- **Where:** `apply.go:1259`.
- **Change:** `EACCES` or `EIO` from the O_PATH open of the systemd socket is now `ErrGuest`.
  Before fix4 it went to `errUnreachable` and was reported offline (unit down). Now it fails
  the member.
- **Assessment:** this fits "a running member with wrong facts fails that member alone", but
  it is not tested. Add an `ErrGuest` row next to `TestRefusedSystemdSocketFailsTheMember`.
- **No other class leak found:**
  - ENOENT stays `fs.ErrNotExist` and is still the unit down.
  - A connect error stays a `*net.OpError` and is still `errUnreachable`.
  - `InitExe` and the pidfd poll are outside `bounded` and stay the host's.
  - `ReadProcStat` reads the guest's own /proc, so `ErrGuest` is correct for it.
