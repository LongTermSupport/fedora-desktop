## New findings

1. **minor**: `src-go/internal/teamchat/matrix/fakehs/fakehs.go:95-97` and `:635-650`.

   - **What is wrong.** The quirk's doc says an account made admin "seeded, registered or set by
     the admin API" joins the admin room "as Tuwunel does". The real server has shown one thing
     only: the registration path (the rooms engine's first red). No tagged test pins any of
     these against Tuwunel:

     - that a `PUT /_synapse/admin/v2/users` with `admin: true` joins the room;
     - when the room is created (fakehs creates it lazily on the first admin, while Tuwunel
       creates it at server start);
     - the room's shape (fakehs gives it 3 events and no power levels; Tuwunel's has its name,
       topic, alias, power levels and join rules);
     - what happens on demotion (fakehs leaves a demoted admin joined).

     The quirk is also applied only when an admin is created. A test that calls `SetQuirks`
     after seeding the admin gets no room.

   - **Why it matters.** SPEC M37 and `TuwunelQuirks` exist so that fakehs stands in for the
     server. Later slices will walk the admin's joined rooms through this model: C 3.6.2 step 3
     (humans), health (C 3.11), and admin-room-aware listing. They would inherit claims nobody
     has seen. Round-1 finding 4 asked for the behaviour to be recorded as a server answer.

   - **Fix.** In `TestTuwunelConverge`, before the first run, assert that the admin's joined
     rooms are exactly one and that its create sender is not the admin. Either narrow the
     quirk doc to "registered or seeded", or add a tagged probe of the PUT path. Carry the rest
     into Task 2.5's list of recorded answers, as report item 6 proposes.

2. **minor**: `src-go/internal/teamchat/rooms/rooms_test.go:415-434`
   (`TestConvergeReportsWhatChangedBeforeAFailure`).

   - **What is wrong.** The test claims RE9's partial result, but it covers only `Changed` and
     `RosterRev`. `res.Rooms != ids` compares against the input IDs. The test would still pass
     if `Converge` returned the caller's `ids` instead of `e.ids`. No test covers a failure
     after a create or an adoption: `TestConvergeAdoptsAfterACrash` discards the result
     (`_, err :=`). So two claims are unproven: "the room IDs" in RE9, and the
     `room main created ...` line before a later failure.
   - **Why it matters.** RE9: "A failure still answers what changed before it: the room IDs,
     the CHANGED lines so far". C 3.6.2: "Every change appends a CHANGED line". SPEC section 0
     requires that every test proves the expectation it claims.
   - **Fix.** Add a case with a fault on the second `/createRoom`. Assert that `res.Rooms.Main`
     is the new main, `res.Rooms.Reports` is empty, and
     `res.Changed == ["room main created " + res.Rooms.Main]`.

## Checked and found right

- **`breaksLine`, `oneLine`, `validLine`.**
  - The cut cannot go out of range: `len(s) > 4096` there, and `s[0]` is a rune start.
  - `strings.Map` turns invalid UTF-8 into U+FFFD before the cut, so the output is always
    valid UTF-8.
  - A message is never empty: every caller prefixes it.
  - `validLine` bounds bytes, not runes. That matches CC6.
- **`distinct`.**
  - Empty IDs are skipped, so a new team passes.
  - The error names the second purpose and step `read`, and it is drift (exit 70).
  - It runs before `find`, so no call is made.
- **`slot`.** It is called before `adoptable`, `Intent` and `CreateRoom`.
- **The partial `Result`.** `rosterRev` is set only after `PutState` of the roster returns
  without error, so a refused roster (`planRoster`, drift) leaves it 0.
- **Adoption across teams.** The admin is `@admin:<server_name>`, and C1 / C 3.2.1 give one
  homeserver per team. So "admin-created, no link" cannot pick up another team's main room.
- **The AdminRoom quirk elsewhere.**
  - The server user is not an account, but no fakehs path indexes `s.users` for a member of
    the admin room: `memberContent` is called only for the new admin.
  - `levels()` of a room with no power levels returns `{}` without error.
  - The matrix, fakehs, M44 and sync tests all pass with the quirk on.
  - Re-promotion after a demotion appends a second join, which is harmless.
- **The new rooms tests.** Each one would go red with its behaviour removed:
  - `TestConvergeIgnoresTheServersAdminRoom`: without the create-sender check, the admin room
    is adopted as main and then refused at `read`.
  - `TestConvergeAdoptsOnlyTheTeamsSideRoom`: one case per RE2 condition, plus the control.
  - `TestConvergeRefusesOneRoomForTwoPurposes`: without `distinct`, the run writes.
  - `TestConvergeReportsWhatChangedBeforeAFailure`: with `Result{}`, `Changed` and `RosterRev`
    come back empty.
  - `TestSlotRefusesAnUnknownPurpose`.
- **`ExitCodeOf`** checks drift first, then unreachable or rate-limited (69), then 1 (C 3.3,
  n2a-D13).
- **Plan drift.** PLAN.md Tasks 2.1 and 2.3 say what the code does and what it leaves out.
  The report matches the code apart from new finding 6.
