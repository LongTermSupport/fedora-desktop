# N2 slice n2c: seats and bundles (Plan 00209 Task 2.4, part)

Branch `feat/bus-v2-n2c`, cut from `feat/bus-v2-n2a`. The slice's contract is
[SPEC-n2c.md](../SPEC-n2c.md) (SN1, SR1-SR3, SW1-SW3, SL1, SC1-SC3, ST1-ST7, SX1-SX6, SD1-SD4,
SP1-SP4, decisions n2c-D1 to n2c-D13). It implements area C's 3.7 and the seam rows 15, 24,
27, 32 and 59, with DC16 (c') and the corrected H-C13 take.

## What was built

- **`internal/teamchat/paths`** (SN1): the seat store's names. These are `SeatName` (n2c-D1),
  `ClaimID`, `Store.PoolSeat`/`PoolClaim`/`SessionSeat`/`ReleasedSession`/`ReleasedPool`,
  `Layout.SeatClaim`, `GuestTokenCopy` and `SeatDevice` (`TCSEAT`).
- **`internal/teamchat/seat`**, the owner's side of the seat store:
  - `records.go`: `seat.json` in its pool and held forms, `held.json`, `released.json`,
    `notice.json` and the issued bundle. All are strict. Every key is lowercase ASCII, and a
    `Secret` never formats or marshals (SR1-SR3).
  - `fs.go`: the directory-fd layer. Every path is opened from the root's fd with `openat2`
    `RESOLVE_BENEATH|RESOLVE_NO_SYMLINKS|RESOLVE_NO_MAGICLINKS`. Files are created
    `O_CREAT|O_EXCL|O_NOFOLLOW` 0600 and fsynced with their directory. Replacements go through
    `<name>.new` and a rename. Directories are 0700 and checked as owned (SW1-SW3).
  - `lock.go`: the allocation lock, bounded at 30 s by the injected clock (SL1).
  - `credential.go`: the `Credential` seam and `Password`, which is (c'). `Mint` logs in as
    `TCSEAT`, logs out, and logs in again (H-C13). `Retire` is a logout (SC1-SC3).
  - `take.go`: take steps 1 to 7 (ST1-ST7). `lockprobe.go`: the L3 seat lock probe and the run
    id (SX1, SD1).
  - `release.go`: release steps 1 to 5, resumable, and `Announce`, the crashed-session path
    (SX1-SX6, SD1-SD4).
  - `place.go`: `Claim`, `Fill`, `Abandon` and `QuarantineLeftovers` (SP1, SP2).
    `guest.go`: `PlaceGuest` and `KeepGuestToken` (SP3, SP4).
- **`tuwunel_test.go`** (`-tags tuwunel`, ST6): take and release against the pinned Tuwunel
  1.9.4. It passes with `-race -count=3`. With `Mint`'s logout removed it fails ("the earlier
  holder's token survived the take").

Gate B holds. The slice is inert Go and tests. Nothing deploys, installs or runs it: no play,
unit, sudoers rule or install step. The test passwords are `rand.Text()` per run. No secret
reaches an error, a log, an argv or a format.

## Decisions

n2c-D1 to n2c-D13 are in SPEC-n2c.md section 10. In short:

- **D1**: a pool seat's directory is named by the whole handle, because `<seat>` collides across
  member types.
- **D2**: a retired seat's pool directory goes to quarantine under a fresh claim id.
- **D3**: a host `cc` session's seats are its session seat directory (C 3.7.1), not B's
  `~/.config/teamchat/seats`.
- **D4**: a stale `held/` met by a take is released under the take's own lock.
- **D5**: a release resumed after step 2 reads the run id from the quarantined seat lock.
- **D6**: the allocation lock's wait is bounded at 30 s and polled every 100 ms.
- **D7**: the credential seam has three members (below).
- **D8**: a placement carries the old record's `released.json`.
- **D9**: a release reads and writes through the fd of the `held/` it found, and does step 5
  only while the claim is still in place.
- **D10**: a credential has no space, and record keys are lowercase ASCII.
- **D11**: a guest placement first removes its own leftovers, and takes no lock.
- **D12**, reworded in round 3: whether release steps 1 and 2 are owed is judged from
  host-owned state only, never from the session's copy. This holding's quarantine name already
  taken means they are done. A session seat directory gone at step 1 is not moved at step 2.
- **D13** accepts two lows of round 2, which are not fixed:
  - Two releases of one holding at once (the launcher's and the seat sweep's) may both ask the
    announcer, and one may fail its `notice.json` replace and stop. The cost is a second
    notice, which M22's transaction id stores once, plus one retry. No state is lost. A fix (a
    per-call `.new` name) would add machinery for a race the sweep heals.
  - A broken `released.json` is refused by both a take and a placement, so only a hand mend
    clears it. Silently dropping it would reset `released_ms`, which bounds area B's store-less
    start (seam row 32). The next round of the design should say whether a reissue may drop it.

These decisions were taken in the build, outside the table:

- The L3 probe and every other path are opened from the store root's fd (SW2), not from the
  fd of `sessions/<session>/` as C 3.7.3 words it. A link is refused on every component.
- A free seat lock whose record is over 4 KiB names no run (SD1), the same as an undecodable
  one.
- Release step 1 stops waiting when the lock is free or the session is not restorable.
- An `Outcome` that is neither posted nor carries a one-line `why` is refused (`ErrInvalid`).
- Release step 4 retires using the pool's `seat.json`.
- `Store.Close` releases the root fd.
- A release does not move a session seat directory that was gone at step 1 (round 3, D12).
  This assumes the caller starts a holding's release only after its take has returned. A
  release run while its own take is still between steps 2 and 7 would leave that take's copy
  in the session. The token is still retired, so the copy is dead.

## The credential seam, and how 7.1 replaces the password for gate B

Gate B waits on the owner: confirm INT6 or choose DESIGN-v2 7.1, (d) tokens only. The seam
makes that choice a matter of store configuration:

- `Credential` has three members. `Kind()` names the pool file (`password` or `token`) and the
  issued bundle's key. `Mint(ctx, bundle, pool secret)` is take step 3. `Retire(ctx, bundle, held token)` is release step 4. The store never names the password. `credentialPath`,
  `credentialName`, `poolSecret`, `Fill`'s kind check and the quarantine unlink all follow
  `Kind()`.
- **(d1), the token reused**, is a `Credential` of kind `token`. Its `Mint` checks the pool's
  token with `whoami` and answers it, turning `M_UNKNOWN_TOKEN` into `ErrReissue`. Its `Retire`
  does nothing. No store code changes. `TestATokenCredentialBehindTheSeam` proves the shape: a
  token-kind credential is placed into the pool's `token` (no `password` written), taken into
  the session copy, and retired once by a release, all by the same store code.
- **(d2), one reissue per take after a release**, is a token-kind `Mint` that answers the
  freshly placed token, plus a `Retire` that logs out. It needs two store additions, which
  n2c-D7 names: release step 5 unlinks the pool's `token`, and take step 1 reads a pool record
  with no `token` as `ErrReissue`. Neither touches `Password`.
- What stays outside the seam is out of this slice under either shape: the root child's
  `--credential pool_token`, the hot reissue's token replace, and the restore's reissue.

## Open after round 3, with its fix

1. **Low, the rest of round 3's finding 2.** The case: step 1 finds the session seat directory
   present, but it belongs to another holding of the same session. This happens when this
   holding's take died before step 5 and a take of another seat of the team then succeeded into
   the session. A leave then waits on the other seat's lock, giving `ErrBusy` while its keeper
   runs. A release of an ended session moves the other seat's copy into this holding's
   quarantine. The other holding's own release then finds its directory gone and names no run.
   Nothing live is lost, since an ended session's copy is dead, but the state is confused.
   **Fix:**
   - Take step 1 refuses, before step 2, a session whose `<team>` seat directory already
     exists (`ErrHeld`, naming it). Then at most one holding of a session and team can have a
     copy.
   - Release step 2, under the lock, moves the directory only when no other pool seat of the
     team in this checkout has a complete `held/held.json` naming this session and newer than
     this holding's `since_ms`.
   - Record both rules as a D12 addendum. The design should say who owns
     `sessions/<session>/<team>` when two holdings name one session.
2. **Accepted, n2c-D13**, as above.

## The narrow check's finding: a member could keep a released seat's token live

`261022-n2c-check.md` found it, FIX-FIRST, medium. A member planted a `seat.lock` link or FIFO,
or set a mode or owner on its seat directory. The remove, the release after the session and
every take of the seat then failed before `Retire`, so the token stayed live (against DC16 and
H-C13).

**The principle: revocation never depends on anything a member can write (n2c-D14).** The check
said `sessions/<session>/` is host-owned. It is owned by the owner's uid, but it is
bind-mounted read-write into the container (C 3.7.1). So the member controls the seat
directory, the mount root above it, the lock file and the lock's flock. A same-parent rename
inside `sessions/<session>/`, which the check proposed, can still be blocked by a mode on the
mount root, so it was not used.

**What is authoritative, and why no two live holders follow.** Whether a seat is held is decided
by host state: `held/held.json`, written under the allocation lock where no container reaches
it, and the session record (`Restorable`). The seat lock is advisory:

- it bounds a release's drain of a live keeper;
- it supplies the notice's run id;
- it adds a live keeper to `sessionHolds`, which a host `cc` session with no record needs.

A refused lock counts as free and names no run, as a deleted lock already did. A member gains
nothing by making its own lock refused. A restorable session stays `ErrHeld` whatever its lock
shows, and every take's fresh login ends all earlier tokens of the device (ST6). So a second
holder can never share a live token with the first.

**The fix:**

- `probe` (`lockprobe.go`) finds the lock with `O_PATH` and `fstat`s it. Only a regular file is
  then opened, `O_RDONLY|O_NONBLOCK`, and it is checked to be the same inode. The errnos a
  container can cause (`ELOOP`, `ENOTDIR`, `ENXIO`, `EACCES`, `EPERM`), and a lock that is not
  a regular file, are `lockRefused` and not an error. Any other fault still stops the release
  or take (fail fast).
- Release step 1 (`awaitFree`) counts a seat directory the owner cannot look into as present
  with its lock refused. **Behaviour change:** a lock still held at the 60 s bound no longer
  gives `ErrBusy`; the release goes on and retires the token. Otherwise a keeper that never lets
  go would keep a removed member's token live, which is the same class. `ErrBusy` is now only
  the allocation lock's (SL1).
- Step 2 (`moveSessionSeat`): when the container's mode or owner stops the move, the copy is
  kept in place. Steps 3 to 5 still run, and the release then returns `ErrCopyKept` naming the
  copy. The take treats `ErrCopyKept` from clearing an ended holding as done, because the kept
  copy belongs to that session, not to the new holder.
- SPEC-n2c.md: SX1 and SX2 are reworded, and n2c-D14 is added.

**Tests** (`planted_test.go`, plus the two changed in `release_test.go` and `lockprobe_test.go`).
The plant, FIFO, mode and owner tests were seen red before the fix, failing with the check's
own errors. `TestAnOwnerFaultIsNotARefusal` and `TestALockSwappedBetweenOpensIsRefused` are
guards written after it.

- Planted at `seat.lock`: a link to `/dev/null`, a link to an owner file, a FIFO and a
  directory. Each is tested through a remove, the release after the session, a take by `s2`,
  and `Announce`.
- Planted in place of the seat directory: a link, a FIFO, a file and a socket.
- `TestAFIFOIsNeverOpened`: an inotify `IN_OPEN` watch on a planted FIFO, through `Announce`,
  `sessionHolds` and a release resumed after step 2 (the quarantined lock). `O_PATH` raises no
  `IN_OPEN`, so the test is deterministic and nothing can block. It caught a real defect in the
  first draft of the fix, which opened the lock before checking its type.
- Modes 0000, 0100 and 0500 on the seat directory and on `sessions/<session>/`, and a chown to
  uid 1 of each. Each runs through a remove, an ended release and a take. The container runs as
  uid 0, which bypasses file modes, so as root these tests re-run themselves under `setpriv`
  (util-linux, through `execx`) with an empty bounding set, plus `+chown` for the chown case.
  They forward `-test.gocoverdir`, so the child's coverage counts. As non-root they run
  in-process. The chown case needs CAP_CHOWN, so it is skipped as non-root.
- `TestAnOwnerFaultIsNotARefusal`: a bad root fd is still an error.
- `TestALockSwappedBetweenOpensIsRefused`.
- `TestReleaseWaitsForTheSeatLock` and `TestAForgedCopyClaimDoesNotSkipTheWait` now assert the
  full bounded wait and then the revocation. `TestSeatLockProbeRefusals` asserts `lockRefused`.

Two consequences carry forward:

- **Open item 1 is worse under D14.** A leave that meets another holding's directory now waits
  60 s and then moves that live copy, where before it gave `ErrBusy`. The precondition is still
  host-only: this holding's take must have died before step 5. Rule 2 of its fix (release step 2
  checks the team's other `held/` records) closes it.
- **The 7-day prune (not in this slice).** It must remove a quarantined copy whose mode or owner
  the member changed. As the owner, a chown to another uid needs `podman unshare`. It must also
  handle copies kept in `sessions/<session>/`.

## Design-text fixes proposed (not edited here)

- C 3.7.1 and the C41 table: `sessions/<session>/` is mounted read-write, so every path under
  it, the mount root's mode included, is the member's. Revocation and the holding record never
  depend on it (n2c-D14).

- C 3.7.3, release step 1: a refused lock is free and names no run. A lock still held at the
  bound ends the wait and the release goes on. Strike "exits 75 naming the holder; the seat
  stays held". Step 2: a copy the owner cannot move is kept, and steps 3 to 5 run (n2c-D14).

- B's header gives a host `cc` session's seats as `~/.config/teamchat/seats`. C 3.7.1 puts them
  in the session seat directory, and the header should say so (n2c-D3).

- B 2.11's host `since` should be `held.json`'s `since_ms`.

- C 3.7.4: `<seat>` numbers are counted per prefix, so a pool directory must be named by the
  whole handle (n2c-D1).

- C 3.7.3, release: a resume after step 2 reads the run id from the quarantined seat lock
  (n2c-D5).

- C 3.7.3: the probe and every path are opened root-relative with `openat2`, not from
  `sessions/<session>/`'s fd.

- C 3.7.3, placement: `released.json` is carried across a placement (n2c-D8).

- C 3.7.3, release: steps 3 and 4 use the `held/` fd, and step 5 runs only while the claim is
  in place (n2c-D9).

- C 3.7.3, release: whether steps 1 and 2 are done is judged from host state only, and a
  session seat directory may be reused by another seat of the team (n2c-D12, and open item 1).

- C 3.7.3 / 3.7.5: say whether a reissue may drop a broken `released.json` (n2c-D13).

- C 3.4: give the allocation lock's wait a bound (n2c-D6).
