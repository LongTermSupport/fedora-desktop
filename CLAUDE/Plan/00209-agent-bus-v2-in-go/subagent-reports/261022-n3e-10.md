# n3e-10 report: the hooks in the link, and membership notices (HK1-HK3, DV6, n3c-D23)

Branch `feat/bus-v2-n3e-10`. Two builders: the first built the engine side (f0fd917e2) and
drafted the link hooks (handoff `261022-n3e-10-handoff.md`); the second got the link compiling
and tested, wired it, and wrote DV6's membership notices.

## What was built

- **Engine** (`member/engine/hookview.go`): the hook view, `OnTeams`, `SetUnusable`, and the
  running-wait count; the unusable counts reach status and status.json (`records.Runtime`'s
  `Unusable`).
- **Link hooks** (`member/link/hooks.go`): the four hook ops answered by the link, never by
  `engine.Serve` (n3e-D18). Every op decodes its args strictly, waits for the keeper's pid
  within its deadline (none: the connection closes unanswered, and the hook gives its own
  recovery line), counts an unusable payload, then answers from fixed templates and the
  engine's memory. No hook op makes a network call.
  - SessionStart: the frame, each team's block and the mode, then the pending, failure and
    refusal lines; `told` and `frame_told` are written before the answer.
  - UserPromptSubmit: an owed membership notice, the pending counts the socket will not push,
    a failure line once per 10 minutes, and the refusals not told yet.
  - Stop: blocks only on `stop_hook_active` false, and only when its guard is written: once per
    not-pushed pending digest, once per 10 minutes for a failed team (never a down one), and
    once per 10 minutes for a wait session with no wait running.
  - SessionEnd: `clear`/`resume` record nothing; any other reason is recorded with the facts in
    one write.
- **Facts** (`member/link/facts.go`): `AwaitPID`, `File`, `Update`, `CountUnusable`, and
  `acceptWith` (AcceptFacts plus an edit in the same write).
- **Server hunk** (`member/link/server.go`): `peerUID` is now `peerCred` (uid and pid). A
  `hook` field answers the hook ops: the answer line (when there is one), then
  `{"done":{"exit":0}}`.
- **Membership** (`member/link/membership.go`, DV6): the engine's `OnTeams` is kept and
  announced by a link goroutine. Each change goes through one `SendMembership`, and `told` is
  written when the notice is written. A notice the socket did not take is owed to the next
  prompt, which renders it with its own nonce and writes `told` then.
- **Link wiring** (`member/link/link.go`): the `hooks` and `mem` fields; `OnTeams` in the
  engine config; the generation from launch and each `desired` message; `srv.hook` and
  `announceTeams` started after `newServer`; and `noteFarewell` before `eng.Remove`.

## Decisions

The first builder's:

- **D1. Stop reasons combine.** When several blocks are due, one block carries every reason,
  and every guard field is written in that one write.
- **D2. The failure line is shared, and down teams count for the prompt.** The prompt's failure
  lines name down and failed teams. The line repeats every 10 minutes and shares `failure_ms`
  with Stop (n3e-D11b). Stop blocks only for failed teams (n3e-D12).
- **D3. The repeat times are wall ms.** A wall clock stepped back makes a repeat due.
- **D4. End reasons map to the closed set.** `exit` and `prompt_input_exit` record `exit`;
  `logout` records `logout`; anything else records `other`. `clear` and `resume` record
  nothing.
- **D5. Waiting is counted, not listed.** It is the number of wait requests running, an atomic
  in `wait`. The engine's `waiters` list keeps stale entries, so it cannot answer this.
- **D6. The pending counts are what the socket will not push.** So the prompt's line and Stop's
  digest agree.

The second builder's:

- **D7. A leave needs a remove.** A team that was told but is no longer held is announced as
  left only when this link saw its remove (with that remove's farewell; a nil farewell is
  `proto.FarewellNone`). Otherwise its told role is kept. Why: a restarted link that is told
  `[]` at Run's start, or whose add fails or is late, would otherwise tell the session it left a
  team it is still on. SessionStart's frame resets `told` to the teams it names.
- **D8. Nothing is announced before the frame.** No notice goes out while `frame_told` is false
  or before the engine has told its teams, because the frame says it all.
- **D9. A probe role is recorded quietly.** `proto.roleLine` refuses `probe`, so a probe team is
  in `told` and in the notice's teams-now list, with no joined or role line.
- **D10. An unrenderable notice is told anyway.** A `*proto.SlotError`, from the engine on the
  socket path or from the link on the prompt path, is logged and `told` is written, because it
  could never render on a retry. The prompt path draws its nonce from `crypto/rand`.
- **D11. `told.generation` is the latest desired generation.** It is launch's, then each
  `desired` message's, at the time of writing. Nothing waits on it: the diff is by role.
- **D12. The prompt does not race a send.** The prompt's fallback takes `sending` with
  `TryLock`. While a socket send holds it, the prompt says nothing, and the send settles `owed`
  itself.

## Tests corrected (the drafted `hooks_test.go`), and why

- `TestAForgedOpIsAnsweredEmpty` read session.json, which a refused op never writes, so the
  read failed on ENOENT. It now checks the session in memory, and that the file is absent.
- `TestAnOpBeforeThePIDIsNotAnswered` waited for exactly two fake-clock waiters, but the link
  already had others armed, so it hung. It now waits for the baseline plus the op's deadline.
- `TestThePromptCountsPendingWhenNotLive` and `TestStopBlocksOncePerPendingSet`: the hook's own
  socket and token made delivery live, so the items were pushable and rightly not counted
  (D6). Their hooks now carry no token (`tokenless`).
- `TestAFailedTeamBlocksEveryTenMinutes`: the prompt's down line had set the shared
  `failure_ms` (D2), so the Stop block that followed was suppressed. The wall clock is now
  stepped between them, and the test also checks that the down line does not repeat within 10
  minutes.
- Lint: `evAt` uses `strconv` (gosec G115), and `blockOf`'s struct has json tags (musttag).
- Added: the pure tests `TestStopDecision` (live with nothing held: no block; a stall's set
  blocks once) and `TestDue` (the clock stepped back). `membership_test.go` covers a join, a
  leave for each reason, a role change, a refused socket and then the prompt fallback (told
  once), a restarted link (nothing told twice, D7), a new session told by SessionStart, no
  notice before the frame, `diffMembership`, and an unrenderable notice.
- OF1 (one team down beside a running one, every hook exiting 0) is
  `TestAFailedTeamBlocksEveryTenMinutes`. A token never in link.log is
  `TestSessionStartAnswersTheFrame`.
