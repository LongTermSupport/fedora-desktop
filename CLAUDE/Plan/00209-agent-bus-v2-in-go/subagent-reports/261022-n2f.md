# N2 slice n2f: `teamchat-admin`'s production wiring

Branch `feat/bus-v2-n2f`. The contract is [SPEC-n2f.md](../SPEC-n2f.md). The six parts are
merged; each has a part report, `261022-n2f-<part>.md`, for the exact API.

## What was built (inert code; no play, unit, tmpfiles or meta-deploy entry)

- **units** (SD1-SD9): systemd over D-Bus through godbus (`go-deps.allowlist` row, vendored).
  It covers unit jobs and state, waits on JobRemoved, and treats an unreachable systemd as
  dropping the connection. `CleanState` and `JournalTail` go through `execx` by absolute path
  in a clean environment.
- **hostnet** (NW1-NW4, FW1-FW2, RD1-RD2): interfaces, routes and listeners read from `/proc`.
  A listener counts as a unit's only when its cgroup sits directly under `/system.slice`. The
  package also holds the firewalld zone and rules, and the readiness probe.
- **ctl** (OP1-OP6): the child's own files and the Opener. That covers the admin password, then
  the token, the device `TCADMIN`, a crash's temporaries removed through the held directory fd,
  and the member client.
- **health** (HR1-HR5): `Refresh` under a held lock, `One`, `host.ReadStamp`, and the production
  file adapters.
- **child** (EX, CS, CO, BU, HF): `execx.Cmd.Credential` and `CleanEnv`; `ExecChild` starts
  `ctl-child` as `teamchat-ctl` with PATH alone in `/`. Root caps the answer and stderr, judges
  the answer against the exit code, and bounds each op with `ChildWait`. The child serves two
  new ops, `team.view` and `member.disconnected`, and also covers bundles, the owner group, and
  the owner and mode check on host files (`state.ReadOwnedFile` and `ReadOwnedTarget`).
- **wire** (VB1-VB4, WR1-WR4): the `health` and `element` verbs, `Env.Wire`, and `admin/wire`,
  which builds the real `System` and reads each part only when a verb needs it. `main` passes
  `wire.New`.
- **Round 1, finding 4**: `admin/execchild_os_test.go` runs the pipe as two real processes. As
  root, the test binary is re-executed as `ctl-child` under a scratch uid and gid, through
  `ExecChild{Runner: execx.OS{}}`. It checks three things:
  - one op is answered ok;
  - a child that floods stdout is drained and refused;
  - a stray variable or another working directory is refused by the child itself (78).

## Decisions

n2f-D1 to n2f-D12 are in [SPEC-n2f.md section 11](../SPEC-n2f.md#11-decisions-where-the-design-is-silent).
In short:

- **D1:** `main_room` travels in the answer.
- **D2:** the admin device is `TCADMIN`.
- **D3:** the pin file is strict JSON.
- **D4:** `CleanState` and the journal go through `execx`; everything else is D-Bus.
- **D5:** "no zone" is exit 2, and routes come from `/proc`.
- **D6:** backups answer none until C 3.12.
- **D7:** the LXC probe fails until C 3.9.2.
- **D8:** `element apply --consent`.
- **D9:** `health --all` or one team.
- **D10:** the op names.
- **D11:** the cgroup-placement rule.
- **D12:** the residual below.

## Owner residuals

- **n2f-D12 (decision for the owner, before the first install).** The admin token goes to
  whatever holds `127.0.0.1:<port>`. Only `team apply` (host steps 2 and 9) checks who holds the
  port. Every later child op, and the health view every 60 s, connects without checking. A
  process that binds the port while the server is down collects the token and gets full admin
  of the homeserver. The proposed fix is to serve the admin client over a unix socket that only
  the server and `teamchat-ctl` can reach, which removes the race. The other option, a holder
  check before each op, is racy. It is now a row in PLAN.md's Decisions table.
- Gates A and B still hold. Nothing here installs, and nothing gives a process a pool seat's
  password.
