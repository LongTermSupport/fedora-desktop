## What was built

`lxc.Guests.Probe(ctx, team, handle)` is the production `health.Guests`. It works in this
order:

1. Read the team's record (`lxcstate.ReadRecord` under `Guests.Root`). An unreadable record is
   an error.
2. `ByHandle` finds the entry that is not `left`. If no such entry exists:
   - a handle that only `left` entries hold is free (`GuestProbe{}`), and no container is
     asked;
   - a handle the record does not name, or a team with no record, is `Stopped`.
3. `Containers` failing is an error, because it is a host fault. A container that is not
   listed, a `State` that errors, or a state other than `RUNNING` (stopped, frozen, stopping)
   is `Stopped`.
4. `Pin` returning `ErrMoved` or `ErrGone` is `Stopped`. Any other pin error is an error. The
   root is closed after the probe, and a close error is joined into the result.
5. The guest's `/etc/passwd` is read through the root and checked by
   `guestfacts.Passwd(.., nil)`. Then `paths.LXCLayout(home, GuestRuntimeDir(k), k)` gives
   `.Seat(team).Lock()`, with `k = rec.SeatOf(e).Key()`, and `Root.ProbeLock` reads the lock.
6. The guest's own files decide these cases:
   - These are free with no record: a refusal (`refused()`, meaning `guestfacts.ErrRefused`,
     `guestroot.ErrRefused` or `ErrTooLarge`), an `fs.ErrNotExist`, no passwd, the user gone,
     a malformed passwd, a home that `LXCLayout` refuses, a link, a FIFO or a directory at
     `seat.lock`, and a link on the path.
   - A read error is `Stopped` when it is `ErrMoved` or `ErrGone`, or when `State` is no longer
     `RUNNING` afterwards. Any other read error is an error.
7. The answer is `GuestProbe{Held, Record}`. The record is the raw lock bytes in both states,
   so a torn record is passed up as it is.

The bound: `ProbeBound = 5 * time.Second` is applied as `context.WithTimeout` around the whole
probe. The probe runs in its own goroutine, so a read that ignores the context (a hung open)
still ends at the bound. A probe that passes the bound is an error wrapping
`context.Cause(ctx)`, as SPEC-n3 LP1 says ("past the bound a probe is an error"). The hung
goroutine finishes later on its own, and its answer is dropped. A probe that ends after its
context is done is reported as the error, never as a `Stopped`.

`health.probeGuests` runs one goroutine per LXC member (`sync.WaitGroup.Go`) and gathers the
results under a mutex. A team's probes therefore take as long as the slowest one, which is
5 s at most.

## The exported API as built (for r2c)

```go
package lxc

const ProbeBound = 5 * time.Second

type Guests struct {
	Root string // the host root ("" on a host) the records are read under
	LXC  interface {
		Containers(ctx context.Context) ([]string, error)
		State(ctx context.Context, c string) (lxccmd.State, error)
	}
	Pin func(ctx context.Context, container string) (Root, error)
}

func (g Guests) Probe(ctx context.Context, team paths.TeamID, handle string) (health.GuestProbe, error)
```

Two points differ from the brief:

- `Guests.Pin` returns `lxc.Root` (the interface), not `*guestroot.Root`, so r2c can give the
  same pin function to `Deps.Pin` and to `Guests.Pin`. `*guestroot.Root` satisfies `Root`.
- `lxccmd.LXC` satisfies the `LXC` field. For r2c's wiring in `admin/wire`, the health tick's
  `Guests: health.GuestsNotBuilt{}` becomes
  `lxc.Guests{Root: root, LXC: <lxccmd.LXC>, Pin: <the Deps pin>}`.

## Tests and coverage

`probe_test.go` has one test for each LP1 row:

- held, free with its record, a torn record, and no lock yet;
- a link, a FIFO and a directory at `seat.lock`, and a link on the path;
- stopped, frozen, stopping, missing, `State` failing, and `ErrMoved` or `ErrGone` at the pin;
- a handle the record does not name, and a team with no record;
- a handle only a `left` entry holds, which is free and asks no `State`;
- two seats of one user in one container, keyed per seat: only seat 2 is held;
- the guest user gone, a relative home, a user named twice, a malformed passwd, and no passwd;
- the container stopping mid-probe: the root gone at the passwd, the pin moved at the lock,
  and a read or lock fault once `State` is not `RUNNING`, each with the root closed once;
- host faults as errors: an unreadable record, the container list, the pin, and a read or lock
  fault in a running guest;
- the bound: the pin's context has a deadline, and `ProbeBound` is 5 s;
- probes that hang: one probe, and four in parallel, each blocked in `ProbeLock`, all return
  `context.Canceled` when the context ends.

The health package has `TestATeamsGuestProbesRunTogether`: four LXC members, and a fake whose
probes wait until all four have started. Run before the change, it failed (sequential, 30 s).
After the change it passes.

Results:

- The probe tests pass at `-count=30` under `-race`.
- golangci is clean on both packages, with and without `--build-tags tuwunel`.
- qa-changed is green before each commit.

## Decisions

- **The passwd answer, the home and an oversized lock are free, not errors.** They are guest
  content. LP1 says an error is only a fault of the host's own reads, and a refused open is
  free with no record.
- **`Containers` failing is an error, not `Stopped`.** It is the host's own `lxc-ls`/`lxc-info`
  fault, and it is the same rule as in `Restart`. It shows as each LXC member's "could not be
  probed" problem.
- **A `left`-only handle is free (`GuestProbe{}`), not `Stopped`.** That is the brief's rule
  ("a handle only `left` entries hold is free"). The tick may then ask for one `disconnected`
  for a run it saw held. A handle the record does not name stays `Stopped`, so nothing is
  asked for it.
- **No `host.Error` wrapping.** The probe is the health tick's, not a verb's. Its errors are
  `lxc: the probe of <handle>[ in <container>]: ...`.

Out of scope, as briefed: the admin verbs, the `admin/wire` wiring (`GuestsNotBuilt` is still
wired), and PLAN.md.
