- **exits**: B 2.2.4's table as data (`Table()`, `ExitOf`, `Classes`, `Class.Does`), `*Error`
  made only by `New(code, team, Template, fills...)`, the exit taken from the code's set.
  `Template` is a named string type, so a caller passes a constant; fills are `Name` (no space,
  quote or control), `Words`, `Description` (`proto.ValidDescription`), `Team`, `Count`, and
  `Format`/`Join` to compose a list. A failing fill shows `?`. `Write(stderr, err)` writes the
  object last (`kind`, `v`, `exit`, `code`, `team`, `message`); any other error gets one
  diagnostic line (controls as spaces) then an `internal` object. `Decode(line)` is the strict
  reader for n3b's TB2.4 parser: exactly the six keys, exit and code in the table and agreeing,
  team id or null, nothing of the line quoted in a refusal.
- **records**: every B 2.2.2 kind plus `team-failed` and `version` as typed structs, sealed by
  an unexported method; `Encode` splices `{"kind":..,"v":1,` before the marshalled body with
  HTML escaping off; `List[T]` encodes nil as `[]`; `History.Item` is a nested record (with its
  own kind and v); `More` always has `"team":null`. `WriteTeams` is CL4.
- **cli**: the verb table (`Verbs()`, `Usage(v)` generated from it), `Parse`, `ParseLaunch`,
  `ResolveTeam(flag, ledger *paths.TeamID, active []ActiveTeam)`, `Run(Env)`. Built: `version`,
  `help`, `--version`. `runs` and `unbuilt` are the dispatch maps.
- **kit**: `Assemble(into, kit paths.Kit, binary io.Reader)` and `Hooks`, `StatusLineRefresh`.
- **cmd/teamchat**: thin main, `var SourceDigest` by `-ldflags "-X main.SourceDigest=..."`. A
  `CGO_ENABLED=0` build prints its digest from `--version` and the record from `version`.

## Decisions, with proposed design text

01. **Error object key order** is `kind`, `v`, then `exit`, `code`, `team`, `message`, as every
    record (B's example has `v` first). Proposed B 2.2.2 text: the error example as
    `{"kind":"error","v":1,"exit":11,...}`.
02. **78 gains `launch`**: B 2.4.1 step 7 exits 78 `launch`, which B 2.2.4's 78 row does not
    list. Proposed: the 78 row's codes read `bundle, membership, store, forge-login, runtime, launch`, its meaning "(bundle, desired membership, store, launch)". The guest builder adds the
    GU2 check names and `identity` to the same row.
03. **75's class** is `ClassLifecycle` ("lifecycle verbs only"), B's `-`; `help exit-codes` shows it.
04. **All teams failed** in a multi-team verb: not partial (nothing succeeded), so the exit and
    object are the first failure's, with every `team-failed` record still printed. Proposed B
    2.2.3 sentence: "When every team fails, the verb exits with the first team's own error."
05. **ResolveTeam**: `--team` and a ledger team that differ is 64 `usage` ("the event named is in
    team U, not --team T"); no active team is 64 `usage` ("this session holds no team ...").
    B 2.4.1's "a verb that needs a team says that none is held" names no code; proposed: "exits
    64 `usage`". The flag is returned as given, not checked against the active set (the verb's
    own refusal).
06. **Value checks at parse time**: `--team`, `--user`, the directories, the integers, `--room`,
    reply's `--verb` (answer verbs only), `--branch`, the event id, `Q<n>`, the hook event. A
    failing value is never quoted. `--to`/`--asked-by`/`--re` are only checked as lists with no
    empty item; name resolution is the verbs' (n3d, n3f).
07. **`--kind` is required** by `run` (B 2.2.1's usage). B 2.1 (line 324) and B 2.14 (line 2127)
    write `teamchat run --plain -- bash` and `-- sleep` without it: proposed to add
    `--kind other` there.
08. **Claude's resume flags** checked only after the `claude` argument (`--resume`, `--continue`,
    `-r`, `-c`, and the `=` forms), so a wrapper's own `-c` (as `sh -c`) is not mistaken;
    `--settings`/`--plugin-dir` are refused anywhere in CMD, `=` forms included.
09. **`--seat T/S`**: T a team id, S a `paths.SeatName`; one seat per team.
10. **A bare ping** lists A 8.1's non-answer verbs (`check fetch halt review run-qa sync`) and
    points at `teamchat status`.
11. **`help`**: positionals joined, so `help seat set-aside` works; anything not a verb or
    `exit-codes` is 64.
12. **CL2's release test** is `member/cli/release_test.go` under `//go:build teamchatrelease`; it
    is red now (24 unbuilt verbs) by design. Task 3.3's build must run
    `go test -tags teamchatrelease ./internal/teamchat/member/cli/`.
13. **Kit**: `into` must exist, be empty, be the euid's and not group- or other-writable; it is
    set 0755. `plugin.json` holds `name` and `description` only (no version, since a kit path
    such as ccy's has no digest in it). The binary is capped at 256 MiB and must not be empty.
