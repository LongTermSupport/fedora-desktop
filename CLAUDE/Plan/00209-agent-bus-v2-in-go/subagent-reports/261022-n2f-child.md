# n2f part "child": the root/child trust boundary (SPEC-n2f EX, CS, CO, BU, HF)

Branch `feat/bus-v2-n2f-child`, packages `internal/execx` and `internal/teamchat/admin`. ctl, health
and host are untouched.

## What was built, with exact exported names

- **execx** (EX1-EX3): `Cmd.Credential *syscall.Credential`, `Cmd.CleanEnv bool`, and
  `execx.ErrBadCmd`. `ErrBadCmd` refuses CleanEnv with Unset, `NoSetGroups`, and a credential given
  to `Exec`. Every runner honours both fields: `OS.Run`, the session run and `Exec` (CleanEnv
  only). The `Fake` records the whole `Cmd` and refuses an `ErrBadCmd` command too. The real-child
  tests run `env`, and as root `cat /proc/self/status` for the uid, gid and groups (an empty list
  and a list of two). These tests ran as root here.
- **admin.ExecChild{Runner execx.Runner; Self string; Lookup func(string) (User, bool, error)}**
  is the `Child` (CS1-CS5). It uses `admin.SelfPath() (string, error)` (CS2), `admin.ErrChild`
  (CS4) and `capped` writers: the answer is capped at `maxAnswer`, stderr at 4096 bytes, and
  stderr appears only in the `ErrChild` text. A context that ends returns the context's error.
  Account failures are a new `configError`, which `ExitCodeOf` maps to 78.
- **The child's ops** (CO1-CO3, BU1): `admin.OpTeamView` and `admin.OpMemberDisconnected`.
  `Answer` gains `View *health.View`, `Notice *health.Notice` and `MainRoom string`. The view is
  validated as a `status.Record` built from it and passed to `status.Encode`, and `answerFits`
  decides which op may carry which field. `asked()` checks the main room and `answerFits`.
  `Serve` uses `openFailure` for the Opener's error on every op: an Opener refusal is 70,
  unreachable is 69, anything else 78 (ctl's n2f-C1).
- **admin.ChildViewer{Child; Root}** (health.Viewer) and **admin.ChildAnnouncer{Child; Root}**
  (health.Announcer), as CO4 specifies.
- **admin.SeatBundles{Clock func() time.Time; Digest paths.Digest}** (BU2). The `Bundles`
  interface is now `Bundle(ctx, team declare.Team, handle, mainRoom string, c apply.Credential)`.
- **admin.OwnerGroupFile(root, lookupGroup) func() (int, error)** (HF1),
  **admin.LookupGroup(name) (int, error)** (os/user, for the wiring), and
  **admin.ReadPin(root) (host.Pin, error)** (HF2). `team apply` checks Fedora first (HF3, 78).

## Decisions

| ID     | Decision                                                                                                                                                                                                                                                             |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| n2f-K1 | `Exec` refuses a `Credential`, because a replaced process keeps its own ids. It is refused, not ignored.                                                                                                                                                             |
| n2f-K2 | The child's answer must be one line ending in exactly one `\n`. Two answers, or no newline, is ErrChild.                                                                                                                                                             |
| n2f-K3 | team.view reads the roster and rooms the way `view.Load` does, through `viewInput`, with the team taken from the request's `team_file`. The child never reads root's team.json, and `view.Load` only takes a path, so the health package was left alone.             |
| n2f-K4 | On the wire, `notice` is `{"posted":bool,"why":string}` with both keys always present. When posted is true, why is `""`. When posted is false, why is one line.                                                                                                      |
| n2f-K5 | A view or notice answer carries no handle, credential or notes, and a failed answer carries none of view, notice or main_room. A view member may not carry `online` (that is root's to set). For validation, an LXC member's online is filled in as false.           |
| n2f-K6 | The guest token copy is `GuestDir/<handle>.token`, which is what apply writes. A copy that is not a valid token is config (78) and is never quoted. A missing rooms record, or one with no main room, is config.                                                     |
| n2f-K7 | HF3 uses `System.Host.Root`, so no new field was added. os-release is the one host file read that follows a link, because Fedora ships it as a link into `/usr/lib`. It must still be a regular file owned by root and not writable by group or other.               |
| n2f-K8 | Expected owner of the files root reads (`rootOwner`): uid 0 when Root is `""` (production). Under a test root it is the owner of the root directory. The exported HF1/HF2 readers always want uid 0, and their tests chown the files to check that when run as root. |
| n2f-K9 | Group names in the owner-group file must match `^[a-z_][a-z0-9_-]{0,31}$` (useradd's default rule).                                                                                                                                                                  |

## Design-text fixes proposed

- C 3.11 / health: when `ChildViewer` reports unreachable, it wraps `matrix.ErrUnreachable` as a
  sentinel. `matrix.Class` names only a `*matrix.Error`, so the record's problem text reads "not a
  homeserver answer". Health's `viewProblem` should check `errors.Is(err, matrix.ErrUnreachable)`
  before `matrix.Class`, or the child should send the class text.
- SPEC-n2f CO2 should say that a guest token copy is `<GuestDir>/<handle>.token`.
  `paths.GuestTokenCopy` takes a `SeatName`, which apply does not use.
