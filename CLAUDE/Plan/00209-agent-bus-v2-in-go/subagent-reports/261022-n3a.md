## What was built

The code is inert: nothing installs or runs it yet.

- **`cmd/teamchat`**: a thin `main` over `member/cli`.
- **`member/cli`**: the whole grammar, including value checks at parse time and `help` with
  `help exit-codes`. CL2's release test is `release_test.go` under `//go:build teamchatrelease`.
  It is red by design until every verb is built.
- **`member/exits`**: the exit codes, their classes and the error object. **`member/records`**:
  the record kinds.
- **`member/kit`**: the kit's layout. It has the plugin manifest and a binary cap.
- **`member/homefs`**: fd-rooted file access below a root the caller owns. It refuses links,
  other owners, FIFOs and files over their cap. Its operations are `Create`, `Replace`, `Read`,
  `MkdirAll`, `Sub`, `Entries`, `Unlink`, `Rename`, `RemoveTree`, `SameFile` and `OpenLock`.
- **`member/lock`**: the seat lock and the run lock.
  - LK1: the waits and their tries.
  - LK2: `AdoptSeat` refuses a description that is not the seat's own `seat.lock`.
  - LK3: `HoldSeat` for removals.
  - LK4: the lock record.
- **`member/state`**: MS1's member files and their codecs, and the store with its list caps
  (B 2.3.2).
  - The member files are session.json, keeper.json, report.json, status.json, session.pid,
    conversation.json and desired.json.
  - MS2's store writer refuses a seat directory whose `seat.lock` is not the held one, and a
    store of another team.
- **`member/bundle`**: MS3's `ReadPair`. It reads seat.json, then the token, then seat.json
  again, and retries once on a torn read. It refuses a password entry and checks against the
  store.
- **`member/guest`**: the guest operations.
  - GU1: identity and home.
  - GU2: `guest check`.
  - GU3: `guest place-bundle`, either a fresh seat placed by a renamed claim, or a seat replaced
    in place.
  - GU4: `guest membership`.
  - GU5: `guest remove`.
  - SA1: `seat set-aside`.
  - Each op has a registered op contract and a fixed set of CHANGED lines (TB2.4).
- **Smaller changes**: to `paths`, `seat` (`NewClaim` is exported), `health` and `reexec`, the
  helper re-run for the lock tests.

## Decisions, with the proposed design text

None of these are applied to the design chapters. Each is proposed here.

### CLI, exits, kit (cli part)

01. **Error object key order.** The order is `kind`, `v`, `exit`, `code`, `team`, `message`.
    - B 2.2.2: the example reads `{"kind":"error","v":1,"exit":11,...}`.
02. **The B 2.2.4 row for 78.** Its codes read: `bundle, membership, store, forge-login, runtime, launch, identity, home, gh, tmux, claude, kernel, reach`. Its meaning reads: "configuration
    refused (bundle, desired membership, store, launch, a guest's identity or check)".
    - `launch` comes from B 2.4.1 step 7. The guest codes come from guest-check decision 1.
03. **75's class** is lifecycle verbs only (B's `-`).
04. **When every team fails.** No team succeeded, so the result is not partial.
    - B 2.2.3: "When every team fails, the verb exits with the first team's own error."
05. **A verb that needs a team when none is held** exits 64 `usage`. So does a `--team` that
    differs from the ledger's team.
    - B 2.4.1: "exits 64 `usage`".
06. **Values are checked at parse time**, and a failing value is never quoted. `--to`,
    `--asked-by` and `--re` are checked only as lists with no empty item. The verbs resolve the
    names (n3d, n3f).
07. **`run` requires `--kind`.**
    - B 2.1 (line 324) and B 2.14 (line 2127) add `--kind other` to their `teamchat run --plain --`
      examples.
08. **Claude's resume flags** are checked only after the `claude` argument. `--settings` and
    `--plugin-dir` are refused anywhere in CMD.
09. **`--seat T/S`**: one seat per team. **A bare `ping`** lists A 8.1's verbs that are not answers.
    **`help`** joins its positional arguments.
10. **CL2.** The install build must run
    `go test -tags teamchatrelease ./internal/teamchat/member/cli/`. This is recorded in PLAN.md
    Task 3.3.
11. **Kit.**
    - `into` must exist, be empty, be the euid's, and be writable by neither group nor other. It
      is then set to 0755.
    - `plugin.json` holds only `name` and `description`.
    - The binary must not be empty and is capped at 256 MiB.

### Member files (codecs part)

1. **session.json.**
   - B 2.3.3: "Until the first SessionStart, `session_id`, `source`, `transcript`, `socket` and
     `claude` are all `null`; afterwards all are set. `source` is SessionStart's (`startup`,
     `resume`, `clear`, `compact`). `socket` is `cc-socks/<claude.pid>.sock`, at most 107 bytes.
     The file is at most 8 KiB."
2. **keeper.json.** `why` is set exactly when the keeper has `failed`. `next_ms` is set exactly
   when it is `restarting`.
   - "`session` is the session's name for kind `ccy` or `lxc`, and `null` for `host` and
     `other`."
3. **report.json.**
   - "`last_sync_ok_ms` is `null` until the first sync succeeds; `seat`'s `<seat>` is the
     handle's seat."
4. **status.json.**
   - B 2.9: "`failed` is `null` or the permanent failure that stopped the team (B17):
     `unauthorized` (401), `forbidden` (403), `trust`, `bundle`."
5. **session.pid.** `session` is `null`, or a process that is not the keeper. `kit` is a digest.
   `launch` is `claude` or `plain`.
6. **desired.json.**
   - B 2.3.3: "`seat` names a seat rule: a seat off A 2.3's grammar, a team twice in `seats`, a
     farewell twice, or a farewell for a seat still desired".
   - A farewell for the same team at another seat is allowed.
7. **Caps the design does not give.** The caps chosen are: session.json 8 KiB, report.json
   4 KiB, conversation.json 1 KiB, session.pid 1 KiB and desired.json 64 KiB. A test proves that
   the largest valid file fits under each.

### The store (state part)

1. **`gate.credit` is an integer.** It is `proto.Bucket`'s credit (P61).
   - B 2.3.2: the example reads `"credit": 540000`, with the line "`credit` is integer credit,
     one token being 60 000 (proto.Bucket, P61)".
2. **Member files go through `homefs`**, which checks the owner (TB4).
3. **Entry sizes.**
   - B 2.3.2: "The sizes assume ... user ids of at most 128 bytes (A4) and 13-digit times."
4. **The rooms and items.**
   - The store's rooms are main, reports and questions. n3f's side rooms will extend
     `storeRooms`.
   - The store's items are human, peer, ping, notice and timeout.
   - A TIMEOUT item's id is `proto.TimeoutKey`.
   - `fresh` is true exactly when `next_batch` is empty.

### Reading the pair (bundle part)

1. **The password entry.** MS3: "a password bundle (a `password` entry in the seat directory)".
2. **The token's mode.** B11: "mode 0600". The reader follows MS3, so a 0400 token is refused.
3. **The mismatch rule.** MS3: "whose `team` is not the directory it sits in, or whose `user_id`
   (and so seat) differs from the store's".
4. **No bundle yet.** No seat directory, or no seat.json, means no bundle yet
   (`fs.ErrNotExist`). A seat.json present with no token is 78 `bundle`.
5. **A store that does not decode** is 78 `store`.
6. **`ReadPair`** takes a root and a `paths.Seat`, so the read stays fd-rooted.
7. **An identity change** no longer pairs the old seat.json with the new token (review 1,
   finding 3). This replaces the part report's observation 7. A same-identity read between the
   renames still pairs the user's own old seat.json with the new token. That is the same
   account, so it is not a mismatch.

### The writer (writer part)

1. **`Load` refuses a store of another team** (code `seat`), as `Write` does.
   - MS2: "The writer refuses to write, and refuses to load, a store whose `team` is not its
     seat directory's name (code `seat`)."
2. **The writer refuses a seat directory whose `seat.lock` is not the held lock** (review 1,
   finding 1).
   - MS2: "the writer is given the seat lock of its own seat directory, and refuses any other".

### Guest check (guest-check part)

1. **78's guest codes.** These are in CLI decision 2.
   - B 2.13: "A caller that is not the user named is 78 `identity`. A home that is not the user's
     own is 78 `home`. Each guest check miss is 78 with the check's name."
2. **Set-id callers and the primary gid.**
   - GU1: "refuses uid 0, a set-id caller, a gid or supplementary group but the user's own ...".
3. **A stdin miss is 64 `usage`.** A bad `base_url` is 78 `reach`.
   - n3-D6: "a stdin that is not exactly this object, or names another team, is 64 `usage`".
4. **The program lookup.**
   - GU2: "the first executable regular file (links followed) of each name on exactly the unit's
     PATH".
5. **gh** runs at the path found, with only `PATH` and `HOME` set, and is stopped after 30 s.
   Its output is never shown.
6. **inotify** counts as usable when an instance and a watch on the home both work. **pidfd** is
   `pidfd_open(getpid())`.
7. **Ops.** Each op is registered in its own file. `Finish` turns an exit outside an op's
   contract into 1 `internal`.

### Guest place, membership, remove, set-aside (guest-place part, as amended by review)

1. **GU3 identity.** The identity is the same when seat.json decodes, in its pool or held form,
   to the same `team` and `user_id`. A missing seat.json, or one that does not decode, counts as
   another identity.
2. **GU3 refusal comes first** (review 2, finding 1). A seat.json or token that is a link, a
   FIFO, another uid's file or over its cap is refused as 78 `bundle`. The refusal comes before
   anything is set aside or unlinked.
   - GU3: "a seat.json or token that is not the user's regular file within its cap is refused
     (78 `bundle`) before anything changes".
3. **The order on an identity change** (review 1, finding 3). Under the seat hold, the store is
   set aside, the old seat.json is unlinked, the token is placed, and then seat.json is placed. A
   read between the renames therefore finds no bundle, never a mismatched pair.
   - GU3: "for another identity, unlink the old seat.json before the token is placed".
   - The CHANGED lines stay `store.json, token, seat.json`.
4. **An absent seat.**
   - Leftover `<team>.new-*` entries are removed first.
   - A fresh claim is filled with the token and then seat.json (`O_EXCL`, 0600), and renamed in
     with no replace.
   - `seat` is printed once.
   - The claim id comes from the exported `seat.NewClaim`.
5. **Replacement.** A file is replaced only where its bytes or its mode differ.
6. **Error mapping.**
   - An `ErrConfig` under the seats is 78 `bundle`, and under membership it is 78 `membership`.
   - A busy seat is 75 `seat-held`.
   - Any other I/O failure is 1 `internal` (see review 1, nit 8).
7. **GU5.** Every entry is listed first. Any directory in the seat refuses the whole removal.
   Links are unlinked, never followed.
8. **SA1.**
   - `--state` is opened `Private`, mode 0700 (review 1, finding 2; the part report said `Owned`).
   - A missing root, seat or store is a success that prints no line.
   - SA1: "without `--state`, the state root of the caller's home layout".

### homefs (review 1, nit 6)

1. **A failed `Create`** after the exclusive create unlinks the name, so no part-written file is
   left. The test needs no seam: it runs the create in a reexec child under a 4-byte
   `RLIMIT_FSIZE`, and Go ignores SIGXFSZ, so the write fails with EFBIG.
