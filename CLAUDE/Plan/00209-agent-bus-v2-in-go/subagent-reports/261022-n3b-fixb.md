## Decisions for the lead

- **B4 checkout grammar.** I did not use the unit's `[A-Za-z0-9/._-]` as the checkout grammar
  for every seat. gate_test pins `checkout=/srv/a,b=c` as valid, and DR4 says "on one line".
  So `ValidGuestPath` refuses control and format characters, and the unit's character set is
  enforced at declare for `service: true` seats only. DR4's wording ("on one line") is now
  stricter in code than in the spec; SPEC-n3 is not mine to edit.
- **B4 admin seat bound.** `admin/serve.go` and `admin/verbs.go` still have their own
  `maxSeat = 9999`, for a request's seat. That is review A's area, and the change is not a
  one-line call change, so it is left as it was.
- **B5 scope.** Reads are bounded. Writes (Writer) and `InitExe` (a host /proc path) run through
  `live`, unbounded but counted in flight. A write follows reads of the same root that passed
  their bounds. An abandoned read's own result is dropped, since it was already answered as
  stalled. Its cleanup error, and a deferred release's, join the next Close; one that comes
  after Close is lost (documented on `bounded`).
- **B5 stall in apply.** A stall on a container-wide file (passwd) fails each live seat of that
  container as refused, through `readsFailed`. A stall on a checkout file fails the seats on
  that checkout. Neither stalls the phase.
