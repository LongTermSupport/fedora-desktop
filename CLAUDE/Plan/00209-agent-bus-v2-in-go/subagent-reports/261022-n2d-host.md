## What was built

All in `src-go/internal/teamchat/host` (inert: nothing installs, runs as root or is started):

- `lock.go`: the team lock (C 3.4).
- `render.go`: config.toml, the drop-in, team.json and the two digest sets (C 3.2.3, 3.2.4).
- `records.go`: units.json, firewall.json and the stamp, each encoded and read back strictly.
- `apply.go`: `Apply`, `team apply`'s steps 1-9 and 11 (C 3.5.2). Step 10 is `Deps.Bootstrap`.
- `remove.go`: `Remove`, `team remove [--purge]` (C 3.5.3).
- `dirs.go`: directory and create-only helpers. Every directory root makes gets its mode set by
  a chmod after the mkdir, so the umask never decides it (tested under umask 077).
- `paths/host.go`: the host names (`UnitsRecord`, `ServerNameFile`, `ServerDropInFile`,
  `ServerUnitTemplateFile`, `HomeserverDatabase`, `HomeserverBackups`,
  `HomeserverPrivateDatabase`).

Every host effect is a seam. Plays, the units' base files, sudoers, install, seats, passwords,
health, status records, backups and Element profiles are not built here.

## The exported API the lead calls

```go
func Apply(ctx context.Context, d Deps, in declare.Input) ([]string, error)
func Remove(ctx context.Context, d Deps, team paths.TeamID, purge bool) ([]string, error)
func TakeLock(ctx context.Context, dir string, team paths.TeamID, verb string, wait time.Duration, clock Clock) (*Lock, error)
func (l *Lock) Release() error
func (l *Lock) Team() paths.TeamID
func SystemClock() Clock
const PlayWait = 10 * time.Minute

type Deps struct {
	Root, LockDir  string            // Root "" on a host; LockDir paths.AdminRunDir
	LockWait       time.Duration     // PlayWait from a play, 0 for a person's verb
	Clock          Clock             // Now(); Sleep(ctx, d) error
	Rand           io.Reader         // crypto/rand.Reader: the first apply's registration key
	Pin            Pin               // {Version paths.ServerVersion; MemoryHigh, CacheCapacityModifier string}
	Software       string            // the stamp's software digest
	CtlUID, CtlGID int               // teamchat-ctl, owner of ctl/<team>/
	Approvals      declare.Approvals // declare.FileApprovals on a host
	Systemd        Systemd           // DaemonReload, Start, Restart, Stop, Enable, Disable, State, JournalTail, CleanState
	Firewall       Firewall          // Zone(source), Query/Add/Remove(permanent, Rule)
	Network        Network           // Interfaces(), Listeners() (/proc/net/tcp{,6} with unit), Bridge()
	Ready          Readiness         // ServerVersion(ctx, port): /_tuwunel/server_version on loopback
	Status         Status            // Refresh(ctx, team, first); Remove(ctx, team) (line, error)
	Backup         func(ctx context.Context, held *Lock) error
	Bootstrap      func(ctx context.Context, b Bootstrap) ([]string, error) // step 10, in the child
}
type Bootstrap struct { Input declare.Input; TeamFile []byte; RegKey string }
type UnitState struct { Active string; Enabled bool }
type Rule struct { Zone string; Source netip.Prefix; Port int } // Rich(), String()
type Interface struct { Name string; Addrs []netip.Addr }
type Listener struct { Addr netip.AddrPort; Unit string }
```

Remove uses only Root, LockDir, LockWait, Clock, Systemd, Firewall and Status.
`Status.Remove` keeps a migration-origin record's pointer, and answers "" when there is nothing
left to remove. `Status.Refresh`'s `first` is true when no stamp existed before this apply.

### Errors and exit codes

Each verb returns its CHANGED lines, including those printed before a failure (Bootstrap's
too). It fails with `*host.Error{Verb, Step, Drift, Err}`, printed as
`team apply, step <step>: <err>` (or `team remove, ...`), and `Unwrap` reaches `Err`. Map them in
this order:

1. **75**: `errors.As(err, **host.BusyError)`. The lock was busy. `BusyError{Path, Holder}`
   names the holder line `<verb> <team> pid=<n> since=<ms>`. Its step is `lock`.
2. **70**: `*host.Error` with `Drift` true. A step 2 refusal: the server_name, the approval
   gate, the listen interfaces, or the port. Only `refusals` sets Drift.
3. If the lead's Bootstrap returns its own typed errors (for example drift from the child),
   find them with `errors.As` through the `bootstrap` step's Error before this fallback.
4. **1**: every other error.

Steps: `lock`, `installed` (remove only), `refusals`, `render`, `files`, `firewall`, `backup`,
`unit`, `ready`, `addresses`, `bootstrap`, `records`, `status` (remove), `purge` (remove).

## Decisions

n2d-H1 to n2d-H16 are in SPEC-n2d.md section 4. This session added:

- **H12**: every directory gets a chmod after its mkdir, so the umask cannot decide the mode.
- **H13**: "not installed" means none of root/<team>/, ctl/<team>/, the drop-in or the stamp
  exists. It is checked under the lock, as a step of its own.
- **H14**: the drop-in directory is deleted only when it is empty.
- **H15**: `--purge` also deletes approved.json, and deletes root/<team>/ last.
- **H16**: `systemctl clean` runs only when the private state directory exists.

## Design-text fixes proposed

- C 3.5.2 step 4 says "the registration secret (3.2.2)", while 3.2.2 says the secret lives only
  in config.toml, which is written in step 7. It should say that step 4 creates config.toml (with
  its new key) by link, beside server-name.
- C 3.5.3 should list approved.json among what `--purge` removes. It should also say that the
  status directory stays, because a migration-origin record keeps its pointer there.
- C 3.5.3 should say the drop-in directory is removed only when empty, because an owner's own
  override in `<unit>.d/` is not the verb's to delete.
- C 3.2.2 should say that the 0755 and 0700 directory modes are set whatever the umask, since a
  `sudo` shell with umask 077 would otherwise make the drop-in and status directories 0700.
- C 3.5.3 should define "not installed" (H13). The play relies on it being a silent success.
