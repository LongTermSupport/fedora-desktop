# N2: one team lock, `teamchat/teamlock`

Branch `feat/bus-v2-n2`, from b5c40f72. The port plan was "Unify with host/lock.go" in
`261022-n2e.md`, and its 7 steps were the contract. Reviews: `261022-n2-lock-review.md`
(round 1, MERGE) and `261022-n2-lock-review-2.md` (round 2, MERGE).

## What changed

- `src-go/internal/teamchat/teamlock/teamlock.go` is now n2d's design with teamlock's holder
  hygiene:
  - `Take(ctx, dir, team, verb, wait, clock)`, `(*Lock).Team` and `(*Lock).Release`, which
    clears the holder line and keeps the file;
  - `BusyError{Path, Holder}`, whose `Is` makes it `ErrBusy`;
  - its own `Clock` interface (`Now`, `Sleep`) and `SystemClock`;
  - the verb regex `^[a-z][a-z.-]{0,31}$`;
  - the sanitised holder read: one printable line of at most 256 bytes, else "an unreadable
    holder".
- Lock directory, with the new owner check. It is made 0700 when missing, then opened
  `O_DIRECTORY|O_NOFOLLOW` and checked through that descriptor (`Fstat`): the mode must be
  exactly 0700 and the uid must equal the euid. The lock file is `openat`'d relative to the
  same descriptor and must be a regular file. Checking and opening through one descriptor
  removes the TOCTOU window that the old `Lstat` and `Join` pair had.
- From the review:
  - an ended ctx takes no lock, even a free one;
  - the busy error is the `*BusyError` itself, not wrapped by a nil-close join;
  - the holder line is written over the old one and then cut to length.
- Callers ported:
  - `host/apply.go` and `host/remove.go` call `teamlock.Take`, and `Deps.Backup` takes a
    `*teamlock.Lock`. `host.PlayWait` and `host.Clock` (a structural `teamlock.Clock`, also
    used for the readiness wait) move into `apply.go`, along with the package doc.
  - `admin/verbs.go` calls `teamlock.Take` with `admin.SeatWait`. `admin/exit.go` maps
    `errors.Is(err, teamlock.ErrBusy)` to exit 75.
  - In health, `Locks` is now `TryLock(ctx, team) (Releaser, error)`, and `Releaser` is
    `{ Release() error }`. `TeamLocks` is `{Dir, Clock}`, and its `TryLock` calls
    `teamlock.Take(ctx, Dir, team, "health", 0, Clock)`. `probe.go` and `health.go` call
    `Release`.
- Tests:
  - `host/lock_test.go` moved into `teamlock_test.go`, and teamlock's earlier tests stay there:
    the link refusal, the bounded and unprintable holder, and the bad verb.
  - New: the owner check, through the `take(..., euid)` seam and through a real chown to
    65534 (the tests run as root); `errors.Is(ErrBusy)` and the unwrapped busy error; a FIFO
    refused; an ended ctx on a free lock; a stale longer line replaced; and every refusal
    checked for its reason.
  - Host's shared test helpers (`fakeClock`, `mustTeam`, `readFile`, `releaseOrFail`) moved
    into `host/fakes_test.go`.
- `host/lock.go` and `host/lock_test.go` are deleted. A grep finds one team-lock
  implementation. The other flocks in `teamchat/seat` are the allocation lock and the seat
  lock, which are different locks (C 3.4).
- Spec: SPEC-n2e TL1 is rewritten (Take, the wait, the directory rule, `Release`). SPEC-n2d HS1
  and HS2 now point at TL1 and keep only what host owns: the verbs, `LockWait`, and step `lock`
  with exit 75. The PLAN Task 2.4 line says the lock is one package, and the slice n2d line
  says HS1-HS15.

## Decisions

- **D1. Check and open through the directory descriptor.** n2d used `Lstat` followed by an
  open by path. This version opens the directory once with `O_NOFOLLOW`, checks it with
  `Fstat`, and then uses `openat`, so the directory that was checked is the one the file is
  opened in.
- **D2. The lock file must be a regular file.** Only root can place a FIFO or a device in a
  0700 directory that root owns, but refusing them costs one `Stat`.
- **D3. The owner check is tested two ways.** An unexported `take(..., euid)` checks the real
  `Fstat` uid against an euid that does not match. A real chown test, which needs root and is
  skipped otherwise, covers the `Geteuid` wiring.
- **D4. `health.Unlocker` is now `health.Releaser`,** so that the interface is named after its
  method, `Release`.
- **D5. `host.Clock` stays as host's own interface** and is not an alias. It also serves the
  readiness wait, and `teamlock.Clock` accepts it structurally, as step 1 of the port plan said.
- **D6. The holder line is written first, then cut** to its length (round 1, finding 3). A
  crashed holder's line is never emptied before the new one is in. A waiter in that short
  window may still name the line it read. TL1 says so.

## Open, and the design-text fixes proposed

- **Round 1, finding 1 (minor, deploy slice):** nothing provisions `/run/teamchat-admin`. The
  sandboxed health and backup units (`ProtectSystem=strict`, with
  `ReadWritePaths=/run/teamchat-admin` and no `-` prefix) cannot start after a reboot until
  some root verb has made the directory. Proposed fix: the play ships the `tmpfiles.d` line
  `d /run/teamchat-admin 0700 root root -` (C 3.5.1 static tasks), and C 3.4 and TL1 say so.
  The mode must be 0700 root:root, or every verb fails at `lock`.
- **Round 2, finding 2 (low, accepted):** `TestTakeReplacesAStaleLongerLine` pins only the
  final contents of the file. It cannot pin the moment between the write and the cut, which
  is too short to test reliably.
