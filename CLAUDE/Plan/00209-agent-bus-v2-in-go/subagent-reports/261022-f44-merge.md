## Conflicts and how each was resolved

### `src-go/internal/execx` (exec.go, execx.go, session.go)

- **Ours (n2f):** `Cmd.Credential` and `Cmd.CleanEnv`, `check()` (ErrBadCmd), `environ()` and
  `sysProcAttr(setsid)`.
- **Theirs (Plan 00191 Task 4.5, commits 7c09e65f9..320e44b4f):** `Cmd.Secrets` and `Cmd.Feed`
  (secret.go: `checkSecrets`, `refuseFeed`, `fed`, `childEnv`), plus a new runner, `Foreground`
  (foreground.go).

Both sides compute the child's environment, so there is now one function for it. `childEnv`
(secret.go) also handles CleanEnv: with CleanEnv the result is `ChildEnv(nil, Env+Secrets, nil)`,
so the base is nothing of the parent's, the secrets are kept, and an empty Env gives an empty
environment that is not nil. `environ()` is gone, and all four call sites use `childEnv`. Duplicate
names in a CleanEnv `Env` now resolve to the last one, as they already do everywhere else.

Every runner now runs both checks:

- `OS.Run`: `errors.Join(c.check(), c.checkSecrets())`, then `fed()`.
- `Fake.Run`: `errors.Join(c.check(), c.checkSecrets())`.
- `OS.Exec`: `errors.Join(c.check(), c.checkSecrets(), c.refuseFeed())`, then the Credential refusal.

The rest of this section is a change outside the conflict hunks. F44's `Foreground` (`OS` and
`Fake`) did not know about Credential or CleanEnv. Merged as it was, it would have silently
ignored a credential and run the child as the parent. It now calls `c.check()` and sets
`cmd.SysProcAttr = c.sysProcAttr(false)`, so the child keeps the terminal's process group. CleanEnv
reaches it through `childEnv`. Two tests cover this in credential_test.go:

- `TestCleanEnvBesideUnsetIsRefused` now also covers `foreground` and `fake foreground`.
- `TestCleanEnvKeepsSecrets` is new: the env under CleanEnv is exactly Env plus the secret.

The Cmd doc comment for CleanEnv now names Secrets.
