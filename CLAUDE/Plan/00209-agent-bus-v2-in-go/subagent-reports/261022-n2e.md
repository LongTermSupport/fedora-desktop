## Decisions

From handoffs 1 and 2, kept:

- A unit state that cannot be read is a problem, with `unit` recorded as `inactive` and `probe`
  as `not-run`; it does not fail the tick. A state that cannot be read during the re-probes
  counts as an answer: there is no restart, and the probe is recorded as `missed`.
- A broken `lxc-online.json` fails that team's tick (fail fast); nothing rewrites it. A dropped
  view (busy lock, changed seq, stamp gone) skips step 6 too.
- A problem never carries an error's text. The error goes to the outcome, and from there to the
  journal.
- An LXC entry: the ended run of a parked member is settled without asking. A launch failure
  settles the entry when the failed run is the entry's own.
- `Team.Origin` is used only when there is no earlier record.
- The view reads `team.json` as well. A missing roster or rooms record is empty. A member-written
  `m.room.member` event that is not one of the five memberships is skipped.
- Pending-op fixes, the questions-room form, the coordinator fixes and the `notice` scan are as
  handoff 2 records them. A 429 is transient. At `until_ms` the announcer is not asked again.

From handoff 3: Holdings, the sweep, Element (`Env`, consent, launcher), `matrix.Class`, HT3's fix,
and a restart whose post-restart state cannot be read keeping the pre-restart state.

From the review fixes:

- **n2e-D11, Viewer classes (round 2, finding 2).** The `Viewer` seam classes its failure.
  `health.ErrViewFiles` covers the team's own files, and `view.Load` wraps every failure in it;
  the fix is "apply the team again (`playbooks/imports/play-teamchat.yml`)".
  `health.ErrViewChild` covers a child that failed or did not answer; the fix is
  `teamchat-admin health`. Only other failures are `matrix.Class` with the homeserver's fix. The
  child adapter that n2a-D6 is waiting for must map its failures onto these two.
- **n2e-D12, a re-probe that stops records the state it read (round 2, finding 3).** This applies
  to a unit no longer active, or to a new invocation. If the unit is not active, the problem is
  "the homeserver unit is <state>". A restart between the two reads is recorded as its event.
- **n2e-D13, `Units.Restart` returns when the restart job is done (round 2, finding 4).** Done
  means D-Bus `JobRemoved` with result `done`; any other result is an error. The DC17 adapter
  must be built to this. A state that cannot be read after the restart is the problem "the
  homeserver unit's state cannot be read after its restart", and the record keeps the
  pre-restart state.
- **n2e-D14, a release's give-up keeps `until_ms` (round 2, finding 1).** A release retried after
  it, because its retire failed, gives the notice up again whatever run the member's lock names,
  so a new run id cannot restart NT3's bound. The crashed-session path's give-up keeps
  `until_ms` 0, so a later run's crash is asked its own notice. Both cases are pinned by tests,
  and the second test was seen red with the gate removed.
- **`paths.IsClaimName` (round 1, finding 8).** It is the one test for a claim's name, used by
  `ParseSeatName` and by `seat.Holdings`.

## Residuals (accepted, no fix on this branch)

- A member that rewrites a valid run id in the free lock of a kept seat makes `Announce` post
  again for each new run. It posts as itself, which it could do with its own token anyway, so
  nothing is gained across a trust boundary.
- The round-1 tests were judged red by the round-2 reviewer from reading the code, not by
  reverting. The four round-2 tests in this report were each seen red.

## Unify with host/lock.go

Slice n2d built a second team lock, `src-go/internal/teamchat/host/lock.go` on
`feat/bus-v2-n2d`. This branch has `src-go/internal/teamchat/teamlock`. Both lock the same file
(`/run/teamchat-admin/team-<team>.lock`), so they interoperate on disk. They differ like this:

| Point            | `teamlock` (n2e)                                                            | `host/lock.go` (n2d)                                                                                     |
| ---------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Wait             | none (`TryLock`)                                                            | bounded by `wait` on an injected `Clock`, ctx-cancellable; `wait` 0 is a try (C 3.4: 60 s, 10 min, none) |
| Path             | the caller passes the file                                                  | derived from `dir` and the team (`paths.TeamLock`'s base name)                                           |
| Lock directory   | not checked                                                                 | made 0700 if missing; a link, a non-directory or another mode is refused (C 3.4's "0700 root directory") |
| Holder line      | `Holder{Verb, Team, PID, Since}`, verb `^[a-z][a-z.-]{0,31}$`, PID injected | verb is one printable word, PID is `os.Getpid()`, since is from the clock                                |
| Busy holder read | one printable line of at most 256 bytes, else "an unreadable holder"        | the first line of up to 512 bytes, raw                                                                   |
| Busy error       | `*BusyError{Holder}`, `errors.Is(err, ErrBusy)`                             | `*BusyError{Path, Holder}`, no sentinel; `admin/exit.go` uses `errors.AsType`                            |
| Release          | `Unlock`: flock off, close                                                  | `Release`: truncate the holder line, flock off, close                                                    |
| Callers          | `health` (the tick's restart and record write)                              | `host` apply and remove, `admin` member verbs, `admin/exit.go` exit 75                                   |

**Survivor: n2d's design, in the `teamlock` package, with teamlock's holder hygiene folded in.**
n2d's design is the superset that C 3.4 needs. Waits are bounded per caller, the 0700 directory
rule is enforced, the path comes from the team so no caller can name another file, and a released
lock leaves no stale holder line. The health tick's no-wait take is the same call with `wait` 0.
The package must be `teamlock`, not `host`. Otherwise `health`, and later the backup timer and
the LXC apply, would import `team apply`'s host steps just to take a lock. From `teamlock` keep:

- the `ErrBusy` sentinel through `BusyError.Is`, so callers test with `errors.Is`;
- the sanitised holder read: one printable line of at most 256 bytes, else "an unreadable
  holder". The line reaches a terminal and the journal, so raw bytes must never be printed;
- the verb grammar regex.

Also add an owner check to the directory (`Stat_t.Uid` equal to the euid). n2d checks the mode
but not the owner.
