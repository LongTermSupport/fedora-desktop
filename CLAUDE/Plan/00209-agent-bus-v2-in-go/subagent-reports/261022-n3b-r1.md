## guestroot RemoveTree flake: not reproduced, cause not proven

`TestEveryFailingCallFailsItsOperationAndLeaksNothing/RemoveTree` did not fail in four full
`go test -race ./internal/teamchat/...` runs, or in 60 iterations of the sweep beside a loop
renaming files. The reported symptom (EIO, then index out of range at `rec.calls[i]` in
`failOne`) means a faulted run made fewer calls than the counting run, so call `i` was never
made and the op succeeded. The sweep assumes a run's call count is deterministic. The production
code breaks that on purpose: `openBelow` retries a real `EAGAIN` up to `openTries` times, and the
read, write, getdents and poll loops retry a real `EINTR`. Each retry is a recorded call. The
EIO is consistent with this: the recorder stays armed, so the cleanup's `Close` made the call
numbered `i` and got EIO. The kernel gives openat2's EAGAIN only for `..` under a scoped
resolve, which these paths do not have, so EINTR under load is the likelier source. That is not
proven. The proposed fix, test-only: the recorder retries a real (not injected) EAGAIN or EINTR
itself before counting, so the sweep's count is deterministic. The production retry stays
covered by `read_test.go`'s injected-EAGAIN test. Not applied, because it is unproven and the
package belongs to its owner.
