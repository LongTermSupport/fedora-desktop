## What was built

- **Room facts** (`teamsync/facts.go`). `readFacts(state, roster, anchors)` gives the main room's
  colour (`proto.MainColour`), description (`proto.MainDescription`) and coordinator (the
  roster's non-parked coordinator's handle), and a note. `Team.setFacts` puts them in `Health`
  when they change and logs the note once per change of the note: a malformed or non-admin colour
  is one link.log line and the team stays trusted. `verify` reads them at each verification
  (`mainState`, then `setFacts`); a colour or topic event in the timeline already triggers
  verification (n3e-3's `StateTypes`).
- **Delivery budget** (`teamsync/budget.go`, hunks in `session.go`). An agent sender's
  (coordinator, worker or probe) PEER, PING or NOTICE that is not carried is budgeted:
  deliver_per_sender items per `proto.DeliveryKey(team, sender)` per `proto.DeliveryWindowMs`.
  An item over the budget adds one to `Batch.HeldBack[sender]` and never enters pending. The
  window is committed with the batch, as `flood` is. Humans and carried NOTICEs are never held; a
  discarded answer counts nothing (T19).
- **Read receipts.** teamsync runs one sender goroutine per session, on the session's client;
  a stopped team runs no session, so sends nothing. Transient failures back off as SY8 does (1 s
  doubling to 30 s, jittered); a 401 ends the sender until the next session; a 404, a 403 or a
  room the roster does not name is dropped through `ReceiptSent` with one line. The engine keeps
  the receipts in the store (`PendingReceipts`, `ReceiptSent`, one store write each) and closes
  the change channel when the store's receipts change (`changeLocked`) or at a removal.
- **status.json pacing** (`engine/statuspace.go`, SL1, T12, OF1). `publish` builds the status
  (`buildStatus`, which also sends each changed keeper report as before) and offers it. A
  change is written at once when the last write is at least 1 s old on the boot clock, or none
  was made; otherwise it is owed, and the newest status is written at last write + 1 s. A status
  equal to the last written one (`reflect.DeepEqual`, `written_ms` left zero) writes nothing.
  While a team is held and not removed (a refused add does not count), the file is rewritten
  60 s after each write with a fresh `written_ms`, also for a team stopped on a permanent
  failure. With no team it is written once at `Run`'s start and then only on a change. A failed
  write is logged and not retried at once; the minute's refresh retries it.
- **Inbox test fix** (`member/inbox/phase_test.go`, n3e-1's file, own hunk):
  `TestAnAuthLineNobodyReadsIsRetry` could hang under one shuffle seed; `expireUntil` advances
  until Dial answers.
- **Test harness changes** for the status timer. `world.status()` flushes an owed write first
  (`flushStatus`), so tests that read status right after several changes stay valid;
  `statusFile()` reads it as the pacing left it. `world.armed(n)` waits for n waiters plus the
  status timer when it is armed; the three engine tests that waited for exactly one waiter use
  it. The link's `TestReadyWaitsTenSecondsForTheAdds` waits for two waiters (the adds' wait and
  the status timer). `linkWorld.start`'s cleanup now waits for the link to end: the engine's
  first write at `Run` could land in the test's home while `TempDir` removed it.

## API as built (for n3e-9 and n3e-10)

```go
// team
type Receipts interface {
	PendingReceipts(t paths.TeamID) (rs []state.Receipt, changed <-chan struct{})
	ReceiptSent(ctx context.Context, t paths.TeamID, id string) error
}
// teamsync
type Config struct{ …; Receipts team.Receipts } // nil sends none
// engine
type TeamConfig struct{ …; Receipts team.Receipts } // the engine passes itself in Add
func (e *Engine) PendingReceipts(t paths.TeamID) ([]state.Receipt, <-chan struct{}) // not held: nil, nil
func (e *Engine) ReceiptSent(ctx context.Context, t paths.TeamID, id string) error  // ErrRemoved after a removal
```

n3e-9 adds a receipt at proof with `state.Store.AddReceipt` inside an `e.change`; the
`changeLocked` hunk wakes the sender. status.json pacing has no exported API: every existing
`e.publish()` call is paced, and nothing else needs to change. A test that counts the fake
clock's waiters in a world with a held team must count the one status timer (`world.armed`).

## Decisions

- **D1** (first builder). Engine receipts live in `engine/receipts.go`. The brief's
  `engine/facts.go` is not needed: n3e-3 already fills `Member`/`Colour` in `statusRow`, and
  teamsync supplies `Health.Colour`.
- **D2** (first builder). The budget is in a new `teamsync/budget.go`, not named in the brief,
  with hunks in `session.go`'s `take`, `judged`, `commit` and `empty`.
- **D3** (first builder). The receipt sender is scoped to a session: it starts before `poll`
  and ends with the session, so "nothing when stopped" holds by construction and the sender
  always uses the session's own client.
- **D4** (first builder). A 404, a 403, or a receipt for a room the roster does not name is
  dropped through `ReceiptSent`, with one line, because a retry could never succeed. A 401 waits
  for the next session.
- **D5** (first builder). The facts note is logged once per change of the note, not once per
  verification, which gives C9's "one link.log line" for each bad state seen.
- **D6** (second builder). One status timer at a time, for the owed write or else the heartbeat,
  re-armed only when its due time changes. With two timers the fake clock's waiter count would
  vary between one and two, and the tests that wait on that count could not be made exact.
- **D7** (second builder). The timer's fire runs on the state goroutine through `onGoroutine`
  (the `do` without a request's context) and a generation counter ignores a stale fire. A
  `context.Background()` there is refused by contextcheck through every caller of `publish`;
  a fire after the goroutine ended runs nothing. On the fake clock the write is made inside
  `Advance`, so the tests are deterministic.
- **D8** (second builder). An owed or heartbeat write rebuilds the status as it is at the fire
  instead of writing a stored copy, so the newest state is always the one written.
- **D9** (second builder). The drafted tests were moved in unchanged. None was wrong; they are
  in `statuspace_test.go` (renamed from `pace`, because the delivery loop already has a
  `paceRetry`). Two tests were added: a failed write is logged once and the minute's refresh
  writes it, and a timer after the end runs nothing. `TestStatusJSONThatCannotBeWrittenIsLogged`
  was made exact: it waits for `Run`'s first write, changes the desired state (setting it to
  `applied` again is no change, so nothing is written), and advances past the second.
- **D10** (second builder). The link test world's cleanup waits for the link to end. This fixes
  a race the pacing exposed, in the test harness only: the engine now writes status.json at
  `Run`'s start, and the cleanup used to close the control socket and leave the link running
  while `TempDir` removed the home.
