## The declines and gaps

1. **A12's test was green before its fix: accepted.** A12 was a test gap. The code was already
   bounded. `TestProbesThatHangEndAtTheirOwnBound` uses no cancellation, and `release` is only
   closed at cleanup. A `Probe` that waited for the hung read would therefore hang the test, so
   the test would catch a regression. It does not assert the elapsed time, as the review
   proposed, but the hang serves the same purpose.
2. **A14 has no test: accepted (nit).** The change is a `defer`. The fakes cannot plant a
   `Release` error. A one-line deferred release with its error kept is safe to take on reading.
3. **The stage-enum simplification was declined: accepted for this slice.** It is not
   defect-bearing on its own, now that A3 and A8 are fixed with tests. It should be recorded as
   a follow-up task in the plan, so it is not lost in a report. The next defect in
   `fail`/`offline`/`settle` will come from the same ten flags.
4. **InitExe stays unbounded: accepted.** It opens the host's `/proc/<pid>/exe` with `O_PATH`
   and fstats it. The binary is the container's init, on a rootfs the host set up. No mount
   that a guest makes after boot lies on that path.
5. **The admin seat-bound test could not be red: accepted.** It is a pure refactor between two
   equal constants. The tests are keyed to `paths.MaxLXCSeat`, so a later drift fails them.

## Leak and isolation check for the bounded calls

- **No leak outlives the process.** A call abandoned at `callBound` (10 s) holds two goroutines
  (the op and its waiter), the fd it opened, and the root fd and pidfd (`Close` defers
  `release` while `inflight > 0`). It holds them until the syscall returns or the process exits.
  No long-lived process holds a `Root`. `lxc apply` and `lxc restart` are CLI runs, and
  `health` runs from `teamchat-health.timer`. A FUSE wait is killable, so the process exits
  normally. The count is bounded by the calls made on a stalled root in one run.
- **No fd-number reuse.** `enter`/`leave` count calls in flight, and only the last `leave` on a
  closed root releases the fds. The late result of `DialSocket` is closed. The late op returns
  its value instead of writing a captured variable, so it cannot race the caller.
- **Isolation holds.** A stall is `ErrRefused`. `readsFailed` and `member` fail that container's
  seats (passwd), or that one seat (a checkout file), as refused. The other containers go on, and
  so does the phase. In the probe, the outer 5 s bound fires first, so a stall is that member's
  "could not be probed" problem.
- **The cost.** A stall on a shared checkout is paid again for every seat on that checkout.
  `member` refuses the seat and the next seat reads the same file (see R2-3).

## New findings

### R2-1 (major): any guest user can fail every seat of its container with an errno that is not TB1's

`pathError` (`guestroot/read.go:217`) makes only ELOOP, ENOTDIR and EXDEV refusals, and B1 added
EWOULDBLOCK on the reopen. Every other errno from an open, fstat or read below the guest root
(EACCES, EIO, ENXIO, and so on) is a plain error, and the callers treat it as a host fault.

Scenario: the guest has `fusermount` setuid, which is the normal state wherever fuse3 is
installed. A non-root guest user, not on any team, mounts a FUSE filesystem without
`allow_other` on a directory it owns: `/run/user/<uid>/teamchat/run`. Host root then gets
EACCES there (`fuse_allow_current_process`).

- A2 now lists that uid. `runsOf` returns the EACCES. `sweepKits` returns it, and `placeKit`
  (`kit.go:121`) calls `r.step` for **every live seat of the container**. Each one fails at
  `kit` on every run for as long as the mount stays.
- A team member can do the same over its own checkout's `.git`. `member` returns the error,
  because it is not refused, and `readsFailed` (`apply.go:~647`) fails **every seat in the
  container** as a host fault.

This is B1's class: one guest user fails its neighbours. It breaks the owner rule, under which a
member with wrong facts fails that member alone.

**Fix:**

1. In guestroot, classify by origin, not by errno. Any error from a call below a live root is
   the guest's (`ErrRefused`, or a new `ErrGuest` that wraps it). The exceptions are the errnos
   that are the host's: EMFILE, ENFILE, ENOMEM, and EBADF/EINVAL as programming faults.
   `pathError` and `reopenFD` are the two places.
2. Add a test with a fake `sys` that returns EACCES and EIO from `openat2` and from `getdents`.
3. Add an apply-level test: a kit-sweep listing error on another user's run root keeps every
   digest and fails no seat.

### R2-2 (minor): a stalled lock probe reads as a free seat

`ErrStalled` wraps `ErrRefused`. Three call sites treat a refusal as benign, and they take a
stall the same way:

- **`waitFree`** (`absent.go:425`): a stalled `ProbeLock` returns "free" at once. The L3 wait
  (`SeatFreeWait`) is skipped, and the leave goes on to `guest remove`. `guest remove`'s exit
  75 still catches a held seat, so nothing is lost, but the wait LP1 asks for never happens.
- **`seatLockOf`** (`probe.go:150`): a stall is `probeFree`. With today's bounds the outer 5 s
  `Probe` bound always fires before the 10 s `callBound`, so this is latent. If
  `Guests.Bound` is set above 10 s, a stalled lock reads as free. A held run then becomes
  "ended", and the tick posts `member.disconnected` for a running member.

**Fix:** keep `ErrStalled` an `ErrRefused` for routing (that member alone). At these two sites,
test `errors.Is(err, guestroot.ErrStalled)` first: a probe error (`probeFailed` in `waitFree`,
an error in `seatLockOf`). Add a test of each.

### R2-3 (minor): a stall on one path is paid again by every call that crosses it

A root has no memory of a stall. If FUSE sits under a checkout that N seats share, every seat's
reads cross it. Each call waits the full 10 s and leaks its goroutines and fds until the process
exits. The phase still ends, but its length grows with N times the reads per seat.

**Fix:** once a call on a `Root` is abandoned, answer `ErrStalled` at once for any later call
whose path is at or below the stalled one. Keep a set of stalled path prefixes, under `mu`. Or,
more simply, cap the abandoned calls per root at one. Test it with two seats on one stalled
checkout: one bound in total.

### N1 (nit): a stalled tmux stat says that tmux is not installed

`tmux()` (`apply.go:859`) turns every `ErrRefused` into "/usr/bin/tmux is not a regular file;
the container's own play installs it". For a stall, that sends the operator to the wrong fix.
**Fix:** keep the wrapped error (`%w: ...: %w`) when it is `ErrStalled`.
