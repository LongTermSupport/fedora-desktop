## V40: the verdict's input set

`declare.Client.Status` keeps the last `declare status` answer under a key and gives it again,
as a copy, while the key is unchanged (`src-go/internal/declare/verdict.go`). A run that failed,
or whose answer did not parse, is not kept. The key is a sha256 over length-prefixed fields:

| Input                                                                                   | How it is read                                                       | v1 source                                                              |
| --------------------------------------------------------------------------------------- | -------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `--file`, `--source` and `--applied` paths, `--installed` (sorted)                      | the arguments                                                        | declare.py:520-528 (`status`)                                          |
| host_vars                                                                               | bytes                                                                | declare.py:521 (`parse(_read(args.file))`)                             |
| every `*.json` in the applied directory                                                 | name and bytes, in name order; a missing directory is its error      | declare.py:473-486 (`read_stamps`, `is_dir`, `glob("*.json")`)         |
| the LXC bridge `lxcbr0`                                                                 | its IPv4 addresses (or the lookup error), in-process                 | bridge.py:31 (`BRIDGE`), 46-60 (`live_subnet`)                         |
| every file under `helpers/pingbus` and `helpers/agent_bus`                              | path, size, mode, modification time (ns), except under `__pycache__` | declare.py:470 (`bundle.build`), helpers/pingbus/bundle.py:39, 79-82   |
| `files/usr/local/sbin/agent-bus-install`, `files/usr/local/share/agent-bus/tuwunel.pin` | size, mode, modification time                                        | declare.py:458-470 (`PIN_FILE`, `INSTALLER_FILE`, `declared_software`) |

### Choices made

- **The bridge.** v1 runs `ip -j -4 addr show dev lxcbr0` and uses the first `inet` address. The
  Go code reads the same thing in-process with `net.InterfaceByName("lxcbr0")` and `Addrs()`,
  keeping the IPv4 addresses in kernel order. If the interface is missing or unreadable, the
  error text goes into the key; it is never a refusal, because the status run judges the bridge
  itself. `Client.Bridge` is the test seam; nil means the in-process read.
- **`__pycache__` is left out.** The bundle excludes it (bundle.py:82). A status run can write
  `.pyc` files, and if those counted, the second pass after any source change would run Python
  again.
- **Only files, not directories.** A directory's modification time changes when `__pycache__`
  is created inside it.
- **Read errors go into the key.** Whatever cannot be read (a missing tree, pin or stamp
  directory) is part of the key as its error text, so its appearing or going changes the key.

### Tests

Tests are in `verdict_test.go`:

- An unchanged world runs Python once over two calls, and the answer given back is a copy.

- A table test changes each input in turn, 15 cases:

  - the host_vars
  - the installed teams
  - a stamp: its bytes, one added, one renamed, the directory gone
  - the bridge: its addresses, the bridge gone
  - a pingbus file's size
  - an agent_bus file's modification time and mode
  - a file added, a file removed
  - the installer
  - the pin

  Each change makes exactly one more run, and the new answer is kept.

- A different source or applied directory runs Python again.

- A new `.pyc` does not run it again.

- B-S1 is pinned: an edit that keeps the size and modification time is not seen.

- A failed run (exit 78) is not kept, and neither is an unparsed answer.

- `interfaceIPv4("lo")` returns 127.0.0.1/8 and no IPv6, and a missing interface is an error.

## V41: what the start-up shares and what invalidates it

### The shared read

`board.Collector.HoldTeams()` starts an open's start-up. The picker calls it first thing in
`pickerSession`. While the start-up is on, the first successful read of the teams is shared by:

- the picker's first `Refresh`
- the offers' `Refresh` (offerUpdate, and ops' `Refresh` through `Statuses`)
- the first `Collect`, which ends the start-up

The read is held as `teamsRead`: the units, the declaration and the verdict. A failed read is not
shared. After the start-up, every pass reads the units again (one `systemctl list-units`), and
there is no time-based expiry.

### What invalidates it

Each of these calls `ForgetTeams`, so the next pass reads again:

- **Every declare.py edit.** `declare.Client.Edited` is called after each editing run, passed or
  failed: create, describe, add-repo, element, drop-limit, set, remove, lxc-add and lxc-role.
  Checks, dry runs and status do not call it. `teams.Wire` sets `h.Declare.Edited = b.ForgetTeams`.
- **Every play run.** `ops.runPlay` now calls `Changed` as soon as the play has run, passed or
  not, and before `applyHeld` or `confirmDown` reads the stamps back. This covers apply, remove
  and create, and the offers' limit, description and update applies. `Changed` is now
  `Collector.Changed`, which forgets both the devices and the shared read.

### Tests

- In `board/startup_test.go`:
  - The start-up runs one systemctl and one status, and the pass after it runs one systemctl and
    no Python.
  - With no start-up, every pass reads the units.
  - `ForgetTeams` mid start-up gives a new read, which sees the new unit.
  - `Changed` forgets both the devices and the shared read.
  - A failed read is not shared.
- In `declare_test.go`, every edit calls `Edited`, and nothing else does.
- In `ops/changed_test.go`, apply and remove call `Changed` between the play and the read-back.
  - Red: the events were `refresh play refresh changed ...`.

### Finding 1: the Edited wiring is tested, and wired once

`board.Wired(h)` (`src-go/internal/teams/board/collect.go`) is `New(h)` plus
`h.Declare.Edited = c.ForgetTeams`. `teams.Wire` and the picker rig (`picker/helpers_test.go`)

- New board test `TestAnEditOfTheHostVarsDuringTheStartUpIsReadAgain` (`board/startup_test.go`):
  `Wired`, `HoldTeams`, a `Refresh`, a `describe` through the host's declare client that rewrites
  the host_vars, then a `Refresh` that must show the new description, with two systemctl and two
  `declare.py status` runs.
  - Red (`Wired` without the line): `the read after the edit shows alpha's description as ""`.
  - Green with the line.
- New picker test `TestADescriptionWrittenAtTheStartUpIsReadAgain` (`picker/offers_test.go`): the
  whole picker, where the start-up describes alpha. It expects `declare.py status` to run twice and
  the list's first draw to show `Builds the example site`. Green.
- **This picker test cannot go red on the wiring line alone, and neither can any picker or
  `teams` test.** Measured: with the line removed from `Wired`, the picker test still passes; only
  the board test fails. The reason is that every start-up edit is followed by `ApplyTeams`
  (`offerPathLimits` and `offerDescriptions` both apply after the edit). `ApplyTeams` runs
  `defer o.changed()`, and `runPlay` calls `o.changed()` right after the play. Both call
  `board.Changed`, which calls `ForgetTeams` too. An edit that fails ends the picker, so no later
  pass happens. After the first `Collect`, `ForgetTeams` has no effect because the start-up is
  over. So `Edited` is a defence for an edit that no apply follows, and no flow makes one today.
  The review's claim that "without the wiring" the first draw would be stale does not hold.
  - Mutation with both drops removed (the line in `Wired` and `c.ForgetTeams()` in `Changed`):
    the picker test is killed (`declare.py status ran 1 times, want twice`).
  - Mutation with only `Changed`'s `ForgetTeams` removed: the picker test passes, because the
    wiring covers it.
  - So the picker test pins the V41 behaviour end to end. The wiring by itself is pinned by the
    board test.
