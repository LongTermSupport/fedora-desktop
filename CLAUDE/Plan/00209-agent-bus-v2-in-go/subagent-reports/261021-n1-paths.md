## Decisions taken

01. **Reserved team ids**:
    - The list is `admin`, `backup`, `ctl`, `fence`, `health`, `install`, `membership`, `seats`,
      `server` and `status`.
    - These are the ids that would make a team-derived name equal a fixed one. For example, team
      `ctl`'s homeserver user would be `teamchat-ctl`, which is `CtlUser`.
    - `membership` was found by the derived per-team roots. The host's `/run/teamchat/<team>`
      (`ServerRuntimeDirectory`) sits beside the ccy session's `/run/teamchat/membership`. Reserving
      it was judged sound in round 3, and D 5.10's short id still lets a v1 team with that name
      migrate.
02. **C's LXC records are under `_lxc/`**, which no team id can be (the same as `_sets/`).
03. **The Element play lives in `playbooks/imports/optional/common/`**, where v1's Element play is.
    The gate takes a `play-teamchat*.yml` or `.yaml` anywhere under `playbooks/imports/`.
04. **`/ccy/membership` is one v1 list entry.** It covers `/run/ccy/membership`,
    `$XDG_RUNTIME_DIR/ccy/membership`, `{{ }}` and Join forms.
05. **K7, and the `SharedFiles` list.**
    - Scoping task files by name alone would let a v2 play include a task file named without
      `teamchat`, unseen. So every path a scoped YAML file names must be in scope or shared. The
      shared list has one entry, `tasks/build-go-command.yml`, with its reason.
    - `vars/` is in scope below a `teamchat*` component.
06. **One allowlist row per line.** A row that covers hits on two lines is a finding, and so is a
    row that covers none.
07. **Opaque ids, and a panic on zero**:
    - The panic is chosen over `(string, error)` on every derivation. A zero id is a programming
      error, and the change would widen the API for the same guarantee.
    - A decoder that must accept a missing field has to check it before deriving.
    - Digests are lowercase hex, 16-64 characters, so no digest can be the kit's `current` link.
08. **The red proofs use in-memory and real-git trees**, not a `testdata/` fixture.
09. **D 3.7's check of every declared v1 team** belongs to C's runtime validator. host_vars are
    private, so a unit test cannot read them.
10. **D 4.1 part 2** (the analyzer over `migrate/v1`) belongs with the adapter in Task 6.1.
11. **The replay rows are recorded for the integration merge**, not landed here (above).
