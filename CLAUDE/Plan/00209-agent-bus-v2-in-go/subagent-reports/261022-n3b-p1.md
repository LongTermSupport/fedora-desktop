## guestroot: the exported API as built

```go
var ErrMoved    // the init changed while it was pinned (a dead or different pid at Pin)
var ErrGone     // the pinned init has gone: every Root call, the Writer's included
var ErrRefused  // TB1: a non-regular inode, a link, a bad path or name, an unsafe directory
var ErrTooLarge // over a read's cap, ReadDir's limit, or RemoveTree's bound

type Kernel interface {
	PidfdOpen(pid int) (int, error)
	PidfdAlive(fd int) error // nil while the process lives, ESRCH once it has exited
}
type LinuxKernel struct{} // PidfdAlive polls the pidfd for POLLIN (readable = exited)

type Pinner struct{ Proc string; Kernel Kernel } // Proc is "/proc" on a host
func (p Pinner) Pin(ctx context.Context, pid func(context.Context) (int, error)) (*Root, error)
func OpenDir(dir string) (*Root, error) // a fixture root: no kernel, Alive always nil, InitExe errors

type Info struct{ Mode fs.FileMode; UID, GID uint32; Dev, Ino uint64; Size int64 }

func (r *Root) PID() int
func (r *Root) Alive() error // ErrGone once the init has exited
func (r *Root) Close() error
func (r *Root) Stat(p string) (Info, error)                                    // never opens the inode; a link is ErrRefused
func (r *Root) ReadFile(p string, limit int64) ([]byte, Info, bool, error)      // found false for a missing file
func (r *Root) ReadDir(p string, valid func(string) bool, limit int) ([]string, bool, error) // sorted; a name failing valid is ErrRefused, unquoted
func (r *Root) ReadProcStat(pid int) ([]byte, bool, error)                       // the guest's /proc/<pid>/stat, cap 4 KiB
func (r *Root) ProbeLock(p string) (held bool, record []byte, err error)          // LOCK_SH|LOCK_NB, record cap 4 KiB; missing wraps fs.ErrNotExist
func (r *Root) DialSocket(ctx context.Context, p string) (*net.UnixConn, error)  // root-owned S_ISSOCK only, dialled through /proc/self/fd
func (r *Root) InitExe() (Info, error)                                           // the host's <Proc>/<pid>/exe, O_PATH, link followed (n3-D17)
func (r *Root) Writer() *Writer

func (w *Writer) MkdirAll(p string) (bool, error)
func (w *Writer) WriteFile(dir, name string, data []byte, mode fs.FileMode) (bool, error)
func (w *Writer) PlaceDir(parent, name string, fill func(d *Dir) error) (bool, error)
func (w *Writer) Symlink(dir, name, target string) (bool, error)
func (w *Writer) Remove(dir, name string) (bool, error)
func (w *Writer) RemoveTree(dir, name string) (bool, error)
func (d *Dir) Mkdir(name string) (*Dir, error)
func (d *Dir) WriteFile(name string, data []byte, mode fs.FileMode) error
```

How each call reads or writes:

- **Reads (TB1).** Each read is an `openat2` with `O_PATH`, `RESOLVE_IN_ROOT`,
  `RESOLVE_NO_SYMLINKS` and `RESOLVE_NO_MAGICLINKS`. Then an `fstat` checks for a regular file
  or a socket. Then a reopen through `/proc/self/fd/<n>` uses `O_RDONLY|O_NONBLOCK|O_CLOEXEC`,
  and the reopen's inode must equal the `O_PATH` one. A FIFO is never opened. The tests prove
  this with a writer that polls every planted FIFO and must never find a reader.
- **Writes** add `RESOLVE_NO_XDEV`. Every directory on the path must be root's and not group-
  or other-writable. Each write goes to a `.new-` temporary, is fsynced, and is renamed into
  place. `PlaceDir` renames with `RENAME_NOREPLACE`.
- **Pin** follows n3-D7. It calls `pid` for the pid, opens a pidfd, and opens
  `<Proc>/<pid>/root` as a directory. It then checks the pidfd is alive and calls `pid` again.
  A dead or different init is `ErrMoved`.
- **The init.** P4 passes `func(ctx) (int, error) { return lxc.InitPID(ctx, c) }` as `pid`.
  Every Root call runs between two `Alive` checks.

## lxccmd: the exported API as built

```go
var ErrRefused // an argument refused before any program runs
var ErrOutput  // a program's output that is not its grammar; names the program and container

type LXC struct {
	Runner     execx.Runner
	DesktopUID int // no attach runs as this uid (TB3)
}

type State string
const (Running, Stopped, Starting, Stopping, Aborting, Freezing, Frozen, Thawed State = "RUNNING", ...)

func (l LXC) Containers(ctx context.Context) ([]string, error)                               // lxc-ls -1
func (l LXC) State(ctx context.Context, c string) (State, error)                             // lxc-info -n c -sH
func (l LXC) InitPID(ctx context.Context, c string) (int, error)                             // lxc-info -n c -pH; > 1 and <= 4194304
func (l LXC) Addresses(ctx context.Context, c string) ([]netip.Addr, error)                  // lxc-info -n c -iH
func (l LXC) Config(ctx context.Context, c string, keys ...string) (map[string]string, error) // lxc-info -n c -c K ...

type Attach struct {
	Container string
	User      paths.GuestUser
	UID, GID  int
	Home      string
	Kit       paths.Kit // HostKitDir(digest): never current
}
type GuestResult struct{ Changed []guest.What }
type GuestError struct {
	Op, Container string
	Exit          term.ExitCode
	Code          string
	Undecodable   bool
}
type AttachError struct {
	Op, Container string
	Exit          int            // -1 for a signal or a start failure
	Signal        syscall.Signal
	Err           error          // the start failure; Unwrap returns it
}
const GuestWait = 60 * time.Second
const MaxGuestOutput = 64 << 10
func (l LXC) Guest(ctx context.Context, a Attach, op guest.Op, args []string, stdin []byte) (GuestResult, error)
```

How each call checks its input and output:

- **Container names** are checked before any program runs. The grammar is a copy of declare's,
  `^[A-Za-z0-9][A-Za-z0-9_.-]{0,63}$`, because P1 cannot import P3's `paths.ContainerName`.
  **P4 should switch it to `paths.ParseContainerName`** once P3 lands.

- **Every lxc-ls and lxc-info line** must be printable ASCII, with no empty line, and the
  output must end in a newline. Empty output is no containers, or no addresses.

  - Containers must be unique.
  - `State` is one of the eight states lxc prints.
  - The pid is `^[1-9][0-9]{0,6}$`, then `> 1` and `<= 4194304`. A stopped container prints no
    pid, which is `ErrOutput`, so P4 asks `State` first.
  - Each address must be in its canonical form (`netip.Addr.String()` round-trips).

- **A failing lxc-ls or lxc-info** gives an error with the exit and its stderr's last line,
  with controls shown as spaces and bounded at 200 bytes. That text is never parsed.

- **`Guest`, before it runs**, refuses with `ErrRefused` and runs nothing:

  - a uid or gid of 0 or less, or uid == `DesktopUID`;
  - a zero user;
  - a home that is not clean and absolute, or holds a control;
  - a kit that is `HostKitCurrent()`, or not below `HostKitRoot` (the ccy kit included);
  - a NUL in an argument;
  - a verb that `guest.Ops()` does not register.

  The registered op is used, not the caller's copy, so its `Changes` and `Busy` cannot be
  forged.

- **`Guest`'s argv** is one literal `append` inside `LXC.Guest`, so the seam rule sees `--`:

  ```text
  -n C -u UID -g GID --clear-env --set-var HOME=<home> --set-var USER=<u>
  --set-var LOGNAME=<u> --set-var PATH=/usr/local/bin:/usr/bin:/bin -- <kit>/bin/teamchat
  <words> --user <u> [args]
  ```

  `<words>` is `strings.Fields(op.Verb)`, and PATH is `guest.SystemDirs` joined. Stdin is
  `Cmd.Stdin` alone, and a test proves the token is not in the argv.

- **`Guest`'s output.** stdout and stderr are each kept to `MaxGuestOutput` by a writer that
  never fails a write. Output over the cap is `ErrOutput`.

- **stdout on exit 0 (TB2.4).** Each line must be exactly `CHANGED\t<what>`, at most 256 bytes,
  with what in the registered op's set, and the output must end in a newline. `guest check`'s
  set is empty, so any output from it is refused. No byte of the guest's output reaches an
  error.

## Decisions

- **P1-D1: AttachError means "no error object".** A failing guest op whose stderr's last line
  does not decode by `exits.Decode` is an `*AttachError`. So is one ended by a signal, and one
  `lxc-attach` could not start. The member binary always writes its object last on a failing
  exit, so a missing object means the attach failed or the op died before it wrote one. That is
  exactly when P4 must ask `State` (n3b-D1). This narrows the brief's "else Code "",
  Undecodable true": that case is an `AttachError`, not a `GuestError`.
- **P1-D2: `GuestError.Undecodable` is an object the op may not give.** The object decoded, but
  the exit is outside 1, 64 and 78 (and 75 from a `Busy` op), or the object's exit differs from
  the process's. `Code` is then empty.
- **P1-D3: a timeout is neither.** When `GuestWait`, or the caller's context, ends the op,
  `Guest` returns a plain error wrapping the context's error, naming the op and the container.
  It is not an `AttachError`, because the container did not go away: the op hung.
- **P1-D4: pid_max is the kernel's ceiling.** It is `PID_MAX_LIMIT`, 4194304 on 64-bit, so there
  is no seam and no read of `/proc/sys/kernel/pid_max`. No host's `pid_max` exceeds it, and a
  lower one only means a pid between the two never occurs.
- **P1-D5: Config's multi-entry settings.** lxc-info prints a setting's further entries
  (`lxc.idmap`) one to a line after the first. Those lines are joined to the value with
  newlines, and empty lines are dropped. Any of these fails the call: a line shaped as a
  setting that was not asked for, a setting printed twice or not printed, or a value line before
  any setting. An unset setting is `K = ` with the value `""`. The VM lab checks this against a
  config with includes (n3-D22). P4 refuses `lxc.idmap` by name when its value is not empty.
- **Carried from the first builder:** `ErrGone`, `InitExe`, `PidfdAlive` by poll,
  `ReadProcStat`'s name, `ProbeLock`'s missing lock (fs.ErrNotExist), `.new-` names refused,
  `RemoveTree`'s bounds (16 levels, 4096 entries), `OpenDir` roots with no kernel, and the
  bind-mount test skipping where mounting is not permitted. Each is in the handoff's "API
  changes" section.
