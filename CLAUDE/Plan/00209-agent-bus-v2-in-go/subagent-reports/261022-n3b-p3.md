## Changes from the handoff, with reasons

01. **Additions to guestfacts.** These were added: `ErrRefused`, `MaxStat`, the three `Key*`
    constants and `ConfigKeys`. P4 classifies a step 03 refusal by `errors.Is(err, ErrRefused)`
    and passes `ConfigKeys` to `lxccmd.Config`. `ParseConfig` refuses a missing key and a key
    that is not in `ConfigKeys`. An empty `lxc.idmap` is unset, and anything else is refused by
    name. `lxc.start.auto` may be `1`, `0` or empty.
02. **`lxcstate` imports `status`**, for `status.OneLine`. The handoff's import list left this
    out.
03. **Rules the handoff left open:**
    - A `joined` entry has an empty `why`.
    - A `joined` or `left` entry has a handle. `deferred` and `offline` may have `""`.
    - Every handle is an lxc agent handle (not the probe, type `lxc`) and is held by one entry
      only, so `ByHandle` is unambiguous.
    - `since_ms` is greater than 0.
    - The entries are sorted by (container, user), and decode refuses an unsorted file.
04. **The two Read functions on no file.** `ReadRecord` gives the team's empty record (`v` 1,
    `members` `[]`). `ReadCopy` gives the empty copy (generation 0), so `Next` makes
    generation 1.
05. **`WriteRecord` refuses a file it cannot decode.** It does not overwrite it, because the
    record is the host's memory of each handle.
06. **Directories.** The record's `lxc/` directory is made 0755. `_lxc/` and `_lxc/<c>/` are
    made 0700. Each mode is set through an `O_NOFOLLOW` fd, whatever the umask. The parents
    (`StatusRoot`, `AdminStateRoot`) must already exist, and a missing parent fails. No gid
    seam was needed: the tests chown to the test's own gid.
07. **Copy.** The copy is canonical (seats sorted by team, farewells sorted by team and seat).
    A copy that `member/state`'s `Desired.Encode` refuses is also refused, so a team named
    twice, a bad seat or a bad reason fails.
08. **Prefix and the git config.** These rules are stricter than the handoff:
    - a nil git config (no file) is refused;
    - with no `[remote "origin"]`, the checkout's base name is used, as the handoff's facts say
      (section 2 step 03 says "origin is required", and the two disagree);
    - an `include` or `includeIf` section is refused, because its file is not read and could
      hold an `insteadOf`;
    - a dotted header (`[remote.origin]`, git's legacy form, which would be a second origin) is
      refused;
    - a continued line is refused;
    - origin's `url` must be a bare value with no quote or backslash, and only one url is
      allowed across all origin sections;
    - the subsection is case sensitive, as git's is.
09. **ccy.env.local.** A second assignment of *any* name is refused, as section 2 says. A
    literal also may not hold a backslash, `;&|<>()` or `~`. The file is parsed even when the
    entry sets `site`, so a malformed file always fails. An empty `HOOKS_DAEMON_HOSTNAME=` is
    refused, because it is not a site.
10. **Group name.** `GroupName` returns the first group with the gid. Its name must pass the
    portable user-name grammar, and no earlier line may give that name another gid.
11. **Malformed lines.** `Passwd`, `HostUIDs` and `GroupName` refuse any malformed line and
    any non-decimal id anywhere in the file, not only on the user's line. That includes NIS
    `+` lines. UTF-8 is checked, and every control character but `\n` is refused (`\t` too,
    for passwd).
12. **StartTicks** accepts 0.

## Tests

The tests check:

- every grammar refusal;
- that no guest byte is echoed in an error;
- the K15 refusal;
- each codec's round trip, with exact bytes;
- every strict refusal of the record and the copy: unknown, duplicate, case-variant and
  missing keys, `v`, status, a duplicate (container, user), unsorted entries, a `why` that is
  not one line, and a link refused on read;
- `since_ms` kept and moved through `Set`;
- that `WriteRecord` does not write unchanged bytes (the mtime is held);
- the modes and the gid;
- that `Next` raises the generation only on a change, and that order is not a change;
- that `Desired` passes `memberstate.DecodeDesired`, with session `lxc-<user>` and inbound
  `accept`.
