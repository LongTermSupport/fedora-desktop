Branch `feat/bus-v2-n2a`, stacked on `feat/bus-v2-n1` (merged in at 5491c405). The spec is
[SPEC-n2a.md](../SPEC-n2a.md): CA1-CA7, CC1-CC6, RE1-RE10, and decisions n2a-D1 to n2a-D13.

## What was built

- **`teamchat-admin`** (`src-go/cmd/teamchat-admin`, `src-go/internal/teamchat/admin`):
  C 3.3's verb table, the caller class from the uid pair (a wrong class exits 77), every
  unbuilt verb exiting 1 "not built yet" (n2a-D1), `version` with the source digest baked in by
  `-X main.SourceDigest`, and the `teamchat-ctl` child's boundary: its typed start spec
  (n2a-D6), the child's check of how it was started, and strict codecs for the request and the
  answer. The answer's one-line rule refuses every character a reader of root's `CHANGED`
  lines could split on or take as an escape (C0, DEL, C1, Cf, U+2028, U+2029). `ExitCodeOf`
  maps a failure to C 3.3's table: drift 70, unreachable or rate-limited 69, anything else 1
  (n2a-D13). `scripts/go-binary-suites.tsv` routes the command to `qa-go`. That row is a QA
  routing row only: nothing in this slice installs anything.
- **The rooms engine** (`src-go/internal/teamchat/rooms`), C 3.6.2 step 4. It finds, adopts or
  creates each room in A 5.2's order. It refuses drift before any write: a foreign creator,
  the wrong version, another creator, encryption, two candidates, a side room linking another
  main, one ID for two purposes. Then it kicks, writes state (the roster by seam 17's `rev`
  rule, after `DecodeRoster`) and invites, in that order. A converged team gets no write. A
  failure names its room and step and still answers what changed before it.
- **fakehs** models Tuwunel's admin room (quirk `AdminRoom`, part of `TuwunelQuirks`): an
  account made an admin is joined to a room the server user created.
- **`matrix/tuwunelhs`** is the real-Tuwunel start, moved out of the matrix package's M44
  test. It imports nothing of the client, so both the client's test and the engine's can use
  it.

## The real-Tuwunel round trip

`rooms/tuwunel_test.go` (`-tags tuwunel`) runs the engine against the pinned Tuwunel 1.9.4
binary, the same asset and config M44 uses (sha256 `8e9a5873...`, through `tuwunelhs`). It
registers the admin through the registration key and makes the roster's accounts. Then it runs
the engine three ways:

- the first run, with the full `CHANGED` list asserted;
- a second run with nothing changed, which writes nothing;
- `VerifyMain` and `VerifySide` over the server's own state.

It passes, and so do M44 (`TestTuwunel`) and the harness's own test.

The first run failed, and fakehs had passed the same case. Tuwunel joins a server admin to the
server's own admin room, which its server user (`@conduit`) created and which has no
`teamchat.room` link. The engine took that room as main and then refused it at the read step.
The fix: a candidate must be a room the admin created (RE2, n2a-D7).

The red was then reproduced on fakehs before the fix. The first form was a room another user
created and the admin joined. After review round 1 the case is the fakehs quirk itself.

The real server also confirmed n2a-D12. A fresh room already holds A's name, topic and power
levels, so the first run writes only the roster after the creates.

## Decisions

n2a-D1 to n2a-D13 are in SPEC-n2a.md section 4. Changed here: **n2a-D7**. Main is adopted only
from a room the admin created, because a server admin is not in the team's rooms alone.

Added in review round 1:

- the one-line rule of CC6;
- the message cut of CC3;
- the partial result of RE9;
- the refusal of one ID for two purposes (RE4).

## Design-text fixes proposed

1. **C 3.6.2 step 4.1.** A candidate's back-link names its purpose, but main has no link
   (A 5.3). Say that main is adopted as the one joined, unrecorded room that the admin created
   and that carries no `teamchat.room`. Also say that a candidate's `m.room.create` must be the
   admin's: Tuwunel joins every server admin to the server's admin room (n2a-D7).
2. **C 3.3.** Give the child's failure answer shape and its classes (`failed`, `refused`,
   `unreachable`, `config`) and root's mapping of them (n2a-D4). Define "one line" as CC6 does.
3. **C 3.3 and SPEC-matrix.** `matrix.Error.ExitCode` is v1's member table (7-10), not C 3.3's.
   The host maps a failure by its class (n2a-D13).
4. **C 3.6.2 step 4.2.** A gives no kick reason, so the engine sends none (n2a-D9).
5. **C 3.6.2.** Say that a failed apply still reports the `CHANGED` lines before the failure,
   and records the roster `rev` the server accepted (RE9).
6. **Task 2.5 / SPEC-matrix M37.** Record Tuwunel's admin room among "Tuwunel's answers
   recorded into fakehs". It is now the `AdminRoom` quirk.
