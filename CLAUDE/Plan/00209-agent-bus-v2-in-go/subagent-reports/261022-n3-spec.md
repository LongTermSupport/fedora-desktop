## What the spec holds

- **Six slices, LXC first.** n3a builds the binary, the CLI, the member files' codecs, the locks,
  the kit layout and the guest operations. n3b builds `lxc apply` and `lxc restart` from the host,
  with the unit as code, the L3 probe and the LXC disconnected notice's child op. n3c builds `run`,
  the keeper, the link, the store, the sync engine, receiving, the ends and hot control. n3d builds
  the sends. n3e builds Claude Code delivery, the hooks, the status line and the skill. n3f builds
  the side rooms, from an addendum reviewed before it starts. n3b and n3c can be built at the same
  time after n3a. The first LXC exchange runs after n3d, under `--plain`, and an LXC Claude Code
  member runs end to end after n3e.
- **The Task 3.1 statement** is SY7. net/http may resend a dropped `/sync`. That is safe within one
  database, because a sync from one `since` is idempotent and ids already held are skipped. It is
  safe across a restore, because nothing is persisted before SY6's epoch check (H-C14). Seven
  tests cover it on fakehs, whose restore stands in for C 3.12 (gaps 6 and 12). Case 3 runs again
  under `-tags tuwunel` in Task 3.4.
- **00194 2.0e** is RS1-RS3. Today's `left exit` is pinned. The switch is
  `CMD exit 75 AND hooks-daemon #127's record names this Claude Code`, recorded as
  `ended.notice: none`. It waits on #127, and its host half (the launcher and the sweep) waits on
  Task 4.2. **00194 2.0g** is UH1: `empty` counts as unheard (the reasons follow).
- **Trust boundary** (TB1-TB4). TB1: host code opens guest paths only through one primitive,
  `O_PATH`, a regular-file check, then a reopen of the same inode, so it never opens a FIFO; the
  guest's systemd socket is reached the same way. TB2: a member's files decide nothing on the host
  beyond four bounded effects, and guest output is parsed against a closed grammar.
- **Gates.** Gate A marks the play, kit and unit placement, and the host runs of H-C9/H-C10. The
  LXC path uses token seats only. So gate B binds just one thing: the host run of a held ccy
  session's hot reissue (LN9, Task 4.4).
- **API gaps 1-14** in the built packages, each with its resolution. The main ones:
  - the guest placement (gap 2);
  - `matrix`'s filter (gap 5);
  - fakehs restore and its timer (gaps 6 and 12);
  - `execx.Start` (gap 7);
  - the real-process test helper (gap 8);
  - failpoints (gap 9);
  - godbus (gap 13);
  - `proto.Lookup` resolved before judging (gap 14).

## Decisions

These are n3-D1 to n3-D20 in SPEC-n3.md section 10. The ones that matter:

- **D1:** a guest bundle is replaced file by file inside an existing seat directory. This keeps
  `store.json` and `seat.lock`. A bundle with a different identity first sets the store aside
  under the seat lock.
- **D5:** the sync filter is sent inline, never uploaded. A filter id uploaded after a backup is
  unknown after a restore.
- **D7:** the guest's init is pinned by a pidfd.
- **D9:** the seat lock record can only quiet the host's notice about that member.
- **D10:** the handle derived from a guest checkout counts at the first join only.
- **D14:** `RESOLVE_IN_ROOT` is the one open rule below a guest root.
- **D17:** `O_PATH` comes first, so a FIFO is never opened.
- **2.0g:** `proto.DecodeHuman` decides `empty` before any addressing rule. So `empty` and `type`
  count as unheard at every member. `not-addressed` counts only when no roster agent was
  addressed, through gap 11's predicate fed by SY4a.

## Design-text fixes proposed

The design chapters were not edited.

01. **C 3.9.2 step 7 and B 2.13 `place-bundle`:** "swapped in as `<team>/`" would delete the store
    and unlink a held `seat.lock` (B 2.5). Say instead: a seat directory that exists keeps
    `store.json` and `seat.lock`, `token` then `seat.json` are replaced inside it, and a different
    identity sets the store aside first (n3-D1). `seat.PlaceGuest` needs the same change.
02. **B 2.6 step 02:** "uploaded once per role and kept by its filter id" becomes the inline filter
    (n3-D5).
03. **C 3.11.1:** `RESOLVE_BENEATH` becomes `RESOLVE_IN_ROOT` below the guest root (n3-D14).
04. **C 3.9.2 step 03 and the L3 probe:** open `O_PATH`, then `fstat`, then reopen the regular file
    through `/proc/self/fd`. The `O_RDONLY|O_NONBLOCK` open comes last. Systemd as init is checked
    by inode, not through the `/proc/<pid>/exe` magic link (n3-D17). The same applies to C 3.7.3's
    ccy probe and to `seat/lockprobe.go`.
05. **C 3.9.4:** name the unit's path and its absolute wants link (n3-D3). The guest's
    `run/systemd/private` is opened through the guest root, as `S_ISSOCK` owned by root, and
    connected through `/proc/self/fd`.
06. **C 3.9.2 step 03 and 3.7.4:** the LXC record pins the handle after the first join, and a
    changed checkout origin is refused (n3-D10).
07. **K10:** pin the init by a pidfd (n3-D7).
08. **C 3.9.2 step 4:** both runtime parents are read for kit collection (n3-D8).
09. **C 3.9.2:** the absent phase treats a missing container as a stopped one. Each phase writes the
    record it changed (n3-D12). `--only-teams` does not shrink a user's desired seats (n3-D13).
10. **B 2.13 `check`:** `check` takes `base_url` on stdin for `reach` and probes `gh` with
    `gh auth status` (n3-D6).
11. **B 2.3.2 `run.ended`:** add `notice: none` with `reason: restart` (n3-D2). **B 2.3.3:** add the
    desired `code` `missing` (n3-D19). **B 2.4.1:** a missing `desired.json` under `--desired` is
    78 `membership` (n3-D16).
12. **A 7.5:** say whether `empty` counts as unheard. The answer is yes, at every member. Say that
    "addressed to no agent" is judged over the roster's agents (UH1). Give B's event cache a bound
    (n3-D20).
13. **B 2.5:** the seat lock is tried three times 50 ms apart, like the other two locks, because
    the host's probe holds a momentary shared lock.
14. **B 37:** give the freeze thresholds (n3-D18).
15. **PLAN.md, 00194's rows:** 00194 files 2.0g under "Task 7.2 (6b)", but this plan carries it in
    N3. 00194's text should point here.
