## New findings

### 1. low: once a release gives up on a notice, a new run id from the member starts the 10-minute bound again

`src-go/internal/teamchat/seat/release.go:288-293`.

**What is wrong.** The give-up record (`whyNotInTime`) has `until_ms` 0 and the run read at that
moment. A later `announce` for the same claim reaches the first case only when `prev.Run == run`.
A member that writes a new valid run id into its quarantined lock (the bind mount follows the
inode) gets no case at all. The announcer is asked again, and the bound starts again from now.
This needs a release that stops after the give-up record and before `finish`, which happens
when `retire` fails. The code comment says "whatever run the member's lock names by then", and
NT3 says "10 minutes at most" with no conditions. Handoff 3 records this residual, but neither
the code nor the SPEC says it.

**Fix.** On the release path (`noticeStep`), treat any not-posted record of this claim as
settled whatever its run: either a `whyNotInTime` record, or one that keeps `until_ms` once it is
past. Keep the run comparison only on the `Announce` path, where a later crash of a new run is
due a notice of its own. Add a test: give-up recorded, `retire` fails, the lock's run changes,
then a retry. That retry must not ask the announcer again.

### 2. low: HT3's class says "not a homeserver answer" for a view that failed on the team's own files

`src-go/internal/teamchat/health/health.go:196-199`, and `matrix.Class` at
`src-go/internal/teamchat/matrix/client.go:262-275`.

**What is wrong.** `view.Load` fails on a missing `team.json`, an `ErrOtherTeam`, or a roster or
`rooms.json` that does not decode. None of these is a `*matrix.Error`, so `Class` returns "not a
homeserver answer". The problem then reads "the team's rooms could not be read: not a homeserver
answer", and its fix points at `systemctl status teamchat-server@<team>.service`. That sends the
owner to a healthy homeserver. The child is a separate process (n2a-D6), so every failure it
reports will come back as a non-matrix error, and the same misleading class will be shown for all
of them.

**Fix.** Give the `Viewer` seam a class of its own, for example "the team's files could not be
read" for a `Load` failure and "the child failed" for a child that did not answer, with
`matrix.Class` used only for a `*matrix.Error` or a context error. Point each class at its own
fix. Add a test with a viewer that returns a `Load`-style error.

### 3. low: a re-probe that stops the miss count records the first unit state beside its probe word

`src-go/internal/teamchat/health/probe.go:70-73` and `112-117`.

**What is wrong.** `probeAgain` returns `not-run` when the unit is no longer active or has a new
invocation, but it drops the state it just read. `f.unit` keeps the first read, so the record
shows `unit: active` with that invocation's `since_ms` next to `probe: not-run`. SR1/HT2 say a
unit that is not active is `not-run`. The record therefore contradicts itself, and the board's
reading of "active" is out of date.

**Fix.** Return the state that was read, and set `f.unit` from it when `probe` is `not-run`. Add
a problem "the homeserver unit is <state>" when that state is not active, as step 1 does.
Extend `TestAReprobeThatIsNotAnAnswer` to assert `Homeserver.Unit`.

### 4. low: re-reading NRestarts after the restart is correct only if `Units.Restart` waits for the job

`src-go/internal/teamchat/health/probe.go:35-39` (the `Units` seam) and `156-161`.

**What is wrong.** Finding 7's fix reads the unit state right after `Units.Restart` returns.
systemd's `RestartUnit` over D-Bus returns when the job is queued. If the adapter returns then,
the read sees the counter from before the restart, and the next tick adds the false "restarted by
hand" again. The seam does not say which behaviour it promises. The fake returns the after-state
on the next read, so the test cannot tell the two apart. When that read fails, the old state is
kept silently and the same false event follows.

**Fix.** State in `Units`' doc that `Restart` returns only after the restart job has finished
(D-Bus `JobRemoved` with result `done`; any other result is an error), so the DC17 adapter is
built to it. Record a problem when the state cannot be read after the restart.
