## Decisions (departures from the brief and the handoff)

- **`Run` takes no context.** A stop reaches the keeper only through `Signals` (TERM, HUP), so a
  context was a second stop route, and threading it to the hot add's lock take (`contextcheck`,
  `containedctx`) would have touched every loop handler. `prepare` and a hot add use
  `context.Background()`; their lock tries are bounded by `Locks` (3 x 50 ms).
- **keeper.json `session`** is set only for a ccy or lxc member (the state schema's rule), not
  for every launch with a desired membership.
- **keeper.json `next_ms`** stays set while a restarting link is starting (it is due now: the
  link's start time), and is cleared when the link is ready or failed; the schema requires it
  exactly for a restarting link, and the launch's first link is restarting too.
- **`fail` logs after** keeper.json and the reports are written, so the log line is the point
  at which a reader sees them.
- **keeper.log lines added** for the states a test (and a person reading the log) needs to see:
  `the link is ready`, `Claude Code's first SessionStart`, `Claude Code <pid> is held by a pidfd`,
  `Claude Code is CMD <pid>`, `seat <team>: its leave notice is owed`. The tests use them as the
  barrier between the keeper's sources, which its loop takes in no fixed order.
- **B14** (decided in the handoff): the scan walks the keeper's imports and every module
  package they import except cli, with and without the build tags, for `net/http`, `crypto/tls`,
  `net/rpc` and `net/smtp`; it proves it can see the guest check's client, and asserts the
  keeper calls no cli function. `net` itself is allowed: the control socket is a Unix socketpair.
- **B11**: no writer call (`logf`, `Write*`, `Fprintf`, `Marshal`, `Create`, ...) is handed a
  value named token, proven against a planted leak; and a token message prints without it.
- **Failpoints**: one test binary helper (`keeper`) runs `Run` in its own process over the
  test's world with in-process fakes for the link and CMD. Under `busfailpoints`,
  `keeper-before-end` and `keeper-link-writing` SIGKILL it and the next keeper sweeps the run
  (T8); without the tag the same environment is inert and the run is removed.
  `keeper-before-store-delete` has no real-process row; its call site is covered in process.
- **Earlier deviations stand** (handoff): `Started` has no `PidFD()`; CMD's first stderr line is
  not captured; a removal answered with no farewell owed closes the lock at once; a store
  removed after a link's exit forgets the user id (SY1 (b)).
- **CCY version** from cdb10e3e9 is left as it is, for the lead to renumber at the merge.
