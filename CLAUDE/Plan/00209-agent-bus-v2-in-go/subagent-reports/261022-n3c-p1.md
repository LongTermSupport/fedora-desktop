## Departures from the brief, and why

1. **`ReachedNoAgent` takes no `server`.** The brief's signature had one; nothing in the
   predicate reads it (the roster's members are already this server's agents), and an unused
   parameter fails the linter. P5 calls `ReachedNoAgent(h, roster, lookup)`.
2. **`RelationIDs` takes the roster.** Without it an agent's `m.text` with a reply would
   decode as a human message and cost a needless fetch. It answers only for a listed human's
   message that `DecodeHuman` accepts (not a carried item, not an emote, not a fallback-only
   reply), which is exactly when `Judge` computes addressing.
3. **"A roster agent" is `Roster.HumanReader`**: a non-parked coordinator or worker with human
   text. A mention of a parked member, the probe, or a worker with `human_text: false` reaches
   no member, since none of them delivers it (rule 08), so it counts as reaching no agent. **P5
   must fill `AddressedToRosterAgent` with the same predicate** (`HumanReader` over an outbox
   entry's `to` and a fetched event's mentions) so the edit rule agrees.
4. **Tuwunel 1.9.4's limit-0 answer.** The tagged test on the real binary found that a
   timeline limit of 0 is answered `"timeline":{"limited":true,"events":[]}` with **no
   `prev_batch`**, which the client refused as malformed. The client now accepts a limited
   timeline without `prev_batch` only when it holds no events (with events it stays malformed;
   `TestSyncMalformed` pins both), and fakehs answers a limit of 0 the same way. **For P5:**
   SY1 (c)'s re-add sync comes back `Limited` with an empty `PrevBatch`; that sync wants no
   history, so it must not try to fill a gap from it.
5. **`RestoreTo`'s new epoch** is one more than the higher of the snapshot's and the one in use,
   not just the snapshot's plus one, so a second restore to the same snapshot still raises it.
   The event ID counter is outside the database and is not rolled back, so an event made after
   a restore never reuses a lost event's ID. A roster in use without an integer epoch also
   refuses the restore; a refused restore changes nothing.
6. **`Hold` is armed only when a sync can wait** (a since and a timeout above 0), so a test's
   fake sees only the long-polls.
7. **The gap-5 pin lives in `matrix/filterpin_test.go`, package `matrix_test`**, which imports
   both matrix and proto. That is a test-only edge; matrix's own code still does not import
   proto, and proto imports nothing of teamchat.

## Tests (each red first)

- proto `reach_test.go`: `HumanReader` per member kind; `ReachedNoAgent` table of 18 rows
  (each clause with the related event known and unknown, the deaf, parked and probe mentions,
  an edit that now mentions an agent); a reply to agent X's event is reached at the
  coordinator, which ignores it as not addressed; an emote never decodes; `RelationIDs` table
  (13 rows); `SyncFilterReAdd` byte-equal to `SyncFilter` but `"limit":0`.
- matrix: `TestSyncSendsFilterJSONByteForByte`, the refusals (both filters, not JSON, not an
  object, surrounding space), `TestTheSyncFilterIsProtosByteForByte` (proto's filter and the
  re-add filter through fakehs, byte for byte), `TestATryEndsWhenItsTimerFires` (no end before
  the fake timer fires; "timed out", transient; timer of the long-poll plus 15 s, stopped),
  `TestEach429RetryArmsAFreshTimer` (three tries, three timers, each stopped),
  `TestSystemTimers`, and the tagged `reAddSync` against the real Tuwunel 1.9.4.
- fakehs `restore_test.go`: rollback of events, a later token and room account data, the epoch
  raised and sent by the roster's sender, twice; a held sync under a restore with the fake
  `Hold` (epoch raised straight after, the sync still held, then the lower `next_batch`); the
  refusals; a snapshot unaffected by later redactions. `replay_test.go` passes unchanged.
