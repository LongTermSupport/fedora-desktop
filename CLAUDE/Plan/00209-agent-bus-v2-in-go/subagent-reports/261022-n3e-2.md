- `internal/teamchat/member/proof` (imports `x/sys/unix` and std): `Needle`; `Scan`, a bounded
  scan of the transcript with TB1's open (15a's correction); `Watch`, inotify on the file and its

  the idle `user` record and the busy `queued_command` attachment, written after a delay on the
  fake clock or never, plus noise, rotation, truncation, `/clear` and the `Attach` adapter.

## Semantics later parts rely on (n3e-9)

- **Scan** reads from `max(0, from.Offset - overlap)`, where overlap is the longest asked
  needle's length less one, to the end, at most `maxRead` bytes. `End.Offset` is where the read
  stopped, so the next call continues from it. A needle counts only when its last byte lies
  past `from.Offset`, so a needle a previous scan reported is never reported again, even with
  nonces of different lengths. `Found` keeps the order of `nonces`, each nonce once.
- **Reset**: the file is shorter than `from.Offset`, or `from.Ino != 0` and the device or inode
  differs. The scan then runs from 0. With only a persisted offset (`Ino` 0) no inode is
  compared (n3e-D10).
- **Errors**: a missing file or directory is `fs.ErrNotExist` (no file yet is not a refusal).
  `ErrRefused`, with the reason named in the message, covers: a symbolic link (the file or its
  directory), a FIFO, a directory, a socket or other non-regular file, a file or directory of
  another uid, a file or directory writable by its group or others, an inode that changed
  between the `O_PATH` open and the reopen, a relative or unclean path, an empty nonce or one
  holding a byte JSON would escape, a negative offset, and `maxRead <= overlap` (a scan that
  could not move forward).
- **Watch**: growth, truncation, the file moved or removed, any name made, moved or removed
  in the directory, and `IN_Q_OVERFLOW` each send a change. The channel holds one value, and
  that value stands for every change since it was sent. When a new inode takes the
  transcript's name (create or move-to), the file watch follows it. The file need not exist
  yet; its directory must. `Changes` is closed when the watcher ends; `Close` waits for that
  and returns any read failure that ended it. A change is only a hint to call `Scan`.

## Decisions

- **D1. TB1 for a member's own file.** `Scan` opens the directory `O_PATH|O_NOFOLLOW` and
  fstats it. The directory must be the caller's (euid) and not writable by its group or others,
  so no other uid can swap the name. The file is then opened `openat(dir, base, O_PATH|O_NOFOLLOW)`, fstat'd, and judged the same way as a regular file. It is reopened
  through `/proc/self/fd/<n>` with `O_RDONLY|O_NONBLOCK|O_CLOEXEC` (no `O_NOFOLLOW`, the one
  TB1 exemption) and its device and inode are checked again. Components above the parent
  directory are resolved normally. The path is the absolute one `AcceptFacts` accepted, and the
  parent check closes the swap that matters. `proof` does not use `homefs`, because the brief's
  imports are `unix` and std, and the transcript lives outside the member's teamchat roots.
- **D2. `proof` does not import `clock`.** The brief listed it, but neither the scan nor the
  watcher reads a clock. Waits and deadlines belong to n3e-9.
- **D3. Nonce check is local.** `proof` does not import `proto`. It refuses any nonce whose
  needle would not appear byte for byte inside a JSON string: empty, or holding a byte outside
  printable ASCII, or `"`, or `\`. proto's `^[0-9a-f]{8}$` passes it.
- **D4. "Found past from.Offset" rather than raw overlap.** This is exact even when nonces
  differ in length, and it is what makes "each nonce reported once" hold across calls.
- **D5. Watcher scope.** Any directory entry event is a change, as section 4's test asks:
  "a new file in the directory". So a `/clear`'s new transcript wakes the scanner, and n3e-9
  decides whether the path changed. The file watch uses `IN_DONT_FOLLOW` and the directory
  watch uses `IN_ONLYDIR|IN_DONT_FOLLOW`. A read failure is kept for `Close`, not dropped.
- **D6. Faithful bytes.** Records are written with `SetEscapeHTML(false)`, as Claude Code's
  `JSON.stringify` writes them, so `<`, `>` and `&` stay literal. Each line is one `write`. A
  delayed `Record` goes to whatever file is at the path when the fake clock fires, which gives
  "after a rotation or /clear". `Rotate` leaves an empty new inode; `Clear` refuses the current
  or an existing session id.
- **D7. `Err()` added.** `Record`, `Noise` and the clock callbacks return nothing (section 4's
  signatures), so the first failed write is kept and a test reads it with `Err()`. Nothing is
  dropped silently.
