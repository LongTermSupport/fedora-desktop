### 2. nit: the `pending` refusal names no remedy

`src-go/internal/teamchat/apply/apply.go:162`.

The message is `operation <op> is pending at step <step>; it is finished before the team is applied`. It does not say what finishes it. Once member verbs exist it should name the verb to
rerun (C 3.6.3: "the same verb asked again for the same handle completes it", so `member <verb> <handle>`, with the handle from `pending.handle`). Fix it together with the roll-forward item of
finding 1.

### 3. nit: `pending.op` and `pending.step` are echoed under a weaker character rule than keys

`src-go/internal/teamchat/apply/files.go:332-333,346` with `apply.go:162`.

The reader accepts any op and step free of C0 and DEL (`isControl`), so U+0085, U+2028, U+2029
and bidi controls get through, and the new refusal prints both unquoted. Python's `splitlines`
(what Ansible's `stdout_lines`/`stderr_lines` use) breaks lines at U+0085 and U+2028. The impact
is small: a tab is refused, so no `CHANGED\t`/`SECURITY\t` line can be forged; the message goes to
stderr; and only the control user writes the file. Still, it is a second rule beside `KeyText`'s.
Fix: use `!unicode.IsPrint` in the reader's op and step check, or print them with `%q`.

### 4. nit: `human`'s doc comment omits the adoption branch

`src-go/internal/teamchat/apply/apply.go:215`: "creates the account (acct nil), or unlocks and
re-activates one locked or removed". It should also say "or records one it did not make (adopted)".
