## The decision as recorded

SPEC-n3 section 10, row n3b-D2, and C 3.9.1 "What an LXC member is":

- An LXC member is (team, container, checkout, seat). The user is only who runs it, a field of
  the entry and never part of its name.
- Any number of entries per user, per checkout and per container. The role is per entry
  through DC6's team `coordinator` (one per team, no entry `role` key). A seat lives in one
  container: equal handles are refused at step 03.
- (team, container, checkout, seat) is the duplicate key (SPEC-n2b DR4 too). The record and
  the host copy are keyed (container, checkout, seat).
- One supervised unit, tmux server and tmux session per seat.
- The offline rule (n3b-D1) holds per seat.
- A new row, n3b-D3: when the errors of `lxc apply` or `lxc restart` include an `OfflineError`
  and another error, the other error decides the exit; 69 only when every error is offline.

## The choices made

- **The seat ruling (the lead's).** `seat` is required in every entry, because it is part of
  the member's identity. `lxc apply` never uses `--seat next`; the tool that adds an entry
  (`ccy-teams lxc-add`) picks the next free seat, counted across the whole team, when it writes
  the declaration, and the declaration records it. This is stated in C 3.9.1, C 3.6.3, the
  n3b-D2 row and LX1. `--seat next` has no caller and is removed by the rework.
- **desired.json is per seat.** B's desired file and state root hold one seat per team, so a
  file per checkout could not hold a coordinator and a worker of one team. This mirrors ccy's
  `sessions/<session>/` and `control/<session>/`.
- **Unit and session grammar.** `<key>` is the first 16 hex of SHA-256 of
  `<team>\n<checkout>\n<seat>`. The unit is `teamchat-session-<team>-<repo>-<seat>-<key>.service`
  (at most 94 bytes). The tmux session is the unit name without `.service`, and the tmux
  server is `-S /run/teamchat-session-<key>/tmux.sock`. `RuntimeDirectory=teamchat-session-<key>`.
  The session name is `lxc-<key>`. Guest roots are `~/.config/teamchat/lxc/<key>/{seats,membership}`,
  the host copy is `_lxc/<container>/<key>.json`, and the target is `--member <container>/<key>`.
- **Launch by key.** The unit and a hand-run seat both use `run --kind lxc --key K`. The run
  root comes from `$XDG_RUNTIME_DIR`.
- **A deactivated account.** An explicit `add --seat S`, or a `return`, records the handle
  `retired` and answers a new error class, `retired` (SPEC-n2a CC5, exit 70). `lxc apply`
  turns only that class into the entry's `DEFERRED`. The next step 03 refuses the retired
  number by name.
- **Join verb.** The roster's state of the handle chooses `add`, `return` or `reissue`. An
  `active` handle with no record entry gets `reissue`.
- **Record.** A handle is unique among entries that are not `left`. A `left` entry is never
  parked again and is changed only by the absent phase. The record is written after each
  team's step 06 joins and at the end of every phase, whether it failed or not.
- **User move.** The seat leaves under the old user, then the new user joins with `return`.
  The record entry is rewritten for the new user (`deferred`, same handle), not dropped, so the
  handle is never derived again. The new user is held back while the key's entry is `left`.
  An old user who is gone from the guest's `/etc/passwd` skips the guest steps.
- **Approval gate.** The SPEC-n2b AG3 entry text is
  `<container>/<seat>,user=<user>,human_text=<bool>,checkout=<checkout>`, with the checkout
  last and split at the first three commas. A `user` change is one AG6 `--set`. DR4 requires
  the checkout to be one line.
- **Shared checkouts.** `ccy.env.local` may be owned by any agent user whose entries name the
  checkout.
- **LXC seat repair.** It is `seat set-aside --team T --state ~/.config/teamchat/lxc/<key>/seats`.
