# n3c P5 report: the sync engine, package teamsync (Plan 00209 N3, slice n3c)

Three builders. The design is in `261022-n3c-p5-handoff.md`; this report is what was built.

## What was built

`src-go/internal/teamchat/member/teamsync` (package `teamsync`): one team goroutine per team.
It covers SY1-SY14, SY4a, UH1, LN6 (Verify, History, Refetch), LN9 (the seat watcher, a torn
pair waited out, the token race) and the notices the ends use. The pieces outside the package:

- `proto.StateEvents` (P5 trust, 8a);
- `matrix.StatusError` (below).

Files: `teamsync.go` (Config, Run, the error table, backoff, the freeze detector), `session.go`
(a session: verify, SY1, the long-poll, an answer's steps, the floor marker), `lookup.go` (SY4a's
resolver and the bounded memories), `ln6.go` (Verify, History, Refetch, the notices) and
`watch.go` (inotify).

## Decisions

The first 18 decisions are in the handoff: 01-11 under "Decisions taken so far" and 12-18 under
"Decisions the second builder took". The third builder added these:

19. **Defect found and fixed.** `decodeMarker` compared `proto.Value.Size()` with 3. `Size()` is
    the length in bytes of the compact JSON, not the number of members. So every valid floor
    marker was read as undecodable, and SY1 (b) always resumed from the member's own join. The
    marker now counts `len(v.Members())`. `TestResumesAfterTheMarker` found it, and
    `TestTuwunelSync` proves the fix on a real server. No other `Size()` call in teamchat is a
    member count.
20. fakehs sends no invite to a room outside the sync filter, and it does not model a sync's
    `leave` section. So SY11's pending and reject paths, and SY14's main-left trigger, are
    unit tested on `sess.invites` and `sess.trustTriggered` directly. The coordinator's accepted
    invite to the questions room, and a failed join of it, run end to end.
21. The test harness keeps the wall clock out:
    - `held` holds the first long-poll in `onPoll` until the test releases it, so that the
      test's posts come back as one answer;
    - `batchOrWait` advances the fake clock through any backoff;
    - a suspend or a restart between polls is made in the engine's persist hook.
22. SY7 case 8's 429 asks for `retry_after_ms: 0`, and the restore comes before the try. On the
    fake clock the 429 wait and the try's deadline timer cannot be told apart.
23. The n3-D20 sentence for n3c-D11 is in SPEC-n3: own sends are kept in memory only, per team,
    inside the resolver, bounded at 1024; a link restart loses them and the fetch backs them.

## For the reviewer

n3-D20 says a 404 or 403 related event is "not counted unheard". `proto.ReachedNoAgent`
(n3b) does the opposite: an event the lookup does not hold reaches no agent, so a human reply
to a missing event that no mention addresses is counted unheard. If the missing event was an
agent's, that count is wrong. teamsync follows proto, and the two texts need settling at the
review. `TestAMissingRelationIsFetchedOnce` checks only the single fetch and the delivery to a
mentioned member.
