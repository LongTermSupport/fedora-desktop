## Decisions taken

- **One file per concern.** `seat.go` holds LoginDevice, Logout, room account data and
  DeleteDevice. `Redact` sits beside `Send` in `member.go`. Presence is in `sync.go`.
- **`answered()` is split out of `do()`.** It does the token check and the 429 loop and gives the
  first answer that is not a 429. This lets `DeleteDevice` read the challenge in a 401 body. `do`
  is unchanged in behaviour.
- **`DeleteDevice` takes the user name and password as arguments.** The client never stores a
  password.
- **A wrong password on the delete is `ErrForbidden`, not `ErrAuthRefused`.** It then matches the
  login, where a wrong password answers 403. A dead token stays `ErrAuthRefused`.
- **fakehs follows a recorded fact where one exists.** Elsewhere it follows the specification's
  shape and says so. It leaves unmodelled whatever neither covers: deleting an unknown device, a
  session not given for that device, another account named, any other auth type, another
  account's account data or presence, and a replayed redact transaction ID.

## Design-text fixes proposed (not edited here)

- **C 3.7.3 take step 3 and DC16:** a login as the seat's fixed device does not end the previous
  holder's token on Tuwunel 1.9.4 (H-C13). The take must log out, or `DeleteDevice` by password,
  before it logs in. A logout ends every token of the device, so a take that logs in first can log
  out with its own new token and then log in again.
- **B 2.3.2 and C 3.7.3:** the marker read is `found=false` only on `M_NOT_FOUND`. Any other 404 is
  a fault.
- **A 6.6 and B 2.6 step 09:** `set_presence=offline` on a sync sets offline on Tuwunel (HC-A1). The
  first sync after an outage uses the default `set_presence`, which marks the member online.
- **B (resume after restore):** a `since` ahead of the server is held to the timeout and answered
  with the lower `next_batch` (H-C14). A member seeing `next_batch` go backwards should treat it as
  a restore.
