## What holds

- **Lengths, computed again.** Team id max 22 (`paths/ids.go:68`), so the unit is
  17+22+1+24+1+4+1+16+8 = 94 bytes (systemd limit 255). The tmux session is 86 characters,
  and every part is `[a-z0-9_-]`, so it has no `.` or `:`. The runtime directory
  `/run/teamchat-session-<key>` is 38 bytes. `link.sock` is 38+14+16+10 = 78 bytes, the
  inbox socket `cc-socks/<pid>.sock` at most 60 with a 7-digit pid, and `tmux.sock` 48. All
  are under `sun_path`'s 107. The claim that the unit's own name would not fit as the
  runtime directory is right: that path would be 131 bytes.
- **Every name is known in advance.** Each name is derived from the declaration (team,
  checkout, seat), and the record now carries checkout and seat. So each name is known for a
  stopped container, before the first join, and for a record-only leaver.
- **Key collisions.** A forced collision is refused, never trusted. The host copy repeats the
  key's inputs and checks them against the file name when it is read.
- **Per-seat state and desired directories.** Making both per seat is the sound choice. It
  matches B 2.10 (at most one seat per team in a desired file) and ccy's
  `sessions/<session>/` and `control/<session>/`. The conversation record
  (`<v2-state>/conversation.json`) is then per seat as well. The rejected per-checkout option
  could not hold a coordinator and a worker of one team, and the text says why.
- **One tmux server per unit (`-S`), not a shared `-L` server.** The reason given is correct:
  with a shared server, every later unit's pane would run in the first unit's cgroup.
- **Launch flags.** `--state` together with `--desired` is legal under CL5 and B 2.4.1 step 6.
  `--seat` is the only flag barred with `--desired`.
- **The offline rule holds per seat.** A stopped, frozen or missing container gives one line
  per seat. A stop mid-phase defers every seat of that container that is not yet done, and
  other containers carry on. No new step waits on a stopped container. A seat's step 08 never
  waits for another seat's.
- **The coordinator.** The coordinator through DC6's team `coordinator`, with no entry `role`
  key, is consistent with DC6. There is one coordinator per team by construction.
- **The rework file.** Every named code location is real: `apply.go` lines 208, 219, 405, 757,
  771, 849, 931 and 993; `absent.go` lines 69/74, 132/138, 219 and 284; `kit.go:222`;
  `lxc.go:40/74`; `restart.go:30/87`; `places.go:61/264`; `gate.go:422`; `lxcstate.go:77/135`.
  `health.Guests.Probe(team, handle)` really is unaffected.

## Findings

### F1. MAJOR: a declared, fixed seat brings back the trap n2d-D21 closed, and C 3.6.3 still says `lxc apply` uses `--seat next`

Where:

- `DESIGN-v2-C-host.md:913-916` still says "`--seat next` is for `lxc apply` only, where root
  chooses under the team lock".
- `SPEC-n2d.md:150` (n2d-D15) and `:154` (n2d-D21) still give `lxc apply`'s retry as
  `add --seat next`.
- The new texts say otherwise: C 3.9.2 step 03 (`DESIGN-v2-C-host.md:1756-1758`) and LX7
  (`SPEC-n3.md:315`) have `lxc apply` pass `--seat <the entry's seat>`.

Failure: n2d-D21 says that an explicit seat whose account is deactivated on the server is
refused with no write. It also says that `lxc apply` "cannot choose another number, and
refusing would repeat on every try". That was the reason `lxc apply` used `next`. Now an
entry's seat can be one of these:

- a number whose account is deactivated, for example after a restore;
- a `retired` handle of the same prefix, for example from a hand-edited host_vars;
- a number `lxc-add` chose before the server knew it was retired.

With any of them, step 06's `member add` is refused on every apply. That happens after step
05 and after other teams' roster changes, so the phase fails part-applied, every time, for a
running container. `lxc-add`'s rule ("no LXC handle in the team's roster holds, in any
state") reads the roster, so it cannot see a deactivated account that is not in the roster.

Fix:

1. Rewrite C 3.6.3's bullet: `--seat next` is gone. Every caller passes `--seat S`, and
   `lxc apply` passes the entry's seat.
2. Amend n2d-D15 and n2d-D21: the retry is `add` of the handle, and a refused explicit seat is
   `lxc apply`'s to report.
3. Add to C 3.9.2 step 03 and LX1: an entry whose derived handle is `retired` in the roster is
   refused by name before any change ("seat N of <prefix> is retired; choose another seat").
4. For a deactivated account found at step 06, make the refusal that entry's
   `DEFERRED ... seat N's account is deactivated; choose another seat`, recorded `deferred`.
   It must not fail the phase, because the child records it `retired` (n2d-D21) and the next
   apply's step 03 then refuses it by name.
5. List this handling in the rework file under `apply.go` (the step 06 join error path) and
   remove "`member add --seat N` already exists" from "Unaffected".

### F2. MAJOR: a seat with `service: false` has no launch line

Where: `DESIGN-v2-B-member.md:19-28` (the `<v2-state>` and `<v2-desired>` rows),
`DESIGN-v2-C-host.md:1633-1634` and `1950`.

Failure: with `service: false` the agent user starts the session by hand. B's defaults for an
LXC guest are still `~/.config/teamchat/seats` and `~/.config/teamchat/membership`, and
nothing writes to either any more. So a plain `teamchat run --claude --kind lxc ... -- claude`
finds no desired file and exits 78 `membership` (n3-D16). Or, with no `--desired`, it holds no
seat. To work it needs `--state ~/.config/teamchat/lxc/<16-hex>/seats --desired ~/.config/teamchat/lxc/<16-hex>/membership`, and no text says how the person learns the
key. v1 and the previous v2 text worked with the defaults. A user with two seats has no way to
tell which key is which.

Fix: pick one of the following.

- (a) Make `run --kind lxc` require `--state` and `--desired` (64 otherwise). Change B's LXC
  column to say an LXC guest has no default root. Have `lxc apply` print the seat's launch
  line, and the board or `lxc-add` show it, as the CHANGED line's `why` or on the board's
  member row.
- (b) Add `run --lxc-seat <key>` (or `--kind lxc --key K`), which derives both directories
  from C 3.9.1's function, so the unit line and a manual line share one rule.

Either way, the rework file gains the `run` change. Today its `member/cli run` section says
"No grammar change".

### F3. MAJOR: `lxc-add`'s seat choice can collide across containers and fail the phase later

Where: `DESIGN-v2-C-host.md:1612-1614`, the rework file's "Not built yet" `lxc-add` line, and
D M1 (`DESIGN-v2-D-migration.md:786`, "the lowest number `lxc-add` would offer").

Failure: handles are `<repo>.<seat>+<site>.lxc`. `<repo>` comes from the checkout's origin and
the container is not part of the handle. `lxc-add` counts only "entries of the team and
checkout" (the checkout path string) and the roster.

Case: container A, stopped, has a declared but never-joined entry for `/home/u/proj` at seat

1. The owner adds container B's `/srv/proj`, a clone of the same origin. `lxc-add` offers
   seat 1, because the path differs and no handle holds 1. Once both containers run, step 03
   finds equal derived handles and refuses. Step 03 runs "before anything changes" for every
   running container, so the whole present phase fails, other containers' entries included. With
   `--seat next` this could not happen.

Fix:

- `lxc-add` offers the lowest number that no LXC entry of the team declares, whatever its
  container or checkout, and that no handle of the team's roster holds in any state. Seat
  numbers are cheap, and this needs no guest read.
- Say in C 3.9.2 step 03 that an equal-handle refusal names both entries and is that entry's
  refusal. Either it fails the phase as a declaration error, stated explicitly, or the
  newcomer is `DEFERRED` and the joined one keeps going. Choose one and write it into LX1's
  tests.

### F4. MINOR: after a completed removal, the record entry's fate is unsaid, and `left` entries meet the equal-handle rule

Where: `DESIGN-v2-C-host.md:1838-1860` (the absent phase, step 5) and `1752-1758`.

Failure: step 5 now deletes the host copy, but the text does not say whether the record entry
is dropped or kept as `left`. If it is kept, an owner who moves a seat to another container,
or renumbers it, meets step 03's "handles equal, derived or recorded" against the old `left`
entry, and the new entry is refused.

Fix:

- State that a completed step 5 drops the record entry, as the missing-container case does.
- State that `left` entries take no part in the step 01 key-collision rule or the step 03
  equal-handle rule. Their handle is parked, so the newcomer's join is a `return`.
- Add the test "a seat moved to another container in one play" to LX8.

### F5. MINOR: the user-change refusal costs two applies and is a whole-phase failure

Where: `DESIGN-v2-C-host.md:1716-1720` (step 01).

Failure: "give the entry a new seat, or remove it and add it again in a later apply" is a
step 01 validation error, so it fails every team's present phase until the owner edits
host_vars. The absent phase cannot help, because the key is unchanged, so the seat is not
leaving.

Fix: either keep it as a declaration error but say so (exit, message) in LX1's test list, or
treat a changed `user` for a recorded key as leave-then-join inside one play. The absent phase
then handles the old user's files, under the old user from the record, before the present
phase. The second is the better behaviour and needs no owner round trip.

### F6. MINOR: DESIGN-v2.md's diagram uses a placeholder no grammar defines

Where: `DESIGN-v2.md:47-48`, `teamchat-session-` / `<seat>.service`.

Fix: write `teamchat-session-<team>-<repo>-<seat>-<key>.service` over three box lines, or
write `teamchat-session-…` / `(one per seat, C 3.9.1)`.

### F7. MINOR: the n3b-D2 row sits out of order, and gap 18 keeps history in a scope list

Where: `SPEC-n3.md:901`, which sits between n3b-D1 and n3-D30, and `SPEC-n3.md:853-854`.

Fix: move the n3-D30 row above the n3b-D1 row so the `n3b-` rows follow the `n3-` rows.
Rewrite gap 18 to state the current target only (`<key>.json`, `lxc-<key>`); the "built per
user" history belongs in the rework file.

## Verdict

FIX-FIRST. The design choices are sound: seat required, desired membership per seat, the unit,
session, socket and runtime grammars, and the coordinator through DC6. Their lengths and the
offline rule check out. F1 to F3 are behaviour gaps that the move from `--seat next` to a
fixed seat and from default roots to per-seat roots opened. Each has a concrete fix above.
