## Round 1 findings

01. **Fixed.** `retryOf` treats `add --seat next` on the pending add's prefix as the same
    verb. Probes: a pending add from an explicit seat on the same prefix is taken over by
    `--seat next`. That is harmless, because C 3.6.3 gives `next` to `lxc apply` alone and its
    prefixes have type `lxc`. A pending add on another prefix is rolled forward and the new
    prefix is claimed. A different `human_text` is refused, and `role apply` is a way out the
    operator can run. The crash tests cover ResetPassword, Invite and Send.
02. **Fixed.** A `set` resumes and then runs again, and `start` skips a value that is already
    equal. An `add` with another `human_text` is refused before any write (tested). `return` and
    `reissue` take only the credential kind, and the kind the caller asked for is the one
    issued.
03. **Fixed for the team-wide wedge.** The deactivated-account look is now in `refuse`, before
    `start`, for `add` and `return`. At the `account` step the claim is dropped and `pending` is
    cleared in one save, so a crash between the drop and the save leaves the old record, and the
    next run drops it again. See new findings 2 and 3 for what the drop leaves behind.
04. **Fixed.** `asked` checks the handle and the credential kind against the request, and a
    credential only on add, return and reissue. Failed answers cannot carry a handle or a
    credential (`validateFailure`), so skipping `asked` when `!a.OK` leaves no gap. A lying child
    can still name any number of the prefix for `next`, but the child is trusted with credentials
    anyway, and the bundle is only printed. Tested with 8 lies.
05. **Partly fixed.** A half-made directory is now converged, and a link or a non-directory
    is refused. The convergence still follows a link for `ctl/<team>/`. See new finding 1
    (major).
06. **Fixed.** `withOp` sets the op only when it is empty, and `rollForward` names the pending
    op (tested).
07. **Accepted (n2d-D20).** The document is printed whatever the exit code. The design text for
    C 3.3 and ccy-teams' contract are not updated yet, so the next design sync must carry the
    change.
08. **Accepted (n2d-D20).** "Stdout is empty when no answer came" is in CV3 and is tested by
    `TestVerbInputRefusals`.
09. **Fixed.** `MkdirStatus` makes both levels, and the fixture no longer pre-makes `teams`.
10. **Fixed.** The old drop-in is written when the installed one does not name the version in
    `units.json`, and that is tested. Not covered: a homeserver left *active* on the new version
    is backed up as it is. That needs a start that failed after the unit came up, and I do not

11. **Fixed.** `createOnly` syncs the parent directory after the link.
12. **Partly fixed, accepted.** The C23 retry test now checks that the credential from before

## New findings

1. **major: root still chmods through a path the control user controls, which C 3.2.2
   forbids.** `src-go/internal/teamchat/host/dirs.go:50-61`, called for `ctl/<team>/` at
   `host/apply.go:456`.

   - Evidence: `mkdirMode` runs `os.Mkdir`, then `isDir` (an Lstat), then `os.Chmod(dir, mode)`,
     and `os.Chmod` follows links. `ctl/<team>/` sits in `/var/lib/teamchat-ctl`, which is 0700
     and owned by `teamchat-ctl` (C 3.2.2, line 222). So the control user can rename the
     directory away and put a symlink in its place between the Lstat and the chmod. Root then
     chmods the link's target to 0700, which can be any file on the host (for example
     `/etc/passwd`, which breaks every name lookup). C 3.2.2 says: "Root writes under `ctl/`
     only through the `teamchat-ctl` child, never directly, so the control user cannot steer a
     root write".
   - The round 1 fix widens the window. Before it, the chmod ran only on a directory root had
     just made. Now it also runs on one that is already there, so on every first apply of a new
     team. A `teamchat-ctl` process left running by a compromised child from any earlier team
     can win the race.
   - This is the trust-boundary class the n2c checks found. The `Lchown` that follows does not
     follow the link, so ownership is not exposed.
   - Fix: open the directory with `O_DIRECTORY|O_NOFOLLOW` and use `Fstat`, `Fchmod` and
     `Fchown` on that descriptor, refusing anything that is not a directory owned by root or by
     the intended uid. Or have the child make `ctl/<team>/` itself; root then makes no directory
     under `ctl/`, which is the design's own rule. Add a test that a link swapped in after the
     mkdir is not followed. A seam between the Lstat and the chmod is enough, or show it by
     construction with fd-based calls.

2. **minor: `--seat next` stays refused (70) on a prefix whose lowest free number has a
   deactivated account, and the n2d-D17 drop puts the prefix in that state.**
   `apply/member.go:236` (`nextSeat` reads only the roster), `:254-266` (the refusal before
   start), and `:453-456` (the drop deletes the claim).

   - Evidence: probe `TestProbeSeatNextWedgedByDeactivatedFreeNumber` adds `myrepo.1` with a
     deactivated account and no roster record. Three `add(0)` calls in a row each answer
     `member.add, step account: member myrepo.1… deactivated`, and nothing changes between
     them.
   - Probe `TestProbeDroppedClaimNumberOfferedAgain` does the same after a D17 drop. The dropped
     number is free in the roster again, so `next` picks it every time and is refused every
     time.
   - `lxc apply`, the only caller that uses `next`, cannot choose another number, and no verb
     clears the state. That is the no-manual-fix wedge again, now limited to one prefix.
   - It is reachable only when an account is deactivated outside any verb (or restored that
     way). That is why this is minor.
   - Fix: in D17, keep the dropped handle as `retired` (with a `changed` line) instead of
     deleting it, so n2d-D3's skip covers it. Also make `nextSeat` and the refusal skip to the
     next number for `next` when the chosen number's account is deactivated.

3. **minor: a roll-forward that drops a claim fails the unrelated caller's verb with 70.**
   `apply/member.go:348` with `:457`.

   - Evidence: probe `TestProbeDropFailsCaller`. A pending add of `myrepo.3` has a deactivated
     account. `add --seat 5` then answers 70 (`Drift`, "member.add, step account: member
     myrepo.3… deactivated"), and the caller's own add is never attempted.
   - `pending` is clear by then, so a second call works. But 70 tells ccy-teams and the play
     that the request was refused and should not be retried. The message also names the op
     `member.add`, the same as the caller's own, with no mention that the problem was another
     handle's pending add.
   - The same happens to `team apply` when its `load` rolls such a record forward.
   - Fix: once the drop is saved, report it as a `notes` line and carry on with the caller's
     verb. Or, at least, return a class that maps to 75 and name the pending handle as another
     operation's.

4. **minor: n2d-D18 gives the guest token copy to writers that C 3.2.2 bars from
   `ctl/<team>/`.** `SPEC-n2d.md`, the n2d-D18 row.

   - The copy `ctl/<team>/guest/<handle>.token` lives in the control user's 0700 tree. D18
     makes it "the seat side's or `lxc apply`'s concern". The seat side runs as root or as the
     owner, and `lxc apply` runs as root. Neither may write under `ctl/` (C 3.2.2, lines
     222-224), and the owner cannot even reach that tree.
   - D18's reason, that "apply.Deps has no file seam into ctl/<team>/", does not hold: the same
     package writes `roster.json` and `rooms.json` there through `files`.
   - Fix: write the copy in `credential`'s token branch through the roster file's directory
     (the child owns it), or record the decision as a design change to C 3.6.3 that names a
     writer allowed there.

5. **minor: the drop note is not one of MO8's `CHANGED` forms.** `apply/member.go:456` emits
   `member <h> claim dropped`. MO8's list (`claimed|account created|issued|revoked|…`) does not
   include it, and the play and ccy-teams parse these lines. Fix: add `claim dropped` to MO8's
   list (and to C 3.6.3's line grammar if one exists there), or use `retired` as in finding 2.
