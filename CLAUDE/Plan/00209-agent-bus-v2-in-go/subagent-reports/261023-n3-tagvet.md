# n3-tagvet: project rules over the tagged builds

## Red (the gap)

Planted a rule violation (exec.Command, WaitDelay without ErrWaitDelay) in a file tagged only
for each tag. The driver built from `qa/driver`, run as the analyzers stage runs it:

- Untagged `go vet -vettool=<driver> ./internal/teamchat/...`: rc=0, plants unseen.
- With `-tags busfailpoints` and with `-tags tuwunel`: rc=1, the plants reported
  (`exec.Command outside internal/execx ...`, `WaitDelay set and exec.ErrWaitDelay never named ...`).

## Stages (src-go/qa/go-qa.toml, phase detectors)

Each builds the driver into a temp dir and runs `go vet -vettool=<it> -tags <tag> <scope>`:

- `teamchat-failpoints-rules`: busfailpoints, `./internal/teamchat/...`
- `teamchat-tuwunel-rules`: tuwunel, `./internal/teamchat/...`
- `teams-ccyteamstest-rules`: ccyteamstest, `./internal/teams/...`
- `claude-yolo-difftest-rules`: difftest, `./cmd/claude-yolo/...`

Not covered: `teamchatrelease` (one test file, member/cli; run by the install build).

## Green

- All four stages with a plant in each tagged scope: all four FAILED on the plant
  (`tagvet-red4.log`).
- Plants removed: all four passed (`tagvet-green4.log`).

  as a select case and an `early` timer read non-blockingly once offline is seen.

- `go vet -tags tuwunel ./internal/teamchat/...`, `go test -tags tuwunel -run XXX ./internal/teamchat/matrix/`
