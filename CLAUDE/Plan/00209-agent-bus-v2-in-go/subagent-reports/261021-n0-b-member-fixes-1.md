Interpretations worth a second look:

- 02: the author's `written: false` state is held in memory only (connect and auth). Nothing has
  reached Claude Code then, so a crash leaves the items pending with no `repeat`; the entry is
  persisted as `unknown` just before the user line. This keeps two store writes per delivery
  (finding 11) and means every persisted entry is one whose write may have begun. Items declared
  missing come back marked `repeat`, since their write did happen.
- 02: the quiet clock also starts at the write when the session was idle then (last hook Stop or
  SessionStart); otherwise an idle session that a delivery failed to wake would fire no Stop and
  wait the full hour.
- 05: Claude Code being killed (no SessionEnd reason when the pidfd fires) now posts "disconnected"
  at once from the live worker, instead of leaving it to the next start; `killed` is gone from
  `run.ended.reason`.
- 10: the review's alternative of having the worker accept the host uid was not taken; `fchown`
  keeps the member's owner.
- 11: the ledger also keeps `item`, beyond the author's list, because `reply --verb` needs to know
  whether the target is a ping.
- 12: the floor is defined as just below the oldest item the store still owes (not the plain
  high-water), since every legitimately owed item is older than the high-water and would otherwise be
  dropped.
- A remove that times out leaves the farewell owed; the keeper marks it in `report.json` for area C
  to post (C6).
