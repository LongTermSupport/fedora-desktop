## Findings

1. NIT, `src-go/internal/teamchat/member/guest/places.go:209`. The token probe reads the
   whole token only to throw it away, and the same-identity path then reads it again in
   `replaceIfDiffers`. That costs one extra read of a file of at most 4 KiB and is correct.
   A one-line comment saying the read is a probe, done before anything changes (GU1), would
   stop a later reader removing it as dead code. Optional.
2. NIT, carried over and not new: a token or seat.json the user cannot read (EACCES, for
   example mode 0000) comes back from `homefs` as a plain error rather than `ErrConfig`, so
   `seatFault` does not turn it into 78 bundle. It still stops the op before any change, so
   nothing is unlinked. The same-identity path behaved the same way before this fix, through
   `replaceIfDiffers`. No change is needed for n3a.

## What was checked and holds

- **Order (GU1, GU3).** `into` now calls `sameIdentity` before `holdSeat`, `setAsideStore` and
  `Unlink`. Any read error other than ErrNotExist on `token` or `seat.json` is returned before
  any of those three run.
- **What `homefs.Read` refuses.** A link (O_NOFOLLOW gives ELOOP, which becomes ErrConfig), a
  fifo (opened O_NONBLOCK; `regular` says it is not a regular file), a directory, a file owned
  by another uid, and a file over its cap are all ErrConfig. `seatFault` makes each of them
  78 bundle (`msgSeatFault`). Leaf mode is not a refusal: `replaceIfDiffers` rewrites a file
  that is not 0600.
- **Identity rules (GU3) unchanged.** A missing `seat.json` is another identity, so the op takes
  the hold, finds no store to set aside, and places the files. A regular `seat.json` that does
  not decode is still another identity, so the op sets the store aside and unlinks it. A
  missing `token` is accepted on both paths.
- **Fresh placement.** The `fresh` path is untouched.
- **Held seat.lock.** With an unreadable file and a held seat.lock, the op now exits 78 rather
  than 75, and changes nothing. 78 is right: that fault needs a person, and retrying would not
  clear it.
- **Tests.** `TestPlaceBundleRefusesASeatFileItCannotRead` runs 12 cases: {link, fifo, over its
  cap} × {seat.json, token} × {bundle 1, the same identity; bundle 2, a different one}. Each
  asserts exit 78 bundle, no CHANGED line, the file still there and the store unmoved.
  `TestPlaceBundleRefusesAnotherUsersSeat` now covers a token and a seat.json owned by another
  uid, with the same assertions. The tests run as uid 0, so the chown cases really run; none
  is skipped.
- **Would the tests fail on the old code?** Yes, by reasoning, not by running them on it. The
  old code took the bundle-2 cases down the different-identity path: it set the store aside
  and unlinked seat.json before the refusal. The test's checks that the store is unmoved and
  the file is still there would then fail.
- **Nit 2 accepted without code: sound.** Once seat.json is unlinked, only `Replace` I/O errors
  or `Release` can fail the op, and the host fails the phase on any error. seat.json is then
  absent. The next run treats a missing seat.json as another identity, so it holds the seat,
  finds no store to set aside, and places both files. The seat converges, and no wrong user's
  bundle is ever readable with the new token.
- **Nit 3.** The message now reads "an entry of <list> is over", and the tests were updated
  to match.
- **Gates.** `go test -race ./internal/teamchat/member/...` passes. `golangci-lint run` reports
  0 issues with and without `--build-tags tuwunel`.
