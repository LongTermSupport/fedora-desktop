## What the tests prove

- **PK1, the hooks.** Each `hooks.json` command is read from the file, checked to be
  `<kit>/bin/teamchat hook <arg>`, and run as written through `/bin/sh -c`. The environment
  is clean (CleanEnv): PATH, HOME, XDG_RUNTIME_DIR and the helper's variables.

  - With no TEAMCHAT_RUNTIME, every hook prints `{}`.
  - With a run directory and no link, SessionStart and UserPromptSubmit print
    `hooktext.Context(event, hooktext.Recovery(ReadDown(run).Error(...).Message))`, and Stop
    and SessionEnd print `{}`.
  - Every exit is 0 with an empty stderr.

- **PK1, the status line.** The settings' command is checked, then run as written.

  - With no session it prints an empty line.
  - With a run directory and no link it prints the red `teamchat stopped: relaunch this session`.
  - Every exit is 0. `refreshInterval` is `kit.StatusLineRefresh`, which is 25 and below 30.

- **OF1 through the kit.** A fake link on `link.sock` answers one team `stopped (forbidden)`
  beside the running team's pending counts. The prompt hook, run from the kit, prints that
  line whole and exits 0, and the request it sent is the prompt op.

- **PK2, every agent-facing text.** The scan covers:

  - the 27 corpus files of A 14 (every kind's entry with its authority sentence and `reply:`
    line, the trailing lines, MEMBERSHIP, the frame);
  - `proto.FrameText`;
  - `hooktext.All()`;
  - the client's 69 messages: no-session, restarting, starting, and failed ccy, lxc and host.

  Every `teamchat` command in them parses with `cli.Parse` to an agent verb. The PING's
  `--verb <VERB>` is parsed once with each of ack, nack, done and blocked, and the reminder's
  `thread Q4 --ask` parses. The answer verbs are pinned to those four.

- **PK2, the skill.**

  - Every code span is either a `teamchat` command that parses whole (placeholders filled)
    or a record kind.
  - The prose outside the spans names no command.
  - Every `--flag` in the text is a flag of some agent verb.
  - Every agent verb of `cli.Verbs()` and every kind of `records.Kinds` is named.
  - Each of the four class lines carries exactly its exits from `exits.Table()` and
    `Class.Does()` word for word, in `exits.Classes` order.
  - `teamchat help exit-codes` is named, and the skill is at most 8 KiB.

## Decisions

01. **The skill's source is `skill.txt`, not `SKILL.md`.** The repository's markdown-location
    hook refuses a new `.md` under `src-go/`. The kit writes it as `SKILL.md`, which is the
    name Claude Code reads.
02. **Commands in the skill are code spans, and every span is checked.** A span is a whole
    command or a record kind, and prose holds no command. This is stricter than the
    prototype's skill, whose commands were prose that nothing parsed. A wrong flag, verb or
    placeholder fails the build, not the agent.
03. **The class lines are tied to the code.** Each line carries `exits.Table()`'s exits and
    `Class.Does()`'s words. The skill cannot drift from the exit table, but it still does not
    copy the table (B 2.12 point 5).
04. **The scan of prose texts is bounded by the verb table** (flags, flag values, positional
    arguments). It stops at clause punctuation or a word that is none of these. A word after
    `teamchat` that is no verb must be on a short list of prose words (`delivery`, `is`,
    `has`, ...). So a misspelled verb in a template fails the test instead of passing as
    prose. A lifecycle verb in agent-facing text fails.
05. **Flags are checked for existence, not completeness.** The skill stays short. It names
    `teamchat help <verb>` (as `teamchat help reply`) for the rest. Verbs, record kinds and
    classes are checked both ways, as B 2.12 asks.
06. **The verb-to-record pairing in the skill is not pinned.** The code has no per-verb
    record table, and several verbs are n3d's and n3f's. A pin in the test would be the same
    hand copy as the skill. Each kind named must exist, and every kind must be named.
07. **The help listing and the exit-codes text are not scanned.** They are generated from
    the verb and exit tables themselves, and their usage forms (`[--team T]`) are grammar,
    not commands.
08. **PK1 runs the commands through `/bin/sh -c` in a clean environment**, as Claude Code
    runs them. The child gets a GOCOVERDIR, because a `-cover` test binary warns on stderr
    without one. The test checks stderr is empty. The shellStrings rule exempts test files,
    so no table row was needed.
09. **The status line with no session prints `"\n"`**, n3e-5's behaviour. It is pinned as
    built: Claude Code draws an empty line. If the lead wants a truly empty stdout, that
    change is in `statusline`.
10. **The import scan uses go/build from source, not `go list`.** No process is started and
    every build tag is covered. It also refuses `testing` and `reexec`, not only the two
    fakes.
