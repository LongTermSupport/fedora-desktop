# N2 slice n2b: the declarations, the DC18 approval gate and apply

Branch `feat/bus-v2-n2b`, stacked on `feat/bus-v2-n2a` (f3aa1bb0). The contract is
`SPEC-n2b.md`. Three builders worked on it in turn; their handoffs are `261022-n2b-handoff.md`
and `261022-n2b-handoff-2.md`. Everything is inert code. Nothing installs, runs as root, or is
wired to a verb, so gates A and B are untouched: no play, task, unit or sudoers file is in the
diff, and no pool password is handled.

## Review

| Round | File                     | Verdict                            | Outcome                                                                                                        |
| ----- | ------------------------ | ---------------------------------- | -------------------------------------------------------------------------------------------------------------- |

Nothing is left open. The round 1 findings:

1. `team apply` erased another operation's `pending` record. Now refused (D22).
2. A tagged top-level merge key was ignored here, but PyYAML merges it. Now refused (D19).
3. A key with a control character was echoed, so an error could forge a `CHANGED` line. Keys
   that do not print are now quoted (`declare.KeyText`).
4. `TestApproveRefuses` passed whatever the change logic did. It now asserts that the refusal
   comes from the change itself.
5. A Jinja template in a v2 string was read as text. Now refused (D23).
6. An account apply adopted printed nothing. It now prints a line (D14).
7. `Run` had no test for a team never approved. Added.

The N0 re-check's two DC18 findings are closed:

- Finding 4: `--only` compares every gated field against the approval with the one change
  applied, so an entry planted beside the owner's `--add` is refused (`TestApproveRefusesAPlantedEntry`).
- Finding 5: an Element entry takes `team` alone, so a `base_url` is refused as an unknown key,
  and the profile's URL is the approved `url` (DR1, AG1).

## Decisions

| ID      | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| n2b-D1  | `trust` is exactly A's `forge` section (`kind` required, no `forge_api`). C 3.8 says its example keys are v1's and the shape is A's.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| n2b-D2  | The gated `url` is the resolved one, so the default URL's inputs (`teamchat_address`, `port`) are gated through it. `port` alone is not gated.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| n2b-D3  | A list field is compared and approved as a set of entries. A reorder is no change. Each entry is one SECURITY line and one `--add` or `--remove`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| n2b-D4  | An absent team is not compared, since removal narrows access. Its `approved.json` is left to `team remove` (not built).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| n2b-D5  | The one-team input carries that team's LXC entries and the address, so `team apply` can compare every gated field DC18 names, LXC members included.                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| n2b-D6  | A coordinator who is retired, or whose `human_text` is false, is refused before any change, rather than demoted first and then failed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| n2b-D7  | A human's file state is `active` or `removed`, and `removed` is locked on the server. The roster event carries only the `active` declared humans.                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| n2b-D8  | While apply runs, `pending` is `team.apply` with the step. Room creates are its `create <purpose>` steps (the engine's intent). Apply clears it at the end, and a leftover `team.apply` record is resumed.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| n2b-D9  | The admin's `role` notice is not posted here. Apply returns each role change, and the verb that posts notices (a later slice) posts it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| n2b-D10 | `keepout` is a new row kind of the go-deps gate (Plan 00204's), so the DC17 rule lives in the gate the design names rather than in a test of one package.                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| n2b-D11 | A declaration error never echoes a value, and it quotes a key that does not print, so the play may print the error as it is.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| n2b-D12 | The roster file has one member intent state, `claimed`: a handle `member add` claimed before its account exists. A member `kind` is `^[a-z][a-z0-9-]{0,31}$`. `cred` is `password`, `token` or null. A member's `needs` is null or `reissue`; a human's is null or `password`.                                                                                                                                                                                                                                                                                                                                                |
| n2b-D13 | Reading the two files is a failure step of its own, `files`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| n2b-D14 | `apply.Run` judges every declared human's account before the first change: an admin or deactivated account is refused with 70, so a refusal changes nothing. A declared account that exists but is not in the file is recorded `active` with `revoked_seq` 0 and prints `human <name> adopted`, since apply did not make it.                                                                                                                                                                                                                                                                                                  |
| n2b-D15 | The roster `rev` the engine wrote is stored even when the engine then fails (C 3.6.1: the file's rev follows the server's acceptance).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| n2b-D16 | `DeriveRoster` validates with A's `Roster.Validate`, using placeholder room IDs and a `rev` of at least 1. So a roster A refuses (one with no active human, say) stops before any room is created. The engine's own decode before the write stays.                                                                                                                                                                                                                                                                                                                                                                            |
| n2b-D17 | AP12's "roster event from the approved team while a different `trust` sits in the input" cannot happen through `Run`, because the gate refuses any difference. It is tested as `TestAsApproved` over `asApproved`, which takes the gated scalars from the approval.                                                                                                                                                                                                                                                                                                                                                           |
| n2b-D18 | AP12's `VerifyMain` needs a member to verify as. The new-team test checks the files and the second run. `VerifyMain` runs once members are in the file: in the wanted coordinator's promotion test, and in the tagged Tuwunel test.                                                                                                                                                                                                                                                                                                                                                                                           |
| n2b-D19 | At the top level, `hostvars` refuses a merge key, an alias key and any tagged key, since each could carry a v2 key not written as one; PyYAML merges by the key's tag (`!!merge` on any text, or a `%TAG` spelling), not its text. It also refuses more than one YAML document, and a `host_vars/<host>/` directory beside the file. It reads `teamchat_address`, `teamchat_teams`, `teamchat_lxc_members` and `teamchat_element_teams`; `teamchat_migrations` is D's and ignored here. A plain scalar is judged by both PyYAML's YAML 1.1 resolver (Ansible's) and the YAML 1.2 core schema, so `192.0.2.10` stays a string. |
| n2b-D20 | Every approve refusal is a `declare.RefusedError` (a bad op or value, a change that changes nothing, a mismatch), all exit 70 through `admin.ExitCodeOf`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| n2b-D21 | A one-change `lxc_members --add` of a container and user already present (with the other `human_text`) is refused: that change is `--set`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| n2b-D22 | For now, `team apply` refuses (70, step `files`) a roster file whose `pending` record is another operation's, before any change. It names the op and step, quoted. C 3.6.3 (C20) says a later verb first completes the pending operation, but no member verb or roll-forward is built yet, and erasing the record would lose a `needs: reissue`. When the member verbs land, this becomes C 3.6.3's roll-forward (carried on PLAN.md Task 2.3).                                                                                                                                                                               |
| n2b-D23 | `hostvars` refuses a v2 string that holds `{{`, `{%` or `{#`. Ansible templates every string it reads, so the play would not read the text as written, and ccy-teams' board would show something other than what is applied.                                                                                                                                                                                                                                                                                                                                                                                                  |
