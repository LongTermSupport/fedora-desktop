## 4. TestWriterRefusesABindMount runs here

It now runs on the real kernel through `reexec`, in an unprivileged user and mount namespace,
and passes in this container.

`execx` is in the ccy Go front's build, so the pre-commit demands a `CCY_VERSION` bump. The
lead ruled (a): CCY 3.99.14.11 to 3.99.14.12 with a `docs/ccy-changelog.md` entry (a test-only
field, ccy's behaviour unchanged), and **no meta-deploy entry**: the N3 branches' bumps are
renumbered once above F44's at the F44 merge, and the lead queues the one deploy then.

- `execx.Cmd.UserNamespace` (new, set only by tests, as its doc comment says): the child is root of a new user namespace mapped to this
  process's uid and gid, with its own mount namespace (`CLONE_NEWUSER|CLONE_NEWNS`, one-id maps).
  A credential beside it, and `Exec`, are refused `ErrBadCmd`. Tests (`execx/userns_test.go`):
  the child's `uid_map`/`gid_map` are `0 <uid> 1`/`0 <gid> 1` and its mount namespace differs,
  with and without `NewSession`; the two refusals. A kernel that refuses (EPERM, ENOSPC) skips.
- `reexec.StartInUserNamespace(tb, name, args...)` (new): `Start` with that field; a kernel that
  allows no such namespace skips the test. `start`'s "ended before it was ready" error now wraps
  the run error (`endedEarly`), so the skip can tell a refused namespace from a helper that
  failed. Tests: a helper that is ready only as root of a namespace mapped to the parent's uid;
  `endedEarly` keeps the error.
- `guestroot`: the test starts the `bindMount` helper with the fixture tree and a bind source.
  The child opens the root, proves a write crossing no mount succeeds (so the ownership mapping
  is right), bind-mounts the source on `/usr/local`, and requires `MkdirAll(kit parent)` to be
  `ErrRefused` wrapping `EXDEV`.

Proof: `go test -race -count=3 -shuffle=on` on guestroot, reexec and member/guest is ok, and
