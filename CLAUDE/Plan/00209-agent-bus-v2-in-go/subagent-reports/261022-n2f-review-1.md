# n2f review, round 1: adversarial security review of the production wiring

Diff `71857e2f..HEAD`, vendor excluded. What was run, in `src-go` of the worktree:

- `go vet` and `go test` over `internal/execx/...`, `internal/teamchat/...` and
  `cmd/teamchat-admin/...`: clean and green. The scratch `dbus-daemon` test in `units` ran; it
  did not skip.
- `golangci-lint run` over the changed packages: 0 issues.
- `go mod verify` passes, and `go build -mod=vendor ./...` is consistent. `go list -deps ./cmd/teamchat-admin` contains godbus and no YAML module.

## Verdict: FIX-FIRST

There is one blocker. A homeserver unit is identified from the last element of a process's
cgroup path, and the owner can forge that element. This defeats the step 2 port refusal and the
step 9 address assertion. It also sends the bootstrap's fresh admin password, and every later admin
token, to a process the owner runs.

The rest of the trust boundary holds:

- **Root's own files.** The pin, owner-group and os-release files are opened with no-follow,
  non-blocking and close-on-exec, then fstat'ed, required to be regular, owner-checked and capped.
  `team.json`, the stamps, the migration state and the status records all live in directories
  only root can write (status is 0750 root:group).
- **The child's own files.** The ctl dir is held open by fd, with owner and 0700 checked. Every
  file in it is opened with openat, no-follow and non-blocking, and written link-not-replace.
- **The answer.** It is capped before it reaches memory and decoded strictly. The answer has to
  fit the op, `main_room` must come exactly with a credential, and a view must re-encode as a
  record.
- **The start.** The credential is set, setgroups(0) runs, the environment is replaced, the
  directory is `/`, and no fd is inherited (every fd root opens is close-on-exec).
- **JobRemoved.** A signal counts only from systemd's current unique name, it is matched before
  the call, and early signals are kept.
- **Gates.** Gates A and B hold. v1 is untouched: the diff touches nothing outside `src-go/` and
  the plan folder. The go-deps row, go.mod, go.sum and modules.txt agree.

## Findings

### 1. Blocker: a listener's unit is the last element of the cgroup path, which the owner can forge

`src-go/internal/teamchat/hostnet/network.go:346` (`cgroupUnit`), used by `holder` at :292.

**What is wrong.** Any process whose cgroup v2 path *ends* in `teamchat-server@<team>.service` is
attributed to the team's unit. The owner controls a delegated cgroup subtree under
`user@<uid>.service`. They can run `systemd-run --user --unit=teamchat-server@alpha.service ...`,
or simply mkdir that name under their subtree and move a process into it. That process gets the
path `0::/user.slice/user-1000.slice/user@1000.service/app.slice/teamchat-server@alpha.service`,
and `cgroupUnit` answers `teamchat-server@alpha.service`.

**What follows.**

- Host step 2 (`host/apply.go:347`, `l.Unit != a.unit`) accepts a squatter on the team's port.
- The real server cannot bind the port. RD1's readiness probe is then answered 200 by the
  squatter.
- Step 9 (`host/apply.go:804`) counts the squatter's sockets as the unit's.
- Bootstrap step 1 then sends the fresh admin password and the registration MAC to the squatter.
- On a team whose admin already exists, every child op and every health view sends the stored
  admin token to the squatter.

This is root deciding from state the owner writes, which the slice's trust rule forbids. C 3.2.5
says the port is refused unless the listener "is this team's own `teamchat-server@<team>`". A
name match is not that. `TestCgroupUnit` (`network_test.go:150`) enshrines the weak rule, and it
has no case for a user-subtree path.

**Fix.** Attribute by systemd's authority, not by the name:

- Either ask systemd for the holder with `Manager.GetUnitByPID(pid)` over the Manager the wiring
  already holds, then compare the object path with `LoadUnit(a.unit)`'s.
- Or compare the process's full `0::` path with the team unit's `ControlGroup` property, read
  over D-Bus.

Do not hard-code `/system.slice/<unit>`. Template instances live in
`/system.slice/system-teamchat\x2dserver.slice/<unit>`. Add red cases for:

- the user-subtree path above;
- a `.../<unit>/child` sub-cgroup;
- a lookalike under `machine.slice` or `lxc.payload`.

### 2. Minor: root connects to whatever bus `DBUS_SYSTEM_BUS_ADDRESS` names, and finds `firewall-cmd`, `systemctl` and `journalctl` on the inherited `PATH`

Locations: `src-go/internal/teamchat/units/bus.go:13`, `hostnet/firewall.go:117,126`,
`units/units.go:632,643`.

**What is wrong.** `dbus.ConnectSystemBus()` reads `DBUS_SYSTEM_BUS_ADDRESS`, which can name a
`unix:` or `tcp:` address (vendored `conn_unix.go:17`). A bus there that answers as
`org.freedesktop.systemd1` makes root believe any job ended `done` and any state it reports. The
three programs run by bare name, with root's whole environment passed through.

**Why only minor.** Today sudo's `env_reset` and secure_path, and the timers' systemd
environment, strip both variables. So this is defence in depth, not an open hole. But it is the
same class as the trust rule: root deciding from input the caller controls.

**Fix.**

- Dial `unix:path=/run/dbus/system_bus_socket` explicitly: `dbus.Dial`, then `Auth(nil)`, then
  `Hello`. The scratch-daemon test already injects its own `dial` through `machine.dial` and
  `NewManager`, so it needs no environment.
- Run `/usr/bin/firewall-cmd`, `/usr/bin/systemctl` and `/usr/bin/journalctl` by absolute path,
  with `CleanEnv` and `PATH=/usr/bin:/bin` (and `LANG=C` where the exit status is all that is read).

### 3. Minor: nothing bounds a child's run, a D-Bus job wait or the bus dial

Locations: `src-go/internal/teamchat/admin/execchild.go:38-55`, `units/units.go:472`, `units/bus.go:13`
(n2f-U8).

**What is wrong.** `main` passes `context.Background()`, and no new code sets a deadline.
`capped.Write` drops what is over the cap, but it keeps draining. So a child that writes forever,
or never exits, keeps root reading for as long as the verb runs. Meanwhile `health --all` holds
that team's lock. The matrix client's own per-try timeout bounds an honest child, but the review's
premise is a lying one. A JobRemoved that never comes, or a bus that accepts and never
authenticates, hangs the same way.

**Fix.**

- Give `ExecChild.Ask` a per-op deadline (`context.WithTimeout`; team.apply larger).
- Bound the job wait by a constant above systemd's TimeoutStartSec, plus a slack.
- Dial through a goroutine raced against the context.

### 4. Minor: the root-to-child pipe is never run as two real processes

Location: `src-go/internal/teamchat/admin/execchild_test.go` (all through `execx.Fake`).

**What is wrong.** EX1's credential is proven on `/usr/bin/cat` (`execx/credential_test.go:119`).
The caps, the exit and answer rules, and the CleanEnv are each proven on the Fake.
`checkStarted` (CC2) is proven on a fake `Process`. No test starts `ExecChild` over `execx.OS`
and has a real `ctl-child` check its own start and answer. So nothing shows that the start
`ExecChild` builds is one the real child accepts. For example, Go adds `PWD` only when `Env` is
nil, so it works today, but no test holds that. The tests already run as root in the container.

**Fix.** Add a root-gated test (skip otherwise) that re-execs the test binary as `ctl-child`
through `ExecChild{Runner: execx.OS{}, Self: os.Executable()}` under a scratch uid and gid. It
should assert:

- one op answered ok;
- an oversized answer refused;
- a stray environment variable refused by the child.

### 5. Minor: a crash leaves `.admin.password.<hex>.tmp` and `.admin.token.<hex>.tmp` holding the secret, forever

Location: `src-go/internal/teamchat/ctl/ctl.go:352-374` (n2f-C9 accepts this).

**What is wrong.** A crash between `Openat(O_EXCL)` and `Unlinkat(temp)` leaves a full copy of
the password or the token. No path removes it. OP3 says the password is deleted once the token is
stored, and a stray copy contradicts that. The copy is inside a 0700 dir the child owns, which is
why this is only minor.

**Fix.** In `Open`, before `bootstrap.token`, unlink every entry matching
`.admin.{password,token}.*.tmp` through the held dir fd. The team lock makes this safe. Add a crash
test that plants one.

### 6. Minor (design, for the owner): the admin token goes to whatever listens on `127.0.0.1:<port>`

Location: `src-go/internal/teamchat/ctl/ctl.go:91`, and the readiness and probes in
`hostnet/probe.go`.

**What is wrong.** Only `team apply` checks the listener (finding 1). Every later child op and
every health view (`team.view` uses the admin token, every 60 s) connects without checking who
holds the port. A process that binds the port while the server is down collects the admin token
and gains full admin of the homeserver. Down means after a crash, in a restart window, or after
`team remove` without purge.

This is not this slice's to fix. C 3.2.5 is silent on it. A recorded decision is needed: accept
it, check the listener's holder before each child op (racy), or move the server to a unix socket.

### 7. Nit: some bus errors that mean systemd is unreachable do not drop the connection

Location: `src-go/internal/teamchat/units/units.go:369` (`dbusError`).

**What is wrong.** SD7 says a bus that cannot be reached is "systemd is not reachable". But the
named errors for that state fall through to `namedError` (ErrSystemd), and the connection is
kept. These are `org.freedesktop.DBus.Error.ServiceUnknown`, `NameHasNoOwner`, `NoReply` and
`Disconnected`.

**Fix.** Map them to `ErrUnreachable` so `failed` drops and redials. Add one fake-conn case each.

### 8. Nit: the team.apply answer is not held to its op

Location: `src-go/internal/teamchat/admin/verbs.go:462` (`bootstrap`).

**What is wrong.** `asked()` is applied to the member verbs only. A `team.apply` answer that
carries a handle, notes, or a credential with `main_room` passes `judge`, and is then silently
ignored. Nothing is written from it, so this is a nit.

**Fix.** Refuse those fields for `team.apply` as `lie(...)`, as the member verbs do.

### 9. Nit: a second trusted-file reader beside `state.ReadFile`

Location: `src-go/internal/teamchat/admin/hostfiles.go:37-74`.

**What is wrong.** The SPEC says "`state.ReadFile` is the one reader". `readRootFile` and
`readOwned` re-implement it and add the owner and mode check.

**Fix.** Move the owner and mode check into `state` as one reader (for example a
`state.ReadRootFile(path, limit, owner)`), and call it from here.
