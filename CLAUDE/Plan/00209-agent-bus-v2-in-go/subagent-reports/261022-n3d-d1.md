## Decisions and departures from the brief

1. **20's new code is `forge-down`, not `forge`.** `forge` is already 13's code (unresolved,
   n3d-D11), and `exits` holds one exit per code (`TestEveryCodeHasOneExit`; `exits.New` takes
   the exit from the code). D6a returns 20 `forge-down` for a forge with no answer.
2. **Pending and ledger entries are 448 bytes, not 320.** The brief said the verb fits 320; it
   does not: the largest agent ping item with its verb is 330 bytes, and a TIMEOUT item keyed on
   the longest localpart (`<event>~<103-byte localpart>`) is 432 bytes, which B's 320 never held
   (a latent defect: such an item would have made the store refuse its own write). `fullStore`
   now builds those largest entries, so the caps are proven against them. The file cap is the
   new sum (3 001 136 bytes) rounded up to the next 256 KiB: 3 MiB, not about 2.6 MiB.
   Proposed B 2.3.2 text: "pending and ledger entries 448 bytes (a TIMEOUT keyed on the longest
   localpart is 432)".
3. **The 20 KiB `sending` entry size cannot be exceeded by a valid entry**: the content's own
   16384-byte rule fires first, and the largest valid entry (content at its cap, a review ping to
   16 of the longest user ids with a 700-character reference) is under 20 KiB, which a test
   proves. "An entry one byte over" is tested as a content one byte over its cap.
4. **`ping` is checked one way**: a `ping` part needs `kind` `ping` and an answer-expecting verb;
   a `ping` send with no part is allowed (a `done` or `blocked` sent by `ping`, n3d-D15). The
   store does not read the content to prove an answer-expecting ping carries its part; D6a sets it.
5. **`MaxRosterCache` is 65 KiB**: a roster is a state event, which Matrix caps at 65536 bytes
   whole, so its content is under that; a test holds a cache with a 65536-byte content within
   the cap. `RosterCache` is not registered in paths' `zeroDerivations` (that list is for the
   guarded types; `Seat` methods are not in it); `Seat.RosterCache` is in `sampleNames`.
6. **Two tiny behaviour edits keep the tree green under the new verb rule**: teamsync's `take`
   sets `Pending.Verb` from `v.Content.Ping.Verb` for a ping item, and the engine's `Ack` copies
   `Verb` into the ledger. Without them the first delivered ping would make the store refuse its
   write. Both have tests (`TestDeliversAgentItems`, `TestN3dD30AnAckedPingKeepsItsVerb`).
7. **`SayArgs.To` and `PingArgs.To` accept `null` as well as `[]`** (the strict decoder's round
   trip cannot tell them apart for a nil slice); D5's client and D6a should treat both as no
   addressees.
8. `team.ForgeProven` is added beside the brief's `ForgeResult`, so the proven outcome has a name;
   the failing outcomes reuse proto's reason constants.
9. The ends fake already embedded `team.Engine`; it gains explicit no-op `SaveRoster` and
   `RecoverSends` anyway, as the lead asked. `member/client` tests have no `team.Engine` fake.
