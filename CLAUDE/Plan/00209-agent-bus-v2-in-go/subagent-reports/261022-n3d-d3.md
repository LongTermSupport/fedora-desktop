## Decisions and departures from the brief

1. **A TIMEOUT is due at deadline + 30 000 + 1 ms, not at + 30 000.** proto's `TimeoutDue`
   (A 8.3: "passes") is strict; one definition of due is kept. SD4-1 tests none at + 30.000 s
   and one at + 30.001 s; the timer arms for `due + 30 001 - WallMS()`.
2. **Pruning at exactly `due + (due - sent)`** (`now >=`), none 1 ms before, as SD4-9 reads.
   Status hides a ping by the same predicate even before the write that prunes it.
3. **`seat set-aside` unlinks `roster.json` instead of moving it aside.** Moving it needs a new
   name in `paths` (a shared file) for a file that is only a composing aid; a restored aside store
   simply waits for its first verification. The same hunk also covers the place of a different
   identity's bundle, which sets the store aside through `setAsideStore`.
4. **A missing `roster.json` is logged at Add** (one line), as the brief says; a seat.json not
   read is no cache (the decode needs its anchors), and `SaveRoster` refuses then.
5. **The cache's rev must equal the decoded roster's `rev`**, else no cache.
6. **An echo is applied before the batch's answers**, so an answer in the same batch is judged
   against the server-time deadline. An echo for a ping not in the outbox is ignored silently
   (n3d-D9 allows it).
7. **Persist sets the pending verb from the verdict for every new `ping` item**, overriding a
   verb teamsync set (D1 decision 6), so the store's verb is always the verdict's.
8. **A refused TIMEOUT write**: `held.timeoutRetryMS` holds the retry's wall time; the timer
   arms for the later of the due time and the retry; the failure is logged once until a write
   succeeds (no line on recovery). Successful TIMEOUT writes prune too.
9. `TestN3dTheSendSeamsAreThere` became `TestN3dTheRecoverySeamIsThere`, since `SaveRoster`
   is no longer a no-op and refuses an unheld team.
