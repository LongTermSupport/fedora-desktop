Branch `feat/bus-v2-n3d-d4`, cut from `feat/bus-v2-n3d` at 0194f1505 (D1 merged). One code

## What was built

- **Answers (SY4, A 8.2).** `take` appends a `team.Answer{Ping, From, Verb, ID, OriginMS}` to
  `Batch.Answered` for a `Record` verdict with an `Answer` (an `ack`, or a stale answer) and for a
  delivered verdict with an `Answer` (`nack`, `done`, `blocked`, still queued as its PING item).
  `From` is the sender's **user id** (what the outbox's `to` and `OwnPing.To` hold). `OnTime` is
  not passed (D3 judges by `due_ms`, n3d-D8).
- **Echoes (A 7.6 rule 3, n3d-D9).** An event ignored `self` whose id is in the View's
  `OwnPings` gives `team.Echo{ID, OriginMS}` in `Batch.Echoes`. An own text gives none.
- **A batch holding only answers or echoes is persisted**: `empty` now counts both, or an `ack`
  alone (a `Record`, which counts nothing) would have been lost.
- **The receive forge check (SD5, n3d-D29, D10, D12, D25)**, `forge.go`. After every event of an
  answer is judged, the verdicts with `Outcome == Deliver` and `Forge != nil` are checked through
  `Config.Forge`, at most 8 at once, under one 30 s `Clock.Hold` for the batch, before SY6's
  epoch read and SY5's persist. Proven: unchanged (its trust stays `ForgeCheck.Trust()`).
  `provenance`, `unresolved`, `forge-rate`: the verdict becomes `Drop` with that reason and its
  `Answer` cleared, so `take` counts it and logs `dropped <id>: <reason>` once. Any error
  (`ErrForgeDown` included), an outcome with no name, a nil `Config.Forge`, and a check still
  running or not yet started at 30 s are all `unresolved`. `ErrForgeLogin` is `unresolved` plus one
  line naming `forge-login`, said once per team goroutine until a check is next answered (any nil
  error). A `Record` answer is never checked; a carried ping has no `Forge` and is never checked.
- **Refetch runs the same check** on its one verdict and returns the drop (n3d-D12).
- **The roster cache (n3d-D3).** Every verification (the session's `verify`, and `rosterFor`'s
  fallback for Verify/History/Refetch) calls `Engine.SaveRoster(ctx, team, rev, content)` when
  `rev` differs from the last rev saved; `content` is the roster state event's `content` exactly
  as main's state returned it (re-compacted through `proto.Parse`). A failure is one line
  (`the roster at rev N was not cached: ...`), blocks nothing, and is tried again at the next
  verification; `ErrRemoved` is not said.
- **The recovery call (n3d-D4).** `session` calls `Engine.RecoverSends(ctx, team, t.Notices())`
  after the start verification and before `Load`, SY1's start (which judges the resume's events),
  the ends and the first long-poll; once per team goroutine, so a session restart (a suspend, an
  epoch change, a backoff) does not call it again once it has succeeded. Its error is returned
  from the session: a transient one is SY8's backoff, with no long-poll sent.
- **A context ended during the checks drops nothing**: `judgeAll` and `Refetch` return the
  context's error after the check, so a link stopping never persists pings dropped `unresolved`
  only because their checks were cancelled.

## go doc facts relied on (section 2c)

- `proto.Judge.agent` sets `v.Forge` before deciding an answer, so a `Record` verdict can carry a
  `Forge`: D4 checks only `Deliver` verdicts.
- `proto.Verdict.Answer` is set for `Record` (ack or stale) and for a delivered answer;
  `proto.Answer` has `Ping`, `Verb`, `OnTime` and no sender, so `From` comes from `v.Event.Sender`.
- `IgnoreSelf` is decided after `Seen`, before the sender's class: an own event is never `Seen`
  (own sends are not in pending or the ledger), so every own ping reaches the echo test.
- `proto.ForgeCheck.Ref.Text` is the reference as sent; `Roster.Forge` is the allow-list a
  check is given.
- `clock.Clock.Hold` is the budget's timer (a `*clock.Fake` in tests).

## Decisions

1. **RecoverSends is once per team goroutine, not once per session.** The brief says "once per
   start"; a session restart is not a link restart, and the team's live sender (D6a) owns the
   sends of a running link. It is retried only until it first succeeds.
2. **RecoverSends runs before SY1's start, not only before the first long-poll**: SY1 (b)
   judges the resumed events, so a recovered ping must be in the outbox before that, as n3d-D4
   requires ("before any answer to it is judged").
3. **The roster content is taken from main's state as read**, not `Roster.Encode()`, so the
   cache holds what the admin wrote.
4. **A failed `SaveRoster` is retried at the next verification** (the saved rev moves only on
   success); each failure is one line. Verifications are rare (start and SY14's triggers).
5. **The forge-login line is said at commit** (after the persist) for a sync, and at once for
   `Refetch`; the "said" state is shared and resets on any check the forge answered.
6. **A check that hangs past its budget is abandoned, not waited for**: its goroutine ends when
   the forge honours the cancelled context; its result channel is buffered so it never blocks.
