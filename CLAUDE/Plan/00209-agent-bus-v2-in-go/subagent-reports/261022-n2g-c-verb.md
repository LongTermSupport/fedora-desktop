## What was built

- **health (HB2, HB3).**
  - `health.RestoreState{Restore *status.Restore; Problem status.Problem}` and the
    `health.Restores` interface (`State(ctx, team)`) are in `health/restores.go`.
  - `Config.Restores` is a new required part, and `New` refuses a config without it.
  - The tick reads the restore state before the homeserver's steps. A read error fails that
    team's tick before any probe, so nothing restarts on a guess.
  - A recorded restore adds its problem, and the tick writes `rec.Restore` every time (null
    when there is no record), in the tick and in `Refresh` alike.
  - While a restore is recorded, a missed probe is recorded as missed. There is no re-probe
    and no restart (`probe.go`, beside `f.held`).
  - `base`'s comment no longer says the restore field is another writer's.
- **restore.Records{Root, OwnerUID}** is the `health.Restores` (`restore/records.go`).
  - It reads `restore.json` with `state.ReadOwnedFile` (OwnerUID: 0 on a host) and decodes it
    strictly with `DecodeRecord`.
  - Problems:
    - `staged` is "restore staged", fixed by `teamchat-admin restore --team T --resume, or teamchat-admin restore --team T --discard`;
    - every other step is "restore interrupted", fixed by `... --resume`;
    - an offline record appends " (offline)".
- **restore.Recorded(root) teamlock.Guard** is the guard for `--resume` and `--discard`
  (RG3). It refuses with a `RefusedError` (70) when no `restore.json` exists. It is built on
  `Guard`, so a link or a directory counts too, and a failed look is a failure, never a pass.
- **restore.ErrUnproven** is a `*RefusedError` (so it is 70) with RW2's text.
- **The verb** (`admin/restoreverb.go`):
  - `restore` is added to the runs map.
  - `System.Restore func() (Restorer, error)` is a new seam.
  - Order of work:
    1. `e.system()`;
    2. the flags (64);
    3. for `--lost`, the export print, with no lock and no engine;
    4. otherwise, the engine seam: nil is 78, and a refusal is 70 before the lock;
    5. `teamlock.Take(..., "restore", host.PlayWait, ...)` with `restore.Guard` for a fresh
       restore and `restore.Recorded` for `--resume` and `--discard`;
    6. the engine's Run, Resume or Discard;
    7. the lock released, the answer printed if there is one, then the error mapped by
       `ExitCodeOf`.
  - `exit.go`: `restore.ErrRefused` maps to 70.
- **The 64 cases.**
  - `--team` is always required.
  - A fresh restore needs `--backup N`, with optional `--offline` and `--roster-from-backup`.
  - `--resume` and `--discard` take nothing else (RO2: the record decides).
  - `--lost` takes only `--backup N`.
  - The three modes exclude each other.
  - N is decimal, from 1 to 2^53-1, with no sign and no leading zero.
  - The parser's own rules give 64 as well: unknown flags, repeated flags, extra arguments
    and missing values.
- **--lost (RS14)** reads `ctl/<team>/restore-<N>-lost.jsonl` with `ReadOwnedFile`, using
  the ctl account's uid from `CtlIDs` (capped at 64 MiB).
  - Every line must parse with `proto.Parse` as an object. It is printed with `Compact`, which
    escapes C0 controls.
  - An empty line is refused; only the final newline is allowed.
  - Nothing is printed unless every line passes, and the error names the line number, never
    its content.
  - A missing export is 1, and a ctl account that cannot be read is 78.
- **run_test.** `TestFlagsBelongToTheVerb` used `restore --resume` as an unbuilt verb. It now
  uses `redact --resume`.

## Decisions (the spec is silent)

1. **Recorded guard.** `--resume` and `--discard` with no record are a refusal (70) from
   their guard: "no restore of team T is recorded: there is nothing to resume or discard".
2. **The engine seam comes before the lock and after the flags.** A bad command line is 64
   even in production, where the engine is refused. `--lost` skips the seam: it only reads,
   so DC8 does not apply to it.
3. **No engine wired is 78** (a wiring defect), not 70.
4. **Lock wait** is `host.PlayWait` (10 min), as the owner's backup verb waits. The lock's
   holder verb is `restore`.
5. **Blank lines in the lost export are refused**, since every line must be one object.
6. **The lost file's owner check** uses the ctl uid as it is (0 allowed), because the test
   container runs as root. `accountID`'s refusal of 0 is for the child's start, not here.

## Merge glue

1. **The engine adapter (C7).** `admin.Restorer` must be implemented over `restore.Deps`:

   - `Run(ctx, held, admin.RestoreRequest{Team, Backup, Offline, RosterFromBackup}) ([]byte, error)`;
   - `Resume(ctx, held, team)` and `Discard(ctx, held, team)`, with the same returns.

   The answer is RS9's or RS13's JSON (nil when there is none), beside the error. The verb
   holds the lock, so the engine must not take it. If the engine's own request type differs,
   C7 wraps it; a small struct in wire will do. In production, `System.Restore` stays
   `restore.ErrUnproven` until DC8.

2. **Exit codes.** `restore.ErrRefused` (and so `RefusedError`, `ErrUnproven` and
   `Recorded`'s refusal) is 70 in `verbExit`. For RS15's 69, the engine must wrap
   `matrix.ErrUnreachable` (or a `ChildError` of the unreachable class) when a homeserver
   that answered at validation is lost mid-step.

3. **Name collisions.** `restore.Records`, `restore.Recorded` and `restore.ErrUnproven` are
   new in `restore/records.go` and `restore/unproven.go`. I told `n2g-c-engine` not to define
   them. If the engine branch has its own record reader, `Records.State` can switch to it.

4. **health.** Part B's HB1 removes `NoBackups`. `files_test.go` and `health_test.go` will
   conflict at the Config literals, which now carry `Restores: w.restores`, and at the world
   struct, which has a `restores` field. Keep both sides. wire's
   `Backups: health.NoBackups{}` line now also holds `Restores:`, so keep that field when B
   swaps in `backup.States`.

5. **The `Status.Refresh` events signature** (A3) does not touch this work: the verb never
   refreshes, since RS8 step 7 is the engine's.

6. **Tests to adjust after the merge.**

   - `TestEveryVerbEveryClass` expects `restore` with no arguments to print the "not wired"
     line when Sys is nil. That holds, because `e.system()` runs first.
   - If part B builds `backups` or `backup`, `unbuilt()` handles it through `rootRuns`.
