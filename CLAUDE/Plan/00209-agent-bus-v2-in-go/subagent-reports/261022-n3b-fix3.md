## Decisions for the lead

- **InitExe stays on `live`, unbounded.** It opens the host's `/proc/<pid>/exe` with
  `O_PATH` from `AT_FDCWD`, and nothing below the guest root is involved. procfs is a host
  kernel filesystem, and no guest mount lies on that path, so a guest has no way to stall it.
- **"The desired copy" has no guest-root write to bound.** The host copy
  (`lxcstate.WriteCopy`) is written to the host's state root, not through a guest root. The
  guest's `desired.json` is written by `guest membership` over `LXC.Guest`, and that call is
  already bounded by `lxccmd.GuestWait`. So nothing changed there.
- **A container-wide stall fails that container's seats, not the phase.** A stalled kit
  write is not a `hostFaultError`, so `placeKit` passes it to `r.step` for each live seat of
  that container. The phase and the other containers go on. I added no test of this at
  apply level: host/lxc has no stalling fake root, and `ErrStalled` wrapping `ErrRefused` is
  what `step` already handles.
- **`PlaceDir`'s fill runs inside the bound**, so it may outlive a stalled call. Its doc says
  that fill touches only what it is given. The kit's fill only reads `k.entries`.
- **DR4 is defined in SPEC-n2b.md, not SPEC-n3.md.** SPEC-n3 n3b-D2 only lists it as
  amended. The brief named SPEC-n3, but the rule lives in SPEC-n2b, so that is where I edited
  it: two lines, in DR4 only.
