## The reported hang (priority 1)

The dump in `untracked/scratch/t1.txt` is not a deadlock. It holds four goroutines: the test
alarm, `main`, the parent test, and the subtest inside `newWorld`'s `MkdirAll` syscall. The
running tests are listed as `TestARestoredItemIsJudgedAgain (2s)` and `its_verdict (0s)`: the
subtest had just begun, and no engine, proof, delivery or timer goroutine of any world was
alive. A deadlock or a timer `Shutdown` does not release would show its goroutines parked. The
panic was the test binary's `-timeout` (4m40s, a flag passed for that run) ending a run whose
earlier tests had used the time on a host loaded by other agents' runs. No defect class, so no
Defence Before Fix rule: there was nothing to detect.

The stress runs did find two real faults:

1. **Engine defect: a restart's whole re-read counted as growth.** When a due entry starts the
   re-read, a mark made in that round began at 0 with `high` 0. Reading the existing file then
   looked like growth "now", which moved the quiet clock 180 s on. So a restarted link never
   declared a due entry missing in its first round, and P10 could not happen. **Fix:** a new
   mark's `high` is the offset sought (the furthest end known), even when the read starts at 0.
   Red then green: `TestARestartedDueEntryIsMissingAtOnce` (engine), and `TestKilledAfterMissing`
   (link), which hangs waiting for the kill with the fix reverted and passes with it.
2. **Flaky test: `TestACutUnseenIsFoundAtTheDeadline`** failed 3 times in about 60 shuffled
   runs. A proof round from an earlier write's kick could run between the test's `Truncate` and
   `Record`. It then saw the shrink and proved the delivery early. The test now cuts and records
   in one `local` call on the state goroutine, so no round can run in between. 300 runs clean.
   This was a single test's ordering assumption, not a class in the production code.

Proof of green: the engine package ran 20 times for each of six shuffle seeds
(1792716039412185248, 1, 42, 7777 and two random ones; see "Verification").

## Decisions (where the prototype or brief was weak)

- **No link hunk** (the brief put the watcher in `member/link`). The engine already gets the
  transcript from `SetSession`, so it owns the watcher. Nothing in `member/link` conflicts with
  n3e-10.
- **Scan on the state goroutine, bounded**: 1 MiB a call, 8 MiB a path a round. A round that
  does not catch up pokes the next one and declares nothing missing.
- **Re-read before a deadline**: every transcript is read whole again before anything is
  declared missing. An offset alone misses a file that was cut and grew back past its mark.
- **A mark's high-water starts at the sought offset** (fix 1 above): a re-read or a restart
  finds no growth that it cannot prove happened.
- **The earlier run's return is keyed by run id** and runs inside `BeginRun`'s one write. It is
  idempotent across a crash on either side of the write. Returned items are `repeat` and not
  `held`. Missed entries are dropped, because their boot times belong to another boot's clock. A
  store not yet begun is neither delivered from nor proven.
- **Late find of handed items**: these are counted `seen twice` and also leave pending, so a
  `Return` cannot show them a third time.
- **Missing count (n3e-D11)**: `status.json` counts the missed entries since the team's last
  proof. They stay in `missed` for the late find.
