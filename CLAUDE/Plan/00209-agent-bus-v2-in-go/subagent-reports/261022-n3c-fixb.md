# n3c fix part B: review B's findings (processes and the client side)

Branch feat/bus-v2-n3c-fixb, from feat/bus-v2-n3c 6b143e850. One commit per finding, each
through qa-changed. Each test below was red without its fix unless the entry says otherwise.

## Majors

1. **An open wait held the link past close.** `link/server.go`: the server has a `stopping`
   channel, which `close()` closes first. Each request's ctx is cancelled by it, so a blocked
   `eng.Serve` returns at once. settle still uses the base ctx, so a hand-out is still returned.
   Test `TestCloseEndsABlockedWaitAtOnce`: hung without the fix. **Declined in part:** cancelling
   on EOF of an abandoned client. Nothing in the link is held past close any more; a waiter whose
   client left stays registered until its deadline; and a hand-out to a closed connection is
   returned. Detecting EOF would need a reader beside the ack reader on the same connection.

2. **A remove with no answer killed the link.** The link now answers every remove. On an engine
   error it logs it, sends `removed` with whatever user id it has, and still runs the leave
   goroutine, so `left` follows. The leave posts nothing when no notices are held.

   - `wire.Removed.UserID` is `omitempty`, and `check` accepts it empty.
   - The keeper's `onRemoved`, given an empty user id, deletes the store under the lock itself,
     as it does with no link or in `settleRemovals`.
   - `engine/teams.go` is untouched: `errNotHeld` needs no export.
   - Tests: `TestARemoveOfNoTeamIsAnswered` (link), `TestRemovedWithoutUserID` (keeper), and a
     wire round-trip row.

3. **No gate ran the failpoint tests.** There was no existing tuwunel wiring to copy:
   `go-qa.toml`, `qa-gates.tsv` and CI set no build tag anywhere. So this adds three go-qa
   `[[stage]]`s in `src-go/qa/go-qa.toml`, all over `./internal/teamchat/...` under
   `-tags busfailpoints`:

   - `teamchat-failpoints-lint`: golangci-lint;
   - `teamchat-failpoints-vet`: go vet;
   - `teamchat-failpoints-test`: go test -race.

   qa-all, qa-changed (diff mode, checked) and CI run them through `qa-go-qa.bash`. The
   `CLAUDE/QA.md` go-qa row has one added sentence. Red proof: a planted printf defect in
   `failpoint/armed_test.go` passed plain `go vet` and failed both the vet and lint stages.
   The project-rules driver is not run under the tag.

## Minors

4. **A relaunch soon after a keeper crash failed 75.** In `takeLaunchSeats`, a busy seat whose
   lock record names a run with a free or missing keeper.lock (`holderEnding`, through
   `lock.Probe`) is retried every 250 ms for up to endWait + 2 s before 75.
   - Unit test `TestHeldSeatOfAnEndingSessionIsWaitedFor` covers keeper gone (waits, then seated)
     and keeper alive (75 at once).
   - E2e `TestFailpointRelaunchWhileTheLinkEnds` (busfailpoints) is **not red without the fix**:
     against the fake server the dying link lets the seat go before the relaunch reaches it. It
     stays as an end-to-end guard of the relaunch.
5. **wait at its deadline exited 69.** `client.serve`: once no link answers, a wait at or past
   its deadline exits 4 timed-out (the engine's wording), and nothing is dialled after the
   deadline. `TestWaitWithNoLinkForItsTimeout` now pins exit 4 and three dials (0, 1 and 3 s,
   none at 4 s).
6. **The desired watch could end silently.** These cases now go to `watchLost`, then
   `rewatch`: the channel closing, `IN_IGNORED`, `IN_DELETE_SELF` and `IN_MOVE_SELF`.
   - `rewatch` re-adds the watch and re-reads the file.
   - While the directory cannot be watched, the membership is refused `missing` and published,
     and the watch is retried every `rewatchGap` (5 s).
   - The inotify Watcher keeps one reader per instance: watches added while it reads share its
     channel, so a re-watch does not split events across two readers.
   - Tests: `TestDesiredEvents` (re-watched, and a later change followed),
     `TestDesiredDirectoryGoes` (all three ops), `TestInotifyWatchAfterTheDirectoryGoes`.
   - No new refused code: the state codes belong to review A's area.
7. **The kit `--version` had no bound.** `kitVersion` cancels its run after `versionWait`
   (5 s) on the keeper's clock, which gives 78 runtime. Subtest `version hangs`: timed out
   without the fix. SIGTERM during the launch is still read only in the loop.
8. **The sweep could remove a sibling's new run.** makeRun now builds the run under
   `paths.Layout.Staging(pid, startTicks)` (`.building-<pid>-<ticks>`, which no run id parses).
   It takes keeper.lock, opens keeper.log and writes session.pid there, then renames the
   directory to the run id (`RENAME_NOREPLACE`). The sweep removes a staging directory only when
   the keeper its name gives is gone.
   - `paths.ParseStaging` is the parser. Tests: `TestStaging`, the zero-value and sampled-name
     tables, and `TestLeftoverSweep` (a gone builder's staging is removed, a live one's left, and
     the keeper's own run renamed into place).

## Nits

09. **Declined.** A link dying after `end()` already recovers through the next take's
    disconnected. A second end-only restart would change the end flow for a case that recovers.
10. **Declined.** "Kill CMD only when !exited" leaks an orphaned CMD after a keeper SIGKILL, or
    after a keeper error exit that leaves CMD running. A safe kill needs a pidfd taken while the
    pid is known to be CMD. That is not a small change, and only the test harness is at risk.
11. **Done.** An EAGAIN connect (full backlog) is no link. `TestAFullBacklogIsNoLink`.
12. **Declined.** `Dup` of a held seat lock cannot be made to fail without a new seam. The fix
    (drop the seat) is one line, but it would land untested.
