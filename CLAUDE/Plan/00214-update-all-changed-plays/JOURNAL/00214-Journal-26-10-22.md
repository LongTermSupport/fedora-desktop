## 10:31 · finding · —   — root cause of the 10 against 25, and what the branch does

The 10 against 25 had one root cause: the health report and `run.bash --changed` counted
stale plays with different rules. The report (`check_freshness`) judged a play only on
commits touching its own file between the commit it ran from and HEAD, plus a hash check
on a dirty run. `--changed` (`changed_plays`) judges its own file and every checkout path
it deploys against the working tree, and also reruns a failed last run and every dirty
run. The report missed every play whose template, lib or helper changed, every failed
play, every dirty run with an unchanged play file, and every uncommitted edit.
`changed_plays.judge` is now the one definition and both read it; the report's own
history code was deleted. The report and the login reminder print the checkout's
`run.bash --changed`, meta-deploy has a `changed-plays` entry, and the host acceptance is
queued. A ledgered play outside `playbooks/imports/` is no longer a report finding,
because `--changed` never ran it.
