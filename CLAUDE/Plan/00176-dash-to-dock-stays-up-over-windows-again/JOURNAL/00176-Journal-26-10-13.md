**Plan 00102's mechanism cannot explain it.** In `ALL_WINDOWS` mode, `intellihide.js` never
consults the window tracker or app identity. An overlap needs only two things:

- a handled window (NORMAL and similar) whose `get_monitor()` is the dock's monitor index
  (the top-window guard);
- a window on the active workspace that is `showing_on_its_workspace()`, with a frame rect
  intersecting the dock's static box.

Nothing is Ptyxis-specific, so any window in the same place should fail the same way.

`_updateDashVisibility` in `docking.js` keeps the dock shown despite an overlap in three
cases:

1. `dash.requiresVisibility`, set for 3 s whenever an app icon turns urgent. This needs
   `show-dock-urgent-notify`, which is on by default, and is a transient reveal.
2. `_box.hover` with autohide on.
3. A stale target box or a wrong monitor index.
