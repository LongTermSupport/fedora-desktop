## Observations (not refutations)

- O1. The play always places the watch unit (play-agent-bus-element.yml, "The unit is always
  placed") but starts the watch only while a lightning team has `lightning_diagnostics` true
  (lines 333-342). Task 1.9 says the cap is "installed by the play that installs the Lightning
  watch", which is true. But the notice option "the watch seeing the pid gone with
  `memory.events` oom_kill risen" would work only on a host where diagnostics is on, while the
  drop-in covers every instance whatever the key says. The plan says the source is chosen test
  first; the choice should account for this.
- O2. `watch.go`'s package doc says it "never signals or kills the process". Task 1.8's kill
  is a deliberate change to that, not a drift. Task 1.9 keeps the watch read-only.
- O3. No `MemoryMax` drop-in for Flatpak scopes and no host_vars memory-cap variable exist yet.
  Both are to be built, which is consistent with the task status 🔄.
