## Findings to record (checked by reading Lightning's source at tag v0.10.7, nothing run)

- **The `--log-file` cap holds for 0.10.7.** `CappedLogFile` (`src/app/LogExport.cpp`,
  `kDefaultMaxBytes = 32 * 1024 * 1024`) rolls once to `<path>.1`, which makes 64 MiB at most.
  0.10.6's `installLogFile` opens a plain `QFile` with no cap.
  - A non-regular file at the path is written uncapped.
  - Unchecked: that the instance on the laptop runs 0.10.7. The seat read its version as 0.10.7;
    the Flatpak app-commit is not a git commit and cannot be matched to a tag here.
- **The per-event sync line is compiled out of the Flathub build.** The manifest at the
  repository root builds with `-DCMAKE_BUILD_TYPE=Release`. CMakeLists.txt defines
  `$<$<CONFIG:Release>:QT_NO_DEBUG_OUTPUT>` for the app target, and the per-event line is
  `qCDebug(lcSyncTrace)` (`SyncLatencyTracer.cpp`).
  - So `QT_LOGGING_RULES=lightning.sync.trace.debug=true` does nothing in that build. Only the
    `qCWarning` lines print: `SLOW event` (total at or above the threshold) and `SLOW sync gap`.
  - `LIGHTNING_SYNC_TRACE=1` means a 2,000 ms threshold. The lowest threshold allowed is 100 ms
    (`kMinSlowMs`), set as `LIGHTNING_SYNC_TRACE=100`.
  - The key ships the values the coordinator set. **The coordinator should decide** whether to
    change `LIGHTNING_SYNC_TRACE=1` to `=100` (still not one line per event) and drop the inert
    rule.
- **The memory line survives the Release build.** `scroll-memory rssKiB=...` is a `qInfo` in
  `src/main.cpp`, every 5 s. The watchdog's silence test rests on it.

## The private-data boundary

- The watchdog reads only `/proc` and the diagnostic log's modification time (`os.Lstat`). It
  never opens the log, and never opens any other file of the instance.
- It reads another process's argv only after that process's comm is `lightning-matri` (test
  W4, "another comm").
- gdb runs with `set print frame-arguments none` and no `bt full`, so no argument or local can
  carry message text. `eu-stack` prints no arguments.
- Its one write is its own record, mode 0600, beside the log: inside the instance's cache
  folder, which agents are already denied (`cc-teams-settings.json`).
- It never signals or kills Lightning. The backtrace tool's ptrace attach pauses the process
  while it reads the stacks.
- `agent-bus-lightning` itself never writes the diagnostic log; Lightning does (test L16).
