## 14:20 · action · T5.6 — the findings actioned, and what was falsified rather than argued

`qa-reviewer` returned FIX-BEFORE-MERGE: 0 blocking, 3 should-fix, 8 minor, 3 nits. What
changed, and how each was checked — several were the kind of fix that is easy to make and
easy to make wrongly.

**M1 — a missing helper library was reported as `rc unreachable`.** The exact misdiagnosis
this plan exists to kill, reproduced inside the plan's own error handling. The stub's message
is "rclone RC helper library not found", which contains neither `401` nor `credential`, so it
fell through to `*)`. Both `rclone-cache-status` and `rclone-tail` now carry a
`*"helper library not found"*` arm FIRST. It matters most on exactly the host where the play
has never run — the host least able to afford a wrong diagnosis.

**M3 — four shipped clients cited `Plan 00067`**, a real and unrelated completed plan, so a
reader tracing why the RC is authenticated was sent somewhere plausible and wrong. All four
now cite 00094. The renumber sweep in `d1f0529c` fixed every other file in the diff and
skipped `files/home/.local/bin/` entirely.

**M2 — the verdict had no denominator, and this is what explains the record.**
`acceptance.bash` printed `ACCEPTED — $PASS check(s) passed` with no expected total anywhere,
and the pass count is data-dependent: check `[2]` emits two passes or one fail, `[3]` emits
one pass or N fails. So "10 passed" read identically whether 10 of 10 ran or 10 of 12 — which
is why `PLAN.md` said 9-failed-then-8/8 while the commit message said 10/10. The gate now
declares `EXPECTED_CHECKS`, registers each check as it runs, and prints
`COVERAGE: n of m checks executed`. An incomplete run is **REJECTED even with zero failures**,
because a gate that did not run all its checks has not established what it claims.

Not taken on trust. A harness runs the real gate against stubbed `findmnt`/`pgrep`/`rclone`
so it reaches its verdict, then runs a mutant with check `[5]`'s registration removed — the
exact failure M2 describes:

```
control : COVERAGE: 9 of 9 checks executed   ACCEPTED   exit 0
mutant  : COVERAGE: 8 of 9 checks executed   NOT RUN: 5   REJECTED   exit 1
```

A coverage line that could not fail would have been decoration, and would have read exactly
the same as this one.

**m4 — the gate hardcoded port 5572, which the repo stopped guaranteeing.** Since `a68c99bb`
the unit template defaults each mount's RC port to `rclone_rc_port_base + mount_index`, so
only the first mount is on 5572. Check `[0]` now reads the address off the mount's own rclone
process, the way every client this plan fixed already does, and aborts if the mount publishes
no `--rc-addr` rather than probing an address nothing is listening on. `[6b]` was worse than a
wrong port: it paired `findmnt | head -n1`'s filesystem with port 5572, so on a multi-mount
host it could ask one mount's RC to refresh another mount's remote. Address and remote are now
read from the same mount in `[0]` and used as a pair.

**m8 — the gate discarded the diagnosis it exists to surface.** Two `2> /dev/null`
redirections threw away the library's stderr and printed a generic failure, so an operator
reading REJECTED could not tell "credential file absent" from "present but valueless", though
the library distinguishes them carefully. Both now capture and report it — the plan's own
defect one level up, inside the gate written to catch it.

**n1 — `awk -F= '{ print $2 }'` truncates a value at its second `=`.** Safe today only
because `play-rclone.yml` generates the password from `ascii_letters` and `digits`; nothing
links the parser to that constraint, and the library's own comment invites overriding
`RCLONE_RC_AUTH_FILE`. Both `rclone-rc-auth.bash` and this plan's `triage.bash` now use
`substr($0, index($0, "=") + 1)`. Falsified, with a password of `pa55==w0rd=x`:

```
before : SAW_PASS=[pa55]
after  : SAW_PASS=[pa55==w0rd=x]
```

The failure mode is worth naming: a truncated password surfaces as a 401, and in this
codebase a 401 reads as a credential mismatch — so the symptom points at the credential
rather than at the parser.

**m7 — the drift gate marked a skip with a tick.** `✓ deployed-drift: skipped (…)` is one
tick among thirty, visually identical to a gate that compared something. All three skip exits
now use `⚠`, this repo's established "ran but incomplete" symbol. Exit status stays 0, so
nothing about pass/fail changes — only a reader's ability to tell a skip from a pass, which is
this gate's own subject one level up.

**m5 — `CLAUDE/QA.md` documented two of the gate's three skip conditions.** The
linked-worktree skip, added by this plan, was missing, and the documented scope still said
`files/home/.local/bin/` only while the gate also compares `EXTRA_PAIRS`. Both fixed as a
table, with the rule stated that a new skip condition must be added there in the same commit
that adds it — the documented skip set being a reader's only way to know when the gate is
inert.

**m1/m2 (help text and index) — corrected.** `--help` listed 7 checks while the script ran 9;
`PLAN.md` and the plan index both said `ACCEPTED 8/8` when the final run was 10/10. Task 5.4
now also records *why* the totals never reconciled: checks `[0]` and `[6b]` were added between
the pre-deploy run and the accepted one.

to give the linter nothing to be wrong about.
