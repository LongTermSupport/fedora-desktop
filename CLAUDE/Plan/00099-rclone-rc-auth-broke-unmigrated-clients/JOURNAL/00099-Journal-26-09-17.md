## 07:45 · finding · T5.10 — round 6, and the blocking defect is live in a user's tool

Round 6 came back FIX-BEFORE-MERGE: 1 blocking, 7 should-fix, 7 nits. The reviewer verified
all six round-5 fixes by EXECUTION, building a stub host and running the gate end to end —
and that is how it found the blocking one, which the round-5 harness could not have found
because it extracts check [6] and never runs check [0].

**The blocking finding, and it is not confined to the gate.** One line, five copies:

```bash
RC_ADDR=$(grep -oE -- '--rc-addr=[^ ]+' <<< "$cmdline" | head -n1 | cut -d= -f2)
```

`grep` exits 1 when the cmdline carries no `--rc-addr`. Under `set -euo pipefail` an
assignment from a failing pipeline kills the shell — so the `if [ -z "$RC_ADDR" ]` guard
written for exactly that case is **unreachable**, in every copy. `bash -n` is fine,
`shellcheck -x` is fine.

Measured, at top level:

```
$ probe, no --rc-addr in the cmdline
EXIT=1   (nothing printed — "REACHED top level" never runs)
```

`rclone-cache-warm --fast` is a **live** user tool and dies this way: exit 1, nothing on
stderr, and its own "no rclone process with --rc-addr found … --fast mode requires the
mount to be started with --rc" never prints. `rclone-cache-status` and `rclone-tail`
survive only because their copy sits inside a `findmnt | while read` pipeline subshell
where errexit is suspended — latent, one refactor from live.

**And the library's copy is safe for a reason that is not the line.** The reviewer said
`rclone-rc-auth.bash:195` "got this right". Checked rather than accepted, and the shape is
identical:

```
--- inside a function used as an `if` condition ---
REACHED the -z guard, matches=[]        rc=1
--- the same line at top level ---
(nothing)                                EXIT=1
```

It survives because every caller wraps it in `if ! rc_addr=$(rclone_rc_addr_for_mount …)`,
where errexit is suspended. That is the CALLER's property, not the line's — so the library
was one non-conditional call site away from the same silent death. All five now capture the
status explicitly, and the guard holds in any context.

`falsification/falsify-round6-rcaddr.bash` drives each shipped site against a cmdline with
and without the flag, plus the pre-fix line as the mutant:

```
SHIPPED   no --rc-addr        all four: exit=0, guard REACHED, address empty
CONTROL   --rc-addr present   all four: exit=0, resolved localhost:5573
MUTANT    no --rc-addr        exit=1, no output at all
MUTANT    --rc-addr present   exit=0, resolved localhost:5573
```

The control is the half that matters: without it, "the mutant exits 1" is equally consistent
with a line that fails on everything.
