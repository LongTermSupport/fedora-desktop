## 17:05 · context · why this plan exists

Two incidents in one session, same shape, one user-facing:

1. **`ssh-handling.bash`** — `gh api user --jq .login 2>/dev/null`, status
   discarded. GitHub answered 502, `gh` put the JSON error body on **stdout**,
   and the blob became "the account name". ccy refused to launch and told the
   owner their `github_accounts` mapping was wrong and to edit `localhost.yml`.
   It was not wrong. GitHub was down. Fixed in CCY 3.36.0 (`b770441`).
2. **`00074/prototype.bash`** — `$?` read after `fi`, which is always 0 (the
   `if` statement's own status, not its condition's). Every legitimate grep
   no-match was reported as `grep failed (exit 0)`. Fixed in `9c47921`.

Owner's instruction: sweep for it, and find **"defence before fix"** tooling —
something that prevents the class rather than catching it in review.

The class in one line: *a command's failure is silently converted into data,
and that data is then used to make a decision or reported as fact.* Worse than
an error, because an error points at the cause and a wrong answer points
somewhere else entirely.

## 17:10 · action · four parallel sweep agents dispatched

Scoped so they cannot collide, each required to answer **"what does this code
believe when the command fails?"** for every finding — a finding without that
answer is not a finding, and the rule is there to keep the reports from filling
up with style noise.

| Agent             | Scope                                                        |
| ----------------- | ------------------------------------------------------------ |
| `sweep-ccy`       | `files/var/local/claude-yolo/`                                |

`sweep-infra` carries the highest-value target: **a QA gate that cannot fail**.
A gate that treats an analyser crash, a missing tool, or an empty file list as
"0 issues" reports PASS on unchecked code — the same defect class applied to the
safety net itself, and the one place where it is invisible by construction.

`research-tooling` was told to produce **real counts**, not estimates: "raise the
shellcheck bar to warning" is only actionable with the number of pre-existing
findings attached.
