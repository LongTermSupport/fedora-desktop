Two of these matter for QA specifically. `rclone-tail` and `ssh-keys-rekey` live
under `files/home/.local/bin/`, which is exactly what `qa-deployed-drift.bash`
compares against `~/.local/bin/`. Until those two plays run,
`./scripts/qa-all.bash` fails on the host **by design** — the documented
edit → playbook → deploy → test order being enforced. The script's header says so
in as many words, so a red QA run does not read as a fault.

The script verifies every play exists before running any of them: a missing play
part-way through leaves the host half-deployed, which is the state this plan's
own subject matter is about avoiding.

Verified in the container: `bash -n` and `shellcheck -x` clean; `--help` returns
0 *before* the environment resolution and the container guard (a script that dies
resolving its environment cannot print its own help on the machine that needs
it); the guard itself refuses with rc=1 and points at the host.
