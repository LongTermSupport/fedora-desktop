## 11:40 · finding · — — why a bare play invocation fails on password sudo

A play run directly on a password-sudo box aborts at its first `become` task with
`Premature end of stream waiting for become success … sudo: a password is required`, and
`sudo ./play.yml` fails instead with `ansible-playbook: not found` (root has no pipx shim).
`run_playbook_with_issue_option` in run.bash already branches correctly on all three sudo
shapes; it is just unreachable outside the installer. Alternatives weighed and rejected:
`become_ask_pass = True` in ansible.cfg (verified in ansible-core's CLI that ask-pass is consumed
before `--become-password-file`, so headless would hang; also prompts on NOPASSWD), and a
`--ask-become-pass` shebang (hard CLI conflict with the headless password file).

The local plan counter read 108 while the remote already held 00113; set it to 113 before
scaffolding, so this is 00114.

## 12:05 · action · T1.1–T1.3 — `--play` built

Arg parsing is now a shift loop; `--play <path>` takes the path and everything after it as
ansible-playbook pass-through. Dispatch sits directly after `run_playbook_with_issue_option`
is defined and before the first install step; the runner gained a third parameter block
(`"${@:3}"`) forwarded to all three become branches. Repo root resolves from `BASH_SOURCE`,
so a streamed run.bash aborts. The headless exclusion is checked before `headless_preflight`
via `fatal` (which routes to `hl_abort` in headless mode); the `--optional-only` exclusion
lives in the dispatch block because interactive `fatal` calls the `error` helper, which is
defined after the preflight point — the first placement hit `error: command not found`.
