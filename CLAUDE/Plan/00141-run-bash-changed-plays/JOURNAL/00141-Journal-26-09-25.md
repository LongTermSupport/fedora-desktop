## 20:08 · action · T2.1   — run.bash --changed (1.28.0)

The flag is refused with a playbook path, `--optional-only`, `--headless`, or a streamed
run.bash. It lists the plays, confirms once (default no), takes one play lock, and runs
each play through `run_playbook_with_issue_option`. At the first failure it stops, names
the plays not yet run, and exits with that play's status.

## 20:58 · decision · T3.1   — keep "a dirty run runs again", and warn

The alternative is to record which paths were dirty at each run. That means changing the
ledger's record format, and the login report, the panel and the freshness check all read
it. A dirty run deployed content no commit describes, so running it again from a clean
tree is the correct catch-up, not just a safe one. Agents commit and push every change,
so the shared checkout is clean nearly all the time. The repeat therefore ends at the
first clean run. `--changed` now warns before it asks, and a `git status` that fails
stops it.
