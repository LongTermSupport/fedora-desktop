# Plan 00228 Task 6.7: the consumer VM scenario installs speech-to-text

## What changed

- Manifest field: a consumer scenario names its menu picks in `optional_plays`. The validator
  allows it only on a consumer scenario, as a non-empty list of unique `play-<words>.yml`
  names, and adds `optional_plays=a,b|-` to the `VMTEST-SCENARIO` line.
  `desktop-consumer-install` picks `play-speech-to-text.yml`; `planned` goes from 17 to 20.
- Go gate, new check V17: each pick is a file in exactly one optional play directory and
  every play in it says `audience: all`. An unreadable pick is exit 2; success output is
  unchanged. A change to an optional play reruns this gate in `qa-changed`.
- Attendant: a prompt can build its answer from earlier output (kept output 1 KiB to 16 KiB).
  An answer it cannot build ends the run as a fail with the reason in the transcript.
- Menu picks: the install run reads the last numbered menu block and types the picks' numbers,
  found by `consumer.MenuLabel`. A missing pick, no menu, or a menu not numbered 1 to n ends
  the run. The re-run still answers Enter, so `rerun-changed-nothing` does not prove the
  speech-to-text play idempotent.
- Guest checker (20 checks): `stt-extension-active`, `stt-whisper-set-up`,
  `stt-post-processing-not-offered`.
- Tests went red, then green (journal entries 131536Z-action-b69b73 and 131852Z-action-ad7998).
- Host run queued in `CLAUDE/Plan/meta-deploy.list`.
