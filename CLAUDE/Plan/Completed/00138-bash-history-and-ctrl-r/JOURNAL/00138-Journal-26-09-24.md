## 08:05 · finding · T1.5 — Atuin cannot weight by directory; no tool meets A

RESEARCH-ranking-and-security.md (read from Atuin 18.12.1 and upstream source): all
Atuin modes rank by match/recency/frequency, cwd and workspace only filter. `skim`
(18.12.1 only, removed 18.19.0) weights by path distance at most ~1.4x and not on an
empty query. McFly ranks by cwd but is unpackaged, thinly maintained, and rewrites
HISTFILE without timestamps. RESH and hiSHtory rejected on security. Atuin security
costs: every command line in a child's argv (readable via /proc, no hidepid),
update_check on by default in Fedora's build, bash-preexec strips ignorespace, and
HISTIGNORE makes it re-record the previous command in the wrong directory.

## 12:55 · finding · —   — after the deploy, terminals opened earlier keep the old history file

The durable history was deployed to the owner's desktop today by `play-basic-configs.yml`, in
Plan 00134's deploy. Straight afterwards, up-arrow in a newly opened terminal did not offer
the last command typed in another terminal.

- **Cause:** terminals opened before the deploy keep the old `HISTFILE`,
  `~/.bash_history`, and write it only when they exit. New terminals read
  `~/.local/state/bash/history`, which the play seeded from `~/.bash_history` once, at
  deploy time.
- **Proof:** new terminals share history correctly. The owner confirmed it, and an isolated
  pty test of the deployed snippets recalled the last command and wrote timestamped entries
  to the new file.
- **What was lost:** commands typed in pre-deploy terminals after the deploy never reach the
  new file. The owner chose to ignore that one-off loss, so no merge was built.
- **Remedy:** open new terminals after a deploy of this history change.
