## 09:25 · action · T3.4 — the per-event tool surface specified; the honest part is what it does not buy

[reports/ci-tool-surface.md](../reports/ci-tool-surface.md). Decision 9 had already settled the
mechanism and two of the three sub-items — assert names not counts, prefer an allowlist where
the vocabulary is not ours — so the residue was sub-item 1, the per-class surfaces, and that is
what this specifies.

Two classes. `push`/`pull_request` keeps `Bash`, because without it there is no `ci.bash` run and
the job has no purpose, and loses `Edit`, `Write` and `NotebookEdit`. `issues`/`issue_comment`
loses `Bash` too — which is what makes the class worth separating, and which also removes `gh`,
so the one write it is allowed to do has to arrive as an enumerated MCP tool rather than an
unbounded shell. That is the design, not a cost of it.

MCP is allowlisted at **server** granularity (`--mcp-config` + `--strict-mcp-config`), and no
`mcp__*` name goes in a denylist. A typo in a server name yields a job that cannot post and says
so; a typo in a denied tool name yields a job that can do more than intended and says nothing.

The part worth writing down is §2's admission. `Bash` is a write vector, so removing `Edit` and
`Write` does not make a class-A job read-only, and what actually stops it pushing is **the
token's scopes** — a property of lts-infra's token store, which has no checkout here. It is named
as a required property to confirm, not asserted as a fact. A boundary described as stronger than
it is, is worse than a weak one described honestly, and Decision 9 half-conceded this already
("read-only cannot be literal") without following it to the consequence.

Four startup assertions, each able to fail. The one an implementer will want to skip as redundant
is assertion 3 — assert `Bash` is *present* for class A. It is the only one that catches an
over-tightened denylist, and once one list feeds two classes, over-tightening is the likelier
mistake. A class-A job whose `Bash` went missing would skip the suite and pass green: the exact
failure this plan exists to prevent, arriving through the mechanism meant to prevent it.

Deliberately not invented: the concrete default tool vocabulary. The 2026-08-10 measurement
recorded counts, not names. The spec names the primitives that must be absent and requires the
implementation to capture the real list and assert against it — a hand-written list of the other
26 names would be exactly the drift §4 forbids.

## 11:35 · correction · T3.4 — two defects in ci-tool-surface.md that its own arguments already refute

Both from the review, both cases of an argument made in one section and not applied in another.

**§2 over-claimed about the credential.** It said "what actually stops a class-A job committing
or pushing is the credential, not the tool list". No credential stops a local `git commit`, and
none stops a shell redirect into the working tree — and Decision 9 forbids three things, "never
write to it, commit, or push", of which the token reaches only the third. It matters because the
runner keeps a *persistent* checkout, so a dirtied tree outlives the job that made it. §2 now
scopes the credential claim to push and files the dirty-tree half as a requirement on lts-infra
Plan 00030, since nothing in this repo can assert it.

**§5 assertion 2 was a denylist wearing the other hat.** It asserted only that the must-be-absent
names are absent — which is the exact fail-open shape §3 argues against for MCP, over a
vocabulary that is likewise not ours, in a CLI that assertion 1's own rationale says changes
daily. A renamed or newly added write primitive is absent-by-name, and every assertion passes
green over a class-A job that can now write. It is now a **diff against a declared expected
set**: an unexpected member fails. The cost is that a benign new read tool also fails the job
until someone declares it, and that review is the point — so it is written down as the trade-off,
not hidden. This makes Task 0.3 a prerequisite rather than a nicety: the set cannot be declared
until the names are captured, and the 2026-08-10 measurement recorded counts only.

Assertion 3 survives as its own item. It is formally the presence half of the diff, but its
failure mode is the silent one, and an implementer who reads assertion 2 as "the denylist" will
drop it.
