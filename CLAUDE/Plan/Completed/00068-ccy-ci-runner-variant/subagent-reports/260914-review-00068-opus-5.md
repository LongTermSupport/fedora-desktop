### 8. §2's boundary claim is right about push and wrong about commit

`reports/ci-tool-surface.md` §2: "What actually stops a class-A job committing or pushing is
**the credential**, not the tool list."

No credential stops a local `git commit`, and none stops a shell redirect into the working tree
— both of which Decision 9 forbids (`DECISIONS.md:260-261`: "never write to it, commit, or
push"). The required-property blockquote beneath it correctly scopes itself to *push* scope; the
sentence above over-claims. It matters because the runner keeps a persistent checkout
(`DECISIONS.md:20-21`, and §7 defect 1's "two jobs checking out different SHAs into one working
tree"), so a dirtied tree or a stray commit outlives the job.

The rest of that question: the reasoning that `Bash` is a write vector and therefore the tool
list does not make class A read-only is **sound**, and it is **correctly marked** as a property
to confirm rather than a fact — the §2 blockquote, §6 first bullet, and `00113 PLAN.md:133-137`
all file it as an open owner question against lts-infra.

### 9. Assertion 2 is a denylist check that inherits the exact fail-open the document argues against for MCP

§3 argues, correctly and from downstream measurement, that a denylist over a vocabulary that is
not ours fails **open** on a typo. `--disallowedTools` over built-in names is that same shape —
the vocabulary is Anthropic's, and §5 assertion 1's own rationale is that the CLI changes daily
underneath the design. But assertion 2 only checks that named tools are *absent*: a renamed or
newly-added write primitive is absent-by-name, and every assertion passes green.

**Fix**: assert the captured tool list against a declared expected **set** and diff it, so an
unexpected member fails — rather than checking a handful of names for absence.

The tool names themselves are fine: `NotebookEdit` is corroborated at `/workspace/CLAUDE.md`'s
R-SECRET-READ row, so §6's "deliberately does not invent the missing names" holds.
