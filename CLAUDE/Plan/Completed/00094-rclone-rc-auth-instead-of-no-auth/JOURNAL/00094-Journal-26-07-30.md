## 12:24 · finding · — — measured endpoint auth matrix, rclone v1.74.3

The whole plan rests on this, so it was measured on the live mount rather than
assumed. `--rc-no-auth` is NOT needed for most of what the repo does:

```
core/pid           REFUSED (auth required)
core/stats         OK (no auth needed)
vfs/stats          OK (no auth needed)
core/stats-reset   REFUSED (auth required)
core/version       OK (no auth needed)
vfs/refresh        REFUSED (auth required)
```

Takeaway: only `vfs/refresh` (`rclone-cache-warm`) and `core/stats-reset`
(cosmetic) actually need credentials. Two earlier claims were wrong and are
corrected here: (1) `rclone-tail` was said to be broken — it is not, it uses only
`vfs/stats` + `core/stats`, and `rclone-tail --once` printed `LTS-G-Drive  idle`
on the live auth-gated mount; the user correctly pushed back on this. Same for
`rclone-cache-status`. (2) The play comment claimed auth rejects "core/pid and
core/stats" — `core/stats` is auth-free.

## 12:26 · finding · — — flag and env-var facts, verified not assumed

Server flags are `--rc-user`/`--rc-pass`; the `rclone rc` client uses
`--user`/`--pass` — different names, so no env collision. The `RCLONE_<FLAG>`
mapping was confirmed empirically (upstream docs page truncated on this):
`RCLONE_URL` drove the client's `--url`, and `RCLONE_USE_JSON_LOG` switched the
log to JSON. Hence `EnvironmentFile=` with `RCLONE_RC_USER`/`RCLONE_RC_PASS`
works for the server side, keeping the secret out of `ExecStart` and `ps`.

## 12:31 · decision · — — why not just re-run the play as written

Deploy-gap context: the live unit predates `9d365ec` (2026-05-16), so it has
`--rc` without `--rc-no-auth`. The obvious move — re-run `play-rclone.yml` — was
rejected because it would *introduce* shell-equivalent local access rather than
fix anything. The user questioned "we want to have the service running with no
auth?" which is what surfaced this; an earlier recommendation in the same session
to just deploy the play was wrong and is retracted.

## 12:38 · action · P1,P2 — playbook + clients implemented (not deployed)

Phase 1 in `play-rclone.yml`: `--rc-no-auth` removed from `ExecStart`;
`EnvironmentFile=%h/.config/rclone/rc-auth.env` added to the unit; two new tasks
generate the credential — a `0600` `.rc-pass` store (`modification_time: preserve`
so re-touching does not churn) and an `ansible.builtin.password`-lookup-rendered
`rc-auth.env` (`no_log: true`, `ascii_letters`+`digits` only so systemd parses the
value without escaping). The lookup writes once and reads back thereafter, so the
credential is stable across runs.

Phase 2: `rclone-cache-warm` now passes `--user`/`--pass` to `vfs/refresh` and
fails loudly naming `play-rclone.yml` if the credential file is absent (never
silently degrading). `ftp-camera` builds an `rc_auth` array and passes it to all
four RC calls, so `core/stats-reset` genuinely resets and the rest keeps working
with or without credentials. Credentials are read with `awk`, not `source`d, so a
config file cannot execute code.

Empty-array expansion `"${rc_auth[@]}"` verified safe (bash 5.3.9; `ftp-camera` is
`set -e` only, `rclone-cache-warm` is `set -euo pipefail`).

## 2026-08-07 07:05 · action · T3.2,T3.3 — plan-local scripts written

(Entry appended eight days after the ones above; the plan sat uncommitted in the
working tree in the meantime and was committed as `2d01dc2`.)

Wrote the three plan-local scripts the handoff left outstanding:

- `triage.bash` — read-only, re-runnable, writes
  `untracked/reports/rclone-rc-auth-triage.log`. Reports the unit RC flags, the
  credential file's mode and key presence (never its value), and an **endpoint
  auth matrix** showing which endpoints answer unauthenticated vs authenticated.
  Renders no verdict, per `CLAUDE/PlanTriage.md`.
- `acceptance.bash` — the pass/fail gate. Exits 0 only when no unit carries
  `--rc-no-auth`, every unit loads the `EnvironmentFile`, the credential is
  `0600` with both keys, an unauthenticated `config/dump` is refused, an
  authenticated call succeeds, and the client scripts run.
- `deploy.bash` — wraps the playbook and enforces the two constraints the
  handoff called out in prose: it **refuses to run inside the CCY container**
  and **refuses while an `ftp-camera` process is alive**, since restarting the
  mount mid-copy interrupts the VFS write-back queue.

Redaction detail worth recording: `triage.bash` substitutes the RC password out
of every line before anything is written, then greps the finished report for the
secret and **deletes the report** if it is found. Substitution, not anchored
line-dropping — the Plan 00066 leak happened because `grep -v '^PASS '` never
matched a payload that `tcpdump` had appended mid-line.

Two things the acceptance gate deliberately does NOT do: it never prints a
`config/dump` response body (that is the OAuth token — it reports the byte count
instead), and it does not run `rclone-cache-warm --fast` automatically, only
`--help`, since `--fast` issues a real `vfs/refresh`. The operator is told to run
it by hand to confirm the authenticated path end to end.

QA green (423 files); the three new scripts add zero shellcheck findings.
