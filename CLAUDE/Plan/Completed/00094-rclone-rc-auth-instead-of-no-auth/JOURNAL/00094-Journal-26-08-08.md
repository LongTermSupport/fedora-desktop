confirmed by direct evidence in the report rather than by inference:

```
  PASS  RCLONE_RC_PASS is present and non-empty
        RCLONE_RC_PASS = <set, 32 chars>
        password store: /home/<user>/.config/rclone/.rc-pass is 33 bytes
### unit runtime state (evidence)
  rclone-lts-g-drive.service: active
      active since: Sat 2026-08-08 07:52:52 CEST
```

(The home-directory path in that excerpt is shown as `/home/<user>/` — the
pre-commit secret scanner rejects real usernames in paths, correctly, since this
is a public repo. The report itself carries the real path; it is gitignored.)

- **Empty-password fix**: `.rc-pass` is 33 bytes (32-char secret + newline)
  where it was previously 0. The stat + `state: absent` recovery removed the
  empty store and the lookup regenerated it, exactly as intended. Without that
  recovery step a re-run would have read the empty store back forever.
- **Missing-restart fix**: `active since` is 07:52:52, seconds before the 07:53
  probe. The new handler restarted the mount; the old `state: started` never
  would have, so the process would still be running the previous environment.

Both auth checks now pass together — `config/dump` refused (401) *and*
`core/stats` + `vfs/refresh` succeeding with credentials. That combination is
what makes the refusal meaningful; the cross-check added yesterday stayed quiet
because authenticated access worked, which is the correct behaviour.

Two precision notes recorded in the success criteria rather than glossed:

- The criterion said unauthenticated access would be refused with **403**; it is
  actually **401**. The criterion was written from expectation, the report from
  the wire — the report wins.
- `core/command` was never probed, and deliberately so: it runs OS commands, and
  firing it at a live mount to demonstrate a point already established by
  `config/dump` is not a good trade. Both are gated by the same global
  `--rc-user`/`--rc-pass`.

Not exercised, and said plainly rather than implied: `rclone-cache-warm --fast`
(only `--help`) and `ftp-camera --copy` (moves real data). Their blocking
dependency — authenticated `vfs/refresh` and `core/stats-reset` — is proven, but
the scripts themselves were not run end to end.
