## 19:31 · finding · T1.1 — sixty unreachable-command warnings for three functions

The first write of `triage.bash` passed its report functions to `plan_gather_leg`, which
invokes them indirectly. The script ends in `plan_finish`, which terminates — so control
never falls off the end, and shellcheck then reports every indirectly-invoked function body
as SC2317 unreachable. Sixty of them, for three functions. Suppressions are banned (R11), so
the fix is structural, and it is the one Plan 00099's round-2 work landed on: call the
function directly, capture its status, and give the leg an external command.

```bash
if report_occurrences; then rc_occurrences=0; else rc_occurrences=$?; fi
plan_gather_leg "occurrence enumeration" test "$rc_occurrences" -eq 0
```

`if cmd; then rc=0; else rc=$?; fi`, never `if ! cmd; then rc=$?` — the `!` inverts the
status before `$?` is read, so the second form records 0 for every failure. Nothing is lost
by the change: the leg records the same failure under the same name, and the linter can now
see the body.

Confirmed by the warnings disappearing one function at a time as each call site was
converted, which is worth more than the clean run at the end — it shows the fix caused the
change rather than coinciding with it.
