# Plan 00112 — Journal 2026-09-17

## The batch run discharged most of Task 2.1, and check [5] earned the bracket

`triage.bash` → `deploy.bash` → `triage.bash` → `acceptance.bash` on the host. The gate
returned **ACCEPTED** on `COVERAGE: 10 of 10` — 10 assertions passed, 0 failed, 0 could
not be established.

Check **[5]** is the one worth recording: *the deploy removed nothing from the enabled
list*, proved by diffing the before/after triage pair rather than asserted. Under a plain
deploy-then-acceptance harness that check can never pass, because no single reading of the
host can answer a question about what changed — it would report COULD NOT ESTABLISH for
ever, however healthy the machine was. Bracketing the deploy with triage is what made it
answerable, and this run is the evidence that the bracket was worth building.

The gate also declined to claim two things, in its own NOT ESTABLISHABLE HERE section
rather than by quietly passing them:

- the VM-lab criteria, which nothing on this host can speak to;
- Success Criterion 2's "a host with EXTRA user-enabled extensions" clause. Check [5]
  proves nothing was removed and reports how many pre-existing UUIDs this repo does not
  declare — but if that count is 0, the removal path was never exercised with a user's
  own extension present. Passing is then compatible with the path being untested.

## What is still owed, and why the run does not cover it

The **second `deploy.bash`**. Task 2.1 asks for two consecutive deploys, the second
reporting no change, and the batch harness deploys once. Nothing in this run speaks to
idempotency: a play that removed something only on a re-run would produce evidence
identical to what is on disk now. That is exactly the failure mode this plan exists to
prevent, so it cannot be waved through on the strength of a single-deploy ACCEPTED.

Also owed: the `play-vm-test-lab.yml` redeploy. Until the host's deployed guest checker
matches this plan's version of it, Task 2.2's vmtest run cannot mean anything — which is
why the two green runs already on record certify nothing.
