reader sizing a disk budget from the smallest model is told roughly half the true number.

The lesson is about the audit, not the doc: **the suspicion picked the mildest example it had**

as confirmed immediately. A finding's severity should be set by its worst instance, not by whichever
one the reviewer happened to cite.

the reader is actually sent. `RUN_BASH_USER_*` is documented in `headless-provisioning.md:54-55` and

## 13:40 — Phase 2 fixed, @-imports removed, and the condition that made it safe

All four harmful docs fixed, and the owner approved removing the `@`-imports **with a
condition that turned out to be the important half**: only do it if `.claude/rules/*.md`
with `paths:` globs make the same documents load on demand, so that editing Ansible still
triggers reading the Ansible rules.

They were right, and I would have shipped the unsafe version. My framing had been "the
imports cost ~108,900 bytes per session" — true, and it makes removal look like a pure win.
It is not: the imports were doing a job. Deleting them without a replacement trigger does not
save context, it silently removes guidance, and the failure would be invisible — a future
session editing a playbook would simply not know about the `root_dir` rule, and nothing
would announce that.

**`.claude/rules/` did not exist in this repo at all.** The `bash-standards.md` and
`plan-script-standards.md` I had been reading all session belong to the **outer lts-infra
checkout** at `/workspace/.claude/rules/`. That is the third time today this nesting has
fooled me — the first was the hook's "On branch main" (lts-infra's branch, not this repo's),
the second was my ruff-config-leak hypothesis. The vendored-checkout layout is a standing
trap: anything resolved from the *working directory* rather than from a known root can
silently answer about the wrong repo.

Seven rules written, each a **thin pointer** to the topic file that owns the fact rather than
a copy — one source of truth per fact still holds:

| Rule                  | Triggers on                                            |
| --------------------- | ------------------------------------------------------ |
| `ansible-editing`     | `playbooks/`, `tasks/`, `vars/`, `environment/`, `*.yml` |
| `bash-scripts`        | `**/*.bash`, `scripts/`, `files/**/bin/`               |
| `ccy-version-bump`    | `files/var/local/claude-yolo/`                         |
| `python-helpers`      | `helpers/`, `tests/helpers/`, `**/*.py`                |
| `secrets-and-vault`   | `environment/`, `vault.bash`, `*_vars/`                |
| `gnome-extensions`    | `extensions/`, gnome-shell dirs                        |
| `qa-gates`            | `scripts/qa-*.bash`, `ruff.toml`, workflows            |

`ccy-version-bump` is the one that most needed to exist: a missed bump is rejected by a
pre-commit hook, so without a trigger an agent discovers the rule by being blocked.

### S2 — reclassified from "simplification" to "wrong factual claim"

`claude-devtools.md:142` reads **"`ccdt` runs:"** and then shows a command `ccdt` does not run.
That is not a readability trade-off, it is an inaccurate statement of fact, and the three
omitted flags are precisely the ones that make the documented workflow work:

- `--name` — deterministic per-project name from `derive_container_name` (`ccdt:129-148`)
- `--replace` — **because** the name is deterministic, without this the *second* run fails
- `--init` — real PID 1; the script prints "Press Ctrl+C to stop" three lines above the `exec`

Fixed by showing the real command and explaining each flag, so they read as design decisions
rather than noise a future editor might trim again.

The play says at its own line 3 that it is not part of a configuration run. Excluding it is
correct. What was wrong is that `docs/playbooks.md` calls itself a "Complete catalog" and
never mentions `playbooks/dev/`, so the absence is indistinguishable from an oversight — which
findings 2 and 9 in this same audit actually were. Fixed by stating the scope, not by
cataloguing the play.
