## 05:52 · finding · P1 — 32 drift findings across 9 doc groups

Nine sonnet verifiers audited every doc under `docs/` plus the root `README.md`
against `playbook-main.yml`, `playbooks/imports/**`, `files/**` and
`extensions/**`. Two groups (headless provisioning, GitHub multi-account) came
back clean — those docs are accurate.

The dominant failure mode was **core plays documented as optional**. Nine
separate cases: Python, VS Code, Firefox, Slack/Flatpak, Kitty, WireGuard,
Docker, GitHub multi-account and gsettings are all imported unconditionally by
`playbook-main.yml`, yet were listed as things the user must opt into. A reader
would have gone looking for a playbook to run that had already run.

The most serious individual findings:

- `docs/fast-file-manager.md` documented an entire **feature that does not
  exist** — `disable_tracker`, with default values, trade-offs, affected
  services and a "Re-enable Tracker" recovery procedure. `grep -rn
  "disable_tracker\|tracker-miner" playbooks/ vars/ environment/` returns
  nothing. The play's real fourth optimisation is disabling GNOME's
  recently-used file history.
- `docs/features/speech-to-text.md` documented `claude_stt_model` as a host var.
  It exists nowhere in the repo; the model is a GSettings key set in the
  extension's own Preferences window, or the `wsi --claude-model` flag.
- `README.md` advertised a **Playwright testing environment** as an optional
  add-on. `play-claude-yolo.yml:440` actively *removes* the `playwright-tests`
  distrobox container — the feature was retired in favour of agent-browser, and
  `docs/playbooks.md:345` already said "no Playwright needed". The link anchor
  was broken too, which is how I found it.

## 06:04 · decision · T2.1 — verified before applying; agents were not taken at face value

Re-checked every finding against source myself. All 32 were real, but two
needed correction before applying:

1. The `play-git-configure-and-tools.yml` finding claimed "grep for ssh returns
   zero matches". False — there are 14 matches. The play *does* have SSH
   content, just an ssh-agent prompt for SSH sessions, not the LXC SSH config
   the doc credited to it. So the right fix was to **replace** the line with
   what the play actually does, not delete it as the agent proposed.
2. `docs/containerization.md:132` uses `docker-compose` inside a Docker-in-LXC
   container. That container's Docker is not installed by `play-docker.yml`, and
   `play-docker-in-lxc-support.yml:92` prints the same `docker-compose up` in its
   own guidance. Changing the doc would have made it disagree with the playbook,
   so it was **left alone** — only the three host-Docker call sites were fixed.
