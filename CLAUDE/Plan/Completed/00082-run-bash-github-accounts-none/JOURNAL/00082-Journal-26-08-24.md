## 12:05 · finding · T3.5 — `qa-all.bash` reported 0 bash files; root cause was
an absolute-path exclusion bug in shared QA discovery, not this plan's files

Running `./scripts/qa-all.bash` failed: "file discovery found 0 bash files
under /workspace/untracked/repos/fedora-desktop". Traced with `bash -x` to
`qa_discover_shell_files()` in `scripts/qa-discovery.bash`: its `find` exclusion
used `! -path "*/untracked/*"`, a substring match against the *absolute* path
`find` walks — which matched this CCY container's own checkout location
(`/workspace/untracked/repos/fedora-desktop`), an ancestor of every file in the
repo, not the repo's own internal `untracked/` subdirectory the exclusion was
meant to hide. `scripts/qa-js.bash` had the identical bug in its own inline
`find` call.

First attempt was to work around the checkout path (symlink — `find` did not
follow it and still found nothing, not investigated further; `mount --bind` —
permission denied; copying the 7.8 GB repo — ruled out as impractical). Asked
the user via `AskUserQuestion` for a path forward, offering three workaround
options. The user rejected all three outright and directed fixing the
exclusion mechanism itself so it only ever ignores `untracked/` as a
subdirectory of the repo root — not the checkout's own ancestor path.

Fixed properly: `qa_discover_shell_files()`/`qa_discover_python_files()` in
`scripts/qa-discovery.bash` now run `find` with no path-based exclusion
predicates and apply exclusion afterward on the repo-relative path
(`rel="${file#"$repo_root"/}"`) via the same `qa_is_excluded`/`qa_py_is_excluded`
functions the git-based tracked-file discovery already used — unifying the two
mechanisms. `scripts/qa-js.bash` (no shared library) got the narrower fix: only
its `untracked` predicate anchored to `"$REPO_ROOT/untracked/*"`; the other
exclusions (`node_modules` etc.) stay anywhere-in-tree since those names
legitimately nest at multiple depths. This is repo-wide QA tooling, not
run.bash-specific — recorded as its own Task 3.5 and a "Scope note" in
PLAN.md rather than folded silently into the run.bash work.
