Check [6] now resolves a real subdirectory of the mount —
`find "$rc_mount" -mindepth 1 -maxdepth 1 -type d -print -quit` — which is the shape

```
library variant                    OLD input     NEW input
                                   (root + /.)   (a real subdirectory)
shipped                            resolves      resolves
mutant %/. strip                   resolves      FAILS
mutant realpath                    resolves      FAILS
mutant none                        FAILS         FAILS
```

The old input killed 1 of 3; the new one kills 3 of 3, and the shipped library passes both,

falling back to the root — a gate that cannot construct the client's input has not tested
it, and silently substituting a weaker one is the blind-reads-like-clean case this whole
plan is about.

**`findmnt --target` can emit more than one row.** On an over-mounted target it prints one
row per stacked mount — demonstrated on this machine against
`/sys/devices/virtual/powercap` — and a restarted rclone unit mounted over its own
mountpoint gives exactly that shape. My normalisation kept the whole output, so `mountpoint`
held two newline-separated copies and the cmdline match could never succeed. It fails
closed, so no wrong address, but it is unserviceable where the *pre-normalisation* code
worked, and the diagnostic named a two-line path.

Round 2 had raised the missing `head -n1` against the address capture one line below. I
fixed that site and introduced the identical un-headed shape six lines above it, in the same
