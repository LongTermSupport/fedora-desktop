# Plan 00079 Journal — 2026-09-10

## 15:05 · finding · the anti-regression test proved nothing, and I proved that

The re-review's gating finding was that `unit-test-selection.bash` never calls
`pick_target` and instead re-implements both candidate predicates inline, asserting that
one is wrong and the other right. Reverting `podfreeze` would leave all 49 assertions
green.

Confirmed the shape at source: the axis-offer decision had exactly one site, inside
`pick_target`, and `pick_target` dies without a TTY, which is why it was skipped. So the
test could only ever have re-implemented it.

Fixed by extracting the decision into `identity_axis_discriminates <axis>`, called by
`pick_target` and by the test. Then **broke it on purpose**: replaced the function body
with the old `[ "${#values[@]}" -ge 2 ]` proxy and re-ran.

```
FAIL    ... so the shipped predicate offers the row  got [suppressed] want [offered]
FAIL    ... and the fixture is restored ...          got [suppressed] want [offered]
VERDICT: FAIL — 2 assertion(s)
```

Restored; 50 assertions PASS. That is the evidence the previous fix commit claimed and
did not have.

While there, added the predicate's **other** side. Every assertion so far only checks that
the row is *offered*; a predicate hardcoded to `return 0` would satisfy all of them. So the
test now also builds the suppression state — every CCY session given one shared token
value — asserts the axis is suppressed, and restores the fixture. A one-sided test of a
two-sided predicate is the same defect class in miniature.

## 15:15 · decision · the `rm` in deploy.bash goes into the play

The review flagged `rm -f "$HOME/.local/bin/podman-freeze"` at `deploy.bash:152` as a
manual system change, and left the decision open because the author's reasoning — that a
same-day rename is transient cruft that should not live in the shared tree forever — was
on record.

Decided for the play. The IaC HARD RULE is unqualified, and the counter-argument is
concrete rather than stylistic: `play-podfreeze.yml` is directly runnable without
`deploy.bash`, so anyone who runs the play alone never gets the migration; and this plan
folder leaves with the plan when it moves to `Completed/`, at which point the migration
vanishes while any un-migrated machine still has both binaries on `PATH`. Five lines of
`state: absent` in the play, and the comment records why it lives there.
