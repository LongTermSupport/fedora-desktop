# Plan 00079 — Journal 2026-09-17

## The marker-cut test aborted at check 0, and the comment above it explains why

`unit-test-selection.bash` sources `podfreeze` up to a marker comment so it can test the
functions without running the main flow. It cut with `grep -n '^# Argument parsing$'`.

In `cfe8afbe` that marker line grew a trailing sentence — it now reads
`# Argument parsing. ACTION and DRY_RUN are the library's …`. The `$` anchor stopped
matching, the test took its hard-failure branch, and it has aborted at check 0 on every
run since. Nothing about that failure looked unusual; it reported a missing marker, which
is precisely what a genuinely deleted marker would report.

The comment directly above the cut says the marker exists "rather than a line number, so
this does not rot as the script grows". The intent was right and the implementation
defeated it: requiring the whole line to match makes the test as brittle as a line number
against any edit that annotates the marker. A marker survives being annotated; an
exact-line match does not.

Anchored at the start only now. Dropping `$` trades strictness for ambiguity, so the
ambiguity is checked rather than assumed — more than one matching line is a hard failure,
because a cut point chosen by guess silently sources a different part of the file, which
is the same class of silent-wrong-answer the strict anchor was trying to avoid.

Falsified both directions against the current `podfreeze`: the old pattern exits 1 and
would abort; the new one matches exactly one line, 795.

## What it reaches now, and what it still does not

Running it in the CCY container, it clears the cut and gets into real work before stopping
on a missing dependency: the shared freeze library is not present here. That is correct
behaviour — the library is deployed by `play-podfreeze.yml` on the host, and this container
is not a deploy target. It is not installed by hand.

So this does **not** yet discharge Plan 00130's Task 2.2 for this script. That task asks
for proof the script reaches its own last line, and an early exit on a host-only
dependency is not that, however legitimate the exit. It needs a host run.
