## 12:30 — three gate defects, all the same shape

The mandatory pre-commit gate exited 1 on a clean tree. Three unrelated causes, and every one is
Plan 00067's pattern with a twist: 00067's gates checked **nothing**; these checked the **wrong
things** — which is worse, because a wrong answer looks like work being done.

**D1 was the one with a moral.** The fail-fast grep flagged
`play-systemd-user-tweaks.yml:242`, a comment explaining that `ignore_errors: true` had been
*removed* and why. Someone did the right thing, wrote down the reasoning, and the gate punished them
for it. The incentive that creates is to delete the explanation — the gate would then be green and
the repo dumber. Fixed by stripping YAML comments before matching, but checking `FAIL-FAST-OK` on
the **full** line first, because that annotation lives in a comment too. Both halves are needed and
a naive strip breaks the second.

**D2 I found while sizing D3, not while looking for it.** `qa-python.bash` has two discovery passes.
The `.py` pass excludes `venv`/`.venv`/`__pycache__`; the executable-shebang pass did not. So the
gate linted `.claude/untracked/venv/bin/pip` — a third-party console script. The tell was in the
finding list: three `pip*` files reporting `UP009` and `I001`. What made it invisible for so long is
that the directory was **half**-excluded: anything with a `.py` extension in that venv was correctly
skipped, so the exclusion looked present and working.

**D3 nearly became a false finding.** My first hypothesis was that a `ruff.toml` in the outer
lts-infra checkout was leaking into this vendored tree — plausible, since this repo lives at
`untracked/repos/fedora-desktop` and that exact nesting caused Plan 00067. `ruff check --isolated`
disproved it: the ~415-rule set is ruff 0.16.0's own default. Had I not run that one command I would
have filed a confident, well-cited, wrong finding — and "a parent config is leaking in" would have
sent the fix in entirely the wrong direction.

The real defect: `ruff.toml` does not enumerate `select`, so the enforced ruleset **is** the default
set, which grows every release — while `ruff.toml:5` claimed "Use default rule set (E, F, W)". Wrong
by ~350 rules. Three unpinned install sites (ccy Dockerfile, CI, dnf), so the gate's strictness was
whatever happened to be installed.

Pinned the two we control. The third — `play-python.yml` → `dnf: ruff` — tracks whatever Fedora
ships and **cannot** be pinned from here, so pinning alone would have left a silent divergence.
`qa-python.bash` now **asserts** the version instead: a mismatch exits 2 naming both values and where
the binary came from. That is strictly better than a pin, because it covers the install path we do
not own.

### Two things I got wrong on the way

**I reached for a suppression before a fix.** For `C408` my first edit was `# noqa: C408`. The
daemon blocked it. The actual fix — writing the dict as a literal — was one edit and obviously
better. The reflex arriving first is the thing worth recording.

**I used `replace_all` on `stats` and broke the file.** Two sites needed `_stats`; six others *use*
`stats` afterwards. `replace_all: true` renamed all eight and produced four `F821 undefined name`
errors. Caught immediately by the edit-time linter, fixed in four edits — but the lesson is that
`replace_all` is only safe when the name's every occurrence is genuinely the same decision, and
"unused variable" findings are per-site by definition.

### What I did not do

Left `BLE001` ×2 in `clip-scan` exempted rather than "fixed", because both handlers are correct —
one records the exception and returns it, the other prints a traceback and exits 1. Narrowing the
first would abort a whole batch scan the first time a corrupt file raised something unanticipated
from LibRaw. The exemption is documented in `ruff.toml` as **a deliberate design decision, not an
external cause**, deliberately distinguished from the N999 precedent so nobody reads it as licence
to exempt any blind catch.

Left the 105 shellcheck findings alone — all advisory tiers; only `error` gates.

### The risk I am not mitigating

**The QA gates have no tests.** Every fix here was proven with a hand-built fixture tree that I then
deleted. Three gate defects across two plans is a pattern, and the gates that guard the repo are
themselves unguarded. Recorded as an unmitigated risk rather than quietly omitted.
