## 22:04 · finding · T1.1 — where the grant is made

`playbooks/imports/play-basic-configs.yml` "Passwordless Sudo": an unconditional
`blockinfile` into `/etc/sudoers`, marker `## {mark} passwordless sudo for <user>`, block
`<user> ALL=(ALL) NOPASSWD: ALL`. Runs on every profile. `provisioning_profile` is already
resolved in this play (the USB-audio and fwupd tasks gate on it), so the profile is available
at this task with no plumbing.

Nothing in `run.bash` depends on the block: the headless preflight accepts an operator-owned
`NOPASSWD:ALL` or `RUN_BASH_SUDO_PASSWORD_FILE`, and the interactive path prompts. Removing
the grant on servers changes what the playbook leaves behind, not how it is driven.

## 22:06 · decision · T1.1 — `absent` on server, not merely "skip"

Skipping the task under `server` would leave a block written by an earlier desktop-profile
run in place, and the operator would have to know it was there. Declaring `state: absent`
makes a server converge to the state its profile says, which is the whole point: the
provisioner owns the posture, nobody downstream undoes it. Only the play's own marker is
removed. An operator-written drop-in (headless-server-install Step 0a) is a supported
credential and is not this play's to touch, so there is no "assert no NOPASSWD anywhere"
here.

One consequence documented rather than hidden: a server box that relied on the play-written
block as its only credential, with no password file, passes preflight and then loses the
block mid-play; later `become` tasks fail with `Missing sudo password`. That is the honest
outcome — the box has no credential the operator owns — and `docs/headless-provisioning.md`
now says so.
