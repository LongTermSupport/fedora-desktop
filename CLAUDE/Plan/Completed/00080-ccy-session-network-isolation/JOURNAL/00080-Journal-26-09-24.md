## 08:13 · decision · T2.2   — owner decides a network per session; Low priority, Dormant

The owner chose **Option 2, a network per session**, because it is the only option that
keeps mid-session `ccy --connect`.

- **Naming:** each network is prefixed `ccy-isolate-`, and `podfreeze` ignores that
  prefix, so its menu gains no per-session rows (D1, Task 4.1).
- **After `--connect`:** a session is on its own network plus the project network it
  joined. It reaches that project's services, and any other session that joined the same
  network, but no one else.
- **Priority is Low, and the plan is Dormant until the owner schedules Phase 3.** The
  owner's judgement is that sessions on one machine reaching each other is not a
  significant attack vector. That agrees with the threat model: nothing is listening that
  a neighbour could reach (F22, F26, F30), and every session runs as the same user.

The measured caveats carry into Task 3.1:

- **Isolation:** on this host, below netavark 2.0 (F24), isolation between networks must
  be passed explicitly (`--opt isolate=`) and proven.
- **DNS:** a fresh network has DNS enabled (F36).
- **Cleanup:** H4 is unmeasured (F37). The broken probes P7, P10, P11 and P12 are to be
  fixed and re-run first.
- **Cost:** a network is a bridge, a small config file and a /24 from podman's pool, and a
  leaked one with no container holds no interface (F38). The cleanup on exit and the
  sweep at launch are about not exhausting the pool, not about performance.
