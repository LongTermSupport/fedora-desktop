### Design points worth knowing

- **State is always read with `lxc-info -s`, parsed independently** — never through lxcfreeze
  and never by reusing its parser — because the success criterion says "verified with
  `lxc-info -s` rather than by the tool's own report".
- **The throwaway container is created, not borrowed**: `lxc-create -t download -- --dist alpine --release edge --arch <mapped uname -m>`, started, and confirmed RUNNING with
  `lxc-wait` plus an independent `lxc-info`. `edge` rather than a pinned release so the gate
  does not rot into one that stops running with no code change.
- **If it cannot create one** (no network to the image index, the download template absent,
  or a container of that name already present — which it refuses to touch), checks 6–9 each
  report **NOT ESTABLISHED** and the run exits 2. They are never counted as passed and never
  silently skipped. `NOT ESTABLISHED` is a third outcome alongside PASS and FAIL: the check
  counts towards coverage because it ran, and blocks the verdict because it did not answer.
- **Check 8's assertion is chosen from the container, not assumed.** lxcfreeze's thaw renews
  the DHCP lease through NetworkManager and declares that a container without it FAILS the
  renewal loudly. So the gate probes for `nmcli` inside the probe container first: where it is
  present a failed renewal is a defect; where it is absent, the named failure — non-zero, with
  a message containing "thawed, but the DHCP lease was not renewed" — IS the declared
  behaviour, and a silent success there would mean the renewal was never attempted. Either
  way the state must independently read RUNNING.
- **Teardown is chained in FRONT of the library's handlers**
  (`trap 'probe_teardown; cleanup_tmp; _plan_finalize_log' EXIT`, and the same for
  INT/TERM/HUP). A plain `trap … EXIT` would REPLACE `_plan_finalize_log` and truncate the run
  log's final buffered chunk. Teardown also runs explicitly before checks 10–11 so the host is
  clean early, and the removal is then verified by re-reading existence.
- **Two annotated deviations.** `# STANDARD-EXCEPTION(R7)`: declared `gather` though it
  changes state — what it changes it created and destroys, and declaring `deploy` would force
  a change gate on a verification run. `# STANDARD-EXCEPTION(R9)`: explicit exit rather than
  `plan_finish`, whose two-valued exit cannot carry a three-valued verdict.
- **No `|| true`, `set +e`, `2>/dev/null`, `sed`, or suppression directives** (grep-verified).
  Failures are captured into a variable with `|| rc=$?` and reported. The one
  `# shellcheck source=` line points at the REPO copy of the library so `-x` can follow it —
  a source directive of the same shape `lxcfreeze` itself uses, not a suppression; check 1 is
  what establishes the two copies are the same bytes.

## Not establishable by a script

1. **Success criterion: "After `lxcfreeze thaw`, ssh into the container succeeds on the first
   attempt, after a freeze longer than the one-hour lease."** It needs a real hour-long freeze
   and a container running both sshd and NetworkManager. Check 8 gets as close as a gate can:
   it proves the renewal runs on the thaw path, gates the thaw's status correctly, and that a
   failed renewal is named and says the container is thawed.
2. **Task 4.6's "podfreeze's fzf path in particular".** fzf's picker needs a TTY and
   keystrokes; a non-interactive gate cannot drive it. Checks 3–5 establish that fzf is
   installed and that the shared layer both tools enter is one implementation — the keystroke
   behaviour itself stays a human check.
3. **Task 3.7** is blocked pending its own plan (the `.semgrep` `|| true` rule widening, two
   of the eighteen sites being the git hooks that gate secret scanning). Nothing a script in
   this folder can settle; left untouched.
4. **A genuinely refused sudo and a genuinely absent lxc** are reached through PATH — a
   refusing `sudo` shim, and a PATH holding only `bash` and `dirname` — rather than by editing
   sudoers or uninstalling lxc. If the harness itself misfires (anything printing "command not
   found"), the check reports NOT ESTABLISHED rather than a pass or a false failure.
