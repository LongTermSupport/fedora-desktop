## 09:17 · finding · — — this plan's central premise was false

Plan 00067 justified its scope with:

> It also bought very little: vfs/stats and core/stats — which is all
> ftp-camera --copy, rclone-tail and rclone-cache-status need — are served
> WITHOUT auth. Only vfs/refresh (rclone-cache-warm) and core/stats-reset are
> gated […]

That is not how rclone behaves. Once `--rc-user`/`--rc-pass` are configured,
**every** rc endpoint is gated. Measured on the host against the mount this
plan deployed:

```
$ rclone rc --url=http://localhost:5572 core/stats
{ "error": "… 401 Unauthorized", "path": "core/stats", "status": 401 }
```

Consequence: `rclone-cache-status` and `rclone-tail` were left un-migrated on
that false premise and stopped working the moment this plan deployed. Each
reported the 401 as `rc unreachable`, so it read as a dead mount rather than an
auth mismatch, and went unnoticed for a week.

## 09:20 · finding · — — the ftp-camera fix never reached the host

This plan changed `files/home/.local/bin/ftp-camera` (adding `--user/--pass` to
its rc calls) but its `deploy.bash` runs only `play-rclone.yml`. `ftp-camera` is
deployed by `play-ftp-camera.yml`, which was never run. The repo carried the fix
and the host kept running the pre-00067 build:

```
<home>/.local/bin/ftp-camera            106837 bytes  mtime=2026-07-30 12:18
<repo>/files/home/.local/bin/ftp-camera 107814 bytes  mtime=2026-07-30 12:23
```

`acceptance.bash` did not catch it because it verified the repo and the mount
unit, not the deployed client. A gate that reads the source tree cannot see a
host that is out of date with it.

## 09:31 · finding · — — the in-flight guard in deploy.bash false-positives

`pgrep -af 'ftp-camera'` is a bare substring match over every process's full
command line, so it matches any shell that merely *mentions* ftp-camera —
including the one invoking the deploy. Observed firing with nothing running.
Left as-is here (this plan is closed and its script will not run again); the
successor's copy anchors the pattern and excludes self/parent.

## 09:50 · handoff · — — superseded by Plan 00072

The *decision* this plan made stands: authenticating the RC was correct, and the
mount, credential and unit it produced are all healthy. Only the rollout was
incomplete. Plan 00072 migrates every client onto a shared credential helper
(`files/home/.local/bin/rclone-rc-auth.bash`), corrects the false premise
wherever it was written down, and adds `scripts/qa-deployed-drift.bash` so a
repo-vs-host divergence fails QA instead of surfacing weeks later.
