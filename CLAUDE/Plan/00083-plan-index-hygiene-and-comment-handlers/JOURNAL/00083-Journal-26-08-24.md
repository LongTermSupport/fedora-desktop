## standing_authorisations enabled — Task 3.3 unblocked

The owner asked why the daemon's standing-authorisation system was not enabled. It was
not, because the handler ships **enabled with every authorisation off** — inert until the
repository owner opts in. That asymmetry is deliberate upstream: it is the one handler that
RELAXES a restriction rather than adding one, so shipping it active would have the daemon
fabricate the very consent its own injected text claims.

Enabled `subagent-delegation` only. `workflow-orchestration` is a separate built-in id and
stays off — authorising delegation says nothing about authorising multi-agent workflow
orchestration, which can spawn dozens of agents and is a different cost decision.

The gap this closes is arithmetic rather than wording: the restriction lives in a system
prompt re-sent on **every** request, while the request that satisfies it was made once, in
a session that has since ended. This repo mandates `qa-reviewer` as the final step of every
plan, so with no durable record the one gate that catches what `qa-all.bash` structurally
cannot stalls until the owner re-grants what they already mandated.

Task 3.3 is therefore unblocked and the review has been dispatched over
`origin/F44..HEAD` (8 commits: the daemon upgrade, its doc reconciliation, Plan 00071, this
plan's two commits, and the authorisation config itself).

## Plan renumbered 00082 → 00083: a live counter collision

While the review ran, a peer session merged its own **plan 00082** through PR #33. The
counter (`hooksdaemon.latestPlanNumber`) is `--local` git config and is never pushed, so
two clones allocated the same number independently — precisely what Plan 00079 recorded
when it renumbered from 00078, and what `plan_number_helper`'s block on hand-created
folders is meant to narrow.

`mkplan.bash` did nothing wrong here: it takes a lock and allocates atomically *within a
clone*. Nothing synchronises across clones, and no local mechanism can. This one renumbered
because its peer's number was already referenced by a merged PR.

`CLAUDE/Plan/CLAUDE.md` still told readers to create a plan folder by hand — a path daemon
3.53.0 blocks outright. Corrected, with this collision as the worked example.
