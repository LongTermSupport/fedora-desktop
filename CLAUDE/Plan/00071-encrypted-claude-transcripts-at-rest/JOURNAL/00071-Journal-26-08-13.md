## 15:14 · finding · — — where CCY state actually lives (corrects the framing)

The request assumed CCY "maps the Claude projects folder into the container".
It does not. `entrypoint.sh:195` does `ln -sf /workspace/.claude/ccy /root/.claude`,
so **all** container Claude Code state is written *inside the project working tree*
at `.claude/ccy/` (gitignored) — not into the host `~/.claude/`. The host
`~/.claude/projects/` is still used by **desktop** (non-container) Claude Code.

So there are two distinct plaintext stores, and any design that only covers one
leaves the other open.

Current footprint in this repo alone:

```
62M	.claude/ccy
68 	*.jsonl transcripts under .claude/ccy/projects/-workspace/
5.7M	largest single transcript
```

Implication: the blobs are per-project and inside a git working tree, which
changes the risk picture (accidental commit / sync exfiltration) as well as the
encryption options available.
