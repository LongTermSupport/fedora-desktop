## Threat Model Verdict

**Encrypting this directory with a key supplied at CCY launch defeats far less than it appears to, because the key is loaded precisely when the most probable attacker is running.**

Scenario-by-scenario, honestly:

**Genuinely defeated**

- **Exfiltration by copy of the project tree** — rsync, tar, restic, borg, Dropbox, Syncthing, rclone, btrfs snapshots leaving the LUKS volume. `.gitignore` does nothing here (F23) and `.claude/ccy` lives *inside* the working tree by design, which makes CCY strictly **more** exposed than `~/.claude` today. This is the strongest justification — and it is conditional on the unverified "does anything actually back this up" premise.
- **Code execution as the user *between* sessions** — the machine is on far more hours than a session runs. An infostealer sweeping `~/.claude`/`.claude` by name (F29, F30) finds ciphertext.
- **Stolen laptop *suspended* with no session live** — LUKS keys are in RAM; the transcript key is not.

**Defeated, but more cheaply by other means**

- **Another local non-root user.** 879 of ~978 state files are other-readable *right now* (F8), including 7.7 MB of verbatim pre-edit file bodies. A `umask 077` + one recursive `mode: u=rwX,go=` closes this for free. Note the irony: `projects/` — the directory everyone proposes to encrypt — is the one directory already at mode 700. **The open hole is beside it.**

**Not defeated at all**

- **RCE / malicious npm-pip-MCP package / prompt-injected agent while a session is live.** Same UID, key loaded, plaintext readable. This is the most probable 2026 attacker (F30) and at-rest encryption is a category error against it.
- **Root on the box.**
- **Stolen laptop powered off** — LUKS FDE already covers this (F11). Zero delta.
- **Secrets entering the transcript in the first place.** Encryption is downstream of the leak.
- **Server-side retention at Anthropic.**
- **Metadata** — sizes, mtimes, directory shape, session counts leak under every scheme.
- **The desktop `~/.claude` store**, which has no container boundary and has never been measured.

**Two premises in the brief are wrong and should not be repeated in the plan.** Transcripts do *not* "persist indefinitely": `cleanupPeriodDays` defaults to 30 and is demonstrably working (F3) — though `history.jsonl` genuinely is never swept (F4). And the archive is not currently "a goldmine": zero live credentials were found across 60 historical transcripts (F10). What *was* found is 27 `$ANSIBLE_VAULT` blobs across 7 files, which proves the **capture mechanism** works end-to-end. **The risk is prospective, not realised.** Frame the plan that way or it will not survive scrutiny.

**Conclusion: most of the available risk reduction is not in encryption.** Ranked by reduction per unit of complexity: (1) fix the 879-file permission posture; (2) block credential reads at source via managed-scope deny-rules; (3) pin `cleanupPeriodDays` in managed scope so a malformed settings file cannot silently degrade retention to forever (F5); (4) mark the tree non-backupable; (5) seal the *archive* with a public key. Encryption of the *live* file is last, costs the most, and — because the hooks daemon reads transcripts by byte offset (F24) — is the one option that can break the repo's own workflow enforcement.

## Recommended Approach

**Ship C (Blast-Radius Reduction) first and unconditionally. Gate any live-state encryption behind a host-run `triage.bash`, and if it proceeds, build it as tmpfs-plaintext + Phase-1's existing `age` sealer — not as gocryptfs, and not as a bespoke store engine.**

Both judges converged on C-first (operability scored it 8 vs 6/4; security recommended "Hygiene amended, plus tmpfs gated on triage, rejecting CryptView"). The reasoning:

1. **C addresses the only exposure that is measured and currently open.** 879 other-readable files including 7.7 MB of verbatim file bodies (F8) is a real hole today. Every encryption proposal leaves it — a FUSE mount with default permissions reproduces the same 755 directories.
2. **C cannot break the repo's own guardrails.** The hooks daemon's byte-offset transcript reads (F24) are load-bearing for the Stop handlers `CLAUDE.md` treats as mandatory. C never touches the live file.
3. **C's sealer is asymmetric.** Sealing needs only a public key, so the common launch path has **no prompt, no secret in RAM, no argv exposure, and nothing that can fail on a human**. Only *unsealing* needs the passphrase. This is what makes "guaranteed to seal" achievable at all.
4. **Security judge's objection to CryptView is decisive and structural**: `user_allow_other` in `/etc/fuse.conf` (F17) is a permanent, host-wide widening — every local user may then traverse any `allow_other` FUSE mount — imposed to protect one directory. That is a bad trade, and it is not reversible per-project.
5. **Operability judge's objection to SEALSTORE is equally decisive**: the log-structured manifest/segment/compaction engine (with a "frozen path" invariant that must never be violated) is where a subtle bug silently eats history, and it introduces a data-loss failure mode plaintext append-only JSONL does not have.
6. **The synthesis takes SEALSTORE's *shape* and discards its *engine*.** tmpfs for the plaintext view (no caps, no FUSE, no SELinux exposure, kernel-guaranteed teardown on `--rm`) with **Phase 1's `ccy-seal` age sealer** running on an interval as the durability mechanism. Same tool, same key material, same format, one codebase.
7. **Port SEALSTORE's two-way mount assertion into whatever ships** (operability judge's explicit recommendation): `entrypoint.sh` must `findmnt -no FSTYPE --target /root/.claude` and hard-exit in **both** directions — expected-tmpfs-but-isn't (plaintext silently on disk) and is-tmpfs-but-not-in-sealed-mode (state silently discarded). Both silent outcomes are unacceptable.
8. **Amendments the operability judge required for C**, adopted: the pre-launch credential scan and posture repair are **advisory** (they print, they do not block the launch path every session traverses); an `flock` guards the seal pass against concurrent sessions.

**Ordering matters for one more reason**: the scanner-blindness trap (F9). Any audit, QA gate or triage script that greps `.claude/ccy` with the shell's `grep` returns "clean" with exit 0 forever. Every script this plan produces must use `command grep`, and the scanner must self-test against a planted canary before any "clean" result is believed.

### CCY launch UX

**Phase 1 — no new prompt.** After the existing SSH-key selection, one informational block on stderr:

```
════════════════════════════════════════════════════════════════
Claude state hygiene
════════════════════════════════════════════════════════════════
  posture     0 group/other-readable files (repaired 3)
  retention   7 days (pinned, managed-settings)
  archive     14 sessions sealed · 2 live
  backup      CACHEDIR.TAG present
  scan        clean (scanner self-test passed)
  live session transcript: PLAINTEXT until sealed
════════════════════════════════════════════════════════════════
```

The last line is deliberate and non-negotiable: the banner must never let a user believe the current session is encrypted.

**Unsealing an archived session — the only place a passphrase appears in Phase 1:**

```
$ ccy --unseal 5cdaf206
Sealed session 5cdaf206 (4.4 MB).
Enter seal passphrase: ▮          <- age reads silently from /dev/tty
✓ passphrase verified (canary)
✓ unsealed → .claude/ccy/projects/-workspace/ (0600)
  This session is plaintext until the next launch re-seals it.
```

Wrong passphrase, third attempt:

```
✗ Passphrase incorrect (canary failed).
  Giving up after 3 attempts. Nothing was decrypted, nothing changed.
  Retry:  ccy --unseal 5cdaf206
```

Ctrl-D at any prompt: `Cancelled — no input. Nothing was decrypted.` exit 1.

**Phase 2 (if triage clears it) — one prompt at launch**, immediately after the SSH-key step, in the same visual block:

```
Encrypted session state — unlocking the archive
Passphrase:                        <- read from /dev/tty, never echoed

  ✓ Unlocked. Restored 12 recent sessions (14.1 MB) to RAM in 0.9s.
  ✓ Sealer running every 30s. Crash exposure: ≤30s of transcript.
  ✓ /root/.claude verified as tmpfs — no plaintext will reach disk.
```

A second concurrent session on the same project reuses the running state and does not prompt. Non-interactive / no TTY fails immediately with an actionable message — it never hangs on an unanswerable prompt.

## Risks & Mitigations

| Risk                                                                                                        | Impact | Probability      | Mitigation                                                                                                                                                                                                  |
| ----------------------------------------------------------------------------------------------------------- | ------ | ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Scanner blindness (F9) makes every audit report "clean"                                                     | H      | H                | `assert_scanner_can_see()` canary self-test before any clean result is trusted; `command grep` mandated in every plan script, script comment explaining why                                                 |
| A new pre-launch gate bricks the path every session traverses                                               | H      | M                | Posture repair + credential scan are advisory in Phase 1; every hard guard prints the exact playbook to run and depends on no network, container, or daemon                                                 |
| Security theatre — user believes the live session is encrypted                                              | H      | H                | Launch banner prints `live session transcript: PLAINTEXT until sealed` on every launch; docs lead with the threat-model scorecard, not the feature                                                          |
| Age passphrase lost → all sealed archives unreadable                                                        | M      | L                | Nothing sealed is a source of truth (code, plans and JOURNAL are in git; OAuth re-establishes in seconds); optional second `age -R` recipient held offline — **must be decided before the first seal runs** |
| Live-file encryption breaks the daemon's byte-offset reads (F24)                                            | H      | H *if attempted* | Structurally excluded: Phase 1 never touches the live file; Phase 3 presents an ordinary POSIX tmpfs view                                                                                                   |
| Filename-length regression silently breaks writes (F25)                                                     | H      | L                | No filename encryption anywhere in the recommended design; `acceptance.bash` asserts a 250-char path every run                                                                                              |
| `podman --tmpfs` or the FUSE mount silently does not apply → plaintext on disk, or state silently discarded | H      | M                | Two-way `findmnt` assertion in `entrypoint.sh` (Task 3.1); the old `rm -rf` branch deleted outright                                                                                                         |
| Phase 3 crash window loses transcript tail                                                                  | M      | M                | Bounded and reported (never silent); tunable interval; exit-trap freshness check names the lost window                                                                                                      |
| Host-wide `user_allow_other` widening                                                                       | M      | —                | Avoided entirely by rejecting host-side gocryptfs                                                                                                                                                           |
| `permissions.deny` blocks legitimate reads (`.env.example`, `*.pem` fixtures)                               | L      | M                | Tight patterns; deny message names how to proceed; patterns tuned after deployment                                                                                                                          |
| `git clean -xfd` destroys the sealed store (it is gitignored)                                               | M      | L                | Documented loudly; `ccy` refuses to launch on partial destruction (manifest missing while segments present) rather than silently starting fresh                                                             |
| btrfs CoW makes shredding migrated plaintext best-effort                                                    | M      | H                | Stated in the migration output, not buried in docs; snapshot expiry named as the user's follow-up                                                                                                           |
| Container version bump forces a rebuild for every user                                                      | L      | H                | The existing `REQUIRED_CONTAINER_VERSION` gate makes it loud, which is correct                                                                                                                              |
| Phase 1's `ccy-seal` gets extended to live files by a later contributor                                     | H      | M                | Explicit non-goal in `PLAN.md` and a comment in `ccy-seal` citing F24                                                                                                                                       |

## Open Questions For The User

1. **Does anything back up or sync the project tree?** If nothing does (Task 0.3), the headline justification for Phase 2 largely evaporates and the honest recommendation is Phase 1 only. This is the single most decision-relevant unknown.
2. **Escrow or not?** If the age passphrase is lost, all sealed transcripts are gone. My position is that this is acceptable — code, `CLAUDE/Plan/**` and `JOURNAL/` are in git, and Claude Code's own 30-day default would have deleted most of it anyway. The alternative is a second offline recipient (YubiKey via `age-plugin-yubikey`, or a printed identity), costing one line in `recipients.txt`. **Retrofitting a recipient requires unsealing and re-sealing everything, so decide before the first seal runs.**
3. **Retention floor: 7 days or 3?** And should the seal keep N most-recent *sessions* or N *days*? A `--resume` of an older session becomes a passphrase ceremony. This wants observed resume behaviour rather than a guess.
4. **Ship CCY-only, or CCY + desktop together?** Phase 1 covers both cheaply (managed settings are host-wide; the umask and mode fix apply to both). Phase 3 roughly doubles in scope if the desktop store is included — and the desktop store has *no* container boundary, so a CCY-only claim would be misleading. Recommendation: measure it in Task 0.4, then decide.
5. **Is a `ccy --ephemeral` flag (exporting `CLAUDE_CODE_SKIP_PROMPT_HISTORY=1`) wanted** for genuinely sensitive sessions? It is the only true zero-plaintext answer, at the cost of `/resume`, up-arrow history, **and** the hooks daemon's Stop handlers. Per-session opt-in, never a default.
6. **How aggressive should the credential deny-rules be?** Tight patterns risk missing `@file` inlining (F41, unverified); broad patterns will block legitimate `.env.example` and fixture reads. Where does the user want the false-positive/false-negative line?
7. **Confirm the framing.** The plan will state plainly that no live credentials were found in the existing archive (F10) and that transcripts do not persist indefinitely (F3) — the case rests on prospective risk plus a proven capture mechanism (27 vault blobs across 7 files), not on a realised breach. Confirm that this honest framing is what you want in a public repo, rather than a stronger claim.
