## 06:24 · finding · T1.1 — prior art: mimeopen is the closest, and still not enough

Surveyed what already exists before writing anything:

- `xdg-open` / `gio open` — open the registered default only; no default means
  failure (frequently silent, exit 3) and there is no chooser at all.
- `mimeopen` (perl-File-MimeInfo) — **does** prompt with a numbered menu when no
  default is registered (`-a` always asks, `-d` sets a default). Genuinely close.
  Its gap: it only ever knows GRAPHICAL `.desktop` apps, so in an SSH session it
  happily offers to launch something with nowhere to render.
- `run-mailcap`/`see` — mailcap-driven, ignores the freedesktop desktop-entry DB.
- `handlr`/`handlr-regex` — good fit, but not in Fedora's official repos
  (COPR/cargo), so not IaC-clean for this repo.
- `rifle` (ranger) — terminal-aware and rule-based, but it is ranger's internal
  opener and needs ranger's config to stand alone.

Takeaway: build a thin wrapper for the two missing behaviours (session
awareness + chooser-when-unsure) and delegate everything hard — type
resolution, the app list, launching, setting defaults — to the packaged tools.

## 06:33 · finding · T2.3 — two real defects the smoke tests caught (review had not)

Ran the script against a `file(1)` shim in the scratchpad (the CCY container has
no `file`/`mimetype`/`xdg-mime`/`gio`):

1. **A known type with no installed handler ran silently.** `sample.mkv` with no
   mpv/ffplay present fell through to the generic `file (identify only)` entry
   and *ran* it, because "known MIME type" was being treated as "confident".
   Fixed by measuring the candidate count before and after the type's case
   branch — a zero delta demotes the type to unknown, which routes to the
   chooser. Same for `.zip` with no archiver.
2. **The chooser hung with no terminal attached.** The guard was `[ -r /dev/tty ]`
   alone; `/dev/tty` was readable in the harness, so fzf drew its UI and waited
   forever for input nobody could supply. Fixed by requiring `[ -t 2 ]` as well
   (the menu is drawn on stderr) and failing fast with guidance naming `--list`,
   `--ask`, and `mimeopen --ask-default`.

Post-fix behaviour, verified:

```
text/plain, application/json, inode/directory, x-scheme-handler/https → confident, no prompt
video/x-matroska (no mpv), application/zip (no archiver), application/octet-stream → ask
no TTY → rc=1 with actionable guidance, no hang
"we ird's file.txt" → bash -c vim\ \"\$1\" open we\ ird\'s\ file.txt
```
