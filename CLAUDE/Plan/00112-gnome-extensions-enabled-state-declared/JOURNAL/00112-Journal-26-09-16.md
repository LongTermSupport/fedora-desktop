# Plan 00112 — Journal, 2026-09-16

## 16:55 · action · acceptance.bash written, and two defects it caught on itself

`deploy.bash` already existed; the verdict did not, so "did it work?" was a question only a
human reading dconf could answer. `acceptance.bash` now renders it: ten COVERAGE-registered
checks, reading the population from the same declaration the play reads and judging live state
through the play's own helper, so the gate cannot drift from the code it vouches for.

The check worth naming is [5], "nothing was removed". It proves that by diffing the triage
report from BEFORE the deploy against the one from AFTER — so without that pair it reports
could-not-establish rather than a pass. Asserting additivity from the after-state alone is not
possible, and a gate that pretended otherwise would pass on a play that had emptied the list
and refilled it.

Two defects were found and fixed while self-testing, both the same shape as the plan's own
subject: a missing tool was being downgraded to "could not establish" (hiding a real absence
behind an honest-sounding word), and check [7] passed when no session was reached at all.

Exit codes are three-valued on purpose: 1 for a failed assertion, 2 for could-not-establish —
no live GNOME session, or no before/after triage pair — and a missing check rejects even with
zero failures. The VM-lab claims are printed as NOT ESTABLISHABLE HERE and never counted.
