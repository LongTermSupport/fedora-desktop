## 16:46 · finding · T2.1   — system font caches 0600 under the host umask; root-umask defence

The host run's acceptance failed 6 of 17 checks (3, 4 to 7, 15) because of a deploy fault, not
the fallback file. The handler's `fc-cache -f` ran as root under the host's umask 0077, so all
the files it rebuilt in `/usr/lib/fontconfig/cache` were 0600 root. No user could read them, and
fontconfig used each user's per-user cache instead. That cache predates the file and still
counts as valid, because the font directory's mtime has not changed. Re-running the play does
not help: the file is unchanged, so the handler does not fire.

Defence Before Fix. The class is a root task that creates files users read, where the mode
comes from the inherited umask. The rule is `root-umask` in `qa-ansible`
(CLAUDE/QA.md#root-umask), proven against `tests/fixtures/ansible-root-umask/`. It reports
four shapes: a system cache rebuilt without umask 022; a download, redirect or tee into
/usr, /opt or /etc without umask 022 or a readable chmod; a git clone under /usr or /opt
without `umask: '0022'`; and an unarchive there without `mode:`. An independent search found
the yq download, the claude-devtools clone and the cuDNN unarchive, which the first
(cache-tools-only) rule missed, so the rule was widened to cover them. The sweep found 7
instances: play-fonts, dconf update, yq, the vscode repo file, the claude-devtools clone, cuDNN
and speedtest. All are fixed.

The fix: the handler now runs `umask 022` before `fc-cache -f`, and a find plus file task
makes the system cache files 0644 on every run. That repairs this host even when the handler
does not fire. acceptance.bash gains check 18, that the cache files are readable by every
user. Once readable, the system caches (built 10-23) are newer than the stale per-user ones
(10-02), and fontconfig uses the newest valid cache, so no per-user cache removal is needed.
