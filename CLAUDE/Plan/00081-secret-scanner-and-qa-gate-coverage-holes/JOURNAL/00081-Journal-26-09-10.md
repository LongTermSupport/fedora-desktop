## 15:48 · decision · three fixes had no gate, and each was proved by breaking it

This is the criterion the plan states and the one it had not met. Each fix below was
verified by re-introducing the original defect and watching something go red — the habit
Plan 00079's re-review put on the AgentNotes page this morning.

**F9** — `qa-ansible-syntax` had the zero guard and not the partial guard, while the three
source gates got exactly that guard *from this plan*. The yardstick has to be independent
or it proves nothing, so: the population is derived by CONTENT (a top-level `- hosts:` or
`- import_playbook:`), and the yardstick by tracked-and-located (every tracked YAML under
`playbooks/`). Narrowing the marker therefore breaks the comparison. Measured 77 of 77
when written. Re-introducing F14 — deriving from `- hosts:` alone — now names
`playbooks/playbook-main.yml` and exits 2. Before, that same regression made the reported
count **rise**, 78 → 79, and fired nothing.

**F10** — the fail-fast regex enforces this repo's #1 rule and had no fixture anywhere.
`scripts/test-qa-ansible-failfast.bash`, 18 cases, reads the `FF_*` definitions **out of**
`qa-ansible.bash` rather than copying them — a copy passes while the shipped gate is
broken, which is precisely the defect the 00079 review found in that plan's unit test.
Reverting F10 fails 5 assertions. Also closed the asymmetry one directive along:
`ignore_unreachable` was checked for booleans but not the templated form, while
`ignore_errors` was checked for both.

**F4** — the `.j2 → playbook dest:` assertion is a pure source-tree invariant that sat
behind three host-availability early exits. So it never ran in the CCY container where it
was authored, and never in CI: both return at the first skip. Moved above them. An unmapped
template now exits 2 here, where the gate previously returned 0 without looking.
