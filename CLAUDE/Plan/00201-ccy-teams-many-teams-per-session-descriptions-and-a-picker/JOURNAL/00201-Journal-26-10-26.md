## 12:37 · finding · T2.26   — masked-substitution rule red

Defence red for `assignment-masks-substitution-failure` (DBF; branch
`fix/bash-multi-substitution-rule`).

Class: a bash assignment whose exit status does not carry the failure of every command
substitution in the values it assigns. Hazard: errexit, `if` and `||` see success after a failed
read, and the script goes on with an empty or partial value (Plan 00211 stage 2, Task 2.22).

Semantics, run under bash 5.2.15 with `bash -ec` in a function body: CONTINUED (status 0) for
`x="$(false)$(true)"`, `x=$(false) y=$(true)`, `a=("$(false)" "$(true)")`, `a+=(...)`,
`x=${u:-$(false)}$(true)`, backticks, arithmetic with two substitutions,
`local/declare/export/readonly x=$(false)`, `local -a a=("$(false)")`, `x=$(false) true`, and
`if x=$(false)$(true)` took its then branch. STOPPED for `x=$(false)`, `x="$(true)$(false)"`,
`x=$(false); y=$(true)`. shellcheck (the gated warning level) reports SC2155 for the scalar
declarations only: not `local -a a=("$(false)")`, not `local x="${1:-$(a)}"`, and nothing for
the bare-assignment shapes.

Shapes taken as the class: several (assignment-only statement, two or more substitutions not
nested in one another), declaration (a declaration builtin assigning any substitution, also as
`builtin local`, `command export`, `\local`), prefix (`X=$(a) cmd`). Next wider rule considered:
any command substitution whose status is discarded (command arguments, nested substitutions
without `inherit_errexit`); not built, because it is a different class with a different fix
(an argument's status is the command's by design; nesting needs `inherit_errexit`), recorded in
CLAUDE/QA.md as what the rule does not see.

Scope (decided here): every bash file `qa-bash-limits` finds, exempt from the limits or not
(tests, plan folders, completed plans), but `src-go/vendor/`, the daemon-owned files (never
edited here) and `.semgrep/` (rule fixtures, never run). Unit tests red against a stub (5 of 6
test functions failed), green with the rule.

Red on the real tree: `./scripts/qa-bash-limits.bash --base F44` exit 1, 27 findings (16
several, 3 declaration, 8 prefix) in 17 files. The
independent search (run before the rule, by text and reading) found the same bash instances,
plus 4 in an Ansible `blockinfile` bashrc snippet the rule cannot see (play-github-cli-multi.yml),
and missed 3 arithmetic ones the rule found.
