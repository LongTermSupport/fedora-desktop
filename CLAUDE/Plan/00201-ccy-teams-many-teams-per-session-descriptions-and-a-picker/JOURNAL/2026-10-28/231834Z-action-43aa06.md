What it does. It makes two throwaway teams, consent201a and consent201b, with the M7 legs. It makes a scratch git checkout under TMPDIR with no .claude/; its origin is a repository of the GitHub owner the teams trust. It asks `agent-bus seat choose --type=host` for each team's new seat and that seat's handle. Then it holds the consent record aside: it renames element-accepted under the passwd home to `element-accepted.held-by-plan00201-consent-check`. If there was no record, it leaves an `.absent-before-...` marker instead. Next it runs the owner's cc in a private tmux server, on its own socket and in a systemd user scope of its own (cc refuses a tmux server that dies with a terminal tab).

- No: the question must name both handles. cc must exit 1 with "Not started. Nothing was recorded". There must be no record, no .claude/ in the checkout, and neither handle a member of its team.
- Yes: the record is written, a plain owner-only file. Both seats are held by those handles. The token chooser is answered with Desktop.
  Then it puts the record back, ends the session with Ctrl-C, checks that the seats are released, and puts back cc's token record (~/.claude/.last-launch.conf). Last, it purges the teams and checks that nothing of them remains.

Restore. The plan_on_cleanup teardown puts the record back first, however the run ends. Every run also starts by putting back what a killed run left. It does not refuse. The held copy is the owner's record by construction. Anything at the record's name was written by that run's Yes, or by the owner accepting again, which records the same acceptance. A record that is about to be replaced is kept in the run directory first.

The judgements are in consent_check.py, with the product's words read from consent.go and token-management.bash. Its tests are in test_consent_check.py: RED with the module missing, then GREEN, 35 tests. The hold, restore and put-back paths were smoke-tested on a scratch home.

Open: cc makes each new host seat with sudo, and sudo's cached credential is per terminal. If sudo asks for a password inside the private tmux, the script pauses: it prints how to attach, and waits 15 minutes.
