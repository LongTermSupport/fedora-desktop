> **Entry grammar** — append new entries at the BOTTOM; NEVER edit earlier
> entries (corrections are new entries):
>
> ```
> ## HH:MM · category · REF   — optional short title
> ```
>
> - `HH:MM` UTC 24h (the date is in the filename, also UTC); times increase
>   down the file. A file with no sentinel line above predates this system —
>   its times are local, zone unrecorded (legacy; never rewritten).

> - `REF` = optional task/phase ref (`T1.2`, `P1`) or `—`.
> - Bodies may embed fenced logs/diffs/snippets — no size limit — with a
>   one-line takeaway above the fence.
> - End a working session with a `handoff` entry so the next agent's entry
>   point is the last entry of the newest day-file.

## 13:14 · decision · T2.17   — ccy-teams waits for the play lock: lock, then write, then apply

Task 2.17, ccy-teams waits for the play lock (branch fix/teams-wait-play-lock).

The lock is helpers/play_lock/lock.py's flock on fedora-desktop-plays.lock in the runtime
directory; run.bash takes it with flock -n and exits 75, or accepts a hold delegated through
FEDORA_DESKTOP_PLAY_LOCK_FD once lock.py held proves it. That delegation is reentrant by design
(the self-update cycle uses it), so ccy-teams can take the lock, write the host_vars and run
every play inside one hold. Chosen over write-then-apply: a stopped or timed-out wait changes
nothing, so no flow can leave a team saved but not applied by the wait.

Red, then green, per layer: internal/playlock (Take, refusals, holder line, bounded wait,
Delegate; the real lock.py accepts a Go-delegated hold), execx ExtraFiles, ops (Locked,
nested holds, the wait on stderr and on a screen, bound, Ctrl-C, Stop waiting, exit 75, a play
outside the hold refused), then each flow (settings, describe, path limit, chooser widen,
create, lxc-add, remove, Element set-up): each failed first for the write outside the hold and
for a stopped wait still writing. The wizard and chooser tests were red as compile failures
(the Locked field did not exist yet). The ccy-teams command suite now runs in a runtime
directory of its own and checks that the stub play is handed the lock as run.bash proves it.
