# Agent-bus infrastructure security audit

## Answers to the six questions (facts first)

**1. Homeserver.** Registration is closed: `allow_registration=false`, `allow_guest_registration=false`, `grant_admin_to_first_user=false`, `login_via_token=false`, `login_via_existing_session=false`, `allow_federation=false`, `trusted_servers=[]`, `allow_room_creation=false`, `auto_accept_invites=false`, `error_on_unknown_config_opts=true` (`/workspace/helpers/agent_bus/render.py:63-83`, the only key table; `test_render` holds it equal to DESIGN §3.6). The only account-creation path is the Synapse-style shared-secret admin register, HMAC'd with a 64-byte random secret written 0600 `agent-bus` (`/workspace/files/usr/local/sbin/agent-bus-install:718-728`, `/workspace/helpers/agent_bus/admin.py:411-428`); `bootstrap` then asserts `admin` is the *only* server admin (`admin.py:470-478`) and creates humans/agents with no `admin` key and a discarded random password (`admin.py:346-351`). No server-side rate limit is configured and Tuwunel 1.9.3 has none for login (DESIGN.md:496-498). Listen = `127.0.0.1` always + the team file's `listen` (`/workspace/helpers/agent_bus/teamfile.py:80-82,151-167`; wildcards refused). Reachability enforced twice: firewalld rich rule per `allow_from` CIDR (`agent-bus-install:549-626`) and the unit's `IPAddressDeny=any`/`SocketBindDeny=any` (`/workspace/files/etc/systemd/system/agent-bus-hs@.service:32-33`) opened by the rendered drop-in to loopback + each listen address /32 + `allow_from` (`render.py:151-163`), then `assert_listening` checks exactly those addresses are bound (`agent-bus-install:692-698,830`). **Who can reach it:** every process on the host and every rootless podman container (pasta connects from the host namespace, DESIGN.md:231-234) reaches `127.0.0.1:<port>`/`<bus_ip>:<port>`; every LXC container on `lxcbr0` reaches it because the play adds the bridge subnet to every team (`/workspace/playbooks/imports/play-agent-bus.yml:152-165`). They cannot register or log in without a token or a 32-char password. **Cross-team:** one unit, one port, one state dir and one firewall record per team, but all teams share the one `agent-bus` uid and bind on the same addresses (see M1).

**2. Secrets on disk.** `/var/lib/agent-bus/<team>/` 0700 agent-bus; `secrets/registration_shared_secret`, `admin.token`, `admin.password` 0600 agent-bus (`agent-bus-install:797-808`, `admin.py:193-213`); `tuwunel.toml`/`team.json` 0640 root:agent-bus (no secret in them); root's firewall/binary records 0600 (`agent-bus-install:604,818`); the applied stamp 0644 holds digests only (`:841-842`). Team files are rendered 0600 into a root `tempfile` directory deleted in `always:` (`play-agent-bus.yml:174-211`). Readers re-check owner, S_ISREG, mode ≤0600 on the open fd with O_NOFOLLOW (`/workspace/helpers/pingbus/config.py:251-299`). Tokens travel only in `Authorization` unredirected headers, no proxy, no redirect, never in argv, URLs, errors or logs (`/workspace/helpers/pingbus/matrix.py:98-101,189-190`; `admin.py:263-294`). Bundles are placed as the sudo user via `setpriv`+`dd` from a root-private copy, 0700/0600 (`/workspace/files/usr/local/bin/agent-bus:89-118`). Nothing secret is git-tracked (`tuwunel.pin` is hashes); `seat take` refuses to write before `git check-ignore` passes (`/workspace/helpers/agent_bus/checkout.py:513-523`). **Human password flow:** `human password` sets a fresh 32-char password, logs out other sessions and prints it once to stdout (`admin.py:830-835`, `/workspace/helpers/agent_bus/cli.py:133-137`); nothing stores it. Element profile is 0700/0600, pinned homeserver, no custom URLs/3PID/identity server/integrations (`/workspace/helpers/agent_bus/element.py:133-181`), keyring access granted so the session is not kept unencrypted (`/workspace/playbooks/imports/optional/common/play-agent-bus-element.yml:81-101`).

**3. Room membership.** Room created by `admin` with `private_chat`, `visibility: private`, room v12, exact power levels and the team record in `initial_state` (`admin.py:535-540`). Power levels: humans 50, agents 0, `state_default/invite/kick/ban/redact` 100, `m.room.power_levels` 100 (`/workspace/helpers/pingbus/protocol.py:997-1007`), re-asserted on every bootstrap (`admin.py:549-556`) and verified byte-exact by every member on join and on every change (`/workspace/helpers/pingbus/syncer.py:295-312`). Agents cannot invite, create rooms (server-side `allow_room_creation=false`), or write state; invites are accepted only when room == bundle room and inviter and `m.room.create` sender == `admin` (`syncer.py:137-160`). **Sender authentication:** every client decision keys on the server-authenticated `event["sender"]` (`protocol.py:851-863,580-587`), team record only when `sender == admin` (`:964-973`), status only when `state_key == sender` (`:976-994`); `@room` is honoured only from a listed human because the sender class is checked first. Display names and body text are never consulted (`grep displayname helpers/pingbus` → nothing). Lookalike user IDs are impossible: `humans` is an exact allowlist and agent handles must contain `+` (`protocol.py:63-70,425-459`). The one impersonation vector left is the *human's eyes in Element* (M4).

**4. LXC members.** Joined only by the play as root on the homeserver host: route checked to be a host bridge inside `allow_from` (`/workspace/helpers/agent_bus_lxc/members.py:720-734`), kit synced with ownership/world-write guards (`:95-171`), bundle produced with `add-member --out=-` and piped straight through `lxc-attach … runuser -u <agent>` stdin into `PLACE_PY`, which writes 0700/0600 with O_EXCL|O_NOFOLLOW (`:753-762,204-224`); the token never touches a disk outside the container. Attach uses `--clear-env`/`env -i` (`:926-928,947-950`). Trust: the LXC agent is trusted exactly as any member; the host trusts the container only to the extent of reading its checkout from the host side, never executing it (`:986-997`).

**5. D26 ("no agent holds a human's session").** Enforced in three places for `host` members: `config.load_bundle` refuses a `host` bundle when the user's home has an Element profile (`config.py:194-197,340-366`), `agent-bus-claude` refuses before launching (`/workspace/files/opt/claude-yolo/optional/agent-bus/agent-bus-claude:48-69`), and the Element play refuses a user holding pingbus bundles (`element.py:209-234`). ccy sessions see only the mounted checkout. **But there is a deliberate hole:** `cc --teams` runs as the owner beside Element with only an `element-accepted` marker (`config.py:201-220`) and file-tool deny rules — see H1.

**6. Flooding/replay.** Client side: send token bucket 20/min burst 10, receive 60/sender/min drop as `rate`, duplicate window 60 s, 24 h human max age (`/workspace/helpers/pingbus/limits.py:26-53`; `syncer.py:482-501`); 429 honoured with a 60 s cap; sends retry with the same txnId (`matrix.py:257-274`); seen-event set and edits refused (`protocol.py:849-850,705-706`). Server side: nothing configured, and Tuwunel 1.9.3 offers no client rate limiting (M3).

## Findings

### High

**H1. `cc --teams` lets a repo-driven agent act as the human (D26 bypass, by design but not contained).**
`/workspace/files/var/local/claude-code/cc-teams.bash:12-21`, `/workspace/files/var/local/claude-code/cc-teams-settings.json:3-11`, `/workspace/helpers/pingbus/config.py:194-197,201-220`, `/workspace/docs/agent-bus.md:509-522`.
The deny list covers only `Read`/`Edit` of Element's folders; the session's Bash (and `secret-tool`, since the Flatpak is granted the secret service at `play-agent-bus-element.yml:95-101` and the keyring is unlocked in the human's session) can read the Element access token or simply drive Element's localStorage, then `curl` the homeserver as the human: every agent on every team accepts that text as a `HUMAN` instruction (`protocol.py:863-864`). Realistic attacker: a malicious repository or prompt-injected content in any `cc --teams` session. Impact: full human impersonation to all agents, plus `@room`. Fix: until a real boundary exists (issue #101), make `cc --teams` refuse unless the launching user has no Element profile (same rule as every other `host` member), i.e. remove the `element_accepted` exception in `config.py:194-197` and `ccy-teams choose-teams`; if the owner insists on keeping it, at minimum deny `Bash(*im.riot.Riot*)`, `Bash(secret-tool*)`, `Bash(*Element*)`, `WebFetch`/`Bash(curl*<bus_ip>*)` and state in the consent prompt that Bash is not covered. Tomorrow's human-in-the-loop use should be done from Element while agents run as ccy or a dedicated user only.

### Medium

**M1. Cross-team secret read through the shared `agent-bus` uid.**
`/workspace/files/etc/systemd/system/agent-bus-hs@.service:14-15,22-23`; `/workspace/files/usr/local/sbin/agent-bus-install:797-801`.
Every team's Tuwunel runs as uid `agent-bus`; `ProtectSystem=strict` + `ReadWritePaths=/var/lib/agent-bus/%i` stops writes elsewhere but not reads, and `/var/lib/agent-bus/<other>/secrets/{admin.token,registration_shared_secret}` and the RocksDB are 0700/0600 *agent-bus*, so a compromised homeserver process of team A reads team B's root of trust and can mint any account there. Attacker: anyone who can exploit Tuwunel over the client API from inside `allow_from` (any local container). Fix: in the base unit add `TemporaryFileSystem=/var/lib/agent-bus:ro` and `BindPaths=/var/lib/agent-bus/%i` (the pattern already used for `/run/systemd/resolve`), or `InaccessiblePaths` for siblings in the rendered drop-in; `sandbox_properties` (`:941-954`) will carry it into the restore unit automatically. Longer term, one system user per team.

**M2. Login endpoint reachable by every local user/container with no login rate limit; human may weaken the password in Element.**
DESIGN.md:496-498; `render.py:53-84` (no rate-limit key); `element.py:165-180` (`UIFeature.passwordReset` hides *reset*, not Settings → Change password); `teamfile.py:151-167` (127.0.0.1 always bound).
The 32-char generated password is the only thing between any local process/rootless container and `POST /login` as the human. If the human changes it to a memorable one in Element, unlimited offline-speed guessing from any container on the host wins. Attacker: another local user, any ccy container (even a non-team one), any LXC guest on `lxcbr0`. Fix: (a) bump the Tuwunel pin as soon as a release with login rate limiting ships (`tuwunel.pin` + `vars/version-pins.yml`), and add its keys to `render.py`; (b) have `bootstrap`/`human devices` report a password-changed-outside-agent-bus signal is not possible, so instead document in the ccy-teams sign-in dialog "never change this password in Element; use Ctrl-P"; (c) consider `agent-bus human lock` as the standing state for humans not expected to log in.

**M3. No server-side flood control; a compromised agent can spam the room with `curl`.**
`limits.py:26-34` (client-only), `syncer.py:482-501` (drop after 60/min but still fetched), `render.py:53-84` (no `max_request_size`/rate keys).
pingbus's limits guard mistakes, not an attacker (docs/agent-bus.md:665-667 admits it). A worker with its token posts thousands of 4 KB events/minute; every member's `/sync` fetches them, humans' Element is flooded, and legitimate pings are buried. Attacker: compromised peer agent / malicious repo in a seat. Fix: enable Tuwunel's per-request size limit (`max_request_size`, small) now; adopt its client rate limiting at the next pin; give the human a one-keystroke `park-member` in ccy-teams (revokes the token, `admin.py:725-735`) and surface "N drops from <handle> in the last minute" in `pingbus status`.

**M4. Agents can impersonate a human's display name in Element.**
`admin.py:346-349,486,711` (display name set once, = localpart), `protocol.py:997-1007` (own `m.room.member` changes are always allowed in Matrix; no config key forbids profile changes).
pingbus is immune (sender ID only), but an agent at power 0 can set its displayname/avatar to the human's name; Element disambiguates only exact duplicates, so "joseph " or a homoglyph passes and the human may read agent text as a teammate's. Attacker: compromised peer agent. Fix: in `bootstrap`/`_sync_team` and the syncer's `_read_membership`, flag any agent member event whose `displayname` ≠ its handle (reset it through the admin API in bootstrap, report it in `pingbus status` and ccy-teams); set `new_user_displayname_suffix` is already `""`, fine.

### Low

**L1. `admin.password` is kept for ever beside `admin.token`.** `admin.py:446-452,464`. A second long-lived credential that is only needed until the token is written. Fix: unlink `admin.password` after `write_private(ADMIN_TOKEN_FILE)` succeeds (keep the "login with stored password if token missing" recovery for the window between).

**L2. Human password offered to the clipboard by ccy-teams.** docs/agent-bus.md:54-57. Any application of the user can read the clipboard (and clipboard managers persist it). Fix: show only; or clear the clipboard after 30 s.

**L3. World-readable applied stamps reveal team names to every local user.** `agent-bus-install:841-842` (0644, by design for `ccy-teams` without sudo). Information only (team names, digests). Fix if wanted: 0640 root:<desktop group>, or route the read through the existing sudoers rule.

**L4. Any agent can write `agent_bus.status` under non-`@` state keys.** `protocol.py:1005-1006` (power 0), DESIGN.md:451-453. Receivers ignore them (`protocol.py:981-983`) but the room state grows without bound and the human sees nothing. Fix: a bootstrap sweep that reports/redacts status events whose key is not a member ID.

### Done well (brief)

Closed registration and every outbound/federation/encryption/room-creation knob off with `error_on_unknown_config_opts`; one admin enforced; exact power levels written by admin and verified byte-exact by every member; invite acceptance requires admin as creator and inviter; all client decisions on server-authenticated `sender`, never display name or body; tokens only in unredirected headers with no proxy/redirect and never in argv/logs/messages; 0600 + owner + S_ISREG checks on open descriptors; root-only tempdir for team files; two independent network layers plus a post-start bind assertion; sudoers rule regex-pinned to two read-only commands; LXC bundles piped, never on disk; `git check-ignore` before a token lands in a checkout; sha256-pinned Tuwunel download; `--no-human-text` as a narrowing-only switch.
