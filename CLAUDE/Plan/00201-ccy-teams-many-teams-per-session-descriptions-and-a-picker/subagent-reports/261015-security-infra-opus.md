# Team bus security audit: homeserver and infrastructure findings (Opus)

Branch `fix/teams-security-infra`. Findings from the Fable audit of 2026-10-15 (M4-M7, L3,
L5, L6). The homeserver is Tuwunel (`files/usr/local/share/agent-bus/tuwunel.pin`); every
config option below was checked against its v1.9.4 source and release notes.

| Finding | What was done                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| M4      | `agent-bus-hs@.service`: `TemporaryFileSystem=/var/lib/agent-bus:ro` + `BindPaths=/var/lib/agent-bus/%i` (systemd.exec(5): the documented hide-then-bind pattern) and `PrivatePIDs=yes` (systemd 257). The PID namespace is needed too: with one shared uid, `/proc/<pid>/root` or ptrace of a sibling homeserver would otherwise reach its secrets. Tuwunel handles SIGTERM and SIGUSR2 itself (`src/main/signals.rs`), so being PID 1 changes neither stop nor backup. The restore unit inherits the lines via `sandbox_properties`.                                |
| M5      | Pin v1.9.3 -> v1.9.4 (release notes: "Password limits arrive", #597). Rendered `[rate_limiting.login.failed]` `per_second = 0.0033`, `burst_count = 3` (three wrong passwords, then one per five minutes, keyed on the account) and `[rate_limiting.login.account]` at the default (0.003/s, burst 5). Members never use `/login` (tokens are minted through the admin API). There is no password-strength option in Tuwunel (`src/core/config/mod.rs`), so none is enforced: documented in the Limits bullet, with "change it only with `agent-bus human password`". |
| M6      | Not possible in the homeserver: Tuwunel 1.9.4's `rate_limiting` holds only the login tables (`RateLimits` in `mod.rs`), and `media_rc_create_*` covers media uploads only. `max_request_size` lowered to `10000000`, the floor Tuwunel starts with (`check.rs`). Documented: the client limits guard against mistakes, not `curl`.                                                                                                                                                                                                                                    |
| M7      | `enable_set_displayname = false` (v1.9.4, #608; server admins exempt, so bootstrap's admin-API display names still work). It gates the profile API only (`profile.rs` `displayname_check`), not a member's own `m.room.member` event, so a per-room name can still be set: documented in Limits; pingbus keys on the account.                                                                                                                                                                                                                                         |
| L3      | `bootstrap` deletes `admin.password` once `admin.token` is written, and on every later run (existing installs). The crash window between registering and storing the token still recovers. A token lost later fails naming `agent-bus-install restore`.                                                                                                                                                                                                                                                                                                               |
| L5      | Stamps 0640 in a 0750 directory, `root:$AGENT_BUS_STAMP_GROUP` (default root's group); the play sets it to `user_login`, the group ccy-teams runs in. Installer statement count unchanged.                                                                                                                                                                                                                                                                                                                                                                            |
| L6      | `bootstrap` empties every `agent_bus.status` event under a key not starting with `@` (the auth rules already hold `@` keys to their sender). Room state cannot drop a key, so content is bounded, key count is not. Uses `GET /rooms/<id>/state` (added to the test fake, spec form).                                                                                                                                                                                                                                                                                 |

`scripts/test-agent-bus-install.bash` (stamp modes/group, restore sandbox lines). DESIGN.md
