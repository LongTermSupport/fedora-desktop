## Nits

1. **The launcher's gate is held by convention, not by structure** (`membership.go:159`,
   `206`). `Run` calls `writeDesired` directly and depends on `desired()` having returned
   `checkWrite`'s error. A later edit that builds a `Desired` in `Run`, or a second caller of
   `writeDesired`, would bypass the gate silently. Two ways to make it structural:

   - call `checkWrite` at the top of `writeDesired`, so the unexported writer cannot write an
     unchecked file; or
   - have `Run` call `Write`, keeping `ExitUsage` by checking first.

   The mutation tests cover the current shape, so this is not blocking.

2. **The comment overstates what the gate checks** (`membership.go:205`). It says "on anything
   pingbus would refuse to read". `checkWrite` also refuses a non-UTF-8 checkout, which pingbus
   would read, but as a different checkout. Suggested wording: "on anything pingbus would
   refuse, or read as another checkout".

3. **The launch-time messages do not help the person launching.**

   - A user in a directory with a tab or a non-UTF-8 name now gets
     `ccy-teams: internal membership-init: the checkout "/c\xff" is not UTF-8. See ccy-teams --help.`
     and then "Not starting". The pointer to `--help` sends them to the internal command's
     usage. Before this change, a no-team ccy launch in such a directory started, with a bus
     that was broken or misnamed. Saying that `--no-bus`, or a directory with a plain name,
     avoids it would be friendlier.
   - The 65-seat message reads "more than 64 seats or 256 farewells", but the launcher has no
     farewells.

   Neither is blocking: the refusal is the correct fail-fast outcome for inputs that were
   already broken.

4. **Pre-existing, outside the branch, and still open:**

   - `hot/list.go:176-178` drops `repErr` silently (`rep = membership.Report{}`).
   - pingbus's `parse_desired` crashes with `TypeError` on a farewell `reason` that is a list or
     an object, and with `RecursionError` on deep nesting.

   Both are named in 922fbf79's message. Each deserves an issue or a plan task so they are not
   lost.
