# F6 review: fix/membership-strict-json (2282ced4 on f460abb7)

Verdict: FIX-FIRST (finding 1). Findings 2 to 4 are small and can go in the same commit.

## What holds

- `go test -race ./internal/teams/... ./internal/pingbus/...` passes. Package coverage is 90.9%,
  and strict.go is covered 100%.
- Every real writer's output passes the new reader:
  - Go `writeDesired` (`json.Marshal(Desired)`): every field is tagged, there is no omitempty
    on Desired, and `Farewell: []Farewell{}` is never null.
  - Python `Applied.to_json` (membership.py:154): AppliedSeat/Refused asdict keys match the
    tags exactly. `inbound` and `told` are only written when set, `told` is an object, and the
    output is `ensure_ascii` UTF-8.
- Numbers behave the same in both readers: `1.0` for an int is refused by both, NaN is
  refused by both.
- The size bound matches: 65536 in both.
- Duplicates are refused at every depth. `pyjson` sees the whole document, `told` included.
- Callers: `discover.go:240` and `hot/{list,add,role,hot}.go`, `restart/jobs.go`. All of them
  only test `errors.Is(err, os.ErrNotExist)` or report the error. None relies on case or
  duplicate leniency, and their tests pass.
- Tests: the four wrong-case and duplicate tests fail under the old `encoding/json` decode
  (it matches keys in any case and keeps the last duplicate), so they test the fix.
- There are no `_ =` assignments and no `//nolint` directives.

## Findings

1. `report.go:36` and `report.go:93`, `strict_test.go:121`. `told` is a `json.RawMessage`, so
   `exactKeys` never looks inside it, and `ToldRole` decodes it with lenient `json.Unmarshal`.
   As a result, `"told":{"ROLES":[{"TEAM":..,"HANDLE":..,"ROLE":..}]}` is accepted and its
   role is shown. Python `_told` (membership.py:244) refuses the whole file: exact keys
   `{generation, roles}` and exact role-entry keys.
   The new test `TestReadReportStillDecodesAValidFileWithTold` asserts that
   `"told":{"Roles":[],"x":1}` is valid. Python refuses that file, so the test pins the
   divergence this change exists to remove.
   Fix:

   - Make the field `Told *Told \`json:"told,omitempty"\`\`.
   - Define `Told{Generation int \`json:"generation"\`; Roles []ToldEntry \`json:"roles"\`}`so`exactKeys\` descends into it.
   - Have `ToldRole` range over `r.Told.Roles`.
   - Turn the test into a refusal of the wrong-case or unknown `told` keys, plus a valid
     `{"generation":2,"roles":[{"team":..,"handle":..,"role":..}]}`.

2. `strict.go:76`. `jsonFields` strips only `,omitempty`. A tag like `json:",omitempty"`
   (name taken from the Go field name), `json:"x,string"`, or `json:"x,omitzero"`, or an
   untagged exported field, would make a valid key refused. None exists today, but this is the
   next silent breakage when someone adds a field.
   Fix:

   - `name, _, _ := strings.Cut(tag, ",")`
   - skip when `tag == "-"` or `!f.IsExported()`
   - `if name == "" { name = f.Name }`

3. `strict.go:13-15`. The doc comment, and the commit subject "read the files as pingbus reads
   them", claim more than the change does. Go still accepts a report with no `seats`,
   `refused` or `generation`, `"inbound":null`, a `why` outside the four values, a bad
   `holder`, and more than 64 seats. Python refuses each of these
   (`parse_applied`, membership.py:258).
   Fix: narrow the comment to "keys are spelt exactly and given once", or record the
   remaining gaps where the follow-up is tracked.

4. `strict.go:52`. The message "the key %q is not spelt as any field is" is also given for an
   unknown key that has no case variant. Because the code ranges over a map, which key gets
   reported is nondeterministic when several are bad.
   Fix: say `unknown key %q (keys are matched exactly, case included)`, and check the keys in
   sorted order (`slices.Sorted(maps.Keys(obj))`).

Note: the test fixtures `validReport` (`why:"w"`, `holder:"x"`, `handle:"h"`) are files
Python refuses. That is harmless here, but the case would be stronger with a fixture a keeper
actually writes.
