# Task 2.28: the plays are handed CCY_TEAMS_HOST_VARS

Branch `fix/00201-host-vars-override`, from F44 `d247e4b2f`. Commit `bc8c860f2` (code and tests), then this
report and the journal entry in a second commit.

## Cause

The plays load host_vars from the inventory (`ansible.cfg`: `inventory = ./environment/localhost`, so
`environment/localhost/host_vars/localhost.yml`). Nothing gave them the file ccy-teams wrote, so
`play-agent-bus.yml` checked `agent_bus_only_teams` against the owner's teams and the assert failed.
`play-agent-bus-element.yml` had the same gap: it would write the Element profiles of the owner's file.

## Fix

- `config.Config.PlayVars()` returns nothing when `HostVars` is the inventory's own file (cleaned path
  compare), and `-e @<HostVars, made absolute>` when it is not. It is made absolute because run.bash
  `cd`s into the checkout before it runs the play.
- `ops.runPlay` passes `PlayVars` then `-e {"agent_bus_only_teams": [...]}`. The later `-e` wins, so the
  scope is never replaced by a key in the file. `ops.elementPlay` passes `PlayVars`.
- Precedence: an extra-vars file outranks the inventory, so each key the override sets replaces the
  inventory's. A key it leaves out is still read from the owner's host_vars, for example
  `agent_bus_address` or `agent_bus_lxc_members`. The `lxc_members` list is filtered to the scoped teams
  anyway. The doc comment on `PlayVars` says this.
- `HostVars` doc comment: the override is for test suites and acceptance harnesses.

## Tests (red, then green)

- `TestPlayVarsNameTheOverrideOnly` (config): no override, the default path, or the default path spelled
  another way gives nothing. An absolute override gives `-e @file`. A relative override is made absolute.
- `TestPlaysReadTheHostVarsCcyTeamsWrites` (ops): with an override, both plays get exactly that argv in
  that order. With the default host_vars, both get their old argv.
- Four existing ops/takedown expectations now include `-e @<rig host_vars>`.
- `scripts/test-ccy-teams-command.bash`: both fake plays now exit 97 unless they get
  `-e @$CCY_TEAMS_HOST_VARS`. This proves the override reaches a play run of the built binary. The six
  `logged 'play -e …'` checks name the file. Result: 383 passed, 0 failed.
- `ansible-playbook --syntax-check -e @<dist file> playbooks/imports/play-agent-bus.yml` passes.
- `./scripts/qa-changed.bash --base F44`: passed (10 files).

## Sweep

No other reader ignores the override:

- `declare.py` and `src-go/internal/bus/declare` read the `--file` or text they are given.
- `helpers/agent_bus_lxc/members.py` `VARS_FILE` appears only in messages. Its members come from the
  play's vars, which now come from the override.
- `src-go/internal/bus` runs no play.
- The plays' assert messages still name the default path. That text is wrong only for a harness run.
  It is left as it is.
