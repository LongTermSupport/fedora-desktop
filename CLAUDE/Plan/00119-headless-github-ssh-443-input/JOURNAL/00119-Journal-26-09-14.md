Observed on a headless box (port 22 blocked at its edge) declared with an account and the
443 flag: (1) `hl_write_localhost_yml` kept the existing `localhost.yml` from an earlier
`none` provisioning, so `github_accounts: {}` stayed and the multi-account play generated no
account key or Host block — `gh` was logged in, SSH had nothing. (2) With the flag on, step 10
migrated the checkout's origin to SSH and pulled over `github.com:22` before the play had
written the 443 override; timed out. Fixed as 1.20.1: with the default config source the
GitHub half of an existing file is reconciled to the inputs (one renderer for fresh write and
reconcile; strip-then-append with everything else preserved; idempotent; unit test extended to
20 checks incl. none→account, flag off, account change, and the config-source keep path); and
step 10 applies the 443 override through `helpers/github443` before any SSH use, bootstrapping
the checkout over HTTPS when absent. The consuming estate then chose to allow port 22 on that
box's own egress instead of the 443 detour, so T2.1 (the flag observed on a real box) remains
open; the reconcile fix is what its next run exercises.
