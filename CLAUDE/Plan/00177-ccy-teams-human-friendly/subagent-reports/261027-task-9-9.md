# Task 9.9: a member that never joined can be taken off

Branch `fix/00177-task-9-9`, from F44 `89ce863f7`.

## The defect

`helpers/agent_bus_lxc/members.py` `_absent_one`, with the team running and the container
holding no bundle for the team, needed `host` and `seat` on the entry to name the handle to
park, and raised 78 otherwise. `ccy-teams lxc-add` writes neither (Task 9.7: the handle is
derived), so a member it declared that never joined (gh missing: `_check_gh` fails before any
bundle is made) could not be set absent. It also hit a member that had joined and later lost
its bundle: the present phase's own refusal says "set state: absent and run the play (which
parks it)", and that run then failed the same way.

## The choice: option 1, the absent path

The absent path now finds the handle in this order:

1. the bundle in the container (as before);
2. the member record's handle (`known_handle`, already used for a stopped container): a
   member that joined and lost its bundle is parked under the handle it really had;
3. host and seat both on the entry: as before (`suggest-handle` for the repo);
4. otherwise `_unbundled_handle`: `<repo>` and `<host>` derived from the checkout by the
   play's own reader (`derive.identity_of`), or the entry's `repo` alone when the container
   is destroyed; then `unheld_handles` looks at `agent-bus list` for active LXC members of
   that repo (and host and seat where known) that no other entry's record item holds.
   - none: nothing can be this member's, so nothing is parked; the bundle directory and the
     env file's team are still cleared, and the record says `left` with no handle;
   - one or more: it may be this container's (a lost bundle) or another's joined by hand, so
     the run refuses, naming each handle and the `seat:` (and `host:` when it is not known)
     to set on the entry to park it. Never skipped (fail fast).

Option 2 (lxc-add writes host and seat) was not taken: an explicit seat freezes what the play
derives on each run (resolve_members leaves an entry that gives both untouched), lxc-add's
preview derives with `unheld_ok`, so its seat can differ from the play's, and it would not
help entries already in the owner's host_vars.

## The present half

A present member whose running container fails a requirement (gh) failing every apply of its
team is by design. The project's per-member skip (SKIPPED/DEFERRED) is only for a container
that is not running, a state the next run converges; a running container that cannot meet a
requirement is a defect, and `test_a_failure_of_a_running_member_still_fails_while_another_is_stopped`
pins that. The way out is now the one that works: `declare lxc-remove`, then apply.

## Sibling sweep

- Lost bundle of a joined seatless member: fixed by step 2 (test added).
- Destroyed container, seatless entry: was the same raise; now judged by `repo` (test added).
- `_absent_held_back` (container stopped): defers when nothing is known, never fails: fine.
- The present path derives without a bundle already (Task 9.7).
- The member record item with a null handle: the Go reader (`lxcrecord`) decodes it to "", as
  for DEFERRED items already.
- Not changed: lxc-add's failure text (`src-go/internal/teams/lxcadd/adder.go`) says only how
  to fix gh, not how to take the member off; there is no `ccy-teams` action for
  `declare lxc-remove`. A possible follow-up.

`ccy-teams` run: lxc-add a throwaway container without gh, `declare lxc-remove`, then
`ccy-teams remove <team>` (which runs `play-agent-bus.yml`) passes with nothing parked.
