# Task 13.1: the create wizard asks GitHub as every gh login

Branch `fix/00177-gh-account-aware`.

## The finding

`ccy-teams create` in the owner's checkout: "`<owner>/<repo>`: not found, or your gh login
cannot see it", three times, then "Giving up after 3 tries". The host has several gh logins
(`play-github-cli-multi.yml` defines a `gh-<alias>` function per entry of `github_accounts`,
each a `gh auth switch` there and back). The wizard ran plain `gh api`, so it asked as the
active login only, and that login was not the one that owns the repository.

## Every gh call in ccy-teams

All are in `src-go/internal/teams/create/wizard.go`; no other ccy-teams package runs gh:

- `needGh`: `gh auth status` (logged in at all). Now `gh auth status --hostname github.com --json hosts`, read by `ghlogin.Read`, then one `gh auth token --hostname github.com --user <login>` per working login, kept as an `execx.Secret` named GH_TOKEN.
- `checkOwner`: `gh api users/<owner> --silent`. Now asked as each login in turn until one sees it.
- `checkRepo`: `gh api repos/<repo> --jq .permissions.push`. Now asked as every login.

Each `gh api` carries one login's token in `Cmd.Secrets`; execx refuses a command whose argv
holds the value. gh's active account is never changed.

## What the person sees

- One or more logins can push: `  <repo>: push access through account-b.` (several: `account-a and account-c`). Nothing is asked.
- None can see it: `  <repo>: not found, or none of your gh logins can see it (tried account-a, account-b).`
- Some see it, none can push: `  <repo>: none of your gh logins can push to it (read-only for account-b; tried account-a, account-b); a team trusts only repositories you can push to.`
- A single login keeps the old wording with its name in it: `your gh login account-a`.
- Owner not seen by any: `GitHub has no user or organisation called '<o>' that any of your gh logins can see (tried …)`.
- No working login: `gh has no working login to GitHub … Run gh auth login (or gh auth refresh for a login whose token failed)`.
- A gh without `auth status --json` (older than 2.81): "too old to list its logins as JSON", naming `play-git-configure-and-tools.yml`.
- A login gh holds no token for ends the run with gh's words, before GitHub is asked.
- The three tries for a mistyped repository stay as they were.

## Why there is no "which login?" question

The brief said to ask when several logins can push. I did not build that question, because
the answer is used nowhere. The team entry (`declare.Entry`) has no gh field. No later
ccy-teams step runs gh. A ccy session in the team's checkout picks its own login when it
starts: `files/var/local/claude-yolo/lib/ssh-handling.bash` tries each account for push
access. The question would block the person and change nothing, so the logins that can push
are named instead. If the owner wants the question anyway, it is one `Gum.Choose` in
`checkRepo`, with `c.head`.

## Shared code

`src-go/internal/ghlogin` (new, 100% covered) holds the status parser, `Read` and `Token`,
taken from `internal/ghaccount` (gh-account-setup), which now uses them. Its parse tests
moved with the code. There is no behaviour change in gh-account-setup.
