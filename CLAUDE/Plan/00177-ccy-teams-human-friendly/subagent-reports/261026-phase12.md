## Task 12.1: "new seat" for seats that exist

- **Cause, confirmed by test.** The fact-check's inference was right. `choose.Block` read the
  seats with `Bus.SeatList(ctx, "")`, which uses the git top of the ccy-teams terminal's cwd.
  There is a second half to it: the host agent's cwd was a checkout ccy never ran in, so
  agent-bus refused the list ("has no .claude/ccy/"). The refusal came back as an empty list,
  and every seat in it was then called new.
- **RED.** `hot/add_test.go` `TestTheBlockReadsTheSessionsCheckoutNotTheWorkingDirectory`
  (cwd's git top is another checkout) printed `seat 1 (new seat: it joins as a worker)` for both
  teams.
- **Fix.** `choose.Block(ctx, h, kit, w, checkout, canonical)`: `hot.blockAfter` passes
  `t.checkout()`. When the list was refused, or could not all be read, a missing seat says
  `role unknown: the checkout's seats could not all be read (the reason is above)`
  (`choose_test.go` `TestDescribeBlockOfAnUnreadSeatListSaysTheRoleIsUnknown`, red then green).
- **DBF judgement.** The class is "a checkout lookup keyed on the cwd, from a flow that targets
  a named session". The sweep covered every cwd-defaulted lookup in `src-go`
  (`SeatList(ctx, "")`, `SeatChoose`, `SeatChooseAs`, `SeatChooseIn(ctx, "")`, `os.Getwd`,
  `Host.Here`). The only other callers are the launcher's own subcommands (`choose-seat`,
  `choose-teams`, `describe-seats`), and the launcher runs those in the checkout by contract.
  No go/analysis rule was written. A rule on a literal `""` at the call site could not have
  caught this defect: the literal was in the launcher package, where `""` is right, and was
  reached through an exported helper. A reachability rule would cost more than it is worth. The
  defence is the API: the one cross-flow entry point now has to name the checkout. This is
  recorded for the owner to overrule.

## Task 12.3: keys typed after Esc

- **Decided rule** (`src-go/internal/ui/drain.go`; the `internal/ttyecho` package doc says
  it). Keeping type-ahead stays the rule. A screen discards the waiting input when either:
  - it follows a leave: Esc, Ctrl-C, or a No. gum confirm exits the same way for Esc and No,
    so both count. Leaving an fzf screen or menu counts too.
  - it belongs to a destructive flow: `ccy-teams remove`, `ccy-teams restore`, or
    ccy-sessions' End question.
- **Mechanism.** `execx.Cmd.DrainInput` makes ttyecho's held runner `tcflush(TCIFLUSH)` the
  terminal once the hold is taken, before the screen runs. `Modes` gained `Flush`. A flush
  failure fails the screen. With no terminal, nothing is flushed. ccy-teams' gum and fzf share
  one `ui.Drain`, so a leave on one drains the next screen of the other. A Gum or Picker without
  a Drain makes its own.
- **Tests.** Each was seen red:
  - `ui/drain_test.go`
  - `ops/takedown_test.go`: every question of remove, and of restore
  - `sessions/picker_test.go`: the End question and the list after a No
  - `ttyecho_test.go`: the fake, and a real pty that read the stale line when the flush was
    disabled
- **Limit.** A key typed after the flush, while gum is still starting, still reaches that
  screen. The rule closes the reported gap (the key queued before the next screen was run),
  not the few milliseconds of gum's start-up.
- **Version.** The launcher's Go front builds from `execx` and `ui`, so 12.3 bumps CCY again,
  to 3.100.30. The container stays 2.79.12.
