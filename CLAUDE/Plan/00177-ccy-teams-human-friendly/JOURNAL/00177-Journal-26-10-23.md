> **Append-only activity log** for plan 00177. One file per day
> (`00177-Journal-YY-MM-DD.md`). `PLAN.md` tracks the plan (what/why,
> current state, tasks); this journal tracks what actually *happened* —
> findings, decisions, dead-ends, hand-off state — the linear lifecycle a plan
> document structurally cannot carry.
>
> **Entry grammar** — append new entries at the BOTTOM; NEVER edit earlier
> entries (corrections are new entries):
>
> ```
> ## HH:MM · category · REF   — optional short title
> ```
>
> - `HH:MM` UTC 24h (the date is in the filename, also UTC); times increase
>   down the file. A file with no sentinel line above predates this system —
>   its times are local, zone unrecorded (legacy; never rewritten).
> - `category` ∈ `action` | `finding` | `decision` | `thought` | `blocker` | `handoff`
> - `REF` = optional task/phase ref (`T1.2`, `P1`) or `—`.
> - Bodies may embed fenced logs/diffs/snippets — no size limit — with a
>   one-line takeaway above the fence.
> - End a working session with a `handoff` entry so the next agent's entry
>   point is the last entry of the newest day-file.

2. Typed-ahead keys echoed between screens (`^[[B` on the next screen after Esc from a menu).
   Nothing owned the terminal mode between fzf/gum children. New `internal/ttyecho`: a hold on
   the echo for the run of an interactive command; children given the terminal for their own
   input run in the mode found (`execx.Cmd.EchoHeld` marks fzf, gum and tput, which may run
   held); the launcher exec and SIGTERM/SIGHUP put the mode back. Red: the real pseudo-terminal
   test shows the unheld echo; `TestEveryProgramUiRunsMayRunWithTheEchoHeld` failed on every ui
   child before the field was set. Wired into ccy-teams (every subcommand, via host.New and
   NewDiverted, App.Run), ccy-sessions, and the other screen-sequence tools the search
   (subagent-reports/261023-search-echo-between-screens.md) found. No rule: run-time state across
   processes; recorded beside the first.
