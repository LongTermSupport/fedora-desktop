## 11:52 · finding · — — a headless desktop run would make the repo's own extension gate vacuous

`helpers/gnome/extension_state.py:58-61` returns `Verdict.SKIP_NO_SESSION`
when no GNOME session is available, and `helpers/gnome/verify_extension.py:111`
then prints `EXT-OK` and exits 0. So a desktop-profile VM driven over plain
SSH with no logged-in session would report extension verification green while
asserting nothing — the `AgentNotes.md` "partial result read as a complete
one" class, row 13 shape. This is why §5.3 dispatches the provisioning run
*into* the autologin session with `systemd-run --user --wait` rather than
beside it.

Related: `releases/44/Workstation/x86_64/os/.treeinfo` is **404** — there is
no Workstation install tree, so the desktop base must come from the Live
ISO's squashfs via `liveimg` (the route `fedora-install/ks.cfg:429` already
uses) or from the Everything tree plus a package environment.

## 11:52 · decision · — — the verb set is the boundary, so the allowlist cannot live in the mount

The sandboxed agent can write anywhere in the bind-mounted checkout, so a
watcher that validated arguments against `vars/vm-test-scenarios.yml` would be
validating against a file the sandbox controls. Resolved in §2.3: the repo
manifest is the *source*, an Ansible-deployed
`~/.local/share/vmtest/scenarios.allowlist` is the *authority*, and drift
between them is reported with both digests and refused — never silently used.
Same shape as `scripts/qa-deployed-drift.bash` and as 00079's acceptance gate
refusing to vouch for a binary that differs from the repo.

Five verbs only: `list-scenarios`, `lab-status`, `run-scenario`,
`refresh-base`, `abort-run`. `run-playbook <name>` is deliberately absent —
it is `exec` wearing a domain name.
