Design choices made in the syncer:

- An admin invite the index does not name is only reachable when the filter names that room,
  so the invite rule is a pure function, `invite_action`, tested on its own.
- A coordinator joins the questions room with POST /join on every verify while it is pending,
  so an invite delivered before it became coordinator is still taken. A room the trusted index
  names is joined before it is verified; a failure is untrusted, not a leave.
- The first sync after the questions join keeps only events after this member's own join
  event. Without the join in the timeline, the whole timeline is taken: a timeline is the
  newest events, so all of it is after the join.
- A malformed rooms index is ignored and logged, not a loss of main-room trust: only admin
  can write it, and an older member never reads it.

The restricted join (Phase 0's spike) is assumed. Only `Syncer._reports_room` depends on it:
if the spike says no, that one method changes (for example to accept an admin invite to the
reports room), and the fake's `_restricted_allows` goes.
