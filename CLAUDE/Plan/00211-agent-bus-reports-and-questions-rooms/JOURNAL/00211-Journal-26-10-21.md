>   down the file. A file with no sentinel line above predates this system —

## 14:30 · correction · 14:08   — Transient side-room errors are retried, not contained

The coordinator's re-review of finding 3 (FIX-FIRST): containing every `MatrixError` also
contained transient ones. A homeserver restart would mark the questions room `untrusted`,
dropping it from the watcher's filter until a main-room trust change, and a contained gap-fill
failure committed the token past messages that then never woke the coordinator.

Now `_side_failure` re-raises any transient error (`exc.transient`: no connection, a 5xx, a
429 past its retries), so the watcher's retry and backoff handle it and nothing is marked or
committed; only non-transient failures (a 400 refused join, no usable answer) are contained.
The questions gap fill is never contained. Tests: each transient class at the reports join,
the questions join and the questions state read raises and leaves no token, then the next run
is joined and trusted; a refused connection on the questions join; a restart mid gap fill
keeps the token and the next sync delivers every missed answer; a restart mid reverify keeps
the room trusted and delivers the answer.
