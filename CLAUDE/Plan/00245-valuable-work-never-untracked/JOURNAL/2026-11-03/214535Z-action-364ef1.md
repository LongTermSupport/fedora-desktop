## 21:45 · action · issue 130   — the private-name guard reads a session on no team as an empty bus, not a failure

The private-name guard refused every commit in a session on no team: `pingbus status` exits 78 there
("no team is active"), and `busStatus` returned any non-zero status as an error, which a container
makes fatal. Filed as issue 130 when a session worked into it, and the owner asked for it to be fixed
("can't assume pingbus").

**The class**: a gate that treats a documented empty answer from its source as a failure of the source.
No analyzer can express it (it is a reading of an exit status), so it is fixed conventionally, said so.
The sweep: `pingbus status` is run as a process in one place in the repository, `busStatus`; the rest
of the mentions are text, or the status line reading in process.

**The fix**: 78 is an empty status. The machine's host names are still learned, the terms an earlier
run left stay in the list, a container that learns no name at all is still exit 2, and every other
non-zero status is still an error.

**Evidence**: red first on the old code, with the exact message `pingbus status exited 78`; the new
tests pin that no team passes on host names, still finds a host name, is fatal with none, and that
statuses 1, 2, 64, 77, 79, 126 and 127 stay fatal. The mutation "every status is empty" fails the new
and the existing failing-bus tests, and the linter reports the always-nil error.

**QA**: `qa-changed` widens to the whole project for any change under `src-go/qa`. Every go-qa stage
passed (format, golangci, analyzers, deadcode, vuln, mod, build) and every test package passed except
`qa/cmd/qa-js`, whose real-tool tests need `extensions/node_modules`. `CLAUDE/QA.md` records that no
playbook installs it and that it is absent in any checkout where `npm install` has not been run; it
is absent in this container's checkout too. Not installed by hand, per the missing-dependency rule.
The three suites the change names (container version hook 120, gh scopes 62, qa-changed 173) passed.
GitHub CI, which installs it, is the judge of that package.

**Not decided here**: whether a bus that fails with some other status should also fall back to the
stored list. It stays fatal, because a team's names would then be missing from what is scanned.
