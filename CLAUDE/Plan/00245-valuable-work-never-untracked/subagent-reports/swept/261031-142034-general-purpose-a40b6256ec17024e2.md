1. **Restart loop is now visible:** the supervisor records every exit in a per-team `state/watcher.json` (new `helpers/pingbus/watcherstate.py`, written atomically) with the cause and the restart count. The first sync that works removes it. `pingbus status` prints a `WATCHER` line, and the session-start notice names the team.
2. **A permanent failure stops:** the watcher records a team it drops for a `_permanent` failure as `stopped`. Once every team is stopped, the supervisor logs one line and exits, and the prompt and Stop hooks say so instead of restarting it.
3. **The defunct `[pingbus]`:** it was not the supervisor's wait (`subprocess.run` waits). The seat keeper, which lives as long as the session, started the supervisor and never waited on it; one that exited, e.g. with 75 because the hook's supervisor already ran, stayed a zombie. `hooks.spawn_watcher` now reaps it from a background thread.
4. **`pingbus recv`, done in part:** a failed sync (other than a homeserver that does not answer, a refused token, an untrusted room or a busy lock) still delivers what the inbox holds and points to `pingbus history --team <team>` and `pingbus status`. Still left: delivering room messages the inbox never stored. That needs `recv` to read the room's history, validate each event and mark it consumed without moving the sync position, which changes protocol sections 9 and 13.
