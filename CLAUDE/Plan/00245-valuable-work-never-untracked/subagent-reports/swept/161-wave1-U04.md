## Review

**Verdict: FIX**

I reviewed commit `bdf1855f` against F44. All 70 tests pass. I found no QA suppressions and no install-specific data (tests use `/home/<user>`, `192.0.2.x`, `example.com`). The code is stdlib-only and writes nothing to stdout or stderr. It follows the §12 schema, the 0600 token rule, plain HTTP only to listed IP literals, `PINGBUS_HOME`/`PINGBUS_TEAMS`, the multi-team rules and the Element refusal correctly.

1. **`helpers/pingbus/config.py:278-281`: some unreadable bundles exit 1 instead of 78.** Only `FileNotFoundError` is caught. A `member.json` that is a directory (`IsADirectoryError`) or unreadable (`PermissionError`) escapes as an uncaught exception, which is exit 1 ("never assigned", PROTOCOL §14). `read_bytes()` also reads the whole file before the 64 KiB check, and blocks forever on a FIFO. Fix: open with `O_RDONLY|O_NONBLOCK|O_CLOEXEC`, refuse anything that is not a regular file (`fstat`), read `MEMBER_FILE_MAX_BYTES + 1` bytes, and map any `OSError` to `ConfigError` using `exc.strerror`. The same applies to `native_parent.iterdir()` at `:263`: catch `OSError` there and refuse with 78. Add a test for `member.json` as a directory.

2. **`config.py:310-311` breaks the module docstring's promise at `:9-11`.** The docstring says messages never quote a bundle value, but `repr(key[:40])` puts up to 40 characters of unknown key names into the message. A token pasted in as a key name would reach stderr. Fix: echo a key name only if it matches `[a-z_]{1,32}`, otherwise say "a key that is not a name". Add a test with `{TOKEN: 1}` that uses `assert_refused`, which already checks the token is absent.

3. **Three refusals have no test, so removing them would not turn the suite red:**
   - the duplicate-key refusal (`:295-301`)
   - `MEMBER_FILE_MAX_BYTES` and `TOKEN_MAX_BYTES`
   - the `check_python` call inside `load_active` (`:234`)

   Fix: add a test that writes `{"protocol":1,"protocol":1,…}` and expects a refusal, oversize tests for both files, and a `load_active` test that patches `config.sys.version_info` to `(3, 10, 0)` and expects 78.

4. **`config.py:367-373` (`_localpart_on`) duplicates U02.** U02's `protocol.parse_user_id(value, server_name)` (branch `-312-2`, protocol.py:304) does the same job. Fix: when merging over U02, delete `_localpart_on` and call `protocol.parse_user_id`, then `parse_handle`.

5. **Integration notes, no fix needed in this unit:**
   - U02's `protocol.py` keeps `is_team_name`, `parse_handle` (`Handle.type`) and `is_room_id` with the same signatures, so the stand-in `protocol.py` and `test_protocol.py` can be dropped in favour of U02's.
