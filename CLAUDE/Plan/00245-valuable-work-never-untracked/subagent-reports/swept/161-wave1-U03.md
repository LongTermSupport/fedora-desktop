**Built on an assumption:** U02's `protocol.py` is not on F44, so `limits.py` imports nothing from it. It keeps its own verb sets: `ACK_EXPECTED_VERBS`, `NO_ACK_VERBS` and `HALT_VERB`, taken from the §5 "Ack expected" column. **Where the design is unclear:**
1. **Byte limits:** the 4096 and 16384 byte size limits are in §10, but the size check belongs to U02's validator. I defined them here as §10 constants. One unit should own them and the other import them.
2. **Saving send state:** a `pingbus send` is a fresh process each time, so the token bucket and duplicate window must be saved between sends. The design does not say where. I made them saveable as plain dicts, assuming U06's outbox stores them.
3. **Spent send credit:** the spec puts the rate check (step 5) before the forge check and the actual send. A send refused later still uses up a token and counts towards the duplicate window. That seems acceptable, but the spec doesn't say.
4. **Receive flood across processes:** the receive flood counter lasts only as long as the process running it. With no watcher running, separate `recv` runs each start from zero. The spec does not say whether that's acceptable.

## Review

**Verdict: FIX.** The limits logic is correct and the tests can fail. They are stdlib-only, inject the clock, and have no I/O, stdout output, suppressions or install-specific data. What needs fixing is two copies of the same facts and some unused code.

1. **The byte limits are a second copy.** `helpers/pingbus/limits.py:44-45` defines `PING_CONTENT_MAX_BYTES` and `HUMAN_BODY_MAX_BYTES`. U02's branch `wf-4df71537-312-2-55af7db9` already has `MAX_CONTENT_BYTES` and `MAX_HUMAN_BODY_BYTES` in `protocol.py:92-93`. Nothing in `limits.py` uses its two. **Fix:** delete them and their checks at `test_limits.py:69-70`. U02 owns the size check.

2. **The verb table is a second copy.** `limits.py:47-50` (`ACK_EXPECTED_VERBS`, `NO_ACK_VERBS`, `HALT_VERB`) repeats the `ack_expected` field in U02's `protocol.VERBS` (`protocol.py:136-143`). The design row says U03 depends on U02, and D22 ties constants to the spec through a contract test. **Fix:** rebase onto U02 once it merges, build the two sets from `protocol.VERBS[v].ack_expected`, and keep only the halt special case. If that waits, add a contract test comparing the two tables in the U06 or merge commit, and record the dependency in the plan.

3. **Constants nothing uses.** `limits.py:41-43` (`SYNC_LONG_POLL_S`, `SERVER_429_MAX_TRIES`, `SERVER_429_DEFAULT_WAIT_S`) are not used here, and `test_limits.py:66-68` only checks their values. **Fix:** move each to the unit whose client code uses it (YAGNI). Or keep them here as the single home for §10 and have that unit import them, saying so in the module docstring.

4. **The two files cite the spec in different places.** `limits.py:9` points to `docs/agent-bus-protocol.md`, which is not on F44 or on this branch. `test_limits.py:6-7` points to `PROTOCOL.md` and says it is "moving to docs/agent-bus-protocol.md in U02", which is history written into a comment. **Fix:** after rebasing onto U02, point both at `docs/agent-bus-protocol.md §9, §10` and drop the "moving" note.

5. **One input is not checked like the others.** `ack_overdue`, `ping_stale` and `human_stale` (`limits.py:133-149`) check `origin_ms`/`sent_ms` but not `now_ms`. **Fix:** pass `now_ms` through `_check_ts` as well, and add a case to `test_timestamps_must_be_integers`.

On the builder's open questions:
- **Saving send state (#2):** this belongs in U06's unit row, so add it there.
- **Spent send credit (#3):** `admit` runs before the forge check, so a send refused at step 6 still uses a token and counts towards the duplicate window. Accept this, but say so in PROTOCOL.md §10 ("a send refused after step 5 still counts").
- **Receive flood across processes (#4):** the counter resets with each `recv` process. That reset needs to be recorded in DESIGN §6 or §10 as a decision. It should not be left implicit.
