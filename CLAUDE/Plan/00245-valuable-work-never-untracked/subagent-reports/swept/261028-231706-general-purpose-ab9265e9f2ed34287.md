**Design:**
- **Scan (root, read-only):** walks the store once and sums the old-range paths per store directory, with owners, sample paths, sizes, and whether a volume holds data.
- **Triage (user):** joins that with c/storage's records and podman's view (container states, volume mounts). Each item gets a proposal: REMOVE, RE-OWN, ASK, or HELD while a running container uses it. Layers go with their images, so an apt `partial` directory is never an item of its own.
- **Decisions file (host agent):** written under `untracked/` with `remove`, `reown` or `leave` per item, plus the old range's start and size.
- **Plan (user):** refuses the file if it misses an item, still has an ASK, or would remove something in use or touch something held.
- **Apply:** root re-owns each old-range id to the same offset in the current range and puts back setuid bits and file capabilities. Then the user removes through podman's own unforced `image rm`, `rm` and `volume rm`. Because removal always comes after the re-own, the store ends clean whatever podman refuses.
- **Where it runs:** the apply goes through `play-podman.yml`, behind the store repair's busy guard. A dry run is the default, and `--apply` is the explicit flag.
