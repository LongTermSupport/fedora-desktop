# R20: Lightning's spaces rail hidden for a new team

Register row R20 (Task 3.2), as triaged in `261126-open-rows-triage.md`.

## The key

`[shell] spacesRailVisible=false` in `config/MatrixClient/matrix-client.conf`. Verified from
REGISTER.md's R35 entry: F16 read it from upstream source (`src/app/SettingsManager.cpp`,
`kSpacesRailVisible`, key `shell/spacesRailVisible`, a bool default true; QSettings organisation
`MatrixClient`, application `matrix-client`), and F29 confirmed the key name in the top-level
`[shell]` section of the installed client's files where the owner unticked the rail (key names
only, no values). Not verified here: the value's spelling (`false`, QSettings' bool form) and
that Lightning keeps a preset at first launch. Both are owed on the laptop.

## The decision

L7 already decides it: the settings file is written only when absent and Lightning owns it
afterwards. So the preset is the same for every team (no per-team key), a person's own change
survives every run, and an instance made before the preset keeps its file and its rail.
