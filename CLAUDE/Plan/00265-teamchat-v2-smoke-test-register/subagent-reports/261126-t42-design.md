# Task 4.2 design report (R90, R89)

Design: [DESIGN-4.2-no-seat-numbers.md](../DESIGN-4.2-no-seat-numbers.md), linked from Task 4.2 in
PLAN.md. Design only, no code.

## Findings that shape it

- R90's root defect: when two or more seats are free, the chooser's default is the lowest free
  seat (`seatchoice.go:63-70`, `chooser/teamchat.go:109-111`). It never reads the seat records in
  `.claude/ccy/seat-conversations/`, so the person has to know which number holds their
  conversation.
- `cc --teams` never calls `seat-resume`: a grep of `cc`, `cc-teams.bash` and `ccrun.go` finds
  no call. Plain `cc` joins no team (`cc-teams.bash:54`).
- Pool keys are hashes of the checkout path (`paths/ids.go:36`), so a restore covering the whole
  machine has to start from `seat-checkouts`.
- `restore --dry-run` prints the replayed argv, which holds `--teams <seat>@<team>`
  (`sessions/restore.go:549`).

## The design

- The detector has two parts: a Go analyzer `project_seat_number_text` and a Go text check over
  docs, help and launcher output. The sweep found about 60 Go instances, 8 help and launcher
  lines, and about 25 doc lines. They are listed with file:line in the design.
- `seatchoice.Pick` replaces the lowest-free default. The person is asked only when two or more
  free seats have conversations, and then in words: role, when it last ran, and the
  conversation's title.
- R89 extends `ccy-sessions restore` with a pass over the seats, which runs the plain launch.
- Seven open questions for the owner, each with a recommendation.

## Not verified

The sweep comes from greps. The detector's own run will produce the final list. The design
recommends a `cc --no-teams` opt-out; it does not exist today.
