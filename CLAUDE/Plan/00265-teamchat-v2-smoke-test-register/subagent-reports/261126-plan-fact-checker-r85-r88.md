## Does anything explain R85 (missing sidecar)?

Yes, a candidate. The daemon decides "live" only by `*.json` files in `<daemon untracked dir>/context-sidecar/` (`discover_session_ids`, operator_signal.py:351-372; an absent directory gives no ids). Go decides "live" by the tmux list plus the process tree (`groupProjects`, routes.go:93-123) and never checks for a sidecar. Its preflight runs only `signal --help` (probeProjects, routes.go:198), so a session Go counts as live with no sidecar passes the check and fails at delivery. Likely causes to test: a ccy session whose claude has not yet written its first sidecar, a sidecar directory under a different project root (`--project-root r.root`, routes.go:264), or a compaction that removed it (claude-supervise.py:8720 notes the sidecar goes during a compaction). The fix should add a sidecar check to the Go preflight, or make the daemon name what it did not warn.

## Does anything explain R88 (doubled output)?

Yes, a candidate by design. `reboot` runs `checkProjects` at reboot.go:105, which prints the "Left out" and "Not shown" blocks. When minutes > 1, `secondWarning` (reboot.go:174-189) runs `signalProjects` at line 187, which calls `checkProjects` again and prints both blocks again. So a countdown of two or more minutes prints each block twice, minutes apart. Single-minute runs and `notify.go:99` call the check once. The paste would show it if the second copy came after the countdown pause.
