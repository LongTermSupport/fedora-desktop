## REFUTED / defective

1. R89 "Unchecked" gives two causes. A third exists (below): no record is written when the launch has no terminal.
2. 00266 claim 10: the `/run` file route has no writable, pre-boot location for the seat user. This needs a decision on the directory and its owner (for example a dir the unit creates with `RuntimeDirectory` cannot work, since it is made after the lookup).
3. R89 claim 5 omits status 88, where the record is kept.

## Session record (R89 unchecked cause)

- The write is in bash, not src-go: `ccy_registry_write` at files/var/local/claude-yolo/lib/tmux-session.bash:423, in `ccy_tmux_insulate`. src-go only reads records (internal/registry, internal/sessions/restore.go); there is no Go write or remove for a `--teams` launch.
- `--teams` is treated like any launch: `teams=$(ccy_tmux_teams_arg ...)` only names the tmux session. It is not exempt.
- No record is written when: `$TMUX` is the ccy socket (the re-exec landing returns 0, line ~340); stdin is not a terminal (`[[ ! -t 0 ]]`, return 0); stdout is not a terminal (return 0); `--no-restore`, `--opencode` or `-oc` writes it with restore=no (session-registry.bash:79-86).
- So a seat started by an agent or `ccy-teams`, with no tty, leaves no record.
- Removal: the pane trampoline (session-registry.bash:609-613) removes it when the launcher returns, whatever the status, except 88. A kill or reboot leaves it.
- Likely cause for "no record": seat launches with no tty, or already in the ccy tmux. Not proven; needs the launch route of the three seats on the host.
