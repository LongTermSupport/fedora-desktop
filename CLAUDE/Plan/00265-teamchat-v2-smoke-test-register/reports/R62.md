# R62: `project_walk_open` does not take a regular-file check written as a switch case

Batch 15, on v2-smoke. QA tooling only (the nested `src-go/qa` module), so no ccy or image
version bump; the pre-commit hook asked for none.

## What changed

- `src-go/qa/rules/walkopen.go:418-428` (`block`): after a tagless `switch` that leaves on a
  failed check (`leavingSwitch`), the statements that follow are guarded, as they already were
  after `if !check { return }`.
- `walkopen.go:495-505` (`compound`, tagless switch): a clause after one that leaves on a failed
  check is scanned guarded (it is reached only when the check holds).
- `walkopen.go:987-1029`: `failedCheck` (the `!check` term of a `||` chain, factored out of
  `leavingCheck`), `leavingCase` (a clause listing a failed check whose body leaves) and
  `leavingSwitch` (such a clause, with every earlier case clause also leaving or running only on
  a passed check; `default` is ignored, as it runs only when no case matches).
- `walkopen.go:1066-1082` (`endsLeaving`, which `leaves` now calls): in a switch clause an
  unlabelled `break` or a `fallthrough` stays in the block, so it is no leave there. The brief
  listed `break` among the leaving forms; in a clause it only leaves the switch, and the open
  after it still runs, so it is refused (fixture `failedCaseThatBreaks`).
- `walkopen.go:65-68` (`walkOpenMsg`): the message now names the guard forms the rule takes
  (`if check { open }`, `if !check { return/continue }` before the open, a tagless switch
  `case !check: return` before it; `||` joining a failed check, `&&` a passed one). This is the
  R62 complaint: the message named only the open.
- `walkopen.go:35-44`: the doc comment says the same.
- `CLAUDE/GoProjectRules.md:2019-2025` (`### project_walk_open`): the switch form in "What it
  flags", the new fixture cases in the red/clean list, and the mutation results.

## Defence Before Fix

This is a false positive in a project rule, not a defect in the code it judges. The guard for
the new form is the rule's own fixture suite: the accepted and refused switch shapes above sit in
`badwalk`, so a change that drops the switch guard, guards past a clause that stays, or takes a
`break` as a leave fails `TestWalkOpen`. The interim `if` form in
`src-go/internal/teams/hot/running_test.go` (`a607fca45`) is left as it is.
