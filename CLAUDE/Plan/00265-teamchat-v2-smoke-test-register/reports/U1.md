# U1: a teamchat refusal names its cause (R6, issue #421; R18)

Branch `v2-smoke-u1-ref-refusal`, based on `v2-smoke`.

## The defect class

**A refusal exit whose message names only its reason code.** The error object already carries
the code; a message filled with it ("the send was refused (ref); fix the message") gives the
agent no cause and no next step. Hazard: an agent retries blind or gives up. In #421 the agent
answered a `fetch` ping with `reply <id> --verb done` and no `--ref`. The message said neither
that the reference was missing nor what it had to be. Before the fix, every send refusal except
four (role, duplicate, rate, size-by-store) used that template.

## The detector: `project_refusal_reason_text` (src-go/qa/rules/refusaltext.go)

The rule flags code in `internal/teamchat`, `cmd/teamchat` and `cmd/teamchat-admin`, outside
test files, where a `proto.RefusalError`'s `.Reason` goes into an argument of a package `exits`
function. It counts both a direct read and a local variable a read was assigned to. The `code`
parameter (`New`'s, `ExitOf`'s) is exempt.

Its catalogue row and section are in `CLAUDE/GoProjectRules.md`. The class is also named in the
"Project rules" sentence of `src-go/CLAUDE.md`. The rule is registered in `rules.All()`, so it
blocks in the Go gate. `TestAllIsValid` now expects 64 rules.

- **Red, fixture:** `testdata/refusaltext/` (5 findings: a direct fill, a concatenation, a `:=`
  copy, an `=` copy, a value refusal in `Format`; the clean forms beside them; a package
  outside teamchat). With the rule reporting nothing, the test missed all 5 diagnostics.
- **Red, real tree:** the driver run as `go vet -vettool` over the three trees gave 3 findings,
  all in `engine/send.go` `refusal()`.
- **Green:** 0 findings untagged, with `busfailpoints`, and with `tuwunel`.
- **What a rule cannot see:** a refusal's `Detail` (its cause) being dropped on the way to the
  message. A test holds that instead: `engine` `TestEverySendRefusalSaysItsCause` gives every
  reason in `proto.SendRefusals` its own message, with no `(<reason>)` in it and no
  "fix the message".

## The fix: every instance the sweep found

The sweep found 3 findings, all in `refusal()`: the role template and both uses of `msgRefused`.

- `refusal()` moved to `engine/refusal.go`. Each proto reason now has its own template that
  names the cause and the next step. `sender` and `role` are separate messages. `forge-rate`,
  `unresolved` and `provenance` now map to their own exits; before, they fell through to
  `schema`. An unknown reason is `internal` ("a bug: tell a human").

- `proto`: reference refusals (`ref`, `allowlist`, `excluded`) carry their cause as `Detail`.
  The causes are `RefCauseMissing`, `Forbidden`, `Form`, `Branch`, `Excluded`, `NotListed` and
  `PathPrefix`. They come from one judgement, `refJudge`, which `checkRef` (the receiver's
  path) and the new `Roster.RefCause` both use, so the two cannot disagree.

  - `verdict.go` changes only `refShape`/`checkRef`/`checkCarried` and the new cause
    constants; `Judge.agent` is untouched (U2's area).
  - `RefForms`, `RefSpellings` and `VerbRule.RefForms()` give each verb's reference forms as a
    person writes them.

- `reply --verb` and `ping` pass what was asked (`refAsked`). The message names:

  - the verb;
  - how a reference is given (`--ref`, or a reference after the verb);
  - the forms the verb takes;
  - for an answer to a fetched or carried ping, the ping's own reference, "which an answer
    normally gives back".

  The issue's case now reads: `done needs --ref: one of path:OWNER/REPO@SHA:PATH or commit:OWNER/REPO@SHA or pr:OWNER/REPO#N@SHA or issue:OWNER/REPO#N; the ping it answers carried commit:...`. A ping answered from the ledger has no stored reference (the store's
  `Ledger` keeps none), so that suffix appears only when the ping was fetched.

- **R18, `teamchat help ping` and `teamchat help reply`:**

  - `help ping` lists the closed verbs an agent sends (fetch, halt, review, run-qa, sync).
  - `help reply` lists the answer verbs (ack, blocked, done, nack).
  - Each verb's line says whether it needs, may take or takes no reference, the forms it takes,
    and "(the coordinator only)" where that applies.
  - Both lists are built from `proto.Verbs` (`Verb.Notes`), so help cannot drift from what the
    protocol accepts. Confirmed with `go run ./cmd/teamchat help ping` and `help reply`.
  - `cli` `TestHelpOfPingAndReplyListsTheVerbsAndTheirReferences` derives its expectations from
    the same table.

- One existing test pinned the old message: `send_written_test.go` expected `(size)`. It now
  asks for the cause instead.

## Tool faults met (for the register)

1. **The QA lock does not serve waiters in order.** One `qa-changed` run waited more than 14
   minutes while the lock passed from run 101434 to 405941 to 622916. Each "still waiting" line
   names a new holder, so a waiter can be overtaken without limit. (The arm64 ast-grep pin,
   #426, is already logged.)
2. **The secret-file guard refused to let me Write a scratch script** that ran `cd`
   on a `$(dirname "$0")` path. Its message says "where this command's paths lead could not be
   worked out", yet the script names no protected path.
3. **The edit hook's Go lint fails with "parallel golangci-lint is running" while agents work
   in parallel.** The edit is reported as a lint failure even though the file was never linted.
   U6 reported the same.
4. **The edit hook's lint runs `go vet` on analysistest GOPATH fixtures**
   (`qa/rules/testdata/*/src/...`). It reports "package fix/... is not in std" as a lint failure
   on every fixture written. Those fixtures cannot be vetted as module packages.
5. **The error-hiding hook blocked `fault, _ := r.refCheck(...)`, where the discarded value was
   a `*ForgeCheck`, not an error.** This is a false positive; the code was restructured to avoid
   it.

## Not proven

- No run against a live team. The messages are proven through the engine's fake world and the
  unit tests only.
- The `pinged` reference is named only for a fetched or carried ping. A ping answered from the
  ledger or a pending item has no stored reference; putting one there would change the store
  format, which is out of scope.
- A queued send refused on re-check (the roster changed between queue and post) gets the
  verb-free reference templates, because `refusal` there has no `refAsked`.
- **Out of scope:** the "the homeserver refused the send; tell a human" message (U6, R10)
  drops `matrix.Error`'s detail. That is a sibling of this class over a different type, which
  this rule does not see. It needs its own row and its own detector.
