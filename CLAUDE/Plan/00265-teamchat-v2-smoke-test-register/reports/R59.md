# R59: `session add` offers a purged team's dead seat as free

Fixed on `v2-smoke`, batch 19 (`058938264`). ccy 3.124.64, container unchanged (2.84.84;
`internal/teams` is no image source). Not yet run live.

## Cause

`HotSeats.Choose` (and every other chooser of a pool seat) judged a seat free from the pool
folder and the seat holdings alone. `team remove --purge` deletes the team's status record,
stamp, drop-ins and server state, but never the owners' seat stores, so the pool seat outlives
the team, and nothing on the choosing path read the team's lifecycle.

## What a reader can use to tell a removed team

Nothing on the host marks a removal: `team remove` leaves no tombstone. "No status record" alone
is not enough either: a member placed from another machine (`seat place-issued`,
docs/agent-bus-cross-network.md) has a pool seat and no record here by design
(`system.Resolve`, `HandleState`'s `StateNoRoster`). The positive record is the owner's own
declaration: `teamchat_teams` in the host_vars, `state: absent`, which is how the play removes a
team. So `system.Life.Check` decides:

| Status record | host_vars entry  | Verdict                                                     |
| ------------- | ---------------- | ----------------------------------------------------------- |
| found         | any              | installed: seats can be taken                               |
| none          | `state: absent`  | removed: refused (`ErrTeamGone`, 78), names `seats abandon` |
| none          | `state: present` | not installed: refused (`ErrTeamGone`, 78), names the play  |
| none          | none             | served on another machine: offered as before                |

A source that cannot be read, or a chooser with no lifecycle wired, refuses (fail fast).

**Decision on the unknown case:** offered, not refused. Refusing would break the supported
cross-machine member. Residual: a removed team whose `absent` entry the owner later deletes
from the host_vars reads as "elsewhere" again and fails only at its login. Closing that needs
`team remove` to leave a removal record (a host-side teamchat change); not done here.

## Way on

The refusal names `ccy-teams seats abandon <team> --reason "<text>"` for a seat a session still
holds (#386's verb; it accepts a team with no status record). An unheld pool seat of a removed
team has no release verb yet (#386 covers held seats only); the refusal says to use a live
team's seat instead, and the dead seat is never offered again.

## Choosers swept (step 3)

- `HotSeats.Choose` (session add): checked first, for a named seat and the lowest free one.
- `Launch.choose` (launch-args for ccy, cc-run for cc, and `HotSeats.Join`): checked per team.
- `system.Cmd.PoolState` (the `--teams` chooser's seat list) refuses; `Cmd.PoolTeams` (its team
  list) leaves a removed team out.
- `seats add` (`seatadd.Adder.Add`): it already refused a team with no record, but called it
  "served on another machine" and named the cross-machine pipe; it now names the removal (78).
- Not changed: `Verbs.poolState` (the ways-on lines) runs only after a refusal for a held or
  unknown seat, which a removed team never reaches now; `seats model`'s resolve sets a model and
  takes nothing; `system.Resolve`/`Live` decide which bus, and a removed team is still a
  teamchat team, refused at the seat.

## Defence Before Fix

The class is "a free-seat judgement that ignores the team's lifecycle". A go/analysis rule
cannot express it: the judgement is semantic (which reads make a seat "free"), not a call shape;
the closest syntactic proxy, "a call of `system.PoolSeats`/`PoolState` not dominated by a
lifecycle check", would need dataflow across packages and would flag `seats abandon`, which must
read a removed team's seats. The guard is structural plus tests: `Launch.Life`, `Cmd.Life` and
`Adder.Life` are required (nil refuses every seat), `TestTheLaunchVerbsJudgeATeamsLifecycle`
pins the wiring, and red-then-green tests pin each chooser.
