# R44: the standard coordinator procedure ships with the teamchat kit

Branch `v2-smoke`. Source: the infrastructure repository's standard coordinator procedure, its
delivery note and its project-layer template (fetched read-only; copies kept untracked).

## What ships

- **The skill.** `src-go/internal/teamchat/member/kit/coordinator.txt` is the one source, embedded
  in the binary (as `skill.txt` is for the member skill) and written by `kit.Assemble` to
  `plugin/teamchat/skills/coordinator/SKILL.md`, so Claude Code names it `teamchat:coordinator`
  (`paths.CoordinatorSkillName`). The image's copy,
  `files/opt/claude-yolo/optional/teamchat/plugin/teamchat/skills/coordinator/SKILL.md`, is held
  byte-equal to the assembled kit by the existing `TestTheImageKitFilesAreTheKitAssembledForTheImage`;
  `tasks/teamchat-ccy-kit.yml` stages it and `play-teamchat.yml`'s kit-whole check lists it.
- **The frame.** `hooktext.tmplRoleCoordinator` now reads "In team T you direct the team's agents:
  load the teamchat:coordinator skill, your procedure, now and at every launch; ask the humans
  ...". Only a coordinator seat's block carries that line, at every SessionStart.
- **The check.** `TestTheCoordinatorSkillNamesWhatTheBinaryHas` parses every `teamchat ...` code
  span with CL2's own parser (an agent verb, every flag and reference valid), refuses a command
  named in prose outside a span (and any lifecycle verb), and requires the verbs a coordinator
  works with (status, recv, say, ping, reply, report, ask-human, thread, close, retitle, bump,
  questions, verify, help). `TestTheCoordinatorCheckCanFail` proves it red on the source's
  mismatches. Tests were seen red before the code (hooktext frame, paths, kit build failures).
- **Versions.** CCY 3.124.48, container 2.84.79 (launcher, Dockerfile LABEL, changelog).

## Corrections to the source's commands (checked against `teamchat help` and `cli/verbs.go`)

01. `teamchat whoami --json` (0.1): a lifecycle verb, not an agent's. Replaced by `teamchat status`.
02. `teamchat ping fetch commit:<repo>@<sha>` (2): a ping needs `--to N` or `--to-coordinator`, and
    the reference is `commit:OWNER/REPO@SHA` or `path:OWNER/REPO@SHA:PATH`. Now
    `teamchat ping fetch <ref> --to <name>`; the "forge does not know it yet" case is exit 13
    (forge), so the text says push first, not "a few seconds later".
03. "answers the fetch with `done`" (2): `done` needs a reference; the text gives
    `reply --verb ack` and `reply --verb done --ref <ref>`.
04. "use a tracker kind instead if the tool has one" (3): there is none; dropped. The tracker form
    uses `ask-human --skeleton`'s `Why a human:` line, whose four kinds the text names.
05. `teamchat close` "with a one-line result on stdin (close waits for it)" (6): the note is
    optional ("a note on stdin, if given"); the text says pipe it and never leave stdin open.
06. Bump "never more often than the minimum age" (6): bump skips a question waiting less than
    `--min-age` (default 3600 s); stated as that. "Never bump a tracker" dropped: no tracker kind.
07. `teamchat reach --team <t>` (10.4): a lifecycle verb. The proof of a live seat is now: in your
    `teamchat status`, a done reply to your fetch, and the seat's own status showing delivery.
08. `--continue` (11): named as `claude --continue`, Claude Code's flag, not teamchat's.
09. Added from the exit table: exit 10 code `secret` (9), exit 64 `ambiguous-team` (12), exit 13
    `forge` (2); that fetch, sync and halt are coordinator-only pings; `thread --note`.
10. `teamchat verify` (3): kept; its record does carry `question` and `human`
    (`records.Verified`), and with no `--room` it tries main, then questions.

  only that a project keeps its layer in its own repository, with the template's headings.

## Review fixes (batch 6 part 2)

- `reply` is not an agent-only verb: on a human's questions-room post it answers in that post's
  thread and tells only that human. The skill now answers humans with `reply`, and keeps
  `thread Q<n>` for what waits on the humans (it tells every human and marks the question waiting,
  which `bump --waiting` would then chase).
- Section 11's restore dry run is named as the ccy seat's check.
