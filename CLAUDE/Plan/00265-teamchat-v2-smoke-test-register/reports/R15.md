# R15: a seat's tmux session, and so its tab, names the seat

Batch 9, branch `v2-smoke`, ccy 3.124.53 (container unchanged, 2.84.80).

## The form chosen

`<launcher>-<team>-<seat>`, for example `ccy-team-a-fedora-desktop-4` for
`ccy --teams fedora-desktop.4@team-a`. Every character of the team or seat outside
`[A-Za-z0-9_-]` becomes `-`; several seats are joined with `_` in list order
(`ccy-alpha-app-1_beta-app-3`). The terminal title is `tmux: #S  (...)`
(`files/etc/tmux.conf`), so the tab shows it.

Why not the owner's `team-a · fedora-desktop.4 · ccy`:

- The tmux session name is not only a label. It is the key of the session registry record
  (`<registry>/<name>`, baked into the pane's trampoline at start), the seat store's session
  (`paths.ParseSessionName`, grammar `^[A-Za-z0-9_][A-Za-z0-9._-]{0,127}$`), and the agent-bus
  membership's session (`membership.sessionName`). `·` and spaces are outside both grammars.
- tmux does not keep `.` or `:` in a session name, and targets are exact (`-t =<name>`), so a
  dot would make the name tmux holds differ from the name every record holds.
- The launcher stays first: `ccy_tmux_project_sessions` (the re-attach offer) matches the
  `${prefix}-` start, and ccy-sessions tells container sessions from host ones by `ccy-`/`cc-`
  (`internal/sessions/routes.go`, `declare.go`).

The order of team and seat is in one place, `seatParts` in
`src-go/internal/teams/sessionname/sessionname.go`, so the owner can reorder it there.

## Where it is built

- `ccy-teams internal session-name <ccy|cc> <project> <seats>`
  (`src-go/internal/teams/sessionname`, wired in `internal/teams/app.go`, usage in
  `usage.txt`).
- `ccy_tmux_next_name <project> [seats]` in `files/var/local/claude-yolo/lib/tmux-session.bash`
  asks it only when the launch has a `--teams` list; `ccy_tmux_insulate` passes the list it
  already reads. A launch with no `--teams` never calls ccy-teams and keeps
  `<launcher>-<project>`. The library stays within its bash-limits ratchet row (one `if` folded
  to a one-line test to pay for the new line).

## What it does not cover

- `cc --teams <team>` (no seat named): cc's chooser runs inside the session, after tmux named it,
  so the name stays `cc-<project>`. Renaming the session afterwards would orphan its registry
  record and stop file, which are keyed by the name.
- Sessions already running, restored (`ccy-sessions restore`) or restarted (`ccy-teams restart`)
  keep their recorded names; a fresh launch takes the new form.
- A seat changed in a running session (hot join, `ccy-teams session add`) does not rename it.
- A name over 120 characters keeps `<launcher>-<project>` and says so on stderr.

## Proof

- Unit tests: `internal/teams/sessionname/sessionname_test.go` (forms, no-seat cases, length
  fallback, refusals, the command) and the dispatch test in `internal/teams/app_test.go`.
- Live proof owed: after the host runs `play-claude-yolo.yml` (already queued in
  `meta-deploy.list`), `ccy --teams <seat>@<team>` should show `tmux: ccy-<team>-<seat>` in the
  tab.
