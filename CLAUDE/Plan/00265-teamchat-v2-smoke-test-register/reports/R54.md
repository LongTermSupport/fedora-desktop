# R54: CI refuses a ccy image change without the version bump (issue #428)

## The class

**ccy version gate only in a local hook.** The rule "a change to ccy, or to a file the ccy image
is built from, bumps `CCY_VERSION`, and for the image the Dockerfile LABEL and
`REQUIRED_CONTAINER_VERSION` together" lived only in `scripts/git-hooks/pre-commit`. A checkout
that runs no hooks (R52, #427) committed past it, and no QA script or CI job ran it on a linear
range. CI judged merge commits only (`qa-ccy-merge-commits.bash`, issue #311). Hazard: a fix
lands on F44 with the container version unchanged, ccy never rebuilds its image, and every
session keeps running the old teamchat (F27).

## The detector

`scripts/qa-ccy-version-bump.bash BASE [REV]` judges the change from BASE to REV (default: the
work tree as `git add -A` would commit it, built in a private index) as one commit. It sets up a
shared clone with HEAD at BASE and the change staged, and runs this checkout's hook there as
`pre-commit --ccy-version-only`. So the matching is the hook's own: `lib/ccy-staged.bash`,
`lib/ccy-image-staged.bash` and the committed `image-source-paths` (one implementation, nothing
copied). Exit 0 passes, 1 refused, 2 cannot judge, 64 usage. It is a small bash wrapper within
the bash limits (one function, about 45 code lines), the same pattern as
`qa-ccy-merge-commits.bash`.

The range is judged as one change, not commit by commit: what a protected line ships is its tip,
so a bump later in the range excuses an earlier source change, and a range that changes a source
and never bumps is refused.

### Where it runs

- **qa-changed** (and so CI on every `ci/<topic>` branch): check `ccy-version-bump`, run as
  `qa-ccy-version-bump.bash <base>` with the same base qa-changed diffs against (local default
  `HEAD`, CI the protected line's tip). Routing row in `scripts/qa-routing.tsv`: `src-go/*`,
  `helpers/*`, `files/var/local/claude-yolo/*`, `files/opt/claude-yolo/*`, `vars/fzf-pin.yml`,
  the git hooks and the check's own scripts. The roots only start the check; which file owes
  which bump stays the hook's. `test-qa-ccy-version-bump.bash` fails if any input the hook counts
  in this checkout (launcher, `lib/`, the ssh agent helper, Dockerfile, both COPY roots, fzf pin,
  every `image-source-paths` spec) lies outside the roots, so the trigger cannot drift from the
  list. SPEC-qa-changed B68.
- **Full mode.** `qa-all` has no base, so it runs only the check's suite (gate row
  `ccy-version-bump` in `scripts/qa-gates.tsv`). CI's full run (a push to a protected line)
  judges the pushed range in the workflow step that judges merge commits:
  `qa-ccy-version-bump.bash "$tip" HEAD` with the tip before the push. A diff-mode run gets this
  from qa-changed, so the step runs it in full mode only. Reason: the full run follows a diff
  run of the same commit through the ci/ flow, but a push that bypassed that flow (R52: no
  pre-push hook) would otherwise never be judged.

## Tests

- `scripts/test-qa-ccy-version-bump.bash` (17 cases, throwaway repositories committed with
  `--no-verify`, the real hook): an image source changed with no bump is refused and named; a bump
  later in the range passes; a LABEL that differs from `REQUIRED_CONTAINER_VERSION` is refused; a
  library changed without `CCY_VERSION` is refused; an uncommitted change and an untracked new
  library are judged with the real index untouched; bad refs exit 2; usage exits 64; and the
  routing roots cover every hook input. Red proof of the last case: with `helpers/*` dropped from
  the row it failed, naming `helpers/ssh_agent_filter/x helpers/pingbus helpers/agent_bus helpers/stdin_text`; the row was restored.
- `src-go/qa/changed`: `TestCcyVersionBumpJudgesTheChangeFromTheBase` (the argv carries the
  base, the gate's verdict is the check's), the order and summary tables, and the golden replay:
  44 scenarios that change a file under the roots gain the check, pinned as deviation B68. Each
  re-pinned file was compared with its old pin after removing the `ccy-version-bump` lines:
  all 44 are otherwise identical.
- `src-go/qa/all`: the new gate row is in `addedAfterPort`.

## QA

`./scripts/qa-changed.bash --base a0ba409e3` (the whole change) ran every check green, including
the new `ccy-version-bump` check and the suites `test-qa-ccy-version-bump` (17),
`test-qa-changed` (202), `test-qa-docs-exit-codes` and `test-bash-history-search`. One check
failed: `go`, because go-qa cannot install ast-grep on linux/arm64 (R26, #426). That check was
covered by hand with `go test ./changed/ ./all/ ./gates/ ./docs/...` in `src-go/qa`, all ok, and
`gofmt -l` was clean. Module coverage was not checked (R53); CI checks it.
