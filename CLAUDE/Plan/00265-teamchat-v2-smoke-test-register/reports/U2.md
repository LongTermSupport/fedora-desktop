# U2: a PEER never reaches the worker; reply refuses it (R1, R2, issue #422)

Branch `v2-smoke-u2-peer-delivery`.

## Root cause

The receiver dropped every agent text (PEER) at a member whose roster entry says
`human_text: false`, and it did so BEFORE it checked the addressees.

In `src-go/internal/teamchat/proto/verdict.go`, `Judge.agent` read:

```go
case reason != "":
    return drop(v, reason)
case kind == KindPeer && !j.Roster.HumanText(j.Self):
    return drop(v, ReasonSender)
case !slices.Contains(addressees(c), j.Self):
    return ignore(v, IgnoreNotAddressed)
```

The seat-issuing tools run `member add --human-text <bool>` with true only for the coordinator
seat (and one devops seat), so every other worker in v2 has `human_text: false`. Such a worker:

- drops its coordinator's `say` as `sender`, and never makes it pending, so `inbox` is empty;
- still delivers pings, since the rule applies to PEER only;
- counts every PEER in the room as `dropped`, even those between other members. This is why the
  incident showed `dropped: 10` against `ignored: 2`.

On the sending side, `Composer.checkMain` ran `checkAgent` only. It never ran the receiver's
`human_text` rule. So `say --to <worker>` answered `sent` for a message its only addressee
would drop. That breaks the Composer's own contract: "refuses what a receiver would drop".

R2 follows from R1. `history` reads the whole main room: a page of `m.room.message` events,
`dir: in` for any sender but self, and no addressees. `reply` re-fetches an id that no store
holds and judges it again. The drop verdict became "team <t> has no item <id> in main".

### Evidence

- **Code.** The ordering is quoted above. `history` is `Team.history` in
  `member/teamsync/verbs.go`. `reply` goes through `Engine.fetched` in `member/engine/reply.go`.
- **Reproduced through the fakes.** `TestAWorkerWithoutHumanTextTakesItsCoordinatorsSay` in
  `member/teamsync/judge_test.go` runs fakehs, the real session and judge, and a roster with the
  worker at `human_text: false`. The coordinator sends a say and a halt ping, and a peer sends
  a say to the coordinator. On the old verdict the batch held only the ping (red, recorded),
  which is the incident. With the fix it holds both, with no drop and one ignore.
- **Live.** The coordinator read the worker seat's `link.log` and found 12 lines
  `dropped <id>: sender` and no other drop or ignore line. The same `say` to another worker
  seat (with `human_text` true) was delivered.

Candidates ruled out by the code:

- The `to:` form: the sender resolves names to user IDs, and the receiver compares user IDs.
- Render of long or multi-line bodies: render failures count under `unusable.render`, not
  `dropped`. The detector also composes a two-line text and delivers it.
- Dedupe or backlog: `seen` is not counted at all.
- History recorded before the filter: history reads the room, so it never consults the filter.

## Spec

`human_text` gating agent text was the spec, not a slip:

- Plan 00209 `DESIGN-v2-A-protocol.md` rule 08 said "`teamchat.text` kind PEER (the same
  `human_text` rule applies, as v1)".
- Plan 00161 D63 said "`human_text: false` drops it (`sender`)".

On the coordinator's direction, which reflects the owner's evident intent, `human_text` now
gates a human's words only. Rule 08 is rewritten to say so and cites this issue. **This is a
spec change for review.** A team that wanted a member to ignore agents' free text now has no
switch for it. Pings were never gated, so v2 never had such a switch for pings either.

## Defence before fix

**Class 1: the composer accepts what an addressee's receiver drops.** The sender is told "sent",
and the drop is only counted.

- Detector: `proto/agreement_test.go` covers every agent sender and every addressee set (singles
  and pairs over a human, the coordinator, two workers, one with `human_text: false`, a parked
  member and the probe), for text, relay and every ping verb, with and without an answered ping.
  Each composition the Composer accepts is judged by every agent it addresses, and each must
  deliver it or record an answer.
- Red on the old code:
  - 8 texts dropped `sender` at the `human_text: false` worker;
  - 111 texts and pings addressing the sender itself, which its receiver ignores as `self`, so
    the send reached no one;
  - with the relay rule removed, the relay to a `human_text: false` worker was dropped `sender`.
- Sweep: the detector found these two instances in the main room, and no other.
- Fixes:
  - (a) `Judge.agent`: the addressee check runs first, and `human_text` drops only a relay (a
    human's post);
  - (b) `Composer.addresseesTake` refuses `target`, with a detail that says why, for a send
    naming its own sender and for a relay to a `human_text: false` member.
- The corpus row `text no human` now delivers. A new row, `text overheard`, ignores
  `not-addressed`.

**Class 2: a drop counted with no reason anyone can read.** The reason went only to `link.log`.

- Detector: `member/teamsync/dropsite_test.go` parses the package and refuses any
  `<x>.Dropped++` or `+=` outside `judged.drop`.
- Red: a bare increment put back in `take` was named, and `TestDropsAndRedacts` failed on the
  empty `DroppedBy`.
- Fix: one `judged.drop(id, reason)` counts under the reason (`team.Counts.DroppedBy`) and logs
  the id. `teamchat status` shows `counts.dropped_by: {reason: n}`, so the incident would have
  read `dropped_by: {sender: 10}`.

**R2: an item that history lists must be answerable, or the refusal says why.**

- `history` records carry `to`, as handles, and `for_me`.
- `reply` to an event its judge does not take says why:
  - not addressed: "was not addressed to this member ... write to its sender with teamchat say
    --to <sender>";
  - judged out: "its link dropped|ignored it by rule `<reason>`, so it was never delivered".
- After the R1 fix, a PEER to a `human_text: false` worker is delivered, so `reply` to it
  works.
- `sent` records carry `to`, the full handles the names resolved to, so a sender can check who
  its say went to.

Docs: the teamchat skill (`files/opt/claude-yolo/optional/teamchat/plugin/.../SKILL.md`) now
says that history covers the whole room, oldest first (it said "received and sent, newest
first", which was wrong on both counts). It also documents `to`, `for_me`, `sent.to` and
`dropped_by`. The examples in `DESIGN-v2-B-member.md` are updated.

## Not proven

- Nothing here ran on a real homeserver. The live checks above are what proves it there.
- The questions-room composers (question, thread, link-back, retitle) are not in the agreement
  detector, which covers the main room only.
- A human message is still dropped `sender` at a `human_text: false` member before it is
  decoded (rule 07, unchanged). Overheard human messages therefore still count as `dropped`
  (`dropped_by.sender`) there, not as `ignored`.
- A drop is now named in `status` and in the link log. No drop is pushed into the session
  unprompted.
- Changing D63 and rule 08 is the owner's to confirm (see Spec).
