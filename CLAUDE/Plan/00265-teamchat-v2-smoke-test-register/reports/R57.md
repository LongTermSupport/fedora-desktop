# R57: `teamchat version` names all of `src-go`, so equal teamchat builds disagree

Fixed on `v2-smoke`, batch 21 (`9114b2b70`). ccy 3.124.66, container 2.84.86. Not yet run
live.

## What each value was (read in code)

| Value                           | Producer                                                                                     | What it was                                                                                                                   |
| ------------------------------- | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| teamchat's digest, in the image | Dockerfile `ccy-builder`: `git -C /repo rev-parse FETCH_HEAD:src-go`, `-X main.SourceDigest` | tree id of all of `src-go` at `CCY_SOURCE_COMMIT` (the image-source commit)                                                   |
| teamchat's digest, on the host  | `play-teamchat.yml`: `git rev-parse HEAD:src-go` (`tc_tree`)                                 | tree id of all of `src-go` at the checkout's HEAD                                                                             |
| teamchat-admin's digest         | the same `tc_tree`, one `go_cross_ldflags` for both commands                                 | the same                                                                                                                      |
| label `ccy-source-commit`       | Dockerfile final stage, `ARG CCY_SOURCE_COMMIT`                                              | the last commit up to HEAD that changed a path of `image-source-paths` (`tasks/claude-yolo-image.yml`), not the checkout HEAD |

So the image's digest was the `src-go` tree at the image-source commit and the host's the `src-go`
tree at HEAD: any `src-go` change outside the image's source (batches 7 and 8, `internal/teams`)
made them differ for identical teamchat code. The label was correct for what it is, but its name
read as "the commit this image was built from": an image built today, with no image source changed
since batch 6, rightly carries batch 6's commit. The observation on the machine (a cached layer)
is consistent with that and needs no cache explanation: the value passed was batch 6's.

## Who reads them at run time (the register said nothing does: wrong for the digest)

- **The keeper compares digests** (`member/keeper/prepare.go` `resolveKit`): it runs the kit
  binary's `--version`, requires it to equal the kit directory's name when the kit is named by a
  digest, and re-execs into the kit when it differs from its own digest. Both sides are always
  the same build's, so the comparison holds under any scheme in which the kit directory is named
  by the digest the binary carries; it would break only if two different binaries shared a digest.
- **The digest is a name on the host**: `kit/<digest>/`, its `current` link, `teamchat-member-<d>`
  and `teamchat-admin-<d>` in `/usr/local/lib/teamchat`; `teamchat-admin`'s `lxc` verbs read the
  kit digest from `current` (`admin/wire/lxc.go`).
- **teamchat-admin's digest is recorded** as `software` in each team's `stamp.json`
  (`host/apply.go`) and in a carry export's seal manifest (`carry/seal.go`); nothing compares it.
- **The label**: only `scripts/test-ccy-image-build-lock.bash` read it. Nothing compares it.

So a digest may cover more than the build's source (spurious differences), but never less (two
binaries with one digest would defeat the keeper's check).

## The choice

**Option 1 (the digest covers what teamchat is built from), for teamchat only.** One shared
script, `files/var/local/claude-yolo/image-source-digest REPO COMMIT PATHS-FILE`: it reads the
commit into a scratch index, lists the files `image-source-paths` matches with
`git ls-files -z --stage` (mode, object id, path; NUL-separated, so no git setting changes it) and
prints that listing's blob id. `git ls-tree` cannot take the list's `:(glob)`/`:(exclude)`
pathspec magic, `ls-files` can; the object store is only read.

- The Dockerfile's builder stage copies it from the build context and runs it at `FETCH_HEAD`
  (`tasks/claude-yolo-image.yml` copies it in, like `image-source-paths`).
- `play-teamchat.yml` runs it on the controller at `HEAD` (`tc_member_digest`) and gives it to
  `teamchat` only; the kit directory, the staged member program and `current` are named by it.
- Equal by construction: the image is built from the last commit that changed those paths, so
  their content at that commit equals their content at HEAD. Checked on this checkout, before the
  fix commit: HEAD, the image-source commit and a depth-1 fetch (as the builder has it) all gave
  `dcb19389…`, where the `src-go` tree id was `3d78311c…`. The fix itself changes an image source,
  so it is the new image-source commit: after it, HEAD (`a4c24ea6c`) and `9114b2b70` both give
  `659a952c…`, where the `src-go` tree id is `e6807c34…`.

Why not option 2 (keep the digest, print the build commit too): the host would print HEAD and the
image the image-source commit, which differ in exactly the cases R57 is about, and `version`'s
record (`{"kind":"version","v":1,"digest":…}`) is a contract; it would need a new field and still
leave the reader comparing two unrelated commits.

**teamchat-admin keeps the `src-go` tree id.** It is no image source, so the image-source paths do
not cover it (using them would let two different admin binaries share a digest, and the admin's
digest names its file). The `src-go` tree covers all it builds from: it can differ spuriously,
never match falsely. A per-command source list for it would need a second generator; not built.

The digest still covers more than teamchat alone (the image's other Go commands and the pingbus
packages share the list). That is the image's source, one stated thing, and over-coverage is safe.
It does not cover the Go toolchain: the host builds with its own Go, the image with the pinned
one, so equal digests mean equal source, not equal bytes (as before).

**The label is renamed `ccy-image-source-commit`**, with the Dockerfile comment saying it is the
image-source commit, never the checkout's HEAD. No second label with the checkout's HEAD: a value
new on every commit would change the image on every commit, which the
[image-build-arg-volatile](../../../QA.md#image-build-arg-volatile) rule exists to prevent. The
rename is a final-stage metadata line; nothing in the repository read the old name.

Where it is printed: `teamchat help version` now says the digest is `image-source-digest`'s, the
ccy image's source, the same on the host and in the image.

## Defence Before Fix

**Class:** a provenance value that covers more or less than what it claims to identify (a digest
or commit stamped on a build that is computed over another set of inputs than the build's).
Hazard: covering less lets two different builds look identical (here the keeper would trust a
wrong kit); covering more makes equal builds look different and hides real staleness.

**No detector.** Whether a value's inputs match what the build reads is semantic: it needs the
build's input set (for the image, `go list -deps` per command, which is what
`ccy-image-source-paths.bash` computes) set against the value's input set. A syntactic proxy
("`-X main.SourceDigest` fed from `rev-parse HEAD:src-go`") matches only the fixed lines. The
opposite direction for build arguments is already a rule (image-build-arg-volatile). The guard is
the shared script and the tests above.

**Sweep** (`-X main.*` stamps, image labels, recorded commits):

| Value                                                      | Verdict                                                                                   |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| teamchat `-X main.SourceDigest` (image and host)           | **Instance, fixed.**                                                                      |
| label `ccy-source-commit`                                  | **Instance (name claimed the checkout's commit), fixed:** `ccy-image-source-commit`.      |
| teamchat-admin `-X main.SourceDigest`                      | Covers more than its source (all `src-go`), never less: safe, kept and documented.        |
| claude-yolo front `-X main.Version`                        | `CCY_VERSION`, the launcher version it claims: not an instance.                           |
| `-X main.RootDir` (ccy-teams, cc-project-dir, cc-claude)   | A path, not provenance.                                                                   |
| `-X main.RequiredVersion` (claude-code-consumer)           | The image version it needs, not its own provenance.                                       |
| label `claude-yolo-version`                                | The container version, held to every image input by the pre-commit gate: not an instance. |
| label `claude-yolo-dockerfile-hash`                        | Named for the Dockerfile and hashes the Dockerfile alone: what it claims.                 |
| label `ccy-version` (build `--label`)                      | The ccy that built the image: what it claims.                                             |
| file `/opt/claude-yolo/source-commit` (host build context) | Holds the image-source commit; internal to the launcher's rebuilds, documented as such.   |

## Review (independent, read-only) and its follow-up

Verdict pass with nits. Checked by the reviewer: host and image digests agree (HEAD, the
image-source commit, a depth-1 fetch, `LC_ALL=C`: all `659a952c…`); the paths list covers every
package `go list -deps` gives for the three image commands; the keeper (`member/keeper/prepare.go`)
cannot see a kit mismatch during or after the deploy, since running sessions keep their old kit
directory and the play never deletes it; nothing reads the old label; no new build argument.

- **Fixed (batch 22, ccy 3.124.67, container 2.84.87):** a listed path with a trailing space
  matched nothing, so the digest silently left it out (exit 0), while the builder's word split
  still archived it: R57's own class, a digest covering less than its list. `image-source-digest`
  now refuses any listed path that names no file at the commit, naming it (exit 1); a typo is
  caught the same way. Red: 5 new checks in `scripts/test-ccy-image-build-lock.bash` failed; green
  after.
- **Left, low:** the digest also covers the pingbus Python (`helpers/…`), so a Python-only change
  gives teamchat a new digest and restarts each team's TLS terminator once with teamchat's code
  unchanged. That is the image's source definition, kept on purpose: one list, one digest.
- **Left, low:** the play refuses uncommitted changes under `src-go/` only. Uncommitted changes
  to `image-source-paths` itself, or under the `helpers/` paths it lists, are not refused, so on
  a controller with such edits the host's digest (read at HEAD) would not describe the files the
  play builds from. Both are committed through the pre-commit gates in normal use.
