## The v1 contract (the floor)

Source: `helpers/agent_bus/checkout.py` `choose()` and `seat_choices()` (agent-bus `seat choose`,
Plan 00177 T4.5/T4.8), shown by `src-go/internal/teams/choose/choose.go` `PickSeat`, and
`files/var/local/claude-yolo/lib/tmux-session.bash` `ccy_tmux_offer`.

1. `ccy --teams <team>` at a terminal lists the checkout's seats of the team, of the launcher's
   member type, each `free` or `held` (held: a running session's desired membership names it),
   numbered seats by number first, then named ones (`_seat_order`), and a `new` seat last.
2. The new seat is the lowest number no seat of the checkout uses and no active member of the
   same `<repo>+<host>.<type>` holds.
3. The default is the lowest free seat, else the new one.
4. A held seat can be chosen; the launcher's tmux offer then lists the detached sessions that
   hold the seat and re-attaches the one chosen (`ccy_tmux_offer` with the canonical list).
5. With no terminal, a team alone is refused (64): name the seat.

## What v2 did and why it failed

`ccy-teams choose-teams` (both `ccy` and `cc` call it) sends a teamchat team to
`chooser.teamchatSeat`. It read the pool through `Teamchat.Seats`, which carries seat names only:
no holder. With one pool seat it took it without asking; with several it defaulted to the first
in directory order. The held check only happened at the take (`seat.Store.Take` → `ErrHeld`),
after the choice, so `cc --teams <team>` in a checkout whose seat a running session held took
that seat and the launch exited 75. The refusals (`seat-check --resolved`, `launch-args`) named
neither the seats nor a way on.

## The change

- `internal/teams/seatchoice` (new, pure): order (v1's), default (lowest free), the chooser row
  (free, or held by session S with the re-attach), and `WaysOn`: the seats with their state,
  then a command per way on (`<ccy|cc> --teams N@team` for each free seat;
  `ccy-sessions` / `ccy-sessions restore S` for each held one; a new seat via
  `ccy-teams seats add <team>`, U5's command), and the new-seat row.
- `system.PoolState` / `Cmd.PoolState`: each pool seat with the session a take would refuse it
  for, by the seat store's own test (complete holding; keeper running via `seat.KeeperOf`, or
  session record kept). Unreadable records are an error, never a free seat. The `seat` package is
  untouched (it is in the image).
- `chooser.teamchatSeat`: chooses only from `Pool`. One free seat is taken as before; no seat at
  all goes to the new-seat seam; otherwise every seat is listed, then a "new seat" row (v1's
  new row), the lowest free seat the default, the new seat when none is free. A held seat
  re-attaches its session (`TmuxReattach`: attach outside tmux, `switch-client` inside ccy's
  tmux, where cc chooses) and starts nothing; a re-attach that cannot be made exits 75 with the
  ways on. No terminal with a team alone: the ways on, exit 64, nothing prompted.
- **The new-seat seam** (owner's direction via the coordinator): `chooser.Teamchat.NewSeat`
  (`NewSeatFunc(ctx, team, memberType) (ref, code)`), reached only through `Chooser.newSeat`,
  which every "no free seat" outcome and the new-seat row call. Unwired (today), it prints
  `ccy-teams seats add <team>` and every way on and exits 78. The follow-on wires U5's
  in-process seat add (`internal/teams/seatadd`) into `NewSeat` in `teams/app.go` after both
  branches merge; nothing else changes. `seatchoice.AddCommand` is the one spelling of the
  command, used by the ways on of every refusal too.
- `teamchatlaunch.Verbs`: `seat-check --resolved` of a team alone (a headless ccy) and a
  `launch-args` take refused as held (75) now print the ways on under the refusal.
- `Teamchat.Seats` (names only) is narrowed to `SeatCount`, so the chooser has no stateless seat
  source left to choose from.

## Defence Before Fix

Class: a seat (a contended resource) chosen from a listing that carries no held state. No
detector can express it in general: whether a consumer of a listing checked a holder is
semantic, not syntactic. The defence is structural: the chooser's only seat source is `Pool`,
which carries the holder, and the stateless `Seats` is gone (a count only). Sweep of the other
seat choosers: `picker` New session (`seats.seatChoices`) offers free seats only; `hot` session
add refuses a held lock; `teamchatlaunch.Launch` takes only a named seat and refuses a held one.
**One instance left for the owner:** v1's `choose.PickSeat` still lets a held seat be chosen
and hands it to the tmux offer; if the holding session is open in another terminal, the launch
goes on and agent-bus refuses it (75). That is v1's own behaviour (the floor), so it was not
changed here.

## Integration with U4 (#417): a chosen, never-used seat starts fresh (ccy 3.124.46)

After both merged into `v2-smoke` (ccy 3.124.45), a plain `ccy --teams <seats>` resumes the seats'
recorded conversation, and with none exits 64 naming `--fresh`; so a seat picked in this
chooser that no session ever used was refused. Now:

- The launcher passes `ccy-teams internal seat-resume` the `--teams` list as the person gave it
  (`--given=`; `TEAMS_GIVEN_LIST` is saved beside the chooser's call, in the same statement, so
  the launcher does not grow). A seat not named in it was picked in the chooser.
- When every seat of the launch was picked and ForSeats says no session ever held them
  (`conversation.CaseNoSession`), the launch starts fresh, said ("chosen in the list, were never
  used: a new conversation starts") and recorded, as `--fresh` does.
- A picked seat with a record resumes it (U4); a seat named in `--teams` (alone or beside a
  picked one) keeps U4's 64 refusal; a picked seat whose record is in trouble (no transcript, two
  records, a session with no conversation) is refused as before: it is not never-used.
- A held seat re-attaches (unchanged). A restore and a headless launch pass the canonical list as
  given, so every seat is named and nothing changes for them.
- Test: `TestSeatResumeAChosenNeverUsedSeatStartsFresh` (red before: `--given` was refused as
  usage). `scripts/test-ccy-teams.bash`'s fake seat-resume reads the new argument and logs it.

## Live proof needed (not attempted here)

After `./CLAUDE/Plan/meta-deploy.bash` runs `play-claude-yolo.yml` on the host (ccy-teams and
the launcher front rebuilt):

1. In a checkout with two teamchat pool seats of team T, start `ccy --teams T` and pick seat 1;
   detach (F12). Run `cc --teams T` (or `ccy --teams T`) in the same checkout. Accept: the list
   shows seat 1 `held by session <name>: re-attach it` and seat 2 `free`, seat 2 is the
   default; Enter starts seat 2; no exit 75.
2. Repeat, choosing the held row. Accept: the terminal is on the first session (attached for
   ccy, switched for cc); nothing new starts.
3. With the first session open in another terminal, choose its row. Accept: exit 75 with the
   seats, which are held, and the `ccy-sessions` take-over line.
4. With every seat held: the "Every seat … is held" line, then the list with the new-seat row
   as default; choosing it ends 78 naming `ccy-teams seats add T` (until `NewSeat` is wired).
5. `ccy --teams T -p hi </dev/null` (no terminal). Accept: exit 64, ways on printed, no prompt.
