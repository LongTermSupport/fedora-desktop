# R65: a leftover empty v1 membership hides a teamchat session from the host lookup

Batch 17, on v2-smoke. Host `ccy-teams` code only (`internal/teams/hot`,
`internal/teams/teamchatlaunch`): neither is an image source, and no launcher `lib/` file
changed, so the pre-commit hook asked for no ccy or container bump.

## Commits

- Fix: `76d9bf5f0`.
- This report, the register row and the n3f-D18 wording (Plan 00209 `SPEC-n3f.md`, a fact-check
  note on batch 16): the commit that adds this file.

## Cause

- A named ccy launch with no `--teams` goes to `ccy-teams internal launch-args` with an empty
  list (`lib/agent-bus-membership.bash:57-67`). `systemOf` sends an empty list to agent-bus,
  and `membership.Init.Prepare` writes generation 1 with `seats:[]`. That file is needed: without
  it the session is BusNone, and `session add` refuses it (`notKit`).
- The teamchat branch of `launchArgs` took the seats and wrote `desired.json`, but never touched
  the v1 directory, so the empty file from the earlier launch of the name stayed.
- `Lookup.Running` read v1 whenever the directory existed and never asked for v2. The session's
  row then went down v1's path: no teams, v1's keeper process absent, so `stateUnguarded`
  ("unguarded: ccy-teams session repair <session>"). `repair` on it would have run
  `podman exec -d <container> pingbus seat keep` in a v2 session.

## What changed

- `teamchatlaunch/verbs.go`: `retireV1(kind, session)` removes
  `membership.DirOf(XDG_RUNTIME_DIR, kind, session)`. `launchArgs` calls it with `KindCcy`
  after a successful `Take` and before printing. It is not called on a refused take, and an
  agent-bus launch, including a no-team one, still writes its membership. A runtime directory
  that is not absolute, or a directory it cannot remove, fails the launch and names the
  directory.
- `teamchatlaunch/ccrun.go`: `ccRunTeamchat` calls it with `KindCC` after its take. If the call
  fails, the session's seats are ended (`ccEnd`), as on the other failures there.
- `hot/running.go`: `Lookup.Running` reads v1 if the directory exists, then asks for v2 too. If
  both exist, the newer `written_ms` wins, and a tie stays v1. If v2 cannot be read beside a v1
  file, that is an error with Bus v2, because which bus is the session's cannot be told. This
  fixes a session already running with a leftover file, with no relaunch.
- `hot/hot.go` (`resolve`): the message for an unreadable v2 membership no longer says the
  session has no agent-bus membership.

## Defence Before Fix

The class is a reader that chooses a bus generation by what exists on disk rather than by what
the launch used. A go/analysis rule cannot express it. The defect is not in a syntax shape:
`os.Lstat` and a branch on the result are right in many places. Whether a file is "the
launch's" is a fact about the launch history, which no analyzer sees. The guards are these:

- The tests above, on both sides: the writer retires the other generation's file, and the
  reader compares the written times.
- R51's existing inventory (`v1Readers` in `hot/running_test.go`, run by
  `TestEveryVerbOnAV2SessionActsOrRefusesByName`). It fails on any new call that reads a v1
  membership outside the lookup. It caught the new `membership.DirOf` call in `teamchatlaunch`,
  which is now listed with its reason (it removes, never reads).
