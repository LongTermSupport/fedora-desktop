# R51: host verbs that read only v1 membership do not see v2 sessions

Plan 00265, register row R51, batch 10, branch `v2-smoke`.

## The cause, checked

The R58 trace held. `session list` (`hot/list.go` `ownMembership`) and `SessionsIn` read only
v1's `membership.json` under `$XDG_RUNTIME_DIR`. `resolve` (`session add`/`remove`) fell back to
the teamchat `desired.json`. So the two disagreed: list said "old or --no-bus" for a session that
add changed. The picker's Running sessions view is built on `Sessions`, so it had the same gap.
`ccy-teams restart`'s in-place path read only v1's membership too. A running cc session on
teamchat did not appear in the list at all, because `runningCC` only lists v1 cc memberships.

## The fix

- **One lookup:** `hot.Lookup.Running(runtime, kind, record)` in `hot/running.go`. It returns the
  session's v1 membership when it has a v1 membership directory, else its teamchat
  `desired.json` in the record's checkout (`Hot.Teamchat`), else none. A record whose own launch
  left the bus out owns nothing (B1). A read error names the bus that failed.

- **`session add`/`remove` (`resolve`):** call the lookup under the change lock and branch on its
  answer. `openV2` and the separate `Lstat` are gone. Messages and exits are unchanged.

- **`session list` and the picker's view (`Sessions`):** a v2 row (`v2Row`) shows each desired
  seat's team, seat and duty as its role (`-` when there is none). Its STATE comes from
  `HotSeats.Applied` for each seat:

  - `ok`;
  - `<seat>@<team>,... not held: <why>`;
  - `its seats cannot be read: ...`;
  - `its teamchat (v2) membership cannot be read: ...`.

  It never reads v1's `keeperLine` or a homeserver unit, and it is never `Unguarded`.
  `Session.V2` marks the row. A running cc session on teamchat (a cc record, a live pane, found
  by the lookup) is now listed as not controllable, with the `v2CCNotBuilt` reason.

- **`SessionsIn`/`TakeOut`:** `SessionsIn` reads through the lookup and counts only v1 sessions.
  Its one caller, `ops.Remove`, takes down an agent-bus (v1) team. A v2 session is never in one,
  and a v2 team of the same name is a different team, so taking a v2 session out would be wrong.
  `TakeOut` on a v2 session is refused by name (exit 78, `--coordinator`).

- **Picker:** a v2 session's menu offers "Remove from <team>", which runs `session remove` with
  no coordinator question, and Attach. "Add to a team" is shown as unavailable and names
  `ccy-teams session add <session> <team>`, because the picker's add asks for agent-bus seats.
  Role and move are not offered. A v1 team's Add a running session refuses a v2 session by name.

- **`ccy-teams restart`:** `prepareInPlace` reads through the lookup (`Restart.Lookup`, wired in
  `teams/app.go`). A v2 session is refused by name: restart in place is agent-bus's supervisor
  request. A session with neither membership names the missing v1 directory.

- **Checked, no change:**

  - **Board:** `addDesired` builds the agent-bus seat index, and a v2 session holds no agent-bus
    seat. `board/v2.go` already shows v2 teams and their members from each team's status record,
    and restart, wind-down and shutdown refuse a v2 team by name (`V2Refusal`).
  - **`internal/conversation`:** already reads v2 first. `sessionSeats` reads the v2
    `desired.json` before v1's report, `v2Sessions` sits beside `v1Sessions`, and `Locate`
    branches on `systemOf`.

## Defence Before Fix

- **Class:** R41's class. A host verb or reader acts on one bus generation's membership for a
  session of the other.
- **Guard:** `TestEveryVerbOnAV2SessionActsOrRefusesByName` (`hot/teamchat_test.go`) is widened
  in two ways:
  1. **`guardV2Readers`** drives `list`, `Sessions`, `SessionsIn` and `TakeOut` on a v2 session.
     Each must act on it or refuse it naming teamchat, and must not write v1's membership.
  2. **`guardV1ReaderCalls`** is an inventory built from the syntax tree. It finds every call of
     `membership.Read/DirOf/Dir/CCDir/ReadReport` and `discover.ReadDesired/RunningCC` in
     `internal/teams` and `internal/conversation`, outside the packages that define them. Each
     call must be in `v1Readers` with its reason, and a stale entry also fails. A new reader
     that does not go through the lookup fails the guard. The test names the lookup and the
     allowlist.
- **No project analyzer.** A `go/analysis` rule would need the same allowlist. A test in the
  package that owns the lookup keeps the list next to the code it describes.
- **Red, seen:**
  - Before `running.go`, the tests did not compile (`Lookup`, `Session.V2`).
  - With the lookup in place but no reader changed, four list tests failed ("old or --no-bus",
    an empty cc list), as did parity v2 (list not controllable, add exit 0) and the guard.
  - With list fixed, the guard's inventory failed on exactly `hot/hot.go membership.Read/DirOf`
    and `restart/jobs.go membership.Read/DirOf`.
  - The restart test failed to compile (`Restart.Lookup`).
  - The picker's two tests failed: the menu offered role and move, and the add did not refuse.
- **Green:** the hot, restart and picker tests pass. `go test -race ./internal/teams/...` exits 0
  (36 packages ok).
- **Parity test:** `TestAddAndListAgreeOnWhetherASessionCanBeChanged`. For a v1 session, a v2
  session and one with neither, list's `Controllable` matches whether add is refused (78).
