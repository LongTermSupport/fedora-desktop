# Independent search: ready-wait that ignores the child's exit

Class: a wait for a process this code started to become ready (poll loop or timer, sleeps or
timeouts between tries) that does not check, on each try, whether that process has already
exited. Hazard: a failure known within seconds is hidden behind the full timeout and reported
as "timed out".

Scope searched: every tracked file except the keep-out list (1511 tracked files minus the
excluded trees). Code files (644: Python incl. extensionless, Bash, JS, YAML, systemd units)
were read where a match pointed; Markdown and docs were skipped except as a pointer.
Nothing was run, no detector or rule directory was opened.

## Forms written down before searching

1. Python: `Popen`/`subprocess.run` then `for ... time.sleep` / `while ... sleep` polling a
   socket, port, PID file, status file, D-Bus name, HTTP endpoint, with a counter or deadline.
2. Bash: `cmd &` (or `setsid`, `nohup`, `systemd-run`) then `for i in $(seq ..)` / `while`/`until`
   with `sleep`, polling `-S` / `-s` / `-f` / `curl` / a log grep / a status command.
3. JS (GNOME extension): `GLib.spawn_command_line_async` / `Gio.Subprocess.new` then
   `GLib.timeout_add` / `setTimeout` retry or debounce waiting for a signal or file.
4. Ansible: `until:` + `retries:` after a start task, `wait_for:` after a service start or
   async launch.
5. Test harnesses that start a stub server or the program under test in the background and
   wait for a port file, a log line or a state.
6. Waiting for a VM / container / LXC that the script started (`virt-install`, `virsh start`,
   `lxc-start`) to answer SSH or get an IP.
7. A single fixed `sleep` standing in for readiness (near miss: no poll, but the same blind spot).

## Instances

Confidence: HIGH = the loop started the process, waits on a signal of its readiness, has no
liveness check, and nothing else catches the death. MED = same shape but the waited-for thing
is one step removed (service manager, VM, container) or the child's error is partly visible.
LOW = shape matches, impact small or the start is indirect.

T1 = text search found it, then read to confirm. T2 = found by reading (a match pointed
at the file, the instance was in code the match did not name).

## What text search found that reading could not have checked

- The breadth: every `sleep`/`seq`/`until:`/`retries:`/`wait_for`/`timeout_add` site across 1500+ files, including extensionless scripts (`docker-in-lxc`, `claude-yolo`, `tmate-*`, `gshell-nested`) that a directory walk by reading would take far longer to enumerate. Instances #3, #4, #6, #11-#14 were found this way and read only to confirm.
- That no `wait_check_async` / `wait_async` / child-watch appears anywhere in `extensions/` or `files/` (only the ESLint config message names them), so no JS site has a liveness mechanism.
- That the only Ansible waits are the two in #9 and #10 (`grep until:/retries:/wait_for/async:/poll:` over `playbooks/`, `tasks/`, `vars/`).

## What reading found that text search could not have

- That #2 is a separate path inside the same loop: the "wait for an existing server" branch, where no process handle exists.
- That `server_pid_alive()` (the flock probe) already existed in `wsi-stream` at HEAD and was not consulted in the loop, so the means to detect death were on hand.
- That the speech-to-text debounce (#5) is a timer-as-wait whose own comment names the dying-child case as covered by the timeout.
- That the counter-examples (`wsi-article-window`, `wsi-stream-server` capture, `copy_to_clipboard`) handle liveness, which text search of `poll(` alone would not have shown to be inside the same polling construct.
- The meaning of each wait (whether the code started the process, or only observes something external, e.g. ftp-camera/rclone, the vmtest session runner, the bridge watcher), which decided most of the exclusions.

## Searches run

- File inventory: `git ls-files` minus keep-out paths, then split into code vs other (non-md, non-doc).
- Spawn forms: `Popen|spawn_async|systemd-run|create_subprocess|GLib.spawn|Gio.Subprocess|nohup|setsid|disown|& *$|async:|Subprocess` over all tracked text files.
- Wait forms over code files: `wait_for|until:|retries:|while .*(sleep|kill -0)|for .* in \$\(seq|sleep [0-9.]+|time.sleep|timeout_add|setTimeout|GLib.timeout|asyncio.sleep|deadline|\[ -S|test -S|wait_ready|until `.
- Same sleep/seq/until/background pattern over extensionless files outside `bin/` (`files/var/local/...`).
- Per-file `grep -n` of sleep/kill -0/until/while/Popen/`&`/nohup/setsid/systemd-run/poll for each bin script, `lib/*.bash`, `run.bash`, helpers, tests, `scripts/test-*.bash`, and every Plan `*.bash`/`*.py`.
- Ansible: `wait_for|until:|retries:|async:|poll:` over `playbooks/`, `tasks/`, `vars/`.
- Liveness-mechanism search: `wait_check_async|wait_async|child_watch|ChildWatch` over `extensions/`, `files/`, `helpers/`.
- Readiness-by-other-means: `run -d|ssh-agent -s|socat|--health|podman wait|inspect .*State|nc -z|/dev/tcp|curl .*retry`.
- `git show HEAD:files/home/.local/bin/wsi-stream` and `git diff HEAD` on it (only to note the uncommitted fix).
