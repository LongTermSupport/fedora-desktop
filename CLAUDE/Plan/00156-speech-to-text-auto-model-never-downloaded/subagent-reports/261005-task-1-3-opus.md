# Task 1.3 and Task 2.1: the ready-wait class, and the originating fix

Class: a wait for a process this code started to become ready (a poll loop or a timer)
that does not ask, on each try, whether that process has already exited. A failure
known within seconds then hides behind the full timeout and is reported as "timed out".

## Commits

1. **Red.** Rule, page, fixtures and gate. The gate fails on 8 real instances.
2. **Instances.** Every instance except `wsi-stream` is fixed. The gate is red only on
   `wsi-stream:793`.
3. **Task 2.1.** The `wsi-stream` fix and `test_server_start.py`. The gate is green
   and `held/` is removed.

## The defence

`ready-wait-rules`. Its page is in CLAUDE/QA.md under `ready-wait-ignores-child-exit`,
and the gate table lists it. It scans every tracked Python file and shell script that
`scripts/qa-discovery.bash` reports, minus the `.semgrep/` fixtures. It proves both
halves against their fixtures on every run.

### Instances recorded as not fixed

- **#8 `helpers/vmtest/serial_console.py`.** It starts nothing. Once it is connected, a
  QEMU that dies closes the socket, and the read ends at once with a named stall. Only
  the connect retry (at most `--connect-wait`, 60 s from vmtest) cannot tell a dead
  QEMU from one between `bind` and `listen`. It ends with the socket's own errno.
  Telling the two apart would need the domain, which the helper is not given.
- **#15 Completed Plan 00111 `insulation-steps.bash`.** Several steps kill the fake
  terminal on purpose and then wait for the effects, so a liveness check in the shared
  `wait_for` would be wrong for them. Each wait is bounded (15 to 60 s) and names what
  it waited for. The plan is complete, and the script is kept as its record.
