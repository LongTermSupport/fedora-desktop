## 13:05 · action · T1.3   — ready-wait defence committed red

The defence for "a ready-wait that ignores its child's exit" is committed red, before
any instance is fixed. It is a new gate, `scripts/qa-ready-wait-rules.bash`, run by
`qa-all.bash` as `ready-wait-rules`, with its page in CLAUDE/QA.md under
`ready-wait-ignores-child-exit`.

- **Python:** a Semgrep rule, `.semgrep/ready-wait.yml`, proven against
  `.semgrep/ready-wait.py` on every run. It reports a sleeping loop in a function that
  starts a process (`subprocess.Popen`, `asyncio.create_subprocess_*`) when the loop
  never polls, waits on, or probes that process.
- **Bash:** `helpers/ready_wait/bash_ready_waits.py` with its unit tests, proven against
  `.semgrep/ready-wait.bash` on every run. Semgrep was tried first and dropped: its bash
  parser rejected 80 of the 371 tracked shell scripts (vmtest, wsi, ccy-sessions,
  claude-yolo among them), so a rule there would have passed over them unread.
- **No rule:** GNOME JS, Ansible, starts that daemonize (`lxc-start`, `virsh start`,
  `virt-install`), and a wait in a later run of a step script. The reasons are on the
  QA.md page; those instances are fixed by hand.

How the bash rule was calibrated, from the first draft to this one:

- At first it counted any background start in the file. That gave 24 findings, most of
  them false: monitors, interactive menus, and loops in files whose only `&` was a
  fire-and-forget `gdbus emit`.
- Now it reads events in order within each function and in the top level. A start
  (`cmd &`, or a call to a function that keeps a `$!`) arms the scope. A sleeping wait
  after it, or in a function called after it, is reported. A `wait` on the child or a
  `;;` disarms the scope.
- Two shapes stopped counting as waits: a loop that runs its whole course (a `for`, or a
  `while true` / `while ((SECONDS < end))`, with no break, return or exit), and a
  function started with `&`.
- The first lexer paired the inner quote in `"$( ... "x" ... )"` with the outer one and
  blanked the rest of `test-wsi-stop-grace.bash`, which hid instance #12. A test pins
  this case.
