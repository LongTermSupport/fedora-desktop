## 10:00 · action · T5.4a   — unlock starts the dock recovery from a separate extension, with a polkit rule


The owner chose option C of `DESIGN-panel.md` §12: a separate small extension, so the panel
stays detect-only. It is written and tested, and is not yet deployed.

- **Extension:** `extensions/dock-recovery-on-unlock@fedora-desktop/`.
  - It connects to `Main.screenShield`'s `locked-changed`. Its `session-modes` include
    `unlock-dialog`, because the shell otherwise disables an extension at the lock and
    enables it after the unlock, so it could never see the signal.
  - On an unlock it waits 5 s and spawns the argv
    `systemctl start --no-block displaylink-dock-recovery.service`, with no shell. The wait
    covers the shell setting logind's `LockedHint` asynchronously; the recovery skips a
    session whose hint still says locked.
  - It is the unit the dock udev rule already starts, so the recovery's own `decide()`
    picks the action. While docked that is `REFRESH_BACKGROUND` at EVERY unlock, since
    `needs_background_refresh` fires whenever dock heads exist. A head that looks wedged
    runs the root ladder: driver restart, USB re-authorisation, evdi reload. With no dock
    heads it does nothing, if the DVI-I connectors go away when the dock is unplugged.
    The desktop user can now set all of that off.
  - A repeat signal inside the wait adds no second start, and a lock inside it cancels the
    start. A spawn error or a non-zero exit is logged with the status and systemctl's
    stderr. It does not notify, because a broken rule would then pop up at every unlock.
- **Permission:** `files/etc/polkit-1/rules.d/50-displaylink-dock-recovery.rules.j2` lets
  the desktop user START that one unit, from an active local session only. The sudoers
  precedent from Plan 00137 was not used, because it would also cover SSH sessions, and
  those never unlock anything.
- **Placement:** `play-displaylink.yml`, not a new play. The extension is useless without
  the recovery units that play deploys, so it ships wherever they do. `deploy.bash`
  already runs that play, so no new leg is needed.
- **Tests:** `tests/extensions/test-dock-recovery-on-unlock.mjs`, 14 cases, run by
  `scripts/test-panel-sections.bash`. RED was the import failure before the extension
  existed.
  - The stubs gained `Main.screenShield` and a subprocess that reports its exit. It returns
    stderr only when `STDERR_PIPE` was asked for, with GLib's real flag values
    (`gioenums.h`: `STDOUT_PIPE` 1\<<2, `STDERR_PIPE` 1\<<4).
  - A mutant spawning with `NONE` fails 2 cases.
  - The polkit rule is rendered and run against a stand-in `polkit`. The start is allowed;
    restart, stop, another unit, another action, another user, a remote session and an
    inactive one are all refused.
- **Review:** a qa-reviewer pass returned FIX-BEFORE-MERGE. The fixes are:
  - the plain statement of what an unlock sets off;
  - a HOST check that tells a refresh from a refusal;
  - the logout line when the extension changes;
  - the flags assertion;
  - the caller added to `run_recovery.py`.

Still open, HOST:

- **Docked:** deploy, log out and in, then lock and unlock. `journalctl -t displaylink-dock-recovery` shows `action=refresh_background` and `RECOVERY-BACKGROUND: refreshed` after the unlock; `action=none` alone is the refusal, not a pass.
- **Undocked:** no DVI-I connector under `/sys/class/drm/`.

**Review:** round 1 FIX-BEFORE-MERGE, round 2 PASS ([260924-qa-reviewer-t54a-opus-5.md](../subagent-reports/260924-qa-reviewer-t54a-opus-5.md)). Merged into F44. The HOST items under T5.4a still gate it.
