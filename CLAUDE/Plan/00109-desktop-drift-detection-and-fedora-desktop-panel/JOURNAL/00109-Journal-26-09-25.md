## 19:56 · finding · —   — the login report named two scratch plays as removed; they were never the repo's

After the reboot, the login report listed two plays under `untracked/scratch/` as "no
longer exists at HEAD". They were throwaway agent probes, run from scratch and since
deleted, so the ledger held a record for each. Any play run from outside the repo's
history is GONE at HEAD for ever, because it was never there, so it would be reported at
every login.

Fix in `helpers/play_ledger/check_freshness.py`: a GONE play that was not in the tree
of the commit it ran from is dropped (`_drop_never_tracked`). A tracked play that was
deleted is still reported. Only GONE plays are asked about, so a clean login costs no
extra git call. A git failure on the question answers untrustworthy. It is never
silence. `TestNeverTrackedPlays` has 5 cases, 4 of them red before the fix.
`TestRetiredPlays`' default stub now says a seeded play existed at the commit it ran
from, which is what a real tracked play does. The old default said it did not, which the
new rule reads as never tracked.
