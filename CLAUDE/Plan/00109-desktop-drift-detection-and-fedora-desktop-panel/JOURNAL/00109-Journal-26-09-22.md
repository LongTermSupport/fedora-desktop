## 14:10 · correction · the SIGPIPE site count was wrong twice, and so was the search

The 26-09-17 entries record this defect class as "roughly 56 other sites", then correct
that to "94, across 38 files". **Both are wrong. It is 137 repo-owned sites**, and the
reason is not arithmetic — each search was narrower than the defect it was counting.

Two independent blind spots. The second is the one that matters.

1. **The left-hand side was over-specified.** The pattern matched
   `(printf|echo|cat) … | grep -q`. The defect is `<any command> | grep -q` under
   `pipefail`: `grep -q` exits on match, the producer dies of SIGPIPE, and pipefail reports
   the pipeline by its worst member. `ss`, `nmcli`, `systemctl`, `container_cmd network ls`
   all qualify. The producer's identity was never part of the mechanism — it was just what
   the first example happened to use.

2. **`--include='*.bash' --include='*.sh'` never examined extensionless executables.**
   That is precisely where this repo's host tools live — `files/usr/local/bin/`,
   `files/home/.local/bin/`, `files/var/local/`. Re-searching by `#!` shebang found
   **28 sites in 13 host tools** that neither previous sweep looked at at all.

A glob that matches nothing is indistinguishable from a clean result. That is the same trap
this plan's 08:53 entry records against `--include="*.yaml"`, and the reason Plan 00076
exists. I hit it again four days later while writing the correction to the first count.

Method, so the number is reproducible: enumerate by shebang, then scope to repo-owned trees
(`files/ scripts/ helpers/ playbooks/ CLAUDE/ tests/ extensions/`). The unscoped figure runs
to four digits because `.claude/` and `.ansible/` carry vendored trees, and should not be
quoted.

## 14:10 · finding · one newly-visible site is NOT latent

Every site counted before today was latent — small left-hand sides that cannot fill the
64 KiB pipe buffer, so SIGPIPE never fires. That is still true of them.

`files/usr/local/bin/ssh-suspend-guard:36` is different, and it was invisible to both
earlier sweeps because the file has no extension:

```bash
if ss -tnp state established 'sport = :22' | grep -q sshd; then
```

`set -euo pipefail` is set at `:6`. There are two defects on that line, and **the first does
not need SIGPIPE at all**: port 22 is hardcoded. On a machine whose sshd listens elsewhere
the condition is never true, the inhibit lock is never taken, and the machine suspends in
the middle of an active SSH session — silently, which is the one outcome the guard exists to
prevent. The SIGPIPE inversion is the latent second defect on the same line.

The repo does not need a new fact to fix this: `helpers/sshd_ports/cli.py` already discovers
the real ports from `sshd -T`, and `play-lxc-install-config.yml` already consumes it. The
fix is to use the existing answer instead of assuming 22.

Not fixed here. It belongs with the firewalld/sshd-port issue recorded in Plan 00135's
out-of-scope section, because that issue's whole subject is the same port-22 assumption —
and this is its second, more damaging instance.
