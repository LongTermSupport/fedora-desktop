# Task 4.3 — the play runner section

Worker report for Plan 00109 Task 4.3. The decisions are recorded as settled in
[DESIGN-panel.md](../DESIGN-panel.md) §9; this file is what was built and how it was proven.

## What was built, producer to panel

1. **`helpers/play_ledger/check_freshness.run(judged=...)`**: an optional sink that receives
   every verdict of a complete judgement, fresh ones included. It stays empty on every path
   that answers untrustworthy: the BROKEN sentinel, an unreadable ledger, an unresolvable
   ledgered commit, or an unappliable retired-plays map.
2. **`helpers/host_health/play_runner.py`** (new):
   - `runnable(verdicts)` gives `{play, state}` rows under `playbooks/`, drops GONE plays, and
     sorts by path.
   - `validate(play, repo_root, ledgered)` is the gate. It requires an allowlisted
     repo-relative path under `playbooks/` ending `.yml`, spelled canonically (no `.` or
     `..` segment, no empty segment), that is listed in the ledger, sits inside
     `<checkout>/playbooks` after realpath, is a file, and is executable.
   - `main --validate PLAY` prints the absolute path on stdout, or `refused: <why>` on
     stderr with exit 64. It exits 2 when the ledger cannot be read.
3. **`status_document.build(plays=...)`**: a new always-present key `plays`, `[]` when there
   is nothing to offer. The key is added under schema 1 without a version bump, because the
   panel reads an absent key as "this document predates the runner" and says so.
   `_cannot_read` carries `plays: []` as well.
4. **`login_report`**: `freshness_findings(judged=...)` passes the sink through to the check.
   `main` collects the verdicts, and `record_host_state` and `publish` then carry
   `play_runner.runnable(judged)` into the document.
5. **`files/home/.local/bin/fedora-desktop-health.j2`**: new `--run-play <play>` option. It
   validates the name through the helper, then runs the play by its absolute path, so the
   play's own shebang hands it to `run.bash`. It reports the play's exit status on stderr
   and exits with that status. `--hold` still applies. A missing value is exit 64.
6. **Panel**:
   - `terminal.js` (new) holds `launchOnDemand(args, byHand)`, the one xdg-terminal-exec
     argv launcher. Both the health section's report row and the play runner use it, and the
     report row's messages are unchanged.
   - `labels.js` (new) holds the `wrap()` helper, moved out of `health.js` so both sections
     share it.
   - `statusDocument.playsOf(document)` is a defensive reader. It reports an absent key, a
     key of the wrong type, or dropped entries as reasons, and filters entries through the
     same path allowlist.
   - `sections/plays.js` (new) renders a header "Plays run on this machine" and one
     clickable row per play (`<path> — <state words>`). A state the panel has no words for
     is shown as it is. A click launches `--run-play <play> --hold` and notifies
     "Launched …"; it never says the play ran. `documentSections: []` means the section
     cannot move the icon.
   - `extension.js` registers the section as `SECTIONS = [healthSection, playsSection]`.
   - `stylesheet.css` gains `.fedora-desktop-play` with the 36em cap.
7. **The contract gate** now reads `sections/plays.js`. It demanded the new `plays` document
   key until the panel read it, which confirms it catches the change.

## Deployment

- **The panel** is deployed by `play-fedora-desktop-panel.yml`. It copies the whole
  extension directory, so the new files need no list change. A logout and login are needed
  on Wayland.
- **The command** is deployed by `play-host-health-login-report.yml`, which templates
  `fedora-desktop-health`.
- **The helpers** run from the checkout.
- **The `plays` list** first appears after the next graphical login's collection. Until
  then the panel shows the "does not list the plays run here" reason under a not-checked
  caveat.
- **No version bump is involved.** `metadata.json` `version` has not been bumped for JS
  changes before.

## Proven by test

- **`test_check_freshness.TestJudgedSink`**: fresh and stale verdicts both reach the sink; a
  broken ledger and an unresolvable commit leave it empty. All three tests failed before the
  change.
- **`test_play_runner`** (12 tests):
  - the rows, GONE plays left out, and plays outside `playbooks/` left out;
  - eleven malformed names refused, among them absolute paths, `..`, `//`, `./`, `.yaml`,
    a trailing newline, and a leading `-e`;
  - an unlisted play, a missing file, a file without its execute bit, and a symlink out of
    the tree are all refused;
  - `main` stdout carries the path and only the path; an unreadable ledger exits 2.
- **`test_status_document`**: the rows are carried; `[]` is present both when nothing is
  given and on a document that could not be read.
- **`test_login_report`**: the sink passes through `freshness_findings`, and the rows reach
  the document through `record_host_state`.
- **`scripts/test-fedora-desktop-health.bash`** (+13 checks), run against a fixture checkout
  whose `helpers` is a symlink to the real code and a fixture play that exits 5:
  - a ledgered play runs, and its status 5 becomes the command's;
  - an unlisted play and a non-canonical path are refused with 64 and do not run;
  - `--run-play` with no value exits 64;
  - `--hold` waits for Enter;
  - `--help` lists `--run-play`.
- **`tests/extensions/test-panel-sections.mjs`** (+13):
  - `playsOf` passes rows through, reports absent and wrong-type keys, and drops malformed
    entries with a reason;
  - rows and state words render, an unknown state is shown, "nothing to offer" is not
    clickable, and an unreadable list renders under the not-checked caveat;
  - the exact spawn argv is checked, and the notification says "Launched" and never
    "ran";
  - a missing command and a failed spawn are both reported;
  - rows wrap;
  - `documentSections` is empty.
- **`tests/extensions/test-panel-indicator.mjs`** (+2): the enabled extension renders the
  runner's rows (registry proof), and a stale play on a clean host leaves the icon neutral.
- **Gates**:
  - ESLint exit 0.
  - `qa-all.bash` is green on every gate except `ansible-syntax`, where all 81 playbooks
    fail because the vault password file exists only in the main checkout.
  - panel-sections passed 60, fedora-desktop-health passed 39, helper-tests ran 1804, and
    the panel contract agrees on 9 document keys, `plays` included.
