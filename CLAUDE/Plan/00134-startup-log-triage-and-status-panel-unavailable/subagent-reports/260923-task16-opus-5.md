# Task 1.6 — fileless runs against real Ansible, and ansible-console

Measured against ansible-core 2.19.13, the pipx venv that `ansible-playbook`'s shebang
names in the CCY container. Paths below are shortened to `<worktree>`.

## What the real CLIs set

| CLI                | `v2_playbook_on_start`?                                                         | `CLIARGS['args']`                                 |
| ------------------ | ------------------------------------------------------------------------------- | ------------------------------------------------- |
| `ansible-playbook` | yes, per playbook                                                               | a list of the playbook files (`["site.yml"]`)     |
| `ansible` (ad-hoc) | yes, with `playbook._file_name = '__adhoc_playbook__'` (`cli/adhoc.py:164,197`) | the host pattern, as a **string** (`"localhost"`) |
| `ansible-console`  | **no** (`cli/console.py:211-231`); no `v2_playbook_on_stats` either             | `None` (the pattern is in `CLIARGS['pattern']`)   |

`context.CLIARGS` is a process-wide singleton set on first parse. Parsing three CLIs in
one process reports the first CLI's arguments for all three, so each probe runs in its
own process.

## Decision on ansible-console

There IS a verifiable marker: a command line that named playbook files. Only
`ansible-playbook` puts a list of files in `CLIARGS['args']`. So
`plugin_support.names_playbooks(cliargs)` is the positive mark of a run whose plays have
files, and `play_to_record(..., names_playbooks=...)` skips a play when either signal
says it has no file: the ad-hoc marker, or a command line that named no playbook.

Fail-fast is kept where it matters:

- A playbook run that loses its playbook-start event still raises on a play with no
  position (`test_a_playbook_run_with_no_start_event_still_refuses`).
- If `ansible-playbook` stopped naming its files in `CLIARGS['args']`, every run would go
  unrecorded silently. `test_only_ansible_playbook_names_playbook_files` asks the real CLI
  and fails instead.

Rejected: skipping whenever no playbook-start event was seen. That signal is an absence,
and it is the one a future Ansible change to `ansible-playbook` would also produce, so it
would turn a regression into an empty ledger. The play name `Ansible Shell` was rejected
for the same reason as `Ansible Ad-Hoc`: any playbook can use it.

## Proven for real (not by fixture)

1. **Ad-hoc, fixed.** A real `ansible localhost -i localhost, -c local -m ping` from the
   checkout, with a throwaway `XDG_STATE_HOME` and a dummy vault file, gave `rc=0` and
   `ok: [localhost]`. The state dir stayed empty: no `BROKEN`, no `LEDGER-WRITE-FAILED`.
2. **Ad-hoc, negative control.** The same run with `ADHOC_PLAYBOOK_FILE` temporarily
   changed to a wrong value printed
   `LEDGER-WRITE-FAILED: ValueError: the play carries no source position …` and wrote
   `<state>/fedora-desktop/play-ledger/BROKEN`. So the callback is live for ad-hoc runs,
   and the skip is what keeps the ledger clean. The change was reverted, and `git status`
   was clean afterwards.
3. **Console, before the fix.** Piping `ping` / `exit` into
   `ansible-console localhost -i localhost, -c local` wrote `BROKEN` with the same
   message. This reproduces reviewer finding 5.
4. **Console, after the fix.** The same run showed `PLAY [Ansible Shell]` and
   `ok: [localhost]`, with the state dir empty.
5. **Mutation check.** Removing `or not names_playbooks` makes
   `test_a_real_console_run_leaves_the_ledger_untouched` fail.

## Now in the suite

`tests/helpers/play_ledger/test_source_position_against_real_ansible.py` has
`TestFilelessRunsAgainstRealAnsible`:

- `test_only_ansible_playbook_names_playbook_files`: each real CLI's parser, one process
  each, through `plugin_support.names_playbooks`.
- `test_the_callback_is_live_for_an_ad_hoc_run`: the control. A relative
  `XDG_STATE_HOME` makes the callback's constructor print the failure marker, so a silent
  ledger in the next two tests means something.
- `test_a_real_ad_hoc_run_leaves_the_ledger_untouched`.
- `test_a_real_console_run_leaves_the_ledger_untouched`.

The real runs use `-i localhost,`, a throwaway vault file and a temporary state home, so
they read nothing of the host's inventory or vault and never touch the real ledger. None
of them runs a playbook.

Fixture-only (unit tests in `test_plugin_support.py`): the `names_playbooks` shapes, and
`play_to_record` for each combination. The tautological constant test
(`ADHOC_PLAYBOOK_FILE == "__adhoc_playbook__"`) is removed; the real ad-hoc run and its
negative control cover that value now.
