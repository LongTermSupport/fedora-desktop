## 11:52 · finding · T1.1 — BROKEN ledger reproduced from an ad-hoc ansible run

`bin_ansible_callbacks = true` means the ledger callback runs for `ansible … -m`
too; an ad-hoc play has no `Origin` and no `ansible_pos`, so `play_source` raises
and the callback marks the ledger broken. Reproduced with
`XDG_STATE_HOME=$(mktemp -d) ansible localhost -m ping` — the throwaway dir gets a
`BROKEN` file with the identical reason, the real ledger untouched. Timestamp on the
host's sentinel matches a `python -c` invocation the day before the reboot, and
`runs.jsonl` has no record there — consistent with an ad-hoc run.

## 11:58 · decision · T1.1 — ad-hoc plays are skipped, not recorded as holes

The ledger's unit is a play *file* at a commit. An ad-hoc play has no file, so there
is nothing to ledger and nothing to be a hole about. A *playbook* play with no

## 16:40 · decision · T2.5 — desktop profile only, and the play owns its ABRT packages (PR #50)

A downstream headless consumer provisioning a server-profile VM aborted at `Probe ABRT
auto-reporting state`: `abrt-auto-reporting` is not on PATH there. Two facts behind the
fix. First, nothing in this repo installed ABRT on either profile — the desktop path
worked because the Workstation image ships it, which is a dependency the repo did not
know it had. Second, the policy is desktop-shaped: the applet and µReports have no
consumer on a headless box, and adopting ABRT on servers (running `abrtd`, pruning
records nobody reviews) would be a new capability rather than this fix, so the server
profile is not given it. The nine tasks sit in one block gated on
`provisioning_profile != 'server'`, the same gate fwupd takes, and the block's first task
installs `abrt` (provides `abrt-auto-reporting`) and `abrt-tui` (provides `abrt-cli`),
names confirmed with `dnf provides` on a Fedora 44 host. A desktop host that later
resolves to the server profile keeps its units and persisted block; only the sudo grant
is actively removed on a flip, for its security reason, and the doc says so. Not run
through `vmtest server-fast-provision` from this branch (no host available to the
session that wrote it); the downstream consumer re-provisions from the merge commit.
