## 12:01 · finding · —   — Bases current; refresh-base left build directories, fixed

The triage run through meta-deploy (`20261006-125042`) read all three VM-lab bases
`current`. It also listed `desktop-44.build` and `server-fast-44.build` beside the bases,
the leftover this triage was written to catch.

Cause: `refresh-base` calls `cmd_build_base` once per base in one process. The build
directory was removed only by the EXIT trap, which by then held the last build's
directory alone, and `BUILD_OK` was never reset, so a failed build after a good one would
have had its directory deleted rather than kept. Fixed by removing a successful build's
directory at the end of that build and dropping `BUILD_OK`: whatever `BUILD_DIR` is still
set at teardown belongs to a failed build. `vmtest` now runs `main` only when executed,
so the new test sources the real script; it was red first. The retention sweep evicts the
fast base's leftover and keeps desktop build directories for diagnosis, so the 328K
`desktop-44.build` goes at the next desktop base build.

`vmtest-nightly`'s last result is still exit-code 1, from 10:43, before the refresh.
