## 09:44 · action · T3.1 T3.2   — SELinux relabel on Permissive and the Docker backend assert, built and reviewed


The owner answered the three open decisions on 2026-09-24.

- **T3.1: option A, relabel whenever SELinux is not Disabled.** In CCY 3.65.0 the
  verdict (`selinux_enforcing_verdict`, `lib/common-pure.bash`) gives a Permissive host a
  new answer, `permissive`, when the engine labels. It relabels exactly as `enforcing`
  does:

  - the workspace is mounted `:z`;
  - the config import is mounted `Z`;
  - keys are staged into a private tmpfs;
  - the launch prints `🔒 SELinux permissive`.

  A Permissive host whose engine does not label still gets `off`, and a Permissive host
  with an unreadable engine report gets `unknown`, which also relabels. Every consumer
  tests `!= off`, so no caller changes meaning.

  - **Test:** `scripts/test-ccy-selinux-verdict.bash`. It was RED on two cases (Permissive
    with a labelling engine, and Permissive with an empty report) and is GREEN at 16/16.
  - **Docs:** `docs/ccy.md` (SELinux section) and `docs/ccy-changelog.md` (3.65.0).

- **T3.2: the proposal as written.** `play-lxc-install-config.yml` reads `docker info`
  (with `check_mode: false`, since it only reads) and asserts that the firewall backend
  is `iptables` or `iptables+firewalld`. The assert comes before the DOCKER-USER tasks,
  and only where dockerd is installed. Under the nftables backend, or when there is no
  `Firewall Backend` line, the play stops and names the reason. The per-boot firewalld
  `COMMAND_FAILED` noise stays unsilenced. `docs/playbooks.md` now mentions the stop.

- **Criterion:** the `RuntimeMaxSec= has no effect` half now covers only units this repo
  deploys. The warning from another project's unit is out of scope.
