## 11:00 · finding · P4 — why manual/unshare removal fails; real root is the key

User confirmed a direct `rm` / `podman unshare rm -rf tempdirs` still returns
`Permission denied` on `diff/run/systemd/netif/{leases,links,lldp}` etc. Cause:
those files are owned by UIDs OUTSIDE the user's /etc/subuid map, so both the
plain user AND `podman unshare` (namespaced root, confined to the sub-UID map)
lack authority. **Real host root** (uid 0, initial ns, CAP_DAC_OVERRIDE over all
UIDs) can. tempdirs is orphaned scratch not referenced by running containers, so
removing it is safe with live sessions — unlike prune/reset, which are NOT used.
