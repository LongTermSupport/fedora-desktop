## 11:00 · finding · P4 — why manual/unshare removal fails; real root is the key

User confirmed a direct `rm` / `podman unshare rm -rf tempdirs` still returns
`Permission denied` on `diff/run/systemd/netif/{leases,links,lldp}` etc. Cause:
those files are owned by UIDs OUTSIDE the user's /etc/subuid map, so both the
plain user AND `podman unshare` (namespaced root, confined to the sub-UID map)
lack authority. **Real host root** (uid 0, initial ns, CAP_DAC_OVERRIDE over all
UIDs) can. tempdirs is orphaned scratch not referenced by running containers, so
removing it is safe with live sessions — unlike prune/reset, which are NOT used.

## Repair play no-op'd on first HOST run — regex vs escaped quotes (root-caused, fixed)

First HOST run of the repair play FAILED its final assert: `Incomplete layers
removed this run: []`, store still rc=125, podman still naming `2737e78…`. Did
NOT guess — read the mechanism from the captured bytes. The play extracted
incomplete-layer ids with `regex_findall('Found incomplete layer "([0-9a-f]{64})"')`
— a BARE quote before the id. But podman's logrus text formatter escapes the
inner quotes, so the literal stderr is `Found incomplete layer \"<id>\", deleting
it` (backslash-quote). Bare-quote regex → 0 matches → the `file: state: absent`
loop iterated over an empty list → removed nothing. Proven by replaying the exact
stderr line from the triage log through Python `re`: old pattern → `[]`, new
pattern `incomplete layer[^0-9a-f]*([0-9a-f]{64})` → `['2737e78…']`.

Fixed the regex (anchor on the phrase, then skip any non-hex run — robust to
whatever quoting podman uses). `ansible-playbook --syntax-check` clean.

Also per user steer: MOVED the playbook out of `playbooks/imports/` into the plan
folder (`podman-store-repair.yml`) — it is plan-local incident recovery, not
durable IaC. Updated `reclaim`'s HOST-repair pointer to the new path (v1.0.3) and
the header run-commands. Being outside `playbooks/`, it is no longer auto
syntax-checked by `qa-ansible-syntax`; documented the manual `--syntax-check` in
Plan-Local Scripts. QA green (405).
