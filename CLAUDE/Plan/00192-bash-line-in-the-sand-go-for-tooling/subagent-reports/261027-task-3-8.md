## Where the reasons came from

- `run.bash --changed` printed no reasons: `helpers/play_ledger/changed_plays.py` writes only
  `RUN`/`UNRESOLVED`/`GONE` markers to stdout, and run.bash lists the play names.
- The reasons a person read were the login report's, from `check_freshness._verdict`
  (`changed: <up to 3 paths> and N more`), which the panel's play rows share. Paths came in
  diff order, so play files and `playbooks/imports/play-golang.yml` (an input of every
  Go-building play) filled the three, and the Go files fell into the count.

## Change (tests first)

- `helpers/self_update/affected_plays.py`: `Inputs.go_builders` maps each Go package to the
  names of the commands built from it (the dependency walk is now per command, with a cache
  of each package's imports); `go_changes(inputs, paths)` gives the changed packages in the
  order seen, each with its commands.
- `helpers/play_ledger/changed_plays.py`: `Judgement.changed_go` (defaulted, so existing
  constructors stand); `reasons(judgement, play)` is the one formatter, moved from
  `check_freshness`. A Go change gets its own line, so other paths cannot hide it:
  `changed Go packages: src-go/internal/ui (built into podfreeze)`, with up to three packages
  and three commands and the rest counted (`and 2 more`, `and 4 more commands`). Files in a
  changed package leave the `changed:` line. Without `--all`, `run` writes
  `changed-plays: <play>: <reasons>` to stderr for each RUN play, so `run.bash --changed` (and
  meta-deploy's log) shows them before its list. run.bash is unchanged; no version bump.
- `helpers/play_ledger/check_freshness.py` calls `changed_plays.reasons`.
- `docs/playbooks.md`: both descriptions say what the reasons name.
