## Defect and class

Originating instance: `tasks/build-go-command.yml:93`, `chdir: ... (root_dir ~ '/src-go')`. The
mapper behind `--changed` (`helpers/self_update/affected_plays.play_inputs`, read by
`helpers/play_ledger/changed_plays.judge`) read only `{{ root_dir }}/<path>`. So no play that
builds a Go command had any of src-go as an input, not even its own `src-go/cmd/<name>`, and a
change to `src-go/internal/ui` left `play-podfreeze.yml` and `play-lxcfreeze.yml` unrun.

Class: a checkout reference in a host play's walked YAML that the mapper neither follows nor
reports UNRESOLVED. Hazard: the play silently never runs again when that path changes.

## Rule

`play-input-dropped`, in `tests/helpers/self_update/test_dropped_input_rule.py`, documented at
`CLAUDE/QA.md#play-input-dropped`. Message:
`[play-input-dropped] <play> drops checkout references the mapper neither follows nor reports; see CLAUDE/QA.md#play-input-dropped:` and one `file:line: <reference>` per finding.

Width: on every non-comment line of every YAML file a host play walks, `{{ root_dir }}/<path>`
(and root_dir's config lookup) and the joins `root_dir ~ '/<path>'` / `root_dir + '/<path>'`,
with its own patterns, not the mapper's. Accounted for: the path is an input, an UNRESOLVED
entry names the line, or (a Go module root) the mapper took it as that module's builds.
Excluded as hazard-free: the bare root (`chdir: "{{ root_dir }}"`, argv elements,
`-X main.RootDir=`), which is the working directory of `python3 -m helpers.x` (whose package
the mapper follows) or a value handed to a program. Next wider rule considered and not built:
any checkout path handed to a program that reads what it likes; what such a program reads is
not in the play text for a reader of text to judge (the three such inputs found are Task 3.7).

## Fixes

All in the mapper (`helpers/self_update/affected_plays.py`); no play was reworded.

- The joins: `root_dir ~|+ '<path>'` is followed like a rooted path; a glob or a join that goes
  on is a prefix on its literal part (`.qa-versions` exact, vm-test-lab's
  `files/home/.local/share/vmtest/*.bash` a prefix); a join with no literal path
  (`root_dir ~ '/' ~ vault_cfg_path`) is UNRESOLVED, as play-self-update already was for 361.
- A Go module root (a directory holding go.mod) is taken as the play's Go builds: each
  `go_command_name` (a `{{ var }}` value resolved through the `var:` the walked files set, the
  freeze plays' `freeze_tool`) builds `<module>/cmd/<name>`, and every package it imports,
  transitively, in the module and `vendor/`, is an input, with go.mod, go.sum,
  `vendor/modules.txt` and embedded directories. A package counts its own files, not
  subdirectories or `_test.go`. A pinned external module (`go_command_module`, md-viewer)
  brings nothing from src-go. No name, an unset variable, or a missing `cmd/<name>` is
  UNRESOLVED.
- Imports are read from the source, not `go list`, so `--changed` needs no toolchain; every
  non-test file counts whatever its build tag (a superset). The real-repo test holds it to
  `go list -deps` for all 24 commands of the 12 plays: equal, bar two build-tagged extras in
  claude-yolo's set (`internal/ccylaunch/difftest/pinclock`, `vendor/golang.org/x/sys/windows`).

Each of the 15 instances was examined individually; 13 share the one site
(`build-go-command.yml:93`), so one change fixed them. Nothing is suppressed or baselined.
