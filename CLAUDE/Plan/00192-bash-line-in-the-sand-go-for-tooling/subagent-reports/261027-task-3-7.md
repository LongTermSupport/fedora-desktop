# Task 3.7: what the programs a play runs read is counted (Defence Before Fix)

Branch `fix/00192-hidden-play-inputs` from F44 `d82ef9ffb`. Commits: the rule alone, proved on
fixtures; then the mapper fix, the declarations, the sweep test and the plan updates, with this
report. The group_vars item is decided (not counted) and was not built.

## Defect and class

`helpers/github_scopes/cli.py` reads `vars/github-required-scopes.yml` through `__file__`, so
`play-github-cli-multi.yml` never ran again when the required scopes changed.
`scripts/qa-toolchain.bash`, run by `play-python.yml`, sources `scripts/lib/go-tool.bash` and
builds and runs `src-go/qa/cmd/qa-toolchain`, which reads `src-go/go.mod` and `src-go/qa/go.mod`.
None of these was an input. Class: a program a host play runs reads a checkout path that is not
an input of that play. `play-input-dropped` reads only the play text, so it cannot see this.

## Rule

`play-program-read-dropped`, in `tests/helpers/self_update/test_program_read_rule.py`, documented
at `CLAUDE/QA.md#play-program-read-dropped`. It uses its own patterns, not the mapper's:

- in each helper package that is an input: a `__file__` path with literal segments, or a
  quoted literal naming an existing checkout path outside the package (with a `/`, or a root
  dot-file);
- in each bash input: a `source` of a file beside it, and a `run_go_tool`/`run_go_command`;
- in the Go packages of a command a script runs this way: literals naming checkout paths.

Not judged: a bare `__file__` climb (a `--repo-root` default or a `sys.path` entry), a source of
a host path or a runtime variable, the literals of Go commands a play installs (those run later
and read live), `__file__` in quotes or backticks, and literals listed for their module in
`affected_plays.NOT_PLAY_INPUTS`. That table is loaded from
`helpers/self_update/not-play-inputs.json`, each entry with its reason. It is kept outside the
modules because `agent_bus/checkout.py` and `pingbus/statusline.py` are baked into the ccy image,
and the commit hook demanded a container version bump for a constant added there. It is kept
outside the mapper's own source because the mapper scans that source's literals too. A test
fails any entry whose module no longer names the literal.

## Fix (mapper, `helpers/self_update/affected_plays.py`)

- **Helper modules.** Each module of a followed helper package is scanned for two forms, each
  resolved against the file:

  - `Path(__file__)[.resolve()](.parent…|.parents[N]) / "seg"…`;
  - `os.path.join(dirname…(realpath|abspath(__file__)), "seg"…)`.

  A `__file__` form that is not recognised is UNRESOLVED. Literal checkout paths are counted
  too. A read is an input as content, so a YAML file a helper reads is not walked as a play.

- **Bash inputs** (by extension or shebang). A sourced sibling is followed. `run_go_tool` and
  `run_go_command` build `<module>/cmd/<name>` (`src-go/qa`, `src-go`): that adds the command's
  packages, `go.mod`/`go.sum`, and the checkout files named by the literals in its non-test
  sources. A missing command or library is UNRESOLVED.

- **Tests first.** `TestHelperReads` and `TestScriptReads` (fixtures), plus two real-repo tests:

  - the scopes file runs github-cli-multi;
  - go-tool.bash, both go.mods and `src-go/qa/toolchain/pins.go` run play-python, and the
    reason names `qa-toolchain`.

  All of them were red before the fix (12 failures). The `go list -deps` oracle test now
  handles the nested module that has no vendor tree.

## Judgement calls for the owner

- Helpers are judged a whole package at a time, so the gnome plays count
  `vars/fedora-version.yml` from `check_extension_compat.py` even though no play runs that
  module. This errs toward running a play too often, never too rarely.
- The github-cli-multi play names `scripts/gh-account-setup.bash` only in a remedy message.
  Counting its Go build is again on the side of running too often.
