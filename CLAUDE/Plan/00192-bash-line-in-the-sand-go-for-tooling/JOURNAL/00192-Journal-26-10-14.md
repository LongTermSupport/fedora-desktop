> **Append-only activity log** for plan 00192. One file per day
> (`00192-Journal-YY-MM-DD.md`). `PLAN.md` tracks the plan (what/why,
> current state, tasks); this journal tracks what actually *happened* —
> findings, decisions, dead-ends, hand-off state — the linear lifecycle a plan
> document structurally cannot carry.
>
> **Entry grammar** — append new entries at the BOTTOM; NEVER edit earlier
> entries (corrections are new entries):
>
> ```
> ## HH:MM · category · REF   — optional short title
> ```
>
> - `HH:MM` UTC 24h (the date is in the filename, also UTC); times increase
>   down the file. A file with no sentinel line above predates this system —
>   its times are local, zone unrecorded (legacy; never rewritten).
> - `category` ∈ `action` | `finding` | `decision` | `thought` | `blocker` | `handoff`
> - `REF` = optional task/phase ref (`T1.2`, `P1`) or `—`.
> - Bodies may embed fenced logs/diffs/snippets — no size limit — with a
>   one-line takeaway above the fence.
> - End a working session with a `handoff` entry so the next agent's entry
>   point is the last entry of the newest day-file.

## 07:08 · decision · —   — The line, its thresholds, and the first work

The owner drew the line (2026-10-14): no more tooling in bash; bash only for very small helpers;
standalone Python follows later. Two read-only surveys ran first. INVENTORY.md: 192 bash tooling
scripts outside plan folders (about 42k code lines) plus 74 test suites; the one Go-to-Python seam
is declare.py. AUDIT-go-qa-ci.md: go-qa-ci is feature-complete with honest recorded gaps, but its
bundled rule set is one analyzer and this repo has no project DBF rules at all.

Decision on the thresholds, from the inventory's counts: at most 60 code lines and 4 functions, no
associative arrays, no interactive UI (gum, fzf, whiptail, dialog, select), no data parsing beyond
one jq -r lookup. The last is written but not gated (a gate cannot tell one lookup from parsing).
Exempt by category: shell snippets sourced into user shells, the run.bash bootstrap, test suites,
plan-local scaffolding. Existing offenders go on a ratchet allowlist that may only shrink.

In flight on worktree branches: the gate, written in Go (stdlib, main module), with the allowlist
and a guard against entries being added; project DBF rules as go/analysis analyzers (exec seam,
command-ownership seams for sudo/tmux/gum/fzf/systemctl/git, wall clock in tests, bare ~
handling), kept out of the shipped binaries' dependency closure. The rule is in CLAUDE.md and
README.md now.
