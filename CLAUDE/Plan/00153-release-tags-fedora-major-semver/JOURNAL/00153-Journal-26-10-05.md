# Plan 00153 — Journal 26-10-05

_Scaffolded by `mkplan.bash`; timestamps in this file are UTC._

> **Append-only activity log** for plan 00153. One file per day
> (`00153-Journal-YY-MM-DD.md`). `PLAN.md` tracks the plan (what/why,
> current state, tasks); this journal tracks what actually *happened* —
> findings, decisions, dead-ends, hand-off state — the linear lifecycle a plan
> document structurally cannot carry.
>
> **Entry grammar** — append new entries at the BOTTOM; NEVER edit earlier
> entries (corrections are new entries):
>
> ```
> ## HH:MM · category · REF   — optional short title
> ```
>
> - `HH:MM` UTC 24h (the date is in the filename, also UTC); times increase
>   down the file. A file with no sentinel line above predates this system —
>   its times are local, zone unrecorded (legacy; never rewritten).
> - `category` ∈ `action` | `finding` | `decision` | `thought` | `blocker` | `handoff`
> - `REF` = optional task/phase ref (`T1.2`, `P1`) or `—`.
> - Bodies may embed fenced logs/diffs/snippets — no size limit — with a
>   one-line takeaway above the fence.
> - End a working session with a `handoff` entry so the next agent's entry
>   point is the last entry of the newest day-file.

## 08:38 · action · —   — Phase 2 built: release command, workflow, docs

Phase 2 built. Design consequence found while writing the tests: F44 takes changes only by pull request, so the release command cannot push a changelog commit to it. It is two steps: `prepare` makes the signed `Release <version>` commit on a release branch and opens the PR; `tag` runs after a merge-commit merge and signs the tag on that release commit rather than GitHub's merge commit. The self-update design already only asks that the tagged commit is reachable from the branch and owner-signed, so it needs no change.

The 42 cases drive the real script against a signed fixture repository with only `gh` stubbed (CI answers success, failure, pending or none). They cover each refusal, numeric ordering with a release-candidate tag ignored, the changelog contents, and that the tag lands on the release commit and is annotated, signed and pushed. The first run had one failing case, a fixture bug (the clone did not check out the branch); fixed in the test.

The first real release will also need F44's CI to be green: the last run on the branch failed at the wsi-stream unit tests, which need a `textual` package CI does not have. That comes from the speech-to-text work, not this plan, and is reported to the owner.
