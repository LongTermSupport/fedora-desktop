## 09:54 · finding · —   — Stage A play written: declare check is unbuilt, and other findings

Stage A's play is written (play-teamchat.yml, the controller build task, the architecture table,
v2's own Tuwunel pin file, the installplay tests, a cross-build QA stage). Building it found four
things the plan and the design had wrong or silent about:

- `teamchat-admin declare check` is not built. The verb table lists it, its run function is nil,
  and it answers "not built yet". Only the library declare.Check exists, and nothing renders a
  host's Ansible declaration into the cross-team checks. `team apply` holds the approval gate
  itself (exit 70), so one team on one host is safe without it; several teams are not covered.
  Recorded as a decision for the coordinator, with a recommendation to build it next.
- The owner's approval gate (DC18) has no owner on a remote host. The play approves the teams an
  operator names in teamchat_approve_teams, exactly as declared; an unlisted new or changed team is
  refused by `team apply`.
- The v2 files may not name v1 files or v1 names (the teamchat-keeps-off-v1 gate): the play
  cannot read v1's Tuwunel pin, and its build task must be a teamchat-named file. v2 now has its
  own pin file with the same values.
- The source digest the binaries carry has no implementation (the closure-based scheme of 3.13 is
  unbuilt). Stage A uses the git tree id of src-go at a clean commit.

Also decided while building, and said in INSTALL-PATH.md: the play never starts a firewall (it
refuses a host whose firewalld is not running, since starting one can cut off the ssh that runs
the play), and the bus address, the LXC phases and installed.json are refused or left out by name
until something reads them.

Not run: the play has not been run anywhere. This container never runs Ansible; the syntax check,
qa-ansible and the Go tests over its text and tables pass. Its first run is the VM-lab scenario.
