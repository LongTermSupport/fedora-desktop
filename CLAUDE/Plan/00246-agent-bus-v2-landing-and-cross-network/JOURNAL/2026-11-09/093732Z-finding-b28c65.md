## 09:37 · finding · —   — Install-path plan: declare check cannot run as root

Correction to the entry before it: the plan said `declare check` runs as root from a staging
directory on the remote host. It cannot: the verb is `ClassOther` (`admin/class.go`, and the class
check in `admin/run.go`), refused to root and to the teamchat-ctl account with exit 77, so that line
of the plan would have failed on its first run.

The play instead runs the copied, digest-named `teamchat-admin` as `nobody` through `setpriv`
(reuid, regid, and the owner group as the one supplementary group, so the set records the v1-name
rule reads stay readable). The binaries are copied straight to their digest-named homes, which
nothing links to until the check passes, so there is no staging directory. INSTALL-PATH.md says
this now. The unit-printing verb is named: `units print <name>` and `units list`, any caller.

How it was found: reading the verb table while sizing stage A's Go work, before any code was
written. The plan made a claim about code that its first review could not catch without reading
the verb's class. The check for this kind of claim is to read the code a plan step runs before the
step is written down.
