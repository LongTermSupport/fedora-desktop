## 14:39 · action · —   — The Go tests that passed only as root, fixed as a class

The first CI run of the Go tests (pull request 124) failed in six packages of `internal/teamchat`,
all of which pass in an agent container because it runs as root. They were fixed on
`spike/v2-merge-up` as a class, in the order Defence Before Fix gives.

Three causes, not two: (1) tests that make "a file another user owns" with `os.Lchown` or
`os.Chown`; (2) the guest root's fixtures, which assume the tree they build is owned by host uid 0;
(3) `homefs.mkdirAt` opening for reading the directory it had just made, which fails for a user
whose umask takes the owner's read bit off, and two tests that made temporary directories under a
umask of 0777, which an unprivileged user cannot read. The third was missed in the first report:
three of the eight `homefs` failures were "permission denied", not chown.

The rule is `project_test_chown` (catalogue section in GoProjectRules.md; fixtures `badchown` and
`guardedchown`; the reporting off turns all 14 `want` lines red and each of the three guards
removed turns `guardedchown` red). It found 8 sites, the same in the default, `busfailpoints`,
`tuwunel`, `ccyteamstest` and `difftest` builds and none in the nested `qa` module, and the tree
is clean after the fix. It does not flag a chown in a branch that tests the user is root, in a
function that skips when the user is not root, or in the init of an `if` whose body skips; those
tests run nowhere CI runs, which stays the owner's question on the pull request.

The fixes take the expected owner as a value, defaulting to production's: `homefs.Owner` with
`OpenFor` (and `Open` as `OpenFor(Caller)`), `proof`'s `scanAs`, and `guestroot.OpenDirOwning` with
an `OwnerOf`, where `hostRoot` is the host uid and gid that are the guest's root (0 and 0 for a
pinned guest, the fixture directory's owner for a fixture). Info reports hostRoot's files as uid 0
and a writer chowns what it makes to hostRoot. The 30 minute hang had one cause: with the walk
refusing the tree, `TestALateDialIsClosed` (and in CI `TestAStalledWriteEndsAtItsBound`) waited on
a socket nothing connected to. The first report said that cause was unverified; as uid 65534 the
whole `guestroot` package now passes in 2.7 s. Each owner check (homefs file and directory, proof,
guestroot's override) was dropped in turn and went red on the intended test.

As uid 65534 on a copy of the tree, 63 of the 65 `internal/teamchat` packages pass; the two that
do not (`failpoint`, `matrix/fakehs`) need the checkout's `.git` and `tests/`, which the copy lacks,
and pass as root on the same copy. As root everything passes, and `qa-changed` passed. Left, as
questions on the pull request: the older tests that skip when not root (guest, teamlock, seat,
bus/seat, admin), and whether the agent containers get a gate that runs the Go tests unprivileged.
