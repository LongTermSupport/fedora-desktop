## 12:52 · action · T1.1 — gh-<alias> wrapper status line → stderr

Root cause confirmed in `playbooks/imports/play-github-cli-multi.yml`: the
generated `gh-{{ alias }}()` wrapper (the `gh-<alias>` consumer path) did
`echo "Switching to {{ username }}..."` on **stdout** at line 781, before
`gh "$@"`. Any `$(gh-<alias> … --json)` capture got that chatter mixed into the
JSON — but only when the account wasn't the box default (the `current_active`
branch). One-word fix: appended `>&2` (plus a WHY comment). Note the sibling
`gh-switch` line uses a different message format (`Switching to <alias>
(<user>)...`) and is a manual command, not a gh passthrough — left for the
audit to classify rather than blanket-fixing.

## 13:02 · decision · P3 — stderr hygiene = its own first-class standard, not folded into InteractiveScripts

`CLAUDE/InteractiveScripts.md` rule 08 already says "prompts/diagnostics →
stderr; machine output → stdout", but that doc is scoped to *human-interactive*
scripts (its litmus test: calls `read`, shows a menu, asks `[y/N]`). The gh
wrapper bug is in a **non-interactive** generated function — outside that scope.
So authored a standalone `CLAUDE/StderrHygiene.md` (the general rule: stdout =
captured payload, all chatter → `>&2`; decision procedure; bash + passthrough +
Python-marker patterns; the "help/status/report command stdout is legitimately
the payload — NOT a bug" carve-out; review checklist). Wired it in as a
first-class Critical Rules subsection in `CLAUDE.md` + an index-table row, and
back-linked it from InteractiveScripts.md rule 08 so the subset/superset
relationship is explicit and the two can't drift.
